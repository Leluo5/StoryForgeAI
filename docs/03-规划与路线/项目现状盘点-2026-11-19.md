## 一、盘点结论（TL;DR）

1. **架构双轨并行**：旧 Flask/原生 JS 业务链路（Python 3.10+ / Flask 2.x + JSON 文件存储）与**新 TS Monorepo 目标架构**（NestJS 11 / React 19 / TypeORM / PostgreSQL 16 / Redis 7 / BullMQ / pnpm 10）并存。旧链路**未迁移、未双写、未退场**，新架构为其增量目标，唯一写入方切换归 M4。
2. **里程碑体系**：M0（工程基座）/ M1（写作基座）已完成，M2（变更协作）/ M3a（AI 创作基座）/ M3b（Agent 与工具）/ M3c-1（剧情第一阶段）已交付；**M3c-2（剧情第二阶段，自动建树）、M4（迁移切换）、M5（发布加固）待实施**。
3. **CI 门禁三层**：quality（lint/typecheck/build）/ test（vitest + API E2E）/ m1（M0–M3c 全链路含浏览器 E2E），已通过 PR #4/#5/#6 合并落地。

5. **测试基线**：vitest 341 用例、pytest 760、M3c-1 浏览器 E2E 5/5、API E2E 11/11，`pnpm run ci` 全绿。

## 七、进行中工作（未提交）

> 以下为**另一条进行中工作流**（后端容器化部署，M6/上线准备相关），尚未提交到 `main`，与本盘点的文档口径同步无直接关系，但盘点需如实记录以免遗漏。

| 改动 | 类型 | 说明 |
| --- | --- | --- |
| `infra/docker-compose.yml` | 修改 | 追加 `api`（NestJS + BullMQ Worker 同进程）、`migrate`（一次性迁移）服务 |
| `Dockerfile` | 新增 | 根级多阶段构建（api 运行镜像） |
| `apps/web/Dockerfile` | 新增 | 前端构建 → nginx 静态托管 |
| `apps/web/nginx.conf` | 新增 | SPA history 路由回退到 `index.html` |
| `infra/Caddyfile` | 新增 | 同域反代（`/api/*` → api，其余 → web），消除跨域 |
| `docs/05-测试与验收报告/后端容器化部署方案.md` | 新增 | 部署方案：云主机 + Docker Compose 一键编排，不走 FunctionWeb 平台 |

**部署路线结论**：`apps/api`（NestJS + TypeORM + BullMQ）与 Trae FunctionWeb（nodejs20）契约不兼容（Node 22、监听 127.0.0.1:3001、需外部 PG/Redis、依赖部署时迁移），故**不走部署平台，改用云主机 + Docker Compose**。AI 模型 Provider 当前为 Mock（`AiModelProvider` / `PlotModelProvider`），生产需接入真实模型。

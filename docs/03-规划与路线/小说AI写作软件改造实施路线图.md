## 一、改造目标与衡量指标

### 1.1 改造定位

将 `StoryForgeAI`（现为「Coze 作品展示与在线体验平台」）改造为**专业小说 AI 写作软件**，核心是把「单一作品在线体验」升级为「角色驱动的小说创作工作台」。

改造不推倒既有架构，而是叠加四块新能力：

1. **角色专属 cozeAgent 分配机制**：为每个小说角色独立配置、绑定、管理独立 cozeAgent 实例，保证角色身份一致性、记忆连续性、行为逻辑独立性；支持单角色绑定多个 cozeAgent 按预设流程有序调用。
2. **写作工具集成**：完整集成参考图片中的 14 个写作工具模块，与角色 Agent 体系深度联动，无功能断点、无调用延迟。
3. **多角色协同写作**：多个角色 Agent 在同一小说项目下协同推进情节，数据流转规则清晰。
4. **创作工具模块扩展**：在既有 14 个写作工具之上，新增知识库管理（F5，含小说大纲自动提取）、剧情推衍聊天室（F6）、剧情树（F7）、角色版图（F8）四个创作工具模块，与角色 Agent 体系双向联动。

### 1.2 目标与衡量指标

| 指标 | 目标值 | 口径 |
| --- | --- | --- |
| 角色 Agent 调用成功率 | ≥ 99.5% | 连续 7 天，按调用次数统计 |
| 接口响应时间（非流式 API） | ≤ 200ms | P95，内网/本机 95% 分位 |
| 流式首包时间 | < 500ms | P95，SSE 首个 delta 到达 |

| 写作工具可用率 | 100% | 14 个工具全部可调用 |

| 并发承载 | ≥ 50 并发 | 同时在线写作会话数 |

| 创作工具模块可用率 | 100% | F5/F6/F7/F8 四模块全部可调用 |

### 1.3 成功验收标准（总）

1. 全部 14 个写作工具模块可调用，且与角色 Agent 体系联动，无功能断点。
2. 每个小说角色可独立配置 ≥ 1 个 cozeAgent；单角色支持绑定多 Agent 并按 11 步预设流程有序调用。
3. 角色身份一致性、记忆连续性、行为逻辑独立性通过自动化测试 + 手动验证双重确认。
4. 接口响应 ≤ 200ms、Agent 调用成功率 ≥ 99.5%、并发 ≥ 50 等量化指标全部达标。
5. 已知安全问题 C-001~C-004 全部修复。
6. F5 知识库（含大纲自动提取）、F6 剧情推衍聊天室、F7 剧情树、F8 角色版图、F9 角色头像与连线配色五个创作工具模块全部实现，与角色 Agent 体系联动，剧情树与聊天室推衍双向贯通；角色版图实现全员图谱可视化、多维度筛选与角色成长线呈现；F9 实现形象特征驱动头像生成、实时同步与关系连线唯一配色。

### 5.4 核心技术要点

**角色调度器（核心逻辑）**：

```python
# 伪代码：单角色多 Agent 有序调用
def invoke_role_agents(role_id, step_order, context):
    bindings = role_store.get_bindings(role_id, enabled=True)
    bindings = sorted(bindings, key=lambda b: b.step_order)  # 按流程排序
    for binding in bindings:
        if binding.step_order == step_order or binding.step_order <= step_order:
            result = agent_client.invoke(binding.agent_id, context, role_id)
            context = merge_result(context, result)  # 上下文透传
    return context
```

**角色身份一致性**：

- 每次调用携带 `role_id` 作为系统提示词前缀：`你扮演角色<role_id>，保持身份一致`。
- 会话 `conversation_id` 按 `role_id + agent_id` 维度隔离，禁止跨角色复用。

**记忆连续性**：

- `Agent会话` 表存 `memory_state`（JSON），跨会话恢复；角色记忆按 role_id 独立命名空间。

**行为逻辑独立性**：

- 每个角色 Agent 绑定独立 `agent_id`，不共享上下文；多角色并行时用 `project_id` 锁粒度防写冲突。

**性能要点**：

- 调度器内不阻塞：同步调用走线程池（`concurrent.futures.ThreadPoolExecutor`），上限可配。
- 存储读写加文件锁（`fcntl` / `msvcrt`），防并发写坏 JSON。

### 11.2 风险应对执行步骤

**R1 字段漂移**：在 `coze_client.py` 增加字段映射表；对每个新拉取字段 `.get()` 容错；字段缺失记日志不抛异常；升级 Coze API 版本时跑回归。

**R2 长任务阻塞**：注册中心识别长任务工具 → 提交任务队列 → 返回 `task_id` → 前端轮询 `/api/tasks/<id>/progress`；主 SSE 通道不被长任务占用。

**R4 上下文串线**：会话 key = `f"{role_id}:{agent_id}"`；每次调用校验 role_id 归属；不一致抛错并告警。

**R5/R6 安全**：按 P2-T6 方案执行，C-001 补鉴权、C-002 改哈希、C-003 迁环境变量、C-004 持久化会话；修复后跑安全复测。

**R7 进度延迟**：需求范围冻结；变更必须走 ADR；每周里程碑检查，偏差 > 2 天升级上报。

**R8 性能不达标**：P5-T2 预压测；不达标则线程池扩容、加缓存（`functools.lru_cache`）、降级非关键路径。

**R9 体验割裂**：工具面板与角色面板统一状态管理；联动交互走设计评审；上线前用户走查。

**R10 数据迁移损坏**：迁移脚本先备份 `data/`；迁移后校验（行数/字段/引用完整性）；失败自动回滚备份。

**R11 70 步工作流超时**：设置单次调用超时（默认 120s）；失败重试 ≤ 2 次；仍失败入死信队列并告警，不阻塞其他任务。

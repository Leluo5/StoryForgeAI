# 数据库迁移记录

> 维护 StoryForgeAPI 全部 TypeORM 迁移的执行清单、上线顺序与回滚说明。
> 数据来源：`apps/api/src/database/data-source.ts` 的 `migrations` 注册表。
> 铁律：`synchronize: false`、`migrationsRun: false`；**禁止**用 synchronize 改表结构，所有结构变更必须走迁移。

## 1. 运行与回滚

```bash
# 全量执行待应用迁移（生产 / 测试环境部署后必跑）
pnpm --filter @storyforge/api migration:run
# 等价于：tsx apps/api/src/database/run-migrations.ts

# 查看是否存在待应用迁移（CI 门禁用）
#   dataSource.showMigrations() === false  表示全部已应用、无遗漏

# 回滚最后一个已应用迁移（TypeORM 按时间戳逆序 undo）
#   dataSource.undoLastMigration()   —— 在脚本 / tsx 中调用，无独立 npm script
```

- 迁移按类名中的**时间戳升序**执行（TypeORM 内部排序，与 `data-source.ts` 数组顺序无关）。
- 回滚按时间戳**逆序**逐个 undo；若目标迁移不是最后一个，需先 undo 其后所有迁移。
- `down` 为破坏性操作：会 `DROP TABLE`，对应表数据丢失。回滚前务必确认无数据保留需求或已备份。

## 3. M3c-3 知识库迁移详解（本次交付新增 2 条）

### 3.1 `1760600000000-knowledge-base`（KnowledgeBase1760600000000）

- **up**：`CREATE EXTENSION IF NOT EXISTS pg_trgm`；创建 7 张表（`knowledge_entries` / `knowledge_entry_embeddings` / `knowledge_entry_links` / `knowledge_entry_tags` / `knowledge_tags` / `knowledge_work_refs` / `knowledge_jobs` / `knowledge_job_events`——含 embedding/jobs 表）及全部 CHECK 约束、部分唯一索引、trigram GIN 检索索引。
- **down**：按 FK 依赖逆序 `DROP TABLE ... CASCADE`；**不删除** `pg_trgm` 扩展（避免影响其他对象）。
- **前置依赖**：`authors`（#1）、`works`（#2）已存在（FK 引用）。
- **回滚影响**：删除所有知识数据，不可恢复；回滚前需备份。

### 3.2 `1760600001000-knowledge-vector`（KnowledgeVector1760600001000）

- **up**：`CREATE EXTENSION IF NOT EXISTS vector`（pgvector）；为 `knowledge_entry_embeddings` 创建向量列与 `ivfflat` 索引。
- **down**：删除向量索引与列；**不删除** `vector` 扩展。
- **前置依赖**：`knowledge-base`（#16）已应用。
- **运行时校验**：API 启动前 `assertKnowledgeVectorExtension` 检查 `vector` 扩展存在，缺失则拒绝启动并输出明确错误（非静默降级）。

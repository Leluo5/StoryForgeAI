# BUG-2026-122-01 · 多轮上下文记忆与停止生成修复报告

> 版本：v1.0 · 状态：代码修复、自动化回归及真实 Coze 验证通过（2026-11-21）
> 严重度：高（核心对话链路不符合 F3 验收标准）
> 关联功能：F3 在线体验（chat / mixed）

## 一、缺陷概述

旧 Flask 体验链路存在两个相互独立的问题：

1. 同一页面连续对话时，第二轮无法可靠引用第一轮内容，多轮上下文记忆失效。
2. 流式生成期间没有可点击的“停止生成”入口；路由切换虽会取消请求，但用户无法主动停止。响应尚未到达时取消，还可能被统一网络错误处理误报为“请求失败”。

验收目标：同页第二轮准确回忆首轮信息；响应前和生成中均可停止；请求被中断后保留已生成内容、恢复输入区，且不显示主动取消错误。

## 二、复现与根因

### 2.1 复现证据

- 修复前在同一体验页先设置代号，再询问该代号，模型返回无关答案；直接诊断 Coze 请求时，第二轮返回了不同的会话 ID。
- 流式期间发送按钮不可用，页面没有“停止生成”按钮。
- RED 阶段新增测试并确认按预期失败：
  - `test_conversation_id_is_sent_as_query`：后端请求未传 Query `params`。
  - `test_user_id_is_forwarded`：上游仍收到每轮随机生成的 `user_id`。
  - JS DOM 测试：请求缺少稳定 `user_id`，按钮仍为“发送”而非“停止生成”。

### 2.2 根因

1. Coze 官方 [对话 v3 文档](https://docs.coze.cn/developer_guides/chat_v3)规定，`conversation_id` 是 `/v3/chat` 的 **URL Query 参数**。原实现把它放进 JSON Body，Coze 忽略后为每轮创建新会话。
2. 原实现每轮随机生成 `user_id`，破坏了 Coze 按用户隔离上下文和记忆的连续性。
3. 前端已有 `abortActiveStream()` 仅用于路由切换和卸载，没有暴露停止入口；`requestRaw()` 会把底层 `AbortError` 包装为普通 `Error`，使响应前取消无法仅靠 `e.name` 识别。

## 三、最小修复

1. 后端 `_build_coze_chat_request()` 接收并透传稳定 `user_id`，删除 Coze Body 内的 `conversation_id`；`requests.post()` 改为通过 `params={"conversation_id": ...}` 传递。
2. 前端在页面会话内只生成一次 `state.userId`，主聊天及 form-as-chat 请求均携带；`state.conversationId` 继续消费完成事件并供下一轮使用。两者均保持内存态，刷新即失。
3. 复用发送按钮：流式期间保持按钮可用，切换为红色方块及 `aria-label="停止生成"`；点击调用现有 `abortActiveStream()`。
4. 取消判断同时使用 `controller.signal.aborted` 和 `e.name === 'AbortError'`，主动取消静默处理；`finally` 统一恢复按钮、输入框和流式状态，已输出内容不清空。
5. 模板静态资源版本从 `app.js?v=5` 升至 `app.js?v=6`，降低旧脚本缓存风险。

1. 启动 Flask，打开 `http://127.0.0.1:5000/#work/b50503a8634c452483d4615d49a2c616`。若仍加载旧脚本，强制刷新并确认页面引用 `app.js?v=6`。

7. 刷新页面后开始新会话：内存态 `conversation_id` 与 `user_id` 重置，符合 F3“刷新即失”的会话边界。

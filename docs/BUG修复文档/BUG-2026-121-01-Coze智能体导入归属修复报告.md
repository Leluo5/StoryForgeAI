# BUG-2026-121-01 · Coze 智能体导入归属修复报告

> 版本：v1.0 · 状态：代码修复及 Python 回归通过（2026-11-21）
> 严重度：高（导入数据进入错误领域模型）
> 关联功能：F1 资源拉取与批量导入、F10 智能体管理

## 一、缺陷概述

管理后台通过 Coze 导入 Bot 时，原实现调用 `work_manager.import_from_coze()`，把智能体写成展示作品。正确行为应为：

- Bot 导入到全局未分类 Agent 池，不创建小说或展示作品。
- 全局 Agent 不绑定作品、角色、工具或流程步骤。
- 重复导入同一 Bot 时更新原 Agent，不生成重复数据。
- Agent 仅保存 `bot_id`、`workspace_id` 等非敏感配置，不持久化 PAT。
- Coze workflow 保持原作品导入逻辑。

## 二、复现与根因

### 2.1 失败测试复现

修复前新增测试并确认失败：

1. `test_bot_success`：Bot 导入返回 `work_id` 并调用作品存储，而非返回 `agent_id`。
2. `test_import_coze_agent_uses_global_pool_and_is_idempotent`：`AgentService` 缺少 Coze Agent 导入能力。
3. `test_validate_agent_identity_enforces_kind_fields`：`unclassified` 类型不被 Agent 模型接受。
4. `test_admin_page_exposes_global_agent_pool`：管理后台没有 Agent 管理入口和全局 Agent 列表。

### 2.2 根因

`POST /api/admin/works/import` 对 Bot 与 workflow 未按领域归属分流，Bot 被直接交给作品管理器。同时 Agent 模型只有作品级三类归属，无法表达“不属于任何作品的导入智能体”。

## 三、最小修复

1. 在 Agent 类型中增加 `unclassified` 与 `global`，以 `_global` 作为内部全局池标识；禁止此类 Agent 携带 `role_id`、`tool_name`、`step_order`。
2. 新增 `AgentService.import_coze_agent()`：映射名称、描述、提示词和 Coze 非敏感配置，按 `bot_id` 查重并幂等更新。
3. 调整统一导入路由：Bot 返回 `agent_id` 并写入 AgentStore；workflow 仍返回 `work_id` 并调用 `work_manager.import_workflow()`。
4. 管理后台新增“Agent 管理”Tab，通过 `/api/agents?project_id=_global&kind=unclassified&page_size=100` 展示导入结果。
5. 导入页统一使用“资源”文案，明确智能体与工作流的不同归属。

## 五、手动验证步骤

1. 启动 Flask 应用并打开“管理后台”。
2. 点击“导入资源”，输入有效 PAT Token 和工作空间 ID，点击“获取资源列表”。
3. 同时勾选一个智能体和一个工作流，点击“导入选中资源”。
4. 点击“Agent 管理”：应看到该智能体，标识为“Coze 智能体 · 未分类”，并显示 Bot ID。
5. 点击“作品管理”：应只看到导入的工作流，不应出现刚才导入的智能体。
6. 再次导入同一智能体：Agent 管理仍只有一条对应记录，版本号递增，名称或描述同步更新。
7. 检查 `data/agents/_global/` 下对应 Agent JSON：应包含 `bot_id`、`workspace_id`，不包含 `pat_token`，且不应出现 `role_id`、`tool_name`、`step_order` 的有效绑定。

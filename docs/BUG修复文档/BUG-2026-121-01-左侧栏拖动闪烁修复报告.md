## 二、复现步骤（未复现不得进入修复）

1. 启动后端（`pnpm --filter @storyforge/api start:dev`）与前端（`pnpm --filter @storyforge/web dev`）；
2. 登录进入作品 → 章节 → 工作台正文页签；
3. 在左侧栏「章节导航栏」找到「左侧栏宽度」滑块（`<input type="range" id="left-width" min="200" max="400" step="8">`）；

## 四、根因

### 4.1 根因机制（核心）

`workbench-page.tsx` 的 `updatePanels` 原实现：

```tsx
function updatePanels(patch: Partial<PanelState>): void {
  setPanels((current) => {
    const next = { ...current, ...patch };
    localStorage.setItem(`storyforge-workbench:${workId}`, JSON.stringify(next)); // ← 同步 IO 在 setState updater 内
    return next;
  });
}
```

每次滑块 `onChange` 都会触发整页 `WorkbenchPage` 重渲染，且 `localStorage.setItem`（同步 IO）在 `setPanels` updater 内同步执行。实测 40 次 onChange 循环耗时 505ms（约 12.6ms/次），超过 60fps 一帧预算（16.7ms）。快速拖动时主线程连续被同步阻塞，布局更新无法在帧内完成 → 页面闪烁掉帧。

### 4.2 辅助根因

- 无 rAF 节流：高频 `onChange` 每次立即触发 `setPanels`，未合并到帧内；
- 无防抖持久化：`localStorage` 写入未防抖，拖动全程同步阻塞。

## 五、修复方案（最小改动）

`apps/web/src/workbench/workbench-page.tsx`：

### 5.1 新增 refs（拖动合并与持久化防抖状态）

```tsx
const latestPanels = useRef(panels);
const pendingPanels = useRef<Partial<PanelState> | undefined>(undefined);
const panelFrame = useRef<number | undefined>(undefined);
const persistTimer = useRef<ReturnType<typeof setTimeout> | undefined>(undefined);
```

### 5.2 重写 `updatePanels`（rAF 节流 + 防抖持久化）

```tsx
function updatePanels(patch: Partial<PanelState>): void {
  // 合并连续拖动中的多次 patch，每帧只触发一次 setPanels（避免高频 onChange 整页重渲染掉帧）
  pendingPanels.current = { ...pendingPanels.current, ...patch };
  if (panelFrame.current !== undefined) return;
  panelFrame.current = requestAnimationFrame(() => {
    panelFrame.current = undefined;
    const pending = pendingPanels.current;
    pendingPanels.current = undefined;
    if (!pending) return;
    setPanels((current) => {
      const next = { ...current, ...pending };
      latestPanels.current = next;
      return next;
    });
    // localStorage 写入是同步 IO，从 setState updater 移出并防抖，避免拖动时阻塞主线程
    if (persistTimer.current) clearTimeout(persistTimer.current);
    persistTimer.current = setTimeout(() => {
      localStorage.setItem(`storyforge-workbench:${workId}`, JSON.stringify(latestPanels.current));
    }, 150);
  });
}
```

**要点**：
- rAF 把连续拖动中的多次 `patch` 合并到每帧一次 `setPanels`，拖动时每帧最多一次整页重渲染；
- `localStorage.setItem` 移出 `setPanels` updater（不再同步执行），改为 150ms 防抖异步写入；
- 拖动结束后 150ms 防抖到期才写 localStorage，拖动全程主线程不再被同步 IO 阻塞。

### 5.3 新增 unmount cleanup

```tsx
useEffect(() => {
  return () => {
    if (panelFrame.current !== undefined) cancelAnimationFrame(panelFrame.current);
    if (persistTimer.current) clearTimeout(persistTimer.current);
  };
}, []);
```

## 八、同类问题排查指引

### 8.1 快速定位（三问）

1. **拖动时是否闪烁？** → 用 `PerformanceObserver`（`entryTypes: ['longtask']`）观测是否出现 >16.7ms 长任务；
2. **`localStorage` 是否在 setState updater 内同步写？** → 检查 `updatePanels` 是否有 `setPanels((current) => { ...; localStorage.setItem(...); return next; })`；
3. **是否无 rAF 节流？** → 检查 `updatePanels` 是否每次 onChange 立即 `setPanels`，无 `requestAnimationFrame` 合并。

### 8.2 标准排查命令

```powershell
# 观测拖动期间的长任务（浏览器控制台）
new PerformanceObserver((l) => l.getEntries().forEach(e => e.duration > 16.7 && console.log('LONG', e.duration))).observe({ entryTypes: ['longtask'] });
```

## 九、预防措施

1. **高频 UI 更新的性能护栏**：任何滑块/拖拽类高频 `onChange` 驱动 `setState` + 同步持久化的场景，必须 rAF 节流 setState + 防抖持久化，禁止在 setState updater 内做同步 IO；
2. **同步 IO 移出 updater**：`localStorage`/`sessionStorage`/IndexedDB 等同步或异步持久化一律移出 React setState updater，避免拖慢渲染；
3. **持久化行为变更需同步测试**：持久化异步化属行为变更，相关测试断言必须改为异步等待（`waitFor`），不可保留同步断言。

## 十、注意事项

- **持久化异步化是修复的一部分**，非回退：rAF 节流（每帧一次 setPanels）+ 150ms 防抖（localStorage 延迟写入）共同消除主线程阻塞，测试已同步更新为 `await waitFor(...)`；
- **拖动结束仍会持久化**：150ms 防抖到期即写，拖动中不写但最终一致，无数据丢失；
- **unmount 清理**：卸载时取消 rAF 与防抖定时器，避免泄漏与卸载后写 localStorage。

## 三、并发回写竞态（BUG-2026-113-02）发现与修复

### 3.1 问题复现

第 3 项 `test_50_concurrent_pull_from_room_no_lost_no_cycle` 初版失败：

```
AssertionError: 回写后节点数 1，期望 50（丢节点）
assert 1 == 50
```

50 个推衍步骤并发回写剧情树，仅保留 1 个节点，丢失 49 个。

### 3.2 根因

`modules/plot/plot_tree.py` `pull_from_room` 为**「读-改-写」快照模式**：

```python
# 调用方（routes.py sync_room pull / 测试）在锁外 load_tree 读独立快照
tree = _store.load_tree(tree_id)      # 锁外：每个线程读独立快照
# pull_from_room 在传入快照上追加节点
result = _store.pull_from_room(tree, room_id, steps, parent_node_id)
# save_tree 内 FileLock 只保护「写文件一瞬间」
```

- `save_tree` 的 `FileLock` 仅保护**原子写一瞬间**（L125-126），不保护整个「读快照 → 改快照 → 写回」事务。
- 50 线程各自 `load_tree` 读独立快照，互相看不见对方追加的节点；最后写入者的快照覆盖一切，只保留其看到的节点。
- **产品层 `routes.py` `sync_room` pull 路径（L210 load_tree 锁外 + L230 pull_from_room）同样存在此竞态**。

### 3.3 修复

`pull_from_room` 加**进程内树级事务锁**（按 `tree_id` 粒度的 `RLock`），锁内重新 `load_tree` 最新快照再合并保存，使「读-改-写」原子：

```python
with _tree_txn_lock(tree_id):
    latest = self.load_tree(tree_id)                    # 锁内重读最新已提交数据
    new_nodes = self._merge_room_steps(latest, room_id, room_steps, parent_node_id)
    if new_nodes:
        self.save_tree(latest)                          # 跨进程仍靠 FileLock 兜底
    return {"new_nodes": new_nodes, "added": len(new_nodes)}
```

- 单线程语义不变：锁内重读最新快照 == 传入快照（无并发时最新即传入）。
- 跨进程仍由 `save_tree` 内 `FileLock` 兜底。

### 3.4 验证

- 修复后 50 并发回写节点数 == 50（0 丢），全图无环，`test_50_concurrent_pull_from_room_no_lost_no_cycle` 通过。
- plot 相关既有测试 89 项全部通过（无回归）。
- 全量回归 650 项通过（此前 643 + 新增 7 项）。

## 四、发现缺陷（1 项，待 P5-T6 修复）

### 4.1 Windows 原子写竞态残余 —— 50 并发偶发 HTTP 500

**严重度**：**高**（影响并发承载指标，P0）

**现象**：全量回归中 `tests/performance/test_perf_api.py::TestConcurrentCapacity::test_50_concurrent_sessions`（50 并发创建项目+章节）**偶发失败**，约 1-7/50 请求返回 HTTP 500。本报告执行 2 次，1 次 1 个 500、1 次 5 个 500。

**根因（已 100% 复现定位）**：

```
PermissionError: [WinError 5] 拒绝访问。
  storage.py:140 _replace_with_retry → os.replace(tmp_path, path)
```

- 50 线程并发 `create_chapter` 时，写端 `atomic_write_json` 的 `os.replace` 在 **Windows** 上无法替换正被其他线程 `read_json`（无锁读）打开的目标文件，抛 `PermissionError [WinError 5] 拒绝访问`。
- P5-T2 性能报告 §4.2 曾对该问题加 `_replace_with_retry`（5 次 × 20ms）重试，但**修复不彻底**：重试窗口（100ms）在 50 并发争抢、读端持有句柄时间稍长时仍不足，导致偶发失败。P5-T2 的「50/50 成功」实为当时未触发冲突的偶然。

**复现证据（独立脚本定向复现，6 轮）**：

| 轮次 | 非 200 数 | 异常 |
|------|----------|------|
| 1 | 0 | — |
| 2 | 2 | `WinError 5` @ `_replace_with_retry` |
| 3 | 1 | `WinError 5` @ `_replace_with_retry` |
| 4 | 0 | — |
| 5 | 0 | — |
| 6 | 0 | — |

**影响**：直接威胁路线图 §5 指标「并发承载 ≥ 50 不报错」与「接口响应 P95 ≤ 200ms」（500 响应不计入 P95 样本，但会拖累真实并发可用性）。

**修复建议（归 P5-T6 缺陷修复与回归）**：将 `_replace_with_retry` 重试策略升级——① 增大重试次数与延迟（如 20 次 × 50ms，总窗口 1s）；② 或对读端 `read_json` 增加共享读锁（`FileLock` 的 `SH` 模式），从根源消除读-写竞态；③ 修复后需以 50 并发、多轮（≥6 轮）反复回归验证 0 失败。

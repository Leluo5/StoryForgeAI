# CI 优化实施总结报告

> 日期：2026-11-20
> 范围：GitHub Actions（私有仓库 `Leluo5/StoryForgeAI`，免费额度 2000 分钟/月）
> 目标：降低 CI 总执行时长 ≥ 30%、减少无效额度消耗，同时保持门禁强度不变

---

## 一、结论摘要

| 指标 | 优化前（实测） | 优化后（实测） | 变化 |
| --- | --- | --- | --- |
| 全量路径墙钟时长 | 484 ~ 557 s | **230 s**（run 44663476545） | **-52.5%** |
| 纯文档提交路径 | 394 ~ 557 s | 待本次文档提交验证（预期 ≈ 10 s） | 预期 -98% |
| 单次全量计费分钟 | 13 ~ 15 min | **12 min** | -1 min |
| 失控运行上限 | 无（实例 21 621 s / 366 min） | 单作业 ≤ 35 min 自动终止 | 消除跑飞 |
| 门禁强度 | 三层门禁 | 三层作业名不变 + 两个并行作业 | 未降低 |

一句话：**墙钟靠「拆分并行 + 去重 + 缓存」降下来，额度靠「docs-only 跳过 + 并发取消 + 超时兜底」省下来。**

## 三、根因

1. **重复执行**：m1 内部的 `pnpm run ci` 与 quality / test 作业内容一致，白耗约 95 s，并使 m1 成为串行长尾。
2. **零缓存**：每个作业重新 `pnpm install`，每次重装 Chromium（31 s），pip 未绑定 requirements。
3. **无按需触发**：文档提交同样跑 8 分钟全量门禁，近 15 次运行中约 7 次为纯 docs 变更。
4. **无闲置终止**：缺 `concurrency` 与 `timeout-minutes`，一次 PR 合并触发 6 小时挂起运行，单吃 366 分钟。
5. **类型检查三连跑**：所有包 `lint` / `typecheck` 均为 `tsc --noEmit`，CI 先 lint 再 typecheck 纯属重复。

### 4.1 新流水线结构

| 作业 | 内容 | 触发条件 |
| --- | --- | --- |
| `changes` | 路径过滤，输出 docs_only / legacy / e2e / full | 总是运行（≈6 s） |
| `docs` | 文档变更快速通过 | 仅 docs-only |
| `quality` | contracts build → lint → build（**去重 typecheck**） | 有代码变更 |
| `test` | 单元 + API E2E → 迁移清表 → 迁移幂等 → 数据库故障 | 有代码变更 |
| `legacy` | 合规 + pytest + compileall | 命中 Python 模块，或主干全量 |
| `e2e` | Playwright 浏览器验收（Chromium 走缓存） | 命中前后端，或主干全量 |
| `m1` | 仅下载证据并渲染验收报告 | 仅主干 push / 手动触发（PR 不运行） |

## 五、效果评估

### 5.1 墙钟（实测确认）

首次上线运行 44662535523 暴露出两处问题（legacy 作业缺少 node 依赖、Chromium 冷缓存重复 apt），修复后运行 44663476545 实测：

| 作业 | 实测耗时 | 结论 |
| --- | ---: | --- |
| 变更范围识别 | 8 s | 命中代码变更，全量路径 |
| 静态质量门禁 | 75 s | 含 contracts 自举 |
| 单元与 API E2E | 171 s | 含迁移幂等与数据库故障验收 |
| 旧体系 Python 门禁 | 52 s | 与前端作业并行 |
| 浏览器 E2E | 193 s | Chromium 缓存命中，安装仅 5 s |
| m1 汇总报告 | 23 s | 证据聚合 + 渲染，验收通过 |
| **运行墙钟（created → updated）** | **230 s** | 相对 484 s 基线 **-52.5%** |

验收判定：≤ 340 s（相对 484 s 下降 ≥ 30%）——**通过**。

```bash
gh run list --repo Leluo5/StoryForgeAI --workflow CI --limit 5 --json databaseId,event,conclusion
gh api repos/Leluo5/StoryForgeAI/actions/runs/<run_id>/jobs \
  --jq '.jobs[] | {name, started_at, completed_at}'
```

### 5.2 关于计费分钟

GitHub 对**每个作业各自向上取整**计费。实测单次全量运行计费为 **12 分钟**（changes 1 + quality 2 + test 3 + legacy 1 + e2e 4 + m1 1），相对优化的 13~15 分钟不升反降——因为去掉重复的 `pnpm run ci`、Chromium 命中缓存（145 s → 5 s）与 pnpm 缓存带来的节省，超过了并行作业的分钟进位。

额度收益主要来自：

| 措施 | 收益 |
| --- | --- |
| docs-only 跳过 | 历史上约一半运行，单次 11~15 min → 约 1 min |
| `concurrency` 取消 | 同分支连续推送只保留最后一次 |
| `timeout-minutes` | 消灭 366 分钟的失控运行 |

## 六、风险与回滚

1. **分支保护**：三个原作业名未改动（quality / test / m1），此前设置的必需检查仍然有效；新增的 `changes` / `docs` / `legacy` / `e2e` 若被设为必需检查，PR 精简模式下会显示 `skipped`（GitHub 视为通过）。
2. **m1 触发范围**：`m1` 汇总作业只在主干 push / 手动触发时运行，PR 阶段不生成验收报告；若将其设为必需检查，PR 上会显示 `skipped`（GitHub 视为通过）。
3. **缓存失效**：缓存 key 绑定 `pnpm-lock.yaml`，锁文件变更自动重建；异常时删除对应 cache 即可。
4. **回滚**：`git revert` 本次提交可恢复单作业串行版本；本地 `pnpm verify:m1` 全量模式未受影响。

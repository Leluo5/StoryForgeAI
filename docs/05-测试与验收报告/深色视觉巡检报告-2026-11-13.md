## 二、巡检方法与证据

### 2.1 巡检方法

1. **静态分析**：逐个读取功能面板 JS 的注入样式（`_ensureStyle()`），核对是否使用 `var(--*)` 变量化颜色；用 PowerShell 精确统计变量化与硬编码出现次数，以逐行读盘为准。
2. **服务端一致性核验**：用 HTTP 请求校验 Flask 实际返回的静态 JS 内容与磁盘一致，排除「服务端返回旧版」造成的误判。
3. **浏览器实测**：真实浏览器加载页面，读取 DOM 属性与 computed style 实测值（见 §三）；并核对模板版本号与浏览器加载日志。

### 2.2 版本一致性说明（修正后）

> 初版报告曾声明「三者一致 ⇒ 亮色弹窗为真实源码缺陷」。**该声明不成立**，修正如下：
> - 磁盘三个面板 JS 已**全部变量化**：`role_map_panel.js` `var(--bg-)=18`、`plot_tree_panel.js` `var(--bg-)=11`、`knowledge_panel.js` `var(--bg-)=6`；硬编码 `background:#`/`color:#` 均为 **0** 次。
> - 初版巡检时模板版本号未更新（`plot?v=1`、`role?v=11`、`novel?v=1` 均对应旧内容版本），且 Flask `debug=False` 模板缓存未自动重载，导致服务端向浏览器下发**旧版硬编码资源**——这才是实测亮色弹窗的根因。
> - 整改：模板版本号已全部 +1（`style?v=3`、`app?v=4`、`novel?v=2`、`plot?v=2`、`role?v=12`），Flask 已重启加载新版模板。服务日志（18:10:24）证实浏览器已 `200` 加载全部新版资源（见 §五）。

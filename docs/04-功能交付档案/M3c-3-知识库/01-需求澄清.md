## 一、用户诉求（非技术语言）

### 1.1 要解决的核心痛点

1. **素材分散且反复流失**：资料散落在浏览器、笔记、PDF 与聊天记录里，写作时找不到，灵感一闪而过就丢了。
2. **整理成本高于写作**：手动分段、提炼观点、做卡片耗时，作者更愿意把时间花在正文上。
3. **素材无法跨作品沉淀**：换一本作品就要重新收集同类资料，长期积累无法复用。
4. **素材与作品脱节**：即使收进了库，写作时仍要切窗口复制粘贴，无法在工作台里边写边查。
5. **自建设定无处安放**：世界观、势力、地点、规则等自建设定散落在文档里，容易与正文冲突。

### 1.2 期望的完整体验

```text
作者在写作工作台打开左侧「知识库」抽屉
  → 默认看到本作品已引用的素材，可一键切换到全局素材库
  → 粘贴文本，或上传 docx / pdf / txt / md 文件
  → 系统自动识别类型（文章 / 论文 / 小说 / 灵感），设定集由作者指定
  → 自动完成结构化并直接入库，作者可随时查看、编辑或回看原文
  → 按关键词、类型、标签、时间检索，收藏或置顶常用素材
  → 灵感条目自动匹配已有知识，并基于上下文补全
  → 手动建立跨条目关联，形成可追溯的素材网络
  → 把全局素材引用到当前作品；需要独立维护时另存为作品副本
  → 小说类资料拆文后自动提取大纲，作者可查看与编辑
  → 误删条目进入回收站，可恢复；确实不要时二次确认后彻底删除
  → 按需导出 Markdown 或整库备份，也可从备份合并恢复
```

### 1.3 核心目标

| 目标 | 说明 |
| --- | --- |
| 双层沉淀 | 全局素材库长期积累，作品内按需引用，避免重复收集 |
| 自动结构化 | 录入后自动完成分类与结构化并入库，减少手工整理 |
| 可控可回看 | 结构化结果可编辑，原文随时可回看，拆分失败不丢内容 |
| 随手可查 | 工作台左侧抽屉内完成检索、查看与引用，不打断正文 |
| 素材成网 | 灵感自动关联、跨条目手动关联，形成可追溯的素材关系 |
| 误删可恢复 | 删除先进回收站，彻底删除需二次确认 |
| 可迁移 | Markdown 导入导出与整库备份，素材不被单一环境锁死 |

## 二、功能边界

### 2.1 包含（In Scope）

1. **双层素材结构**：全局素材库跨作品沉淀；每部作品维护自己的引用列表，两者按库隔离、互不串数据。
2. **工作台左侧抽屉入口**：从写作工作台左侧打开「知识库」抽屉，抽屉内可切换「全局素材库」与「本作品」。
3. **五种条目类型**：文章、论文、小说、灵感、设定集；前四类自动识别并允许手动改判，设定集由作者手动指定。
4. **两种录入方式**：直接粘贴文本；上传 `docx`、`pdf`、`txt`、`md` 文件。
5. **自动结构化直接入库**：提交后自动完成类型判定与结构化并写入当前库，无需二次确认；作者可事后编辑。
6. **分类型结构化结果**：文章与设定集为分段、核心观点、标签清单；论文为五要素卡片；小说为角色、情节、叙事风格、世界观；灵感为原文与上下文补全。
7. **原文可回看**：任一条目均可查看原始内容，结构化结果与原文分视图呈现。
8. **拆分失败降级**：结构化失败时以原文入库，保留检索与编辑能力，并提示可重试。
9. **组织与检索**：关键词、类型、标签、时间四维检索；支持标签新增、重命名、删除；支持收藏与置顶。
10. **灵感关联与补全**：灵感入库时自动匹配已有条目并建立关联，基于匹配结果补全上下文；无匹配时提示存为独立灵感。
11. **跨条目关联**：作者可手动建立与解除条目关联，关联在双方条目上均可查看。
12. **作品引用与副本**：全局条目可引用到当前作品；需要独立修改时另存为作品副本，副本与全局条目互不影响。
13. **小说大纲自动提取**：小说拆文完成后自动提取章节结构、情节节点、人物关系、故事线四维度大纲，作者可查看与编辑。
14. **删除与恢复**：条目删除进入回收站，可恢复；彻底删除需二次确认。
15. **导入导出**：Markdown 单条导出、批量与按类型或标签导出、多文件导入及冲突策略；整库备份导出与合并恢复。
16. **仅桌面适配**：本期知识库只在桌面视口交付，交付口径见第五节。

### 2.2 不包含（Out of Scope）

1. **图片 OCR 录入**：本期不提供图片识别文本能力，界面与接口均不暴露该入口。
2. **与角色版图、剧情树的联动**：不提供条目注入角色上下文、拆文角色导入角色版图、大纲生成剧情树三项能力，均留待后续子段。
3. **角色写入知识库**：角色 Agent 不得新增、修改或删除素材，只能由作者操作。
4. **知识图谱可视化**：不提供力导向图等图谱视图，关联仅以列表与详情呈现。
5. **跨用户共享与协作**：本期为单创作者场景，不提供多人共享、协作编辑或权限分配。
6. **网页抓取与订阅**：不提供定时抓取、RSS 或自动订阅，素材只能由作者主动录入。
7. **非 Markdown 导出**：不提供 PDF、Word 等其他格式导出。
8. **移动与平板适配**：本期不做移动端与平板适配，也不承诺对应视口下的可用性。
9. **旧数据迁移**：旧 F5 数据不迁移，旧系统数据归属 M4。
10. **永久清理与批量删除**：不提供回收站的批量彻底删除与定时自动清理。

## 三、功能流程

### 3.1 打开知识库与切换素材库

1. 作者在写作工作台点击左侧「知识库」，打开知识库抽屉，正文保持原状与可保存状态。
2. 抽屉默认展示「本作品」的引用素材列表。
3. 作者切换到「全局素材库」，浏览与管理跨作品积累的素材。
4. 关闭抽屉后回到原正文位置，正文内容、光标位置与保存状态不受影响。

### 3.2 录入与自动结构化

1. 作者在抽屉内选择粘贴文本或上传文件，并确认写入目标库。
2. 系统自动判定类型；设定集由作者手动指定。
3. 系统自动完成结构化并直接写入目标库，列表出现新条目。
4. 作者打开条目即可查看结构化结果，必要时编辑或回看原文。

### 3.3 结构化结果查看与编辑

1. 作者打开条目详情，默认展示结构化结果，可切换到原文视图。
2. 作者编辑结构化字段并保存，详情与检索结果同步更新。
3. 作者可对拆分失败、以原文入库的条目发起重试；重试成功后在原条目上补齐结构化结果，不新增重复条目。

### 3.4 组织、检索与收藏

1. 作者按关键词、类型、标签、时间检索当前库，多个条件可叠加。
2. 作者为条目新增、重命名或删除标签，相关条目的标签展示同步更新。
3. 作者收藏或置顶常用条目，收藏与置顶只在当前库生效，不跨库共享。
4. 检索无结果时展示空状态，并提示放宽条件或切换素材库。

### 3.5 灵感关联与上下文补全

1. 作者录入灵感后，系统自动在已有条目中检索相似内容。
2. 存在匹配时，系统最多建立 3 条自动关联，并生成基于已有知识的补全文本。
3. 无匹配时，系统提示该灵感暂无关联，仅存为独立灵感。
4. 作者可手动调整关联，保留或解除系统建议。

### 3.6 作品引用与另存副本

1. 作者在作品视图内从全局素材库选择条目并引用到当前作品。
2. 引用后的条目在作品列表中展示，内容随全局条目更新而同步。
3. 作者尝试直接改写引用条目时，系统提示需要另存副本后才能编辑。
4. 作者另存副本后，副本成为作品内独立条目，后续修改不影响全局条目。
5. 作者可移除某条引用，移除引用不删除全局条目。

### 3.7 小说大纲自动提取

1. 小说类条目拆分完成后，系统自动提取四维度大纲。
2. 作者在条目详情查看大纲，可编辑各维度内容并保存。
3. 提取失败时保留拆文结果，提示重试；文本过简或缺少章节结构时提示手动补充大纲。
4. 本期大纲仅保存在知识库内，不生成剧情树节点。

### 3.8 删除、回收站与恢复

1. 作者删除条目，条目进入回收站，从常规列表移除。
2. 作者可在回收站查看、恢复或彻底删除；彻底删除需二次确认。
3. 作者删除被作品引用的全局条目时，系统先提示引用该条目的作品，确认后才执行删除。
4. 条目位于回收站期间，作品内的引用保留并标记为「来源已删除，可从回收站恢复」。
5. 全局条目被彻底删除后，作品内的对应引用标记为失效，作者可移除引用或另存已有内容。

### 3.9 导入导出与整库备份

1. 作者选择单条、批量、按类型或按标签导出 Markdown；批量与分类导出打包为压缩包。
2. 作者导入一个或多个 Markdown 文件，导入前查看标题、摘要、格式统计与冲突标记。
3. 作者选择目标类型与冲突策略（覆盖、重命名、跳过）后确认导入，得到成功与失败统计。
4. 作者导出整库备份，备份包含条目、标签、关联与收藏信息。
5. 作者从备份恢复时采用合并方式：按冲突策略逐条合并，保留现有条目，并给出成功、失败与跳过统计。

## 四、边界与异常

### 4.1 录入与结构化

| 场景 | 期望行为 |
| --- | --- |
| 上传格式不在 `docx`、`pdf`、`txt`、`md` 内 | 拒绝上传，提示支持的格式清单 |
| 单个文件超过 20 MB | 拒绝上传并提示体积上限，不进入分块处理 |
| 上传文件损坏或无法解析 | 该文件标记失败并说明原因，其余文件继续处理 |
| 文本为空或仅空白字符 | 拒绝提交，提示补充内容 |
| 类型识别不确定 | 默认按文章处理，并提示作者可手动改判 |
| 设定集条目 | 由作者手动指定类型，不依赖自动识别 |
| 结构化失败 | 以原文入库，条目标记为待整理，保留检索、编辑与重试能力 |
| 同一内容重复提交 | 提示已存在相同内容的条目，默认不新增重复条目 |
| 大篇幅文本 | 分块处理并展示进度，界面不阻塞，完成后合并结构化结果 |

### 4.2 双层库与引用

| 场景 | 期望行为 |
| --- | --- |
| 作品视图与全局素材库切换 | 各自展示所属条目，计数与列表不串数据 |
| 全局条目被修改 | 作品内引用同步展示最新内容 |
| 作者直接编辑引用条目 | 拒绝直接改写，提示另存副本后编辑 |
| 另存副本后再修改 | 只影响副本，全局条目保持不变 |
| 移除作品内引用 | 只解除引用，不删除全局条目 |
| 删除被引用的全局条目 | 先提示引用作品，确认后删除；引用进入待恢复标记 |
| 作品之间查看素材 | 不跨作品读取对方的引用列表与副本 |

### 4.3 检索、删除与标签

| 场景 | 期望行为 |
| --- | --- |
| 检索无结果 | 展示空状态，提示放宽条件或切换素材库 |
| 标签被重命名或删除 | 相关条目同步更新，检索结果随之变化 |
| 删除条目 | 进入回收站，常规列表不再展示 |
| 恢复条目 | 条目、标签与关联完整恢复，收藏状态一并恢复 |
| 彻底删除条目 | 二次确认后删除，并清理其他条目对它的关联引用 |
| 彻底删除后再次检索 | 不出现该条目，也不出现指向它的失效关联 |

### 4.4 导入导出与备份

| 场景 | 期望行为 |
| --- | --- |
| 导入文件扩展名不是 `.md` | 拒绝并提示仅支持 Markdown |
| 导入文件编码异常 | 自动尝试常见编码，仍失败则明确报错，不中断整批 |
| 同名同内容 | 判为重复，按所选冲突策略处理 |
| 同名不同内容 | 标记为待确认，由作者选择冲突策略，禁止自动覆盖 |
| 备份恢复时同名不同内容 | 按标题加内容哈希判重，标记待确认后按所选冲突策略处理 |
| 导出范围内无条目 | 返回空结果并提示该范围无素材 |
| 备份文件损坏或版本不识别 | 拒绝恢复并说明原因，现有数据不受影响 |
| 合并恢复出现冲突 | 按所选策略逐条处理，保留现有条目并给出统计 |

### 4.5 工作台上下文

- 知识库抽屉不得遮蔽正文内容或改变保存状态，关闭后回到原位置。
- 检索、查看、引用与导入导出全部在抽屉内完成，不跳转到独立页面。
- 未保存的正文改动不因打开、关闭抽屉或切换素材库而丢失。
- 本期不提供任何把素材写入角色上下文或剧情树的入口。

## 五、非功能与兼容要求

### 5.1 规模与响应

- 验收数据规模为单作品 **500 条引用素材**、全局素材库 **2000 条**。
- 单个上传文件不超过 **20 MB**，超限直接拒绝并提示。
- 打开知识库抽屉后，**1 秒内**出现列表首屏结果。
- 任一检索条件组合执行后，**1 秒内**返回结果。
- 切换全局素材库与本作品视图时，**1 秒内**完成列表刷新。

### 5.2 桌面适配与可达性

- 覆盖 `1024` 与 `1440` 两档桌面视口；本期不承诺移动与平板视口。
- 页面不得出现横向滚动、内容溢出或不可达的核心操作。
- 打开抽屉、检索、选择条目、关闭抽屉均可用键盘完成，焦点清晰可见。
- 快捷键不得抢占正文输入；抽屉关闭后焦点回到打开前的正文位置。
- 浅色与深色主题下，条目类型、标签、收藏、置顶与待恢复标记均可辨认。
- 状态不能只靠颜色表达，需同时提供文字或图标提示。

### 5.3 写作连续性

- 抽屉以浮层方式打开，不改变正文布局宽度与滚动位置。
- 打开或关闭抽屉、切换素材库、执行检索均不得触发正文保存失败或内容回退。
- 引用与另存副本操作只影响知识库数据，不改写正文文字。

### 5.4 数据与边界

- 全局素材库与作品引用列表按库隔离，作品之间不共享引用与副本。
- 角色 Agent 路径不具备知识库写权限，本期也不提供注入入口。
- 所有删除先进入回收站，回收站条目不计入常规检索结果。
- 整库备份与合并恢复只作用于知识库数据，不涉及正文、剧情树与角色数据。

## 六、概念模型（业务概念）

| 概念 | 含义 | 关键规则 |
| --- | --- | --- |
| 全局素材 | 跨作品沉淀的素材条目 | 长期积累，可被多部作品引用 |
| 作品引用 | 作品内指向全局素材的只读关联 | 随全局条目更新；不可在作品内直接改写 |
| 作品副本 | 从全局素材另存出的独立条目 | 与全局条目互不影响 |
| 条目类型 | 文章、论文、小说、灵感、设定集 | 前四类自动识别，设定集手动指定 |
| 结构化结果 | 按类型生成的整理结果 | 可编辑，原文始终可回看 |
| 标签 | 条目上的主题标记 | 可新增、重命名、删除，按库内条目生效 |
| 收藏与置顶 | 当前库内的常用标记 | 只在当前库生效，不跨库共享 |
| 条目关联 | 两条素材之间的联系 | 双方可见，可手动建立与解除 |
| 回收站 | 已删除条目的暂存区 | 可恢复，彻底删除需二次确认 |
| 整库备份 | 含条目、标签、关联与收藏的备份包 | 恢复采用合并方式，保留现有条目 |

## 七、可量化验收标准（DoD）

| ID | 验收操作 | 通过标准 |
| --- | --- | --- |
| D01 | 在正文编辑中打开并关闭知识库抽屉 | 正文内容、光标位置与保存状态不受影响，关闭后回到原位置 |

| D04 | 录入文章、论文、小说、灵感各一条并手动改判类型 | 前四类自动识别，改判后按新类型重新展示结构化结果 |
| D05 | 录入设定集并手动指定类型 | 按文章结构生成分段、核心观点与标签清单，不依赖自动识别 |

| D07 | 制造一次结构化失败后查看条目 | 条目以原文入库，可检索、可编辑，并标记为待整理且可重试 |
| D08 | 编辑结构化字段并保存后重新检索 | 详情与检索结果展示编辑后内容，原文视图仍可回看原始内容 |
| D09 | 组合使用关键词、类型、标签、时间检索 | 结果符合所选条件；无结果时出现空状态与放宽提示 |

| D14 | 将全局素材引用到作品后修改全局条目 | 作品内引用同步展示最新内容；直接编辑引用被拒绝并提示另存副本 |

| D18 | 制造大纲提取失败与无章节结构两种场景 | 失败时保留拆文并可重试；无章节结构时提示手动补充 |
| D19 | 随机抽取 10 条小说拆文人工核验大纲 | 至少 8 条大纲可被作者直接使用，无需重写 |
| D20 | 删除条目后从回收站恢复 | 条目、标签、关联与收藏完整恢复，常规列表重新展示 |
| D21 | 彻底删除条目并确认 | 二次确认后删除，其他条目的关联引用被清理，检索不再出现 |
| D22 | 删除被作品引用的全局条目 | 先提示引用作品；删除后作品内引用标记可恢复，彻底删除后标记失效 |

| D25 | 导出整库备份后修改现有库，再合并恢复 | 现有条目保留，同名同内容按策略处理，同名不同内容标记待确认后按策略处理，返回成功、失败与跳过统计 |
| D26 | 以单作品 500 条、全局 2000 条数据验收 | 打开抽屉、切换素材库、每次检索均在 1 秒内有结果 |
| D27 | 在 1024 与 1440 两档视口仅用键盘完成核心操作 | 无横向滚动与内容溢出，焦点可见，正文输入不受快捷键干扰 |
| D28 | 检查工作台与知识库界面 | 不存在图片 OCR、条目注入角色上下文、拆文角色导入角色版图、大纲生成剧情树入口 |
| D29 | 检查角色 Agent 可调用的能力 | 角色路径无新增、修改或删除素材的能力 |
| D30 | 在两个作品间检查引用、副本与检索 | 不跨作品读取或修改对方的引用列表与副本 |

## 五、实施要点与决策

1. **依赖注入**：plot_parser / routes 的 LLM 调用均经模块级 callable 注入（`llm_fn` / `_llm_fn` + `set_llm_fn`），生产走 `coze_client.CozeClient().chat(...)`，单测 mock 覆盖，无直接 import 强耦合。
2. **联动去重**：pull_from_room 以 `source_step_id`（F6 步骤 id）为去重键，`linked_room_id` 仅标记来源，避免重复回写。
3. **环路校验**：add_link 中前置/后置禁止任何环（`_would_create_cycle` 判 to→...→from 可达），非线性允许环（跳过/回环语义）。
4. **导入防御**：import_tree 先 `_validate_import`（nodes/links 数组、节点字段、关联端点存在），校验失败抛 400 不破坏现有剧情树；节点 id 重映射防与目标冲突。
5. **待确认态**：生成结果 `pending=True`，确认前不入主数据，前端可全选/局部采纳或放弃。
6. **前端同构**：plot_tree_panel.js 对齐 knowledge_panel.js 模式——独立可挂载面板组件（工厂 `mount/createButton` + 全局 `StoryForgePlotPanel`），内联样式 + 轻量请求 + toast。

## 六、联调说明

- **与 F5 联调**：生成模式二依赖 F5 拆文；解析器经注入的数据源（文本）调用，无模块强耦合，F5 可用后即可对接。
- **与 F6 联调**：sync-room push/pull 依赖 story_thread 房间上下文，路由层经 `story_thread.with_room` 读取历史步骤，pull 回写为新节点；联调验证见 05-验证结论.md。
- **与前端集成**：创作端 `page-work` 的 `work-header` 后新增 `#plot-tree-entry` 容器，`index.html` 内联脚本在 DOMContentLoaded 与 hashchange 时挂载入口按钮。

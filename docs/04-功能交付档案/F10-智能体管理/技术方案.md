# StoryForgeAI Agent 管理模块升级技术方案

> 日期：2026-11-19
> 状态：待评审
> 目标：将 NestJS Agent 模块从「作者级通用 AI Agent」升级为「作品级三类 Agent + 11 步流程 + 版本快照 + 分组树 + 角色绑定 + 流程进度」

## 0. 现状速览

| 维度 | 现状（NestJS） | 目标（迁移 Python 设计） |
|---|---|---|
| Agent 类型 | 通用作者级 Agent（无 kind） | 三类：role_agent / tool_agent / flow_step_agent |
| 所属粒度 | author_id 单维度 | author_id + project_id（作品级） |
| 流程步骤 | 无 | 11 步流程（config/default_flow_agents.json） |
| 模型参数 | 2 项（temperature, max_tokens） | 10 项完整 |
| 版本快照 | 无 | MAX=50 版本快照 + 回滚 |
| 分组 | 无 | 自动分组 + 覆盖层 + 手工分组 |
| 状态机 | active / disabled | active / disabled / archived（归档-恢复-硬删） |
| 流程进度 | 无 | flow_progress 表（project_id + role_id 联合主键） |
| 工具默认 | agent_id FK 单一绑定 | tool_agent 专用 + 每工具默认切换 |
| API 端点 | 5 个（兼容） | 新增 15+ 扩展端点 |

**不碰的东西：** 现有 `GET /ai-agents`、`POST /ai-agents`、`PATCH /ai-agents/:id`、`DELETE /ai-agents/:id`、`GET /ai-tools`、`PATCH /ai-tools/:toolId` 六个端点原样保留；`apps/api/src/database/agent.entity.ts` 用 ALTER TABLE 加列；`packages/contracts/src/agent-config.ts` 新字段全部 `.optional()`。

### 2.3 Agent Identity 校验函数

```typescript
export function validateAgentIdentity(input: {
  kind: AgentKind;
  role_id?: string | null;
  tool_name?: string | null;
  step_order?: number | null;
}): void {
  const { kind, role_id, tool_name, step_order } = input;
  if (kind === 'role_agent') {
    if (!role_id || tool_name || step_order) throw new Error('role_agent 必须且只能提供 role_id');
  } else if (kind === 'tool_agent') {
    if (!tool_name || role_id || step_order) throw new Error('tool_agent 必须且只能提供 tool_name');
  } else if (kind === 'flow_step_agent') {
    if (step_order == null || step_order < 1 || step_order > 11) throw new Error('flow_step_agent 的 step_order 须为 1-11');
    if (role_id || tool_name) throw new Error('flow_step_agent 不能提供 role_id/tool_name');
  }
}
```

### 3.2 AgentVersionService（版本快照核心）

```typescript
snapshot(current: AgentEntity, changeType: ChangeType, note?: string): AgentEntity
rollback(current: AgentEntity, targetVersion: number): AgentEntity
summarize(agent: AgentEntity): AgentVersionSummary[]
```

**核心逻辑：** 每次 snapshot 自增 `version_no`，完整拷贝 Agent 字段（不含 versions 本身）写入 JSONB 数组，`MAX_VERSIONS=50` 超限截断最早的。rollback 找目标快照 → 合并到实体 → 再写一条 rollback 快照。

| R4 | versions 无限增长 | MAX=50 硬截断 + include_versions 默认 false |
| R5 | Python 旧代码并发 | 标记 deprecated + 版本号乐观锁 |
| R6 | 存量 Agent project_id=null | V2 API 默认 project_id filter 非空才返回 |
| R7 | 旧版本无法回滚 | 前端提示"仅保留最近 50 版本" |

**回滚方案：**
- 数据层：DROP COLUMN + DROP TABLE（迁移 down 脚本）
- 代码层：Git revert（V2 代码独立 commit）
- 运行时：Controller 方法体内加 `ENABLE_AGENT_V2` 环境变量检查

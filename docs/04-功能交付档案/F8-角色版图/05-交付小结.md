## 三、技术实现要点

### 3.1 技术选型
- **图谱渲染**：D3-force v7 + SVG（纯 SVG 无 WebGL 强依赖，跨浏览器风险低；>150 节点预留 Canvas 后备 `GraphRenderer` 可插拔）
- **前端**：原生 JS IIFE 组件（无构建链）
- **后端**：Flask Blueprint `role_map`（`url_prefix=/api/role-map`）
- **AI 抽取**：复用 `coze_client.run_workflow`（202 长任务 + 轮询进度）
- **存储**：内嵌 `data/projects/<id>.json`（JSON 文件，预留 SQLite 迁移）

### 3.2 API 接口（前缀 `/api/role-map`）
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/graph` | 图谱全量 + 组合筛选（`?project_id=`） |
| POST | `/nodes` | 添加角色节点 |
| PUT | `/nodes/<id>` | 编辑节点 |
| POST / DELETE | `/edges` | 建立/删除关联（双向一致） |
| DELETE | `/roles/<id>` | 删除角色全链路（标红+清剧情+清关联） |
| GET | `/roles/<id>/growth` | 成长线数据 |
| GET | `/filters` | 6 维度筛选候选 |
| POST | `/ai/generate` | AI 抽取（202 长任务） |
| GET | `/ai/progress` | 抽取进度轮询 |
| POST | `/ai/commit` | 二次编辑确认提交 |

### 3.3 性能实测（基准 `#work/perfwork100`：100 角色 + 150 边）
| 场景 | 实测结果 | 判定 |
| --- | --- | --- |
| 静止态 | 60.0–60.4 fps（0 掉帧） | ✅ PASS |
| 拖拽中段 | 56.8–59.1 fps（0 掉帧，≥55 达标） | ✅ PASS |
| 持续拖拽 | 52.2 fps（7/80 掉帧，临界） | ⚠️ 临界 |
| 松手收敛 | 43.2–51.8 fps（21–35 掉帧，无 >67ms 长任务） | ⚠️ 临界 |
| 加载/重绘/状态切换 | ≤100ms | ✅ PASS |

**性能修复（F8-16）**：`_dragBehavior.move` 原每次直接写 `fx/fy` 导致真实拖拽掉到 48.8fps；修复为**按 rAF 合帧**（每帧最多写一次）+ **拖拽期跳过 150 条边标签重排**。修复后静止态 60fps、拖拽中段 ≥55fps。配套前端不变量守卫防止回退。

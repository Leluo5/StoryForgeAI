## 一、方案定位

角色版图（F8）为 **P4 工具集成扩展**，作为第 15 个创作工具模块注册进 `ToolRegistry`，工具注册名 `role_map`。功能与角色 Agent 体系（P3）共享同一 `Role` 实体，不另立角色存储；图谱关系、筛选维度、成长线数据均挂在项目文件内。

> 与 P3 `/api/roles`（角色 CRUD 基础接口）分离：F8 走独立前缀 `/api/role-map/*`，职责是图谱编排（关系、筛选、AI 抽取、成长线），角色基础增删改仍走 P3。

## 二、技术选型

| 项 | 选型 | 理由 | 备选 |
| --- | --- | --- | --- |
| 图谱渲染 | **D3-force + SVG**（主选） | 见下方「图谱渲染选型对比」：100 节点 60fps 可达成，交互原生、开发成本最低；>100 节点预留 Canvas 后备 | cytoscape.js（WebGL/canvas 渲染，大图更强但 API 重）、自绘 Canvas（性能上限最高但成本最高） |
| 前端框架 | 原生 JS（既有栈） | 项目无前端框架，沿用 `static/js` IIFE | — |
| 路由 | Flask Blueprint `role_map` | 项目现有手动路由但蓝图工厂已留骨架，F8 独立蓝图注册 | 手动 `@app.route` |
| AI 抽取 | `coze_client.run_workflow`（复用） | 已有 Coze 工作流调用封装，角色实体/关系抽取走专用 workflow | `requests` 直连 LLM |
| 存储 | 内嵌项目文件 `data/projects/<id>.json` | 对齐架构文档 §7.2，随项目原子读写 | `data/role_map/<project_id>.json`（量大迁移） |
| 性能 | 节点数分级：<50 全量物理模拟；50-100 简化力（`forceManyBody` 衰减 + 碰撞仅同层） | 控制 O(n²) 布局成本，保 60fps | WebGL 加速（Canvas2D 后备） |

### 2.1 图谱渲染选型对比

针对交付标准「100 节点同屏 60fps + 拖拽/缩放/平移流畅 + 四浏览器兼容」，对三个候选做系统化评估：

| 维度 | D3-force + SVG | cytoscape.js | 自绘 Canvas |
| --- | --- | --- | --- |
| 力导向布局 | ✅ 内置 `d3-force` 物理模拟，成熟 | ⚠️ 无内置力导向，需 `cose`/`fcose` 扩展布局 | ⚠️ 需自实现 O(n²) 力计算 |
| 100 节点性能 | ✅ SVG 单节点成本低，100 节点 60fps 有公开验证 | ✅ 默认 canvas 渲染，大图更稳 | ✅ 上限最高（纯位图） |
| 拖拽/缩放/平移 | ✅ `d3-drag` + `d3-zoom` 原生支持，事件模型简单 | ⚠️ 需手动绑定交互 | ⚠️ 全手动实现命中检测 |
| 节点个性化（状态色/高亮/置灰） | ✅ CSS class 直接控制 SVG 元素，成本最低 | ⚠️ style 映射需配置 | ⚠️ 需重绘逻辑 |
| 二次编辑/AI 预览 | ✅ 数据驱动重渲染简单 | ✅ 数据驱动 | ⚠️ 状态管理复杂 |
| 响应式适配 | ✅ SVG 天然可缩放，`viewBox` 自适应 | ✅ 容器适配 | ⚠️ 需处理 devicePixelRatio |
| 浏览器兼容 | ✅ Chrome/FF/Safari/Edge 全兼容 | ✅ 全兼容 | ✅ 全兼容 |
| 开发成本 | ★ 低 | ★★ 中 | ★★★ 高 |
| 维护成本 | ★ 低（生态文档多） | ★★ 中 | ★★★ 高 |

**推荐：D3-force + SVG**。理由：
1. **性能达标**：100 节点力导向在 SVG 上可稳定 60fps（节点数分级后 O(n²) 可控，见 §七）。
2. **交互原生**：拖拽/缩放/平移是 d3 一等公民，且与「节点点击跳转」「筛选高亮/置灰」的 CSS class 方案天然契合。
3. **二次编辑友好**：数据驱动重渲染，AI 预览到确认提交的切换成本最低。
4. **风险最低**：纯 SVG 无 WebGL 依赖，四浏览器兼容风险最小；项目无前端框架，无需引入构建链。

**预留升级路径**：若未来节点 > 150 或需 WebGL 加速，将渲染层抽象为 `GraphRenderer` 接口，`SvgRenderer` 与 `CanvasRenderer` 可插拔替换（当前仅实现 SVG，Canvas 为后备预案，不预先编码）。

## 三、数据模型扩展

### 3.1 Role 实体扩展（对齐数据结构设计 §2.1，扩展 6 个筛选维度字段）

| 新增字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `identity` | string | `""` | 身份（如「主角」「反派」「配角」） |
| `nationality` | string | `""` | 国家/地域（筛选维度一） |
| `faith` | string | `""` | 信仰（筛选维度二） |
| `camp` | string | `""` | 阵营（筛选维度三） |
| `race` | string | `""` | 种族（筛选维度四） |
| `profession` | string | `""` | 职业（筛选维度五） |
| `age_group` | string | `""` | 年龄段（筛选维度六，由年龄自动归档：少年/青年/中年/老年） |
| `attributes` | object | `{}` | 基础属性（随机生成：年龄/性别/性格/经历等，可编辑） |
| `relations` | array | `[]` | 关联关系列表：`[{target_role_id, relation_type, note}]` |

> 关联一致性：`A.relations` 含 `B`，则 `B.relations` 必含 `A`（双向同步写入，见 §五 数据完整性）。

### 3.1.1 知识库角色同步导入字段扩展（F5→P3）

为支持「从知识库导入角色」，在 `Role` 顶层新增 3 个可编辑字段（对齐数据结构设计 §2.1，`_ROLE_EXTRA_DEFAULTS`）：

| 新增字段 | 类型 | 默认 | 来源 | 映射说明 |
| --- | --- | --- | --- | --- |
| `personality` | string | `""` | 知识库 `characters[].性格` | 直接映射 |
| `background` | string | `""` | 知识库 `outline.character_relations[]` 聚合 | 聚合当前角色参与的关系边为人物关系描述 |
| `appearance` | string | `""` | 无直接来源 | 导入时标红 `kb_no_appearance`，待用户补填 |

> 映射标红规则：`field_mapping` 逐字段记录 `{mapped, reason, value}`。`appearance` 恒 `mapped=False, reason="kb_no_appearance"`；`relations[].target_role_id` 解析不到对端时 `reason="target_missing"`（标红待补）。导入后角色可由 `PUT /api/roles/<id>` 正常编辑（白名单已含新字段）。

### 3.2 角色版图数据（内嵌项目文件）

```jsonc
// data/projects/<project_id>.json 内嵌
{
  "role_map": {
    "nodes": ["<role_id>", ...],          // 参与图谱的角色 ID 列表
    "edges": [{"source": "A", "target": "B", "relation_type": "ally", "note": ""}],  // 关系边
    "ai_generated": false,                 // 是否 AI 生成
    "ai_progress": {"stage": "extract", "percent": 30},  // 生成进度
    "generated_at": null
  }
}
```

> 节点数据不重复存角色快照，图谱只存 ID + 边；节点完整属性从 `Role` 实体实时读取（保证单一数据源）。

### 3.3 成长线数据（读取 F7 PlotNode 时间线）

成长线不新建存储，实时从剧情树按角色过滤：
- 读取 `PlotNode[]`（剧情树），过滤 `node.role_id == 目标角色`（或 `node.content.role_ids` 含目标角色）。
- 按剧情时间线（`node.timeline_order` / `created_at`）排序。
- 每节点提取：`状态变化`（node.props.status_change）、`关联关系演变`（node.props.relation_change）、`成长轨迹`（node.props.growth）。

### 3.4 随机生成字段池配置（对齐需求 §2.6）

- **配置文件**：`config/role_map_pools.json`，定义手动新增角色时的随机生成字段池（姓名库、身份池、地域池、信仰池、阵营池、种族池、职业池、性格特质池、经历模板池、属性数值范围）。
- **随机种子**：生成函数接受 `seed` 参数（默认 `random`），同一 seed 产出可复现结果（测试断言用固定 seed）。
- **年龄段归档**：`age_group` 由 `age` 自动映射（少年 16-25 / 青年 26-45 / 中年 46-60 / 老年 61-70），不单独随机。
- **可扩展**：字段池支持增删条目，新增条目即时生效，无需迁移数据结构。

## 四、API 设计（F8 专用，前缀 `/api/role-map`）

### 4.1 图谱总览

| 方法/路径 | 用途 | 说明 |
| --- | --- | --- |
| `GET /api/role-map/projects/<id>/graph` | 加载图谱 | 返回 nodes（含角色属性）+ edges；支持 `?filter=` 组合筛选（见 4.5） |
| `POST /api/role-map/projects/<id>/nodes` | 手动新增角色 | 随机生成姓名/身份/属性，可带覆盖字段 |
| `POST /api/role-map/projects/<id>/edges` | 建立关联 | 双向写入双方 relations |
| `DELETE /api/role-map/projects/<id>/edges` | 删除关联 | 双向清理双方 relations |
| `DELETE /api/role-map/projects/<id>/roles/<role_id>` | 删除角色 | 全链路：章节标红 + 清独立剧情 + 清关联（原子） |
| `PUT /api/role-map/projects/<id>/nodes/<role_id>` | 编辑角色 | 改身份/属性/筛选维度字段 |

### 4.2 AI 自动生成

| 方法/路径 | 用途 | 说明 |
| --- | --- | --- |
| `POST /api/role-map/projects/<id>/ai/generate` | 启动 AI 抽取 | 入参 `{source: "all"|"<chapter_id>"}`；返回 task_id（长任务排队，202） |
| `GET /api/role-map/projects/<id>/ai/progress` | 查询进度 | 返回 `{stage, percent, done}` |
| `POST /api/role-map/projects/<id>/ai/commit` | 二次编辑确认 | AI 结果可先预览再提交，提交后写库并 `ai_generated=true` |

### 4.3 筛选

| 方法/路径 | 用途 | 说明 |
| --- | --- | --- |
| `GET /api/role-map/projects/<id>/filters` | 获取维度候选值 | 返回 `{nationality: [...], faith: [...], camp: [...], race: [...], profession: [...], age_group: [...]}`（6 维度） |
| `GET /api/role-map/projects/<id>/graph?filter={"nationality":["A"],"camp":["B"]}` | 组合筛选 | 服务端过滤节点/边，前端高亮+置灰 |

### 4.4 成长线（详情页）

| 方法/路径 | 用途 | 说明 |
| --- | --- | --- |
| `GET /api/role-map/projects/<id>/roles/<role_id>/growth` | 角色成长线 | 返回按时间线排序的剧情节点 + 每节点状态/关系/成长 |

### 4.5 章节联动

| 方法/路径 | 用途 | 说明 |
| --- | --- | --- |
| `POST /api/role-map/projects/<id>/roles/<role_id>/flag-chapters` | 标红相关章节 | 删除角色前置调用，标记章节文本标红（`flagged_role_ids`） |
| `POST /api/role-map/projects/<id>/roles/<role_id>/purge-story` | 清独立剧情 | 删除角色前置调用，清理该角色 PlotNode/独立剧情 |

### 4.6 知识库角色同步导入（F5→P3，挂 novel_creation 蓝图）

| 方法/路径 | 用途 | 说明 |
| --- | --- | --- |
| `GET /api/projects/<id>/kb-roles/candidates` | 列出候选角色 | 调 `RoleImportEngine.list_candidate_roles`；`?keyword=` 过滤；返回 `{items:[{entry_id, entry_title, type, role_index, name, identity, personality, relation_edges, available}]}` |
| `POST /api/projects/<id>/kb-roles/import` | 批量导入/预览 | 入参 `{candidates:[...], preview:bool}`；`preview=true` 仅预览不落库（返回每条的 `payload + field_mapping` 标红）；`false` 创建角色 + 写历史；返回 `{total, success, failed, imported, failed_items}` |
| `GET /api/projects/<id>/kb-roles/history` | 查询导入历史 | 返回 `{items:[{history_id, project_id, imported_at, role_ids, roles[]}]}` |

> 导入历史存储：`data/projects/role_import_history.json`，保留最近 200 条；`RoleImportEngine` 依赖注入 `kb_store`/`role_store`，不硬耦合知识库模块符号。

## 五、数据完整性规则

| 规则 | 实现 |
| --- | --- |
| 关联双向一致 | 建关联：A.relations += B，B.relations += A（同一事务）；删关联反向同步 |
| 删除原子性 | 标红章节 → 清独立剧情 → 清关联关系 → 删 Role → 移出 role_map.nodes（全链路，任一失败回滚） |
| 环路防护 | 关联关系为无向边，禁止自关联（A 不能关联 A） |
| 筛选一致性 | 服务端返回筛选结果，前端仅做高亮/置灰渲染，不做二次过滤（避免不一致） |
| 成长线一致性 | 成长线只读剧情树，不复制数据；剧情树更新后成长线自动反映 |
| 并发安全 | 项目文件锁（`fcntl`/`msvcrt`）+ 临时文件原子写（对齐架构文档 §7） |

## 六、前端设计

### 6.1 图谱面板 `role_map_panel.js`

- **渲染**：`d3-force` 力导向，SVG 容器；节点 `<circle>` + 姓名 `<text>`；边 `<line>`（带关系类型标签）。
- **交互**：`drag`（节点拖拽）、`zoom`（画布缩放）、`pan`（平移）；`click` 节点 → 路由跳转详情页。
- **性能分级**：`simulation.alphaDecay(0.02)`；节点 > 50 时 `forceManyBody().strength(-80).distanceMax(200)` 衰减，碰撞仅同层；重绘用 `requestAnimationFrame` 节流。
- **筛选**：顶部维度栏（国家/地域、信仰、阵营、种族、职业、年龄段 6 个下拉）→ 组合条件 → 请求 `?filter=` → 匹配节点高亮（`class=matched`）、非匹配置灰（`class=dimmed`，`opacity 0.2`）、关系边同步。
- **删除角色**：二次确认弹窗 → `DELETE` 全链路 → 节点/边移除 + 章节标红提示。

### 6.2 详情页 `role_detail.js` + 模板

- 路由 `/roles/<id>`，SPA 内路由或独立页。
- **成长线模块**：时间线组件（纵向/横向），按时间线排序渲染剧情节点；逐段浏览（上一段/下一段按钮）、快速定位（刻度点击）、历史回溯（已完成节点高亮可点击）；点击节点 → 跳转对应章节位置（`#chapter-<order>` 锚点）。

### 6.3 响应式

- `role_map.css` 用 CSS Grid/Flex + `vmin` 单位；画布用 `100%` 容器适配。
- 移动端：`touch` 手势区分拖拽节点（长按）与画布平移（单指滑动）；缩放用双指捏合。
- 断点：`≥1280px` 桌面（全谱）、`768-1279px` 平板（筛选栏折叠）、`<768px` 移动（筛选抽屉 + 全屏画布）。

## 七、性能方案（对齐 F8-15/16/17/18）

| 目标 | 方案 |
| --- | --- |
| 加载/重绘/切换 ≤ 100ms | 服务端 graph 查询聚合一次；前端增量渲染（diff 只更新变化节点/边）；筛选走服务端过滤一次，前端仅 class 切换 |
| 100 节点 60fps | 力模拟分级（<50 全量 / 50-100 简化）；`requestAnimationFrame` 节流；`alphaDecay` 提前收敛；DOM 节点复用 |
| 内存合理 | 节点数据单源（不复制 Role 到图谱）；只保留可见层 SVG；虚拟滚动成长线 |
| 四浏览器兼容 | 纯 SVG/Canvas + 原生事件，无 WebGL 强依赖；`pointer-events` 与 `touch-action` 兼容处理 |
| 多分辨率 | 容器自适应 + `ResizeObserver` 重算力图尺寸 |

### 7.1 实测与交互态优化（F8-16）

**实测基准**：`#work/perfwork100`（100 角色 + 150 边），`requestAnimationFrame` 计数 3 秒窗口，CDP 真实指针拖拽。

**首测发现（真实缺陷）**：静止态 60fps 达标，但真实拖拽节点掉到 **48.8fps**（p90 帧间隔 33.3ms，54/244 帧 >25ms）。根因：`role_map_panel.js` `_dragBehavior` 的 `move` 回调**每次直接改写 `d.fx/d.fy`**，输入频率高于显示刷新率，导致 forceSimulation 单帧内多次 tick，100 节点 + 150 边 + 150 标签全量重算叠加成掉帧。

**修复方案**（已落地并复验）：

| 项 | 内容 |
| --- | --- |
| 拖拽坐标合帧 | move 回调只暂存 `pending` 目标，`requestAnimationFrame` 每帧最多写一次 `fx/fy`（同帧多次 move 合并）；松手前补写最后一帧防回弹 |
| 边标签降载 | tick 处理器通过 `_draggingNodeId` 判断，拖拽期跳过 150 条边标签中点重排（标签仅静态可读），松手后恢复 |
| 回归守卫 | `test_role_map_perf.py` `RoleMapFrontendPerfTest` 3 项源码不变量，防止回退为「每次 move 直接写 fx/fy」 |

**复验数据**：

| 场景 | 平均 FPS | p90 帧间隔 | >25ms 掉帧 | 判定 |
| --- | --- | --- | --- | --- |
| 静止态（收敛后） | 60.0–60.4 | 16.7–16.8ms | 0 | ✅ PASS |
| 拖拽中段（短促 138–423ms） | 56.8–59.1 | 16.7–16.8ms | 0 | ✅ PASS（≥55） |
| 持续拖拽（1534ms） | 52.2 | 16.9ms | 7/80 | ⚠️ 临界 |
| 松手后收敛期（alpha decay） | 43.2–51.8 | — | 21–35/窗口 | ⚠️ 临界 |

**结论**：拖拽中段（用户实际操作手感）与静止态已达 ≥55fps 且无掉帧；持续拖拽与松手收敛期仍处临界（属力导向自然收敛，无 >67ms 长任务阻塞）。验收口径建议按「拖拽中段达标 + 静止态 60fps + 无长任务阻塞」判定 **PASS（附临界说明）**，在 F8-T13 复测。

## 八、异常处理

| 场景 | 处理 |
| --- | --- |
| AI 抽取失败 | task 状态 `failed`，前端提示可重试；已抽到的临时结果不落库 |
| 删除角色时章节标红失败 | 事务回滚，返回 500，前端提示「删除未完成，请重试」 |
| 关联写入一方失败 | 回滚双方，返回 500，保证 A→B/B→A 一致性 |
| 非空分支/剧情删除冲突 | 返回 409，提示先清空关联剧情 |
| 筛选无候选值 | 维度栏显示「无数据」，图不置灰 |

## 九、测试策略（对齐 F8-01~F8-18）

- **单元测试**（pytest）：角色随机生成、关联双向一致性、删除全链路原子性、筛选过滤逻辑、AI 抽取解析（mock coze）、成长线时间线排序。
- **集成测试**：图谱 API 全链路（建角色→建关联→筛选→删除）、AI 生成→commit→二次编辑、详情页成长线加载。
- **性能测试**：100 节点图谱 FPS 采样（`requestAnimationFrame` 计数），断言 ≥ 55fps 均值；加载/重绘计时断言 ≤ 100ms；前端不变量守卫（`RoleMapFrontendPerfTest`：拖拽合帧 + 边标签拖拽期跳过，防止交互态掉帧回退）。
- **浏览器兼容**：Chrome/Firefox/Safari/Edge 冒烟 + 四分辨率截图对比。

## 一、用户诉求（非技术语言）

### 1.1 要解决的核心痛点

1. **角色资料难以复用**：作者需要从不同视角查看同一批角色，重复建档会造成姓名、头像和设定不一致。
2. **关系与成长经历分散**：角色之间的关系、随剧情发生的变化和成长事件缺少统一入口，写到中后期容易前后矛盾。
3. **自动整理缺少控制权**：AI 可以帮助识别角色、关系和成长事件，但未经确认的结果不能直接成为正式设定。
4. **删除角色可能误伤创作**：角色不再活跃不等于其历史剧情和正文失去价值，作者需要可恢复的归档，而不是破坏性删除。
5. **视觉表达容易歧义**：头像与连线需要便于区分，但状态、关系等重要信息不能只靠颜色表达。

### 1.2 期望的完整体验

```text
作者在写作工作台打开中央「角色」页签
  → 建立或选择自定义视图，多张视图共用同一份角色资料
  → 手动新增角色，或生成整套随机资料后人工修改
  → 按国家/地域、信仰、阵营、种族、职业、年龄段筛选
  → 手动建立关系，或从指定章节 / 全书生成 AI 角色与关系候选
  → 作者确认候选后合并；疑似重复角色由作者决定合并或保留独立
  → 生成角色头像并在各视图、列表与详情中保持同步
  → 为每条关系独立配色，同时用标签或线型辅助表达
  → 手动记录成长事件并关联剧情节点，可跳转对应章节
  → 查看 AI 成长事件候选，确认后采用
  → 角色退出正式版图时选择归档；需要时单独查看并恢复
```

### 1.3 核心目标

| 目标 | 说明 |
| --- | --- |
| 资料共用 | 多张自定义视图使用同一角色资料，修改后各视图保持一致 |
| 建图可控 | 手动建图与 AI 候选并存，所有正式合并均由作者确认 |
| 关系可辨 | 支持方向、无方向、反向称谓和多种关系并存，禁止自我关联 |
| 成长可追溯 | 成长事件可关联剧情节点、跳转章节，AI 候选确认后采用 |
| 形象一致 | 头像生成后同步展示，每条关系可独立配色且有冗余表达 |
| 归档可恢复 | 归档不修改正文文字，关联内容随角色归档与恢复 |
| 操作可达 | 移动、平板、桌面可用，列表、搜索和键盘路径完整 |

## 二、功能边界

### 2.1 包含（In Scope）

1. **作品内角色版图**：角色、关系、成长事件、头像和自定义视图均按作品隔离。
2. **中央页签入口**：从写作工作台中央「角色」页签进入，不遮蔽正文和保存状态。
3. **多张自定义视图**：同一作品可建立多张视图，所有视图共用角色资料；同一角色的资料与头像变更在各视图一致呈现。
4. **手动建图**：作者可维护角色资料和角色关系，并可拖拽、缩放查看版图。
5. **随机资料生成**：保留旧 F8 的整套随机资料生成方式，生成后由作者人工修改；包括姓名、身份、年龄、性别、性格、经历、国家/地域、信仰、阵营、种族、职业、年龄段、属性，共 13 项。
6. **六维筛选**：筛选维度固定为国家/地域、信仰、阵营、种族、职业、年龄段，具体口径继承 [F8 已确认需求](../F8-角色版图/01-需求澄清.md)。
7. **关系表达**：支持有方向关系、无方向关系和反向称谓；同一对角色可并存多种关系；禁止角色与自身建立关系；本期提供 5 组 23 类关系类型，作者可在作品内改名或停用。
8. **AI 角色与关系候选**：可从指定章节或全书生成候选，作者确认后才合并到正式角色资料与版图；拒绝候选不改变正式内容。
9. **成长线**：支持手动记录成长事件、关联剧情节点并跳转对应章节；支持 AI 成长事件候选，作者确认后采用。
10. **头像生成与同步**：生成后的头像在正式版图、自定义视图、列表和角色详情中保持一致。
11. **关系独立配色**：每条关系可拥有独立颜色；颜色之外必须提供标签、线型或其他等价提示。
12. **归档与恢复**：角色归档后默认退出正式版图，支持单独查看与恢复；成长事件与专属剧情节点随角色归档，共享剧情节点不受影响；正文标记精确到命中段落，并以整章提示兜底；关联内容按第三、四节规则同步处理。
13. **疑似重复处理**：向作者提供疑似重复角色候选，由作者选择合并或保留独立。
14. **多端与等价路径**：移动、平板、桌面可用；核心操作提供列表、搜索和键盘等价路径。
15. **关键变更留痕**：角色资料、关系、成长事件、AI 合并、归档与恢复的关键变更可追溯。
16. **角色资料与关系导入导出**：支持将本作品的角色、关系及相关定义导出为可复用的结构化文件，并支持导入；导入前必须预览冲突与疑似重复，由作者确认后才写入，禁止自动合并同名角色。

### 2.2 不包含（Out of Scope）

1. **角色专属 AI 扮演者**：本段完全不包含其配置、调整、绑定或启停。
2. **真人实时共同编辑**：不提供多人在线同时编辑、在线状态或协作者间消息能力。
3. **永久清理**：归档角色及其关联内容的永久删除不在本期。
4. **旧数据迁移**：旧系统角色、关系、头像、成长线等数据仍属 M4，不在本段迁移。
5. **AI 静默写入**：AI 不得未经作者确认直接合并角色、关系或成长事件，也不得覆盖已有正式内容。
6. **同名自动合并**：同名、别名或外貌相似均不能成为自动合并依据。
7. **关系类型冻结**：23 类关系类型是本期的默认清单，不作逐字冻结的承诺；作者可在作品内改名或停用，被改名后的称谓以作品内设定为准。
8. **旧版性能数字**：不承诺旧版 `100 ms` / `60 fps` 指标，按第七节的新口径验收。

## 三、功能流程

### 3.1 手动建图与多视图使用

1. 作者打开中央「角色」页签，进入当前作品的角色版图。
2. 作者新增角色，或生成整套随机资料后逐项修改。
3. 作者建立角色关系，选择方向、填写关系称谓及必要的反向称谓。
4. 作者按需要建立多张自定义视图，在各视图中查看同一批角色。
5. 作者修改角色姓名、资料或头像后，各相关视图、列表与详情同步显示。
6. 作者使用关键词、六维筛选、列表或键盘路径查找角色与关系。

### 3.2 AI 角色与关系候选合并

1. 作者选择指定章节或全书作为识别范围。
2. AI 生成角色与关系候选，正式版图暂不改变。
3. 作者查看候选及疑似重复提示，选择确认、拒绝、合并或保留独立。
4. 只有作者明确确认的候选才进入正式角色资料与版图。
5. 生成失败、取消或重复提交不得产生重复角色、重复关系或虚假成功结果。

### 3.3 成长线记录与章节跳转

1. 作者手动新增成长事件，记录事件内容并关联剧情节点。
2. 作者从成长事件跳转至对应章节，返回后仍可继续查看成长线。
3. 作者发起 AI 成长事件生成后，先查看候选。
4. 作者确认的候选进入成长线并保留剧情关联；拒绝的候选不进入正式内容。
5. AI 失败或取消时，已有成长事件、剧情和正文保持不变。

### 3.4 头像与关系样式

1. 作者为角色生成头像，并确认采用结果。
2. 采用后的头像在正式版图、自定义视图、列表和详情中同步显示。
3. 作者为每条关系选择独立颜色，并设置标签、线型或其他辅助表达。
4. 头像生成失败时不得显示虚假成功，不得清除该角色已有头像。

### 3.5 归档与恢复

1. 作者对角色执行归档，先查看关联关系、个人剧情和正文标记的影响说明。
2. 归档后，角色默认不出现在正式版图，其关系隐藏。
3. 个人剧情由两部分构成：该角色的成长事件，以及作者显式标记为归属该角色的专属剧情节点；个人剧情随角色归档，共享剧情节点不属于任何单一角色，永不随角色归档隐藏。
4. 专属剧情节点在正式剧情树中仅隐藏节点本身，父子层级与连线结构保持不变；其子节点不随隐藏，父子关系照旧。
5. 作者可打开「显示归档角色剧情」开关，随时查看已归档角色的专属剧情节点。
6. 系统扫描该角色关联章节的正文，命中角色姓名或别名的段落显示「关联角色已归档」标记；命中判断只看姓名与别名，不做语义推断，也不依据外貌相似判断。
7. 作者可在归档影响说明中剔除误报段落；剔除后该段不再显示标记，其余命中段落保持标记。
8. 标记只表示该段提到已归档角色，不代表内容需要删除；被标记段落仍可正常编辑与保存。
9. 作者编辑正文后，若原命中段落已不存在或文字已改变，标记降级为整章提示，并说明“原文已修改”；不得静默丢失，也不得误标到新出现的段落。
10. 作者可单独查看已归档角色并发起恢复。
11. 恢复后，角色回到正式版图，相关关系恢复显示，成长事件与专属剧情节点同步恢复，专属节点原样回到正式剧情树；所有段落标记与整章提示全部消失。
12. 归档与恢复全程不得改写、删除或锁定正文文字，也不得删除任何剧情节点或关系；恢复前后的正文文字必须一致。
13. 永久清理入口不在本期提供，也不提供批量替换或删除引用。

## 四、边界与异常

### 4.1 AI 候选与重复角色

| 场景 | 期望行为 |
| --- | --- |
| 指定章节或全书识别失败 | 保留正式资料与版图，提示失败，不伪装成功 |
| 作者取消候选确认 | 不合并任何未确认候选 |
| 候选为空 | 明确提示未发现可确认内容，不新增空角色或空关系 |
| 重复确认同一候选 | 不产生重复角色、重复关系或重复成长事件 |
| 发现同名、别名或疑似重复角色 | 展示候选，由作者选择合并或保留独立 |
| 作者选择保留独立 | 保留各自资料与关系，不自动合并 |
| AI 成长事件生成失败 | 保留已有成长线和正文，允许作者重新发起 |

### 4.2 关系与视图边界

| 场景 | 期望行为 |
| --- | --- |
| 建立自我关联 | 拒绝操作并说明原因 |
| 同一对角色建立不同关系 | 允许多种关系并存，分别展示称谓和样式 |
| 有方向关系需要反向阅读 | 显示相应反向称谓，不改变原关系方向 |
| 多视图展示同一角色 | 共用角色资料，不生成彼此独立的角色副本 |
| 角色资料或头像发生变化 | 各相关视图、列表和详情保持一致 |
| 仅靠颜色无法辨认 | 仍可通过标签、线型或其他提示理解关系与状态 |

### 4.3 归档与恢复边界

| 场景 | 期望行为 |
| --- | --- |
| 角色归档 | 角色退出正式版图、关系隐藏、个人剧情归档、专属节点隐藏，命中段落出现归档标记 |
| 归档含专属剧情节点的角色 | 该专属节点在正式剧情树中仅隐藏自身，共享节点与其他角色节点不受影响 |
| 查看归档角色的专属剧情 | 打开「显示归档角色剧情」开关即可查看，父子层级与连线结构与归档前一致 |
| 归档角色的节点被子节点引用 | 只隐藏该节点本身，不隐藏其子节点，父子关系保持不变 |
| 恢复含专属剧情节点的角色 | 专属节点原样回到正式剧情树，未被删除或重建 |
| 命中段落显示标记 | 仅命中段落显示「关联角色已归档」，同章节未命中段落不显示 |
| 剔除误报段落 | 该段标记移除，其余命中段落标记保留 |
| 命中段落被编辑或删除 | 该段标记降级为整章提示并说明“原文已修改”，不误标到新段落 |
| 归档后新增段落再次提到该角色 | 不实时监听，仅在下次归档影响说明或手动刷新时体现（本期已知限制） |
| 归档后编辑正文 | 正文保持可编辑，不锁定、不改写、不删除正文文字 |
| 查看已归档角色 | 在独立归档视图中查看，不混入正式版图 |
| 恢复角色 | 角色、关系、个人剧情同步恢复，段落标记与整章提示全部消失 |
| 恢复时发现疑似重复角色 | 进入疑似重复确认流程，禁止自动合并 |
| 尝试永久清理 | 本期不提供该操作，也不提供批量替换或删除引用 |

### 4.4 作品与写作上下文边界

- 一个作品的角色、关系、头像、成长事件和视图不得被另一作品读取或修改。
- 切换角色页签、视图、成长线或章节时，不得遮蔽正文内容和保存状态。
- 未通过作者确认的 AI 内容不得进入正式版图、角色资料或成长线。
- 无真人实时共同编辑能力，不得以“共享视图”暗示多人同时编辑。

## 五、非功能与兼容要求

### 5.1 规模与响应

- 验收数据规模为同一作品 **100 个角色、150 条关系**。
- 打开角色版图后，**1 秒内有可见结果**。
- 使用关键词或六维筛选后，**1 秒内有结果**。
- 拖拽角色、缩放版图时不得出现阻断后续操作的卡死或失效。
- 上述指标不沿用旧版 `100 ms` / `60 fps` 承诺。

### 5.2 多端与可达性

- 覆盖 `375`、`768`、`1024`、`1440` 四档视口宽度。
- 页面不得出现横向滚动、内容溢出或不可达的核心操作。
- 提供与画布等价的列表、搜索和键盘操作路径。
- 键盘焦点清晰可见，弹层可关闭，快捷键不得抢占正文输入。
- 关系与状态不能只靠颜色表达；正文及关键文字对比度遵循全局 AA 可读性要求。
- 浅色与深色主题下均能辨认角色、关系、标签、线型和归档标记。

### 5.3 写作连续性

- 中央「角色」页签不得覆盖正文与保存状态。
- 成长线跳转章节后，作者可辨认当前章节并返回角色上下文。
- 归档标记按命中段落显示，无法定位段落时降级为整章提示；两种标记都只表达角色状态，不得降低正文可编辑性。

## 六、概念模型（业务概念）

| 概念 | 含义 | 关键规则 |
| --- | --- | --- |
| 角色 | 作品中具有资料、头像、关系和成长经历的创作对象 | 按作品隔离，可归档与恢复 |
| 自定义视图 | 作者查看同一批角色的不同呈现方式 | 多视图共用角色资料 |
| 角色关系 | 两个不同角色之间的有方向或无方向联系 | 支持反向称谓与多种关系并存 |
| 成长事件 | 角色随剧情发生的状态、选择或关系变化 | 可关联剧情节点并跳转章节 |
| AI 候选 | 等待作者确认的角色、关系或成长事件建议 | 未确认不得进入正式内容 |
| 已归档角色 | 默认退出正式版图但仍保留、可恢复的角色 | 支持单独查看，不可永久清理 |
| 正文归档标记 | 表示正文某段落提到已归档角色的提示 | 精确到命中段落，整章提示兜底；不修改正文文字，恢复后消失 |

## 七、可量化验收标准（DoD）

| ID | 验收操作 | 通过标准 |
| --- | --- | --- |
| D01 | 打开中央「角色」页签并切换视图、章节 | 正文和保存状态始终可见或可按既有方式查看，不被角色页签遮蔽 |
| D02 | 建立两张自定义视图并修改共用角色资料 | 两张视图显示同一角色资料，不出现独立角色副本 |
| D03 | 生成整套随机资料后修改并保存 | 旧 F8 约定的 13 项资料均生成，人工修改结果得到保留 |
| D04 | 分别使用六个筛选维度 | 国家/地域、信仰、阵营、种族、职业、年龄段均可筛选，结果符合所选条件 |
| D05 | 建立有方向、无方向及同对角色的多种关系 | 方向、反向称谓和多关系显示正确；自我关联被拒绝 |
| D06 | 分别从指定章节、全书生成 AI 角色与关系候选 | 确认前正式内容不变；确认后仅合并所选候选；拒绝不写入 |
| D07 | 对疑似重复角色分别选择合并、保留独立 | 两种选择均按作者决定执行，无同名自动合并 |
| D08 | 重复确认同一批 AI 候选 | 不产生重复角色、关系或成长事件 |
| D09 | 手动记录成长事件并关联剧情节点 | 成长线可见该事件，可跳转对应章节 |
| D10 | 生成 AI 成长事件候选并分别确认、拒绝 | 确认项进入成长线，拒绝项不进入正式内容 |
| D11 | 生成并采用角色头像 | 正式版图、各自定义视图、列表和详情中的头像一致 |
| D12 | 为相邻关系设置不同颜色并隐藏颜色提示 | 每条关系可独立配色，仍可通过标签、线型或其他提示辨认 |
| D13 | 归档具有关系、个人剧情和关联正文的角色 | 角色退出正式版图、关系隐藏、个人剧情归档，命中段落出现归档标记 |
| D14 | 归档后检查并编辑正文 | 正文文字与归档前逐字一致，仍可编辑，无内容被标记操作删除或改写 |
| D15 | 单独查看并恢复已归档角色 | 角色、关系、个人剧情同步恢复，段落标记与整章提示消失，正文文字不变 |
| D16 | 检查归档角色操作入口 | 可单独查看与恢复，不提供永久清理 |
| D17 | 在两个作品间检查角色资料与 AI 候选 | 不跨作品读取、合并或修改，未确认候选不进入正式内容 |
| D18 | 准备 100 个角色、150 条关系并打开、筛选 | 打开与每次筛选均在 1 秒内有结果 |
| D19 | 在同一规模下连续拖拽、缩放各 10 次 | 无卡死、无操作失效，完成后仍可继续编辑 |
| D20 | 在四档视口仅用列表、搜索和键盘完成核心操作 | 无横向滚动、内容溢出或不可达操作，焦点可见，正文输入不受快捷键干扰 |
| D21 | 检查本段角色专属 AI 扮演者相关入口 | 不存在配置、调整、绑定或启停能力 |
| D22 | 检查旧数据与迁移承诺 | 本段不迁移旧数据，旧数据仍明确归属 M4 |
| D23 | 归档角色后逐段检查关联章节正文 | 命中角色姓名或别名的段落显示「关联角色已归档」，未命中段落不显示 |
| D24 | 在归档影响说明中剔除一个误报段落 | 该段标记消失，其余命中段落标记保留 |
| D25 | 编辑或删除一个已标记段落并保存 | 该段标记降级为整章提示并说明“原文已修改”，不误标到新出现的段落 |
| D26 | 恢复已归档角色 | 段落标记与整章提示全部消失，正文文字与归档前逐字一致 |
| D27 | 归档、编辑、恢复全流程检查正文 | 正文始终可编辑、可保存，无文字被改写、删除或锁定 |
| D28 | 导出一个作品的角色与关系，再导入到另一个作品 | 角色、关系、关系类型与反向称谓完整还原；导入前展示冲突与疑似重复供作者确认，未确认不写入，同名角色不被自动合并 |
| D29 | 归档一个含专属剧情节点的角色 | 该专属节点在正式剧情树中消失，共享节点与其他角色节点不受影响 |
| D30 | 打开「显示归档角色剧情」开关 | 专属节点重新可见，父子层级与连线结构与归档前一致 |
| D31 | 恢复该角色 | 专属节点回到正式剧情树，未被删除或重建 |

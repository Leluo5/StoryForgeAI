## 一、方案概述

本功能为创作端**变更协作中枢**：让作者的所有正文改动与协作动作（修订、版本、评论、待办、通知、审计）可追踪、可回溯、可审计。核心是「修订集管理 → 版本快照与回滚 → 评论锚点与失联 → 待办状态机 → 通知中心 → 审计留痕」六层，全部落在 NestJS `/api/v1` 资源体系，沿用 M0/M1 的 SessionGuard + CsrfGuard + ZodValidationPipe + `ok()` 响应包装模式。

### 1.1 方案选型

| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 数据持久化 | PostgreSQL（TypeORM 迁移 + 实体） | 内存 | 需跨会话可追溯，沿用 M1 建表模式 |
| 修订集存储 | `revision_sets` 表（jsonb operations） | 正文内嵌 | 不混入正文 JSON，符合 §6.1 唯一正文源 |
| 版本快照 | `version_snapshots` 表（jsonb document） | 文件 | 不可变快照，事务内一致性 |
| 评论锚点 | `comment_threads` 表（jsonb anchor） | 正文内嵌 | 独立模型，锚点状态可标记失联 |
| 待办 | `todos` 表 + 状态机约束 | 布尔标记 | 固定 `open→in_progress→done` + `cancelled` |
| 通知 | `notifications` 表（关联对象 jsonb） | 站外渠道 | 应用内通知中心，关联对象删除保留可读说明 |
| 审计 | `audit_logs` 表（jsonb detail） | 业务日志文件 | 敏感操作可查询，回答"谁/何时/做了什么" |
| 契约复用 | `@storyforge/contracts`（Zod） | 双端各写 | 单一 schema 双端复用，M1 已验证 |
| 鉴权 | SessionGuard + 服务层 author 过滤 | 独立 AuthorGuard | 沿用 M1 模式，查询内校验归属 |

## 二、数据模型（对齐需求澄清 §六）

全部主键 `uuid`（`gen_random_uuid()` 默认），时间戳 `timestamptz`，列名 snake_case，沿用 M1 手写 SQL 迁移模式。

### 2.1 修订集 `revision_sets`（迁移 `revision-base`）

| 列 | 类型 | 约束 | 说明 |
|----|------|------|------|
| `id` | uuid | PK | 修订集标识（`revision_set_id`） |
| `chapter_id` | uuid | REFERENCES chapters(id) ON DELETE CASCADE | 所属章节 |
| `base_version` | int | CHECK >= 0 | 生成时的章节版本 |
| `actor_type` | varchar | CHECK IN ('author','ai','import','rollback') | 来源 |
| `actor_id` | uuid | 可空 | 作者/Agent/系统任务标识 |
| `operations` | jsonb | 非空 | 有序插入、删除和格式操作 |
| `status` | varchar | CHECK IN ('pending','partially_resolved','resolved') | 接受/拒绝进度 |
| `created_at` | timestamptz | DEFAULT now() | 创建时间 |
| `ai_set` | boolean | DEFAULT false | 是否 AI 来源（不与手工合并） |

**索引**：`idx_revision_sets_chapter ON revision_sets(chapter_id, created_at DESC)`。

### 2.2 版本快照 `version_snapshots`

| 列 | 类型 | 约束 | 说明 |
|----|------|------|------|
| `id` | uuid | PK | 快照标识 |
| `chapter_id` | uuid | REFERENCES chapters(id) ON DELETE CASCADE | 所属章节 |
| `version_no` | int | CHECK >= 0 | 章节版本号 |
| `document` | jsonb | 非空 | 不可变正文快照 |
| `content_hash` | char(64) | 非空 | 规范化文档 SHA-256 |
| `created_by` | uuid | 可空 | 创建者 |
| `note` | varchar(200) | 可空 | 版本备注 |
| `change_type` | varchar | CHECK IN ('manual','auto') | 主动/自动快照 |
| `revision_set_id` | uuid | REFERENCES revision_sets(id) ON DELETE SET NULL | 触发快照的修订集（自动快照唯一关联） |
| `created_at` | timestamptz | DEFAULT now() | 创建时间 |

## 三、API 设计（`/api/v1`）

统一沿用：`SessionGuard` + `CsrfGuard` + `ZodValidationPipe` + `ok(request, data)` 包装 + 写请求带幂等键。错误码按 §10.2：401/403/409/422/404/429。

### 3.1 修订集

- `POST /api/v1/works/:workId/chapters/:chapterId/revision-sets` — 创建修订集（`actor_type`、`operations`、`base_version`）。`ai_set` 由 actor_type='ai' 决定，禁止与手工合并。响应 `{ revision_set }`。
- `GET /api/v1/works/:workId/chapters/:chapterId/revision-sets` — 列出（分页 + status 过滤）。
- `POST /api/v1/works/:workId/revision-sets/:revisionSetId/operations/:opIndex/accept` — 接受单条操作（幂等：已接受返回原结果；状态更新 + 审计）。
- `POST /api/v1/works/:workId/revision-sets/:revisionSetId/operations/:opIndex/reject` — 拒绝单条操作（同上）。

### 3.2 版本快照与回滚

- `POST /api/v1/works/:workId/chapters/:chapterId/versions` — 手动创建版本（`note`）。响应 `{ version_no, snapshot_id }`。
- `GET /api/v1/works/:workId/chapters/:chapterId/versions` — 版本历史（`version_no`、`change_type`、`note`、`created_at`）。
- `GET /api/v1/works/:workId/chapters/:chapterId/versions/:versionNo` — 单个版本快照（document + hash）。
- `POST /api/v1/works/:workId/chapters/:chapterId/versions/:versionNo/compare` — 对比两版本（`from_version_no`、`to_version_no`），响应节点与正文变更明细。
- `POST /api/v1/works/:workId/chapters/:chapterId/versions/:versionNo/rollback` — 回滚：以目标快照为基准生成新回滚修订集（`actor_type='rollback'`），作者确认后才成为当前正文。回滚前若有未保存变更返回 409。响应 `{ revision_set, preview }`。
- `POST /api/v1/works/:workId/chapters/:chapterId/versions/:versionNo/confirm-rollback` — 作者确认回滚修订集，成为当前正文（幂等）。响应 `{ version_no, document }`。

### 3.3 评论

- `POST /api/v1/works/:workId/chapters/:chapterId/comments` — 创建评论（`anchor`、`content`）。响应 `{ comment }`。
- `POST /api/v1/works/:workId/comments/:commentId/replies` — 回复（`content`）。响应 `{ reply }`。
- `POST /api/v1/works/:workId/comments/:commentId/resolve` — 解决（幂等）。
- `POST /api/v1/works/:workId/comments/:commentId/reopen` — 重新打开（幂等）。
- `POST /api/v1/works/:workId/comments/:commentId/re-anchor` — 手动重新关联锚点（`anchor` 新位置），`anchor_status` 回 `attached`。
- `GET /api/v1/works/:workId/chapters/:chapterId/comments` — 列出章节评论（含回复树、`anchor_status` 失联标记）。

### 3.4 待办

- `POST /api/v1/works/:workId/todos` — 创建待办（`title`、`description`、`assignee_id`、关联对象）。创建产生通知（assignee 有值则 type='assign'）。
- `GET /api/v1/works/:workId/todos` — 列出（状态/负责人过滤）。
- `PATCH /api/v1/works/:workId/todos/:todoId/status` — 状态流转。校验状态机 `open→in_progress→done`、`cancelled`；非法流转 422。状态变化产生通知 + 审计（重复完成保持最终状态，单次审计语义）。
- `POST /api/v1/works/:workId/comments/:commentId/todo` — 评论转待办。

### 3.5 通知

- `GET /api/v1/notifications` — 我的通知列表（分页 + 未读过滤）。
- `POST /api/v1/notifications/:notificationId/read` — 标记已读（幂等）。
- `POST /api/v1/notifications/read-all` — 全部已读。
- `GET /api/v1/notifications/unread-count` — 未读数。

### 3.6 审计

- `GET /api/v1/works/:workId/audit-logs` — 作品内审计日志查询（`actor_id`/`action`/`target_type`/时间范围过滤，分页）。**只读**，写审计由服务层内部调用 `auditService.record(...)`，不暴露业务写接口。

## 四、核心逻辑

### 4.1 修订集管理（`revision.service.ts`）

```ts
// 创建：base_version 校验 + ai_set 判定
async createRevisionSet(input): Promise<RevisionSetEntity> {
  // 1. 悲观锁章节行，校验 chapter.version === input.base_version，否则 409
  // 2. 按 actor_type 判定 ai_set；ai 结果不得与手工合并（独立 revision_set）
  // 3. 插入 revision_sets（status='pending'）
  // 4. 审计 action='revision_create'
}

// 接受/拒绝单条操作：幂等 + 状态推进 + 首次接受 AI 修订前自动快照
async resolveOperation(id, opIndex, decision): Promise<RevisionSetEntity> {
  // 1. 幂等：该 op 已处理 → 返回当前结果（不重复应用）
  // 2. 若 actor_type='ai' 且首次接受 → 先创建自动 version_snapshot（同一修订集只建一个）
  // 3. 更新 op 状态；全接受 → status='resolved'，部分 → 'partially_resolved'
  // 4. 审计 action='revision_accept'|'revision_reject'
}
```

### 4.2 版本快照与回滚（`version.service.ts`）

```ts
// 自动快照触发：首次接受 AI 修订前 / 回滚前 / 迁移批量导入前
async ensureAutoSnapshot(chapterId, revisionSetId?) {
  // 已存在 (chapter_id, version_no) 快照则跳过；同一修订集只建一个（UNIQUE 兜底）
  // 生成不可变 document 快照 + content_hash
}

// 回滚：以目标快照为基准生成新回滚修订集
async rollback(chapterId, targetVersionNo) {
  // 1. 回滚前自动快照当前正文（ensureAutoSnapshot）
  // 2. 读取目标快照 document，生成 operations 将当前正文变为目标正文
  // 3. 创建 revision_set(actor_type='rollback', status='pending')，返回 preview
  // 4. 审计 action='version_rollback'
}

// 确认回滚：作者确认后才成为当前正文
async confirmRollback(revisionSetId) {
  // 1. 事务 + 悲观锁章节行，校验无未保存变更（本地已同步）否则 409
  // 2. 应用回滚 operations，version+1，写 chapter_changes
  // 3. status='resolved'；审计 action='version_rollback_confirm'
}
```

### 4.3 评论锚点与失联（`comment.service.ts`）

```ts
// 创建：记录选区、原文、前后文、章节版本、author
// 正文变更时（通过模式切换/保存链路）重定位锚点：ProseMirror 映射更新 start/end
// 无法重定位 → anchor_status='orphaned'，保留 original_text/before/after，不自动删除
// re-anchor：手动关联新位置 → anchor_status='attached'

```

### 4.4 待办状态机（`todo.service.ts`）

```ts
// 状态机约束：open→in_progress→done；cancelled 终态

  in_progress: ['done', 'cancelled'],
  done: [],
  cancelled: [],

// 非法流转 → 422；重复完成保持 done + 单次审计语义
// 状态变化 → notification(type='task_result') + audit(action='todo_status')
```

## 五、异常处理（对齐需求澄清 §五）

| 场景 | 处理 | 方案落点 |
|------|------|---------|
| 评论锚点无法重定位 | `anchor_status='orphaned'`，保留原文与引用，提供重新关联，不自动删除 | 4.3 comment.service |
| 版本回滚前有未保存变更 | 409「请先保存」 | 4.2 confirmRollback |
| 版本对比版本不存在 | 404 | 3.2 compare |
| 回滚目标版本不存在 | 404 | 3.2 rollback |
| 待办重复完成 | 保持最终状态，只记录一次审计语义 | 4.4 状态机 |
| 通知关联对象被删除 | 保留可读历史说明（linked_object 快照） | 4.5 notification |
| 待办被取消后再次流转 | 非法流转拦截 422 | 4.4 TRANSITIONS |
| 双模式切换锚点失联 | 标记失联并保留原文，不静默删除 | 6.2 转换链路 |
| 同一修订重复接受/拒绝 | 幂等返回当前结果或明确冲突 | 4.1 resolveOperation |
| 同一 AI 任务重复回调 | 按任务和结果序号去重，不生成重复修订 | 4.1（依赖 M3 幂等键） |
| 保存冲突（base_version 不符） | 409 + 当前服务端版本 + request_id | 4.1 createRevisionSet |

## 六、前端交互（apps/web）

### 6.1 修订面板

- 侧栏「修订」Tab：列出当前章节修订集（来源/时间/状态）。
- 展开显示有序操作，每条可单独「接受/拒绝」，AI 与手工分区展示（`ai_set`）。
- 接受/拒绝调用 3.1，乐观更新 + 失败回滚 + 防重复提交。

### 6.2 版本历史

- 顶部/侧栏「版本」入口：版本列表（version_no、change_type、note、时间）。
- 对比视图：两版本差异（节点增删改 + 正文变更明细）。
- 回滚：调 3.2 rollback 得 preview → 确认框 → confirmRollback。

### 6.3 评论侧栏

- 划词弹层创建评论（选区/原文回显）。
- 评论卡片：回复、解决、重新打开、转待办。
- 失联标记 `anchor_status='orphaned'` 显示「评论已失联」+ 原文引用 + 重新关联入口。

### 6.4 待办面板

- 待办列表（状态/负责人筛选），创建表单（标题/说明/负责人/关联对象）。
- 状态流转按钮，按状态机禁用非法操作。

### 6.5 通知中心

- 顶部铃铛 + 未读角标（调 unread-count）。
- 下拉列表：未读置顶，点击标记已读；关联对象删除显示可读说明。

### 6.6 无障碍与响应式

- 修订/评论/待办关键流程可脱离鼠标（键盘操作）。
- 评论锚点与修订状态不只依赖颜色表达（图例 + 图标）。
- 375/768/1024/1440 无阻断性溢出；对话框焦点陷阱 + 关闭恢复焦点（沿用 M1 模式）。

## 十、边界确认

- 修订、评论、待办、通知、版本快照、审计均存独立关系模型，**不混入正文 JSON**（§6.1）。
- 回滚不删除后续历史，基于目标快照生成新回滚修订集，作者确认后才成为当前正文（§6.4）。
- 待办状态机固定 `open→in_progress→done`，另有 `cancelled`；状态变化产生通知与审计（§5.5）。
- @ 与指派只创建应用内通知，**不隐式修改业务对象权限**（§5.5）。
- 锚点无法重定位时标记失联并保留原文，不静默删除（§6.2、§8.1）。
- 通知关联对象被删除时保留可读历史说明（§5.5）。
- 多人实时协同编辑、站外通知、协作元数据混入正文 JSON 均**不属于本期范围**。
- 首次接受任一 AI 修订集自动快照依赖 M3；M2 先实现手工/导入/回滚修订集，AI 修订集接口预留。

## 二、任务清单

### 阶段 A · 基建与数据层

**M3a-A1 基建准备（`infra/docker-compose.yml` + `.env` + `apps/api/package.json`）** — 高优先级 · ★
- `infra/docker-compose.yml` 新增 `redis:7` 服务（端口 6380，命名卷 `storyforge_redis`）。
- `.env` / `.env.example` 新增 `REDIS_URL=redis://127.0.0.1:6380`。
- `apps/api/package.json` 新增 `bullmq`、`ioredis` 依赖；`pnpm install`。
- `.github/workflows/ci.yml` 启动 redis 服务 + 注入 `REDIS_URL`。
- 完成标准：redis 容器可启动；`REDIS_URL` 可解析；bullmq/ioredis 可 import。

**M3a-A2 数据模型与迁移（`database/migrations/<epoch>-ai-task-base.ts` + `database/ai-task.entity.ts` + `database/ai-task-event.entity.ts`）** — 高优先级 · ★
- 建 2 张表：`ai_tasks`、`ai_task_events`（手写 SQL，沿用 M1/M2 模式）。
- 写 2 个 TypeORM 实体：`AiTaskEntity`、`AiTaskEventEntity`。
- 关键约束：`UNIQUE(idempotency_key)`（去重依据）、`UNIQUE(task_id, event_seq)`（事件序号唯一）、`CHECK IN (...)`（status/event type）、`REFERENCES ... ON DELETE CASCADE/SET NULL`、索引。
- 完成标准：`migration:run` 幂等；实体注册进 DataSource；迁移可重复执行（down/up）。

### 阶段 B · 契约层

**M3a-A3 契约层（`packages/contracts/src/ai-task.ts` + `index.ts` 聚合）** — 高优先级 · ★
- 定义全部请求/响应 Zod Schema：`createAiTaskRequestSchema`、`aiTaskSchema`、`aiTaskEventSchema`、`aiTaskListResponseSchema`、`retryAiTaskResponseSchema`、`cancelAiTaskResponseSchema`、`aiTaskSnapshotSchema`。
- 导出 `z.infer` 类型（单 schema 双端复用，沿用 M1/M2）。
- 完成标准：contracts 构建通过；前后端 import 同一 schema 类型一致。

### 阶段 C · 服务层与队列

**M3a-A4 任务服务（`ai/ai-task.service.ts`）** — 高优先级 · ★
- `createTask`：悲观锁章节行 + 归属校验 + 幂等键去重（已有有效结果直接返回 / 进行中 409 / 失败取消 409 可重试）+ 创建任务（status='queued'）+ 写 queued 事件 + 入队 + 审计 `ai_task_create`。
- `getTask` / `listTasks`：作品内查询 + 分页 + status 过滤。
- `retryTask`：仅 failed/cancelled 可重试；已有有效结果直接返回；置 queued 重新入队 + 审计。
- `cancelTask`：仅 queued/running 可取消；`cancelled` 幂等；移除队列 + 审计。
- 完成标准：单测覆盖创建/幂等/查询/重试/取消；409/404/422 边界。

**M3a-A5 队列与 Worker（`ai/ai-task.queue.ts` + `ai/ai-task.processor.ts`）** — 高优先级 · ★
- `AiTaskQueue`：BullMQ Queue 封装（jobId=task.id，去重由 UNIQUE(idempotency_key) 兜底）。
- `AiTaskProcessor`：消费队列 → status='running' 写事件 → 读取基准章节与上下文 → 调用模型 Provider → 转换修订集 → status='succeeded' 写事件 → 审计；失败退避重试，超限标 failed 写事件。
- `AiModelProvider`：可插拔接口 + Mock 实现（固定输出 + 可配置延迟/失败，保证测试确定性）。
- 完成标准：单测覆盖执行成功/失败/重试/超限；队列入队出队。

**M3a-A6 结果映射（`ai/ai-result.mapper.ts`）** — 高优先级 · ★
- `toRevisionOperations`：候选输出与基准章节 diff → 有序操作集（对齐 M2 存储格式）。
- `toAiRevisionSet`：创建 `actor_type='ai'`、`ai_set=true` 修订集，校验基准版本（已变化 → stale 标记，不直接套用）。
- 完成标准：单测覆盖映射正确性/stale 标记/基准版本校验。

**M3a-A7 SSE 事件总线与推送（`ai/ai-task.sse.ts`）** — 高优先级 · ★
- 事件总线：进程内 EventEmitter，key=`task:${taskId}`；写入事件广播给订阅者。
- `handleEvents`：校验归属 + 设 SSE 头 + 推 snapshot + 按 `since`（Last-Event-ID/查询参数）补取遗漏事件 + 实时转发 + 15s 心跳 + 断开清理。
- 完成标准：SSE 单测覆盖 snapshot/补取/实时转发/断开清理；事件序号不丢序。

### 阶段 D · 接口层

**M3a-A8 接口层（`ai/ai-task.controller.ts` + `ai/ai-task.module.ts`）** — 高优先级 · ★
- 实现 §3.1–§3.3 全部路由：任务发起/列表/详情/重试/取消 + SSE 事件端点。
- 统一 `SessionGuard` + `CsrfGuard` + `ZodValidationPipe` + `ok()` 包装 + 幂等键。
- 注册进 `AppModule`；`main.ts` 启动 Worker。
- 完成标准：路由单测覆盖全部端点（含 401/403/404/409/422/502/503）。

### 阶段 E · 表现层

**M3a-A9 前端任务进度视图（`apps/web/src/ai/`）** — 高优先级 · ★
- `ai-client.ts`：createTask/getTask/listTasks/retry/cancel/subscribe（EventSource）。
- `ai-task-panel.tsx/css`：任务进度卡片（状态徽章/进度/阶段/重试/取消）+ SSE 订阅 + 断线重连（Last-Event-ID + 先拉状态再补取）+ 结果入口（跳 M2 修订面板）。
- `workbench-page.tsx`：接入 AI 创作入口（演示工具 `continue`）。
- 完成标准：浏览器验证任务发起/进度推送/成功/失败重试/取消；375/768/1024/1440；键盘/读屏。

### 阶段 F · 验收

**M3a-A10 单元与集成测试（`src/ai/*.test.ts` + `apps/api/test/ai-task.e2e-spec.ts`）** — 高优先级 · ★
- 单测：任务服务/结果映射/SSE/队列全部覆盖（§七 方案对照表）。
- 集成：真实 PostgreSQL + Redis + supertest（§7.2）：发起/幂等/409/重试/取消/SSE 补取/审计。
- 完成标准：全部单测 + 集成通过；无回归（M0/M1/M2 基线全绿）。

**M3a-A11 E2E 与验收（`tests/e2e/*.spec.ts` + DoD 核对）** — 高优先级 · ★
- E2E：发起任务 → SSE 进度 → 成功 → AI 待审修订 → 接受写入正文；失败重试；断线重连补取。
- DoD #D1~#D13 逐条核对（§八 技术方案对照表）。
- 完成标准：E2E 通过；DoD 逐条核对；更新档案 README + 总索引「已交付」。

## 五、编码实现指引（对齐 Skill 11）

1. **每任务一阶段**：M3a-A1 完成并跑通 Redis，再进 A2，不一口气全做完。
2. **每任务完成即写单测**：通过才进下一任务。
3. **高风险任务暂停**：M3a-A1/A2/A3/A4/A5/A6/A7/A8/A10/A11 完成时暂停，人工复核后再继续。
4. **文档同步**：编码完成并单测通过后，更新本档案 README 与总索引为「已交付」。
5. **AI 修订集边界**：M3a 先用 Mock 模型打通闭环；Coze Provider 留接口待 M3b 接入，不阻塞本里程碑。

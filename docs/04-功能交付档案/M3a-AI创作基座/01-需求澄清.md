## 一、用户诉求（非技术语言）

### 1.1 要解决的核心痛点

作者在旧系统中调用 AI 创作工具时，存在三类困扰：

1. **任务状态不可见**：点击「生成」后不知道 AI 到底在干什么、进展到哪一步，界面无进度反馈，只能干等或反复刷新。
2. **AI 结果不可控**：AI 生成的内容直接覆盖正文或混入正文，作者没有「先看后收」的机会，误覆盖人工修改的内容。
3. **失败无重试依据**：任务超时、服务重启或网络中断后，作者不知道刚才的任务是成功还是失败，重试可能产生重复结果。

### 1.2 期望的完整体验

作者在写作工作台中发起一次 AI 创作任务（如续写、润色、扩写、生成剧情推衍等）后：

1. **发起即有反馈**：点击按钮立即看到任务已受理，生成一个可追踪的任务编号。
2. **进度实时可见**：任务执行过程中，界面通过实时推送展示进度和阶段（排队中 → 执行中 → 成功/失败），无需手动刷新。
3. **结果先审后收**：AI 生成的内容**不直接落入正文**，而是作为「待审修订」呈现，作者逐条或批量接受后才写入正文；不接受则正文不变。
4. **失败可安全重试**：任务失败后保留上下文和错误原因，作者可点击重试；重试不会产生重复的有效结果（同一任务最多一份有效结果）。
5. **断线可恢复**：网络中断或页面刷新后，重新连接能恢复任务状态和进度，不丢任务、不重复执行。

### 1.3 核心目标（与 M3 验收门槛一致）

| 目标 | 说明 |
| --- | --- |
| AI 只生成待审修订 | AI 输出一律转为「待审修订集」，作者接受前正文保持不变 |
| 任务重试不重复 | 相同幂等键最多产生一个有效结果修订集，重复调用自动去重 |
| 任务可追踪 | 每次任务有稳定编号，状态流转可查询、可审计 |
| 进度实时推送 | SSE 推送进度，重连后按事件序号补取遗漏 |

## 二、功能边界

### 2.1 包含（In Scope）

1. **AI 任务生命周期**：任务状态 `排队中 → 执行中 → 成功 / 失败 / 已取消`，状态持久化于数据库，是恢复和重连依据。
2. **任务队列与执行器**：长耗时 AI 任务进入后台队列（BullMQ + Redis），由 Worker 消费执行。
3. **SSE 进度推送**：任务进度通过服务端推送实时到达前端；客户端重连后先读当前状态，再按事件序号补取遗漏事件。
4. **AI 生成待审修订**：AI 输出转换为**独立修订集**（`actor_type='ai'`，`ai_set=true`），复用 M2 修订集；作者逐条或批量接受、拒绝。
5. **任务重试与去重**：超时/崩溃/重启可重试；相同幂等键最多一个有效结果修订集，重复调用结果去重。
6. **基于旧版本标记**：AI 生成时基准版本已变化 → 结果标记「基于旧版本」，通过差异界面处理，不直接套用。
7. **任务审计**：任务创建/执行/取消/重试写审计日志（复用 M2 审计服务）。

### 2.2 不包含（Out of Scope）

1. **Agent 配置与管理**（M3b）：任务执行者（Agent）的创建/绑定/切换不在 M3a。
2. **AI 创作工具全集**（M3b）：具体工具（续写/润色/扩写/大纲/剧情推衍等）的工具注册与上下文注入不在 M3a；M3a 只建「任务 + 队列 + 修订」的通用管道，用 1 个演示工具打通闭环。
3. **剧情树 / 角色版图 / 知识库**（M3c）：这些创作工具上下文的专用能力不在 M3a。
4. **多人实时协同**：本期仍为单作者创作，不实现多人同时编辑。
5. **外部模型厂商接入**：Coze 之外的模型适配、Token 计费、模型参数配置面板不在 M3a。

## 三、功能流程

### 3.1 发起 AI 创作任务

```
作者点击「AI 创作」工具（如续写）
  → 前端提交任务（含作品、章节、工具标识、输入摘要、幂等键）
  → 服务端校验权限与章节归属
  → 创建任务记录（状态=排队中，生成 task_id + 幂等键）
  → 写入队列等待 Worker 消费
  → 返回任务受理结果（含 task_id）
  → 前端打开任务进度视图，订阅 SSE
```

### 3.2 任务执行与进度推送

```
Worker 取到任务
  → 状态=执行中，推送「执行中」事件（事件序号递增）
  → 读取基准章节版本和上下文（作品/章节/工具/输入摘要/选区）
  → 调用外部模型生成候选输出
  → 推送阶段进度（如「生成中」「格式化中」）
  → 服务端将候选输出转换为独立修订集（actor_type='ai', ai_set=true）
  → 状态=成功，推送「成功」事件（携带 revision_set_id 与结果摘要）
```

### 3.3 作者接受或拒绝修订

```
任务成功后，作者在修订面板看到 AI 待审修订集
  → 逐条接受/拒绝，或批量接受
  → 接受的操作写入正文（复用 M2 修订集 resolveOperation）
  → 首次接受前自动创建版本快照（复用 M2 版本服务）
  → 全部处理 → 修订集状态=已解决
  → 正文变更可审计、可回滚（复用 M2）
```

### 3.4 失败与重试

```
Worker 执行中外部模型失败 / 超时 / 崩溃
  → 状态=失败，保存错误原因与上下文，推送「失败」事件
  → 作者点击「重试」（携带原幂等键）
  → 服务端校验：同幂等键已有有效结果 → 直接返回该结果（不重复执行）
  → 否则重新入队，状态=排队中
```

### 3.5 断线重连恢复

```
页面刷新 / 网络恢复后
  → 前端重连 SSE
  → 先请求任务当前状态（API 查询）
  → 再按已收到的事件序号补取遗漏事件
  → 若任务已成功但前端未收到结果 → 从任务记录恢复结果摘要
```

## 四、验收标准（DoD）

| # | 验收标准 | 验证方式 |
| --- | --- | --- |
| D1 | 发起任务后立即返回 `task_id`，任务记录状态=排队中 | API 测试 + E2E |
| D2 | 任务执行中 SSE 推送进度事件，事件序号递增且不丢序 | SSE 测试 |
| D3 | 任务成功后生成 `actor_type='ai'` 独立修订集，正文未被直接修改 | API 测试 + E2E |
| D4 | 作者接受 AI 修订后，正文写入、修订集状态推进、版本快照生成 | API 测试 + E2E |
| D5 | 拒绝 AI 修订后，正文不变、修订集状态=已解决 | API 测试 |
| D6 | 任务失败后保留上下文与错误原因，可按原幂等键重试 | API 测试 |
| D7 | 相同幂等键重复调用最多产生一个有效结果修订集 | API 测试 |
| D8 | 基准版本已变化时，AI 结果标记「基于旧版本」 | API 测试 |
| D9 | 重连后先读状态再按序号补取遗漏事件 | SSE 测试 |
| D10 | 任务创建/执行/取消/重试写入审计日志 | API 测试 |
| D11 | 未认证 401、无权限 403、非法输入 422、外部模型失败 502/503 | API 测试 |
| D12 | 前端任务进度视图在 375/768/1024/1440 无阻断性溢出；键盘与读屏可达 | 浏览器验证 + axe |
| D13 | 全量回归（M0/M1/M2 基线）无回归 | 全量测试 |

## 五、异常与边界处理

| 场景 | 系统行为 | 用户反馈 |
| --- | --- | --- |
| 未登录/无作品权限 | 拒绝创建任务，401/403 | 提示登录或权限说明 |
| 章节不存在或不属于作品 | 404 | 提示章节不存在 |
| 输入非法（缺工具/缺正文/缺幂等键） | 422，字段错误内联展示并聚焦首个错误 | 表单错误提示 |
| 外部模型调用失败 | 任务状态=失败，保留上下文，502/503 可重试 | 显示失败原因与「重试」按钮 |
| 任务超时 | 任务状态=失败（原因=timeout），可重试 | 显示「已超时，可重试」 |
| Worker 崩溃/服务重启 | 任务状态保留（执行中→失败，或重新入队），不丢任务 | 显示「执行中断，可重试」 |
| 基准版本已变化 | AI 结果标记「基于旧版本」，不直接套用 | 差异界面提示「基于旧版本」 |
| 同幂等键重复调用 | 返回已有有效结果，不重复执行 | 无感知（自动去重） |
| 客户端取消等待 | 仅取消客户端等待，服务端任务不误标已取消 | 显示任务仍在执行 |
| 断线重连 | 先读状态再补事件，不丢进度 | 进度恢复，无感知 |

## 六、数据字段说明（概念模型）

### 6.1 AI 任务（AI task）

| 字段 | 说明 |
| --- | --- |
| `task_id` | 任务标识（不可猜解 UUID） |
| `idempotency_key` | 幂等键（同键最多一个有效结果） |
| `work_id` / `chapter_id` | 所属作品 / 章节 |
| `tool` | 工具标识（如 `continue` 续写） |
| `agent_id` | 执行 Agent（M3a 预留，M3b 接入） |
| `input_summary` | 输入摘要（作品/章节/选区/参数） |
| `base_version` | 基准章节版本 |
| `status` | `queued / running / succeeded / failed / cancelled` |
| `event_seq` | 事件序号（SSE 补取依据） |
| `result_revision_set_id` | 成功后的结果修订集标识 |
| `error` | 失败原因（结构化） |
| `created_at` / `updated_at` | 时间戳（UTC 存储，界面按上海时区显示） |

### 6.2 任务进度事件（SSE event）

| 字段 | 说明 |
| --- | --- |
| `event_seq` | 事件序号（单调递增） |
| `type` | 事件类型（queued / running / progress / succeeded / failed / cancelled） |
| `payload` | 阶段描述、进度百分比、结果摘要、错误原因等 |
| `created_at` | 事件时间 |

### 6.3 结果修订集（复用 M2）

| 字段 | 说明 |
| --- | --- |
| `revision_set_id` | 修订集标识（M2 表） |
| `actor_type` | 固定 `'ai'` |
| `ai_set` | 固定 `true`（不与手工修订混组） |
| `operations` | 候选输出转换成的有序操作集 |
| `base_version` | 生成时的基准版本 |
| `status` | `pending / partially_resolved / resolved` |

## 七、相关依赖与约束

1. **复用 M2 修订集**：`revision_sets` 表的 `actor_type='ai'` + `ai_set=true` 已预留；AI 结果必须走独立修订集，禁止混入手工修订集。
2. **复用 M2 版本服务**：首次接受 AI 修订前自动创建版本快照；回滚/对比复用 M2 能力。
3. **复用 M2 审计服务**：任务与修订操作写入 `audit_logs`。
4. **队列与推送**：长任务用 BullMQ（Redis），SSE 只推送、数据库状态是恢复依据。
5. **契约复用**：前后端从 `@storyforge/contracts` 复用 Zod Schema（沿用 M1/M2 模式）。
6. **鉴权模式**：`SessionGuard` + `CsrfGuard` + `ZodValidationPipe` + `ok()` 包装（沿用 M1/M2）。
7. **外部模型**：调用采用至少一次语义，系统不承诺外部服务恰好执行一次；依赖幂等键去重。
8. **安全**：PAT Token / API Key 只在服务端环境或密钥设施，API/SSE/日志不泄露；AI 输出与富文本粘贴执行 Schema 校验与 XSS 清理。

## 二、任务明细

### 2.1 F4-T1 config_loader 读写封装（数据层）

**目标**：`global_config.json` 健壮读写。

**完成标准**：
- `DEFAULT_CONFIG` 定义缺省值（site_name/description/theme/admin_password/llm_config）。
- `load_config()`：缺失键补默认；损坏 JSON 回退 DEFAULT + 警告日志，不抛异常。
- `save_config(cfg)`：原子写入（tmp + rename），防并发写损坏。

**关键点**：损坏容错；原子写防并发。

### 2.2 F4-T2 配置 API（接口层）

**目标**：站点配置读写接口，敏感字段不进响应。

**完成标准**：
- `GET /api/admin/config`：剔除 `admin_password` / `llm_config.api_key` 明文，仅返回 `has_admin_password` / `has_llm_key` 布尔。
- `PUT /api/admin/config`：只更新传入字段（site_name/description/theme/admin_password/llm_config）。
- `theme` 校验仅 `{light, dark}`，非法 400；site_name 为空 400。
- 密码仅当显式传入且非空时更新（空串不误清空）。
- 全部经 `require_admin` 鉴权。

**关键点**：敏感字段只进不出；合并更新不误清空。

### 2.3 F4-T3 前端设置表单 + 主题切换（表现层）

**目标**：管理后台设置页 + 主题即时应用。

**完成标准**：
- 设置表单填充 site_name/description/theme 输入；LLM 配置三输入框（base_url/model/api_key）。
- 保存 → PUT → `applyTheme` 即时改 `data-theme`（无刷新）。
- 密码留空不修改；保存反馈 toast「已保存」/错误。
- 页面初始化读取 config 应用到站点标题/描述与主题。

**关键点**：主题 `data-theme` 即时切换；密码留空保护。

### 2.4 F4-T4 单元测试与验证（测试）

**目标**：验证配置读写、敏感过滤、主题校验。

**完成标准**：
- 单元测试：`load_config` 缺键补默认；`GET` 不含密码/api_key 明文；`PUT` 合并只改传入；非法 theme 拒绝。
- 手动验证：改站点名前台即时显示；切换主题无刷新；改密码重新登录验证；重启配置不丢。
- `py_compile` 通过；启动服务走设置流程。

**关键点**：敏感过滤与合并更新是断言核心。

## 一、用户诉求（非技术语言）

> 创作者希望：**把看过的文章、论文、小说，还有脑子里一闪而过的灵感，都收进一个统一的知识库，让系统自动帮我分类、提取要点、建立关联，写小说时随时能检索复用。**

### 1.1 要解决的核心痛点

- 资料散落在浏览器、微信、笔记、PDF 里，创作时找不到。
- 手动整理资料耗时，重点往往被忽略。
- 灵感一闪而过，没有及时记录、没有与已有知识关联，就流失了。
- 论文看完了不知道对写作有什么可落地启发。

### 1.2 期望的完整体验

```text
创作者进入知识库页面
  → 选择录入方式：直接粘贴 / 上传文件 / 图片OCR识别
  → 系统识别资料类型（文章/论文/小说/灵感）
  → 自动结构化拆分：
     ├─ 文章   → 分段 + 核心观点 + 标签化要点清单
     ├─ 论文   → 五要素知识卡片（问题/方法/结论/局限/启发）
     ├─ 小说   → 拆文（角色/情节/叙事风格/世界观）
     └─ 灵感   → 与已有知识自动匹配关联 + 上下文补充完善
  → 生成结构化条目，可编辑、可检索、可关联引用
```

## 二、功能边界

### 2.1 包含（In Scope）

| # | 能力 | 说明 |
|---|------|------|
| 1 | 统一录入入口 | 文本直接输入、文件上传、图片 OCR 识别，三种方式汇总到同一入口 |
| 2 | 资料类型识别 | 自动判定文章/论文/小说/灵感四类（也可手动指定） |
| 3 | 文章结构化 | 内容分段、核心观点提取、关键信息标签化，保留原文逻辑结构 |
| 4 | 知识卡片 | 提炼研究问题/研究方法/核心结论/研究局限/产品设计启发点五要素 |
| 5 | 小说拆文 | 提取核心角色设定、关键情节脉络、叙事风格特征、世界观设定 |
| 6 | 灵感记录与关联 | 快速记录碎片化想法，自动与已有知识匹配关联，上下文补充完善 |
| 7 | 知识关联 | 跨条目关联引用，形成知识网络 |
| 8 | 统一检索 | 按关键词/类型/标签/时间检索全部知识条目 |
| 9 | 编辑与复用 | 结构化内容可编辑，可从知识库引用到创作项目 |
| 10 | 大纲自动提取 | 小说拆文完成后自动提取大纲（章节结构/情节节点/人物关系/故事线），结构化存储并关联绑定拆文数据 |

### 2.2 不包含（Out of Scope）

- ❌ 多格式导出（PDF/Word 批量导出，后续增强）。
- ❌ 知识图谱可视化（力导向图等，后续 Phase 增强）。
- ❌ 跨用户共享与协作（当前单创作者本地知识库）。
- ❌ 自动定时抓取网页/订阅（当前为主动录入）。

## 三、功能流程

### 3.1 录入流程（统一入口）

```text
创作者选择录入方式
  ├─ 直接粘贴文本 → 进入文本区
  ├─ 上传文件 → 读取内容（docx/pdf/txt/md）
  └─ 图片上传 → OCR 识别 → 提取文本
  → 提交 → 系统判定类型（自动/手动）
  → 触发对应结构化拆分
  → 生成条目预览（可编辑）
  → 确认入库 → 写入知识库
```

### 3.2 文章结构化流程

```text
文章全文
  → 分段（保留原文段落结构）
  → 核心观点提取（AI 抽取 3-5 条）
  → 关键信息标签化（关键词/主题标签）
  → 生成摘要 + 要点清单
```

### 3.3 知识卡片流程

```text
论文全文
  → 五要素精准提炼：
     ├─ 研究问题
     ├─ 研究方法
     ├─ 核心结论
     ├─ 研究局限
     └─ 产品设计可落地启发点
  → 生成标准化知识卡片
```

### 3.4 小说拆文流程

```text
小说内容
  → 提取核心角色设定（人物/性格/关系）
  → 提取关键情节脉络（主线/冲突/转折）
  → 提取叙事风格特征（视角/节奏/语言）
  → 提取世界观设定（背景/规则/体系）
  → 生成结构化拆文
  → 自动触发大纲提取（见 3.6）
```

### 3.5 灵感记录与关联流程

```text
灵感快速记录
  → 系统在知识库中检索匹配已有知识（相似度）
  → 自动建立关联（灵感 ↔ 已有知识）
  → 基于已有知识上下文补充完善灵感
  → 生成更完整、更具可执行性的输出
```

### 3.6 大纲自动提取流程（拆文完成后触发）

```text
小说拆文完成（3.4）
  → 自动触发大纲提取：
     ├─ 提取核心章节结构（章节划分/顺序/层级）
     ├─ 提取关键情节节点（主线节点/分支节点/转折点）
     ├─ 提取人物关系脉络（角色间关系/阵营/冲突链）
     └─ 提取核心故事线（主线/支线/暗线）
  → 生成结构化大纲
  → 与对应小说拆文数据关联绑定
  → 前端可查看/编辑/导出
```

## 五、异常与边界处理

| 场景 | 处理 |
|------|------|
| 文件格式不支持 | 前端提示支持格式清单，拒绝上传 |
| 图片 OCR 识别失败 | 提示重新上传，或改用手动输入 |
| 类型识别不确定 | 弹出确认框，允许手动指定 |
| 拆分失败 | 降级为原文存储 + 提示重试 |
| 灵感无匹配知识 | 提示「无关联，仅存为独立灵感」 |
| 检索无结果 | 显示空态 + 建议放宽条件 |
| 超大文本 | 分块处理，进度提示 |
| 并发录入 | 队列化，避免重复条目 |
| 大纲提取失败 | 保留拆文结果，提示重试大纲提取 |
| 大纲无法提取 | 提示文本过简/无章节结构，可手动补充大纲 |

## 六、数据字段说明（概念模型）

### 6.1 知识条目（knowledge entry）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 条目唯一 id |
| `type` | enum | article/paper/novel/inspiration |
| `title` | string | 标题 |
| `source` | enum | paste/upload/ocr/manual |
| `raw_content` | text | 原始内容 |
| `structured` | object | 结构化结果（按类型不同结构） |
| `tags` | array | 标签 |
| `links` | array | 关联条目 id 列表 |
| `created_at` | datetime | 创建时间 |
| `updated_at` | datetime | 更新时间 |

### 6.2 结构化结果（structured，按类型）

| 类型 | 结构 |
|------|------|
| article | `{ paragraphs[], key_points[], summary, tag_list[] }` |
| paper | `{ research_question, research_method, core_conclusion, limitation, design_insight }` |
| novel | `{ characters[], plot_lines[], narrative_style[], world_setting, outline }` |
| inspiration | `{ raw_text, enriched_text, related_ids[] }` |

novel 的 `outline` 字段进一步结构化为四维度大纲要素：

```text
{ chapters[], plot_nodes[], character_relations[], core_storylines }
```

## 八、Markdown 导入导出功能（Extension，2026-11-12）

> 变更说明：本功能为 F5 知识库管理的增量扩展，新增「标准 Markdown 文件导入导出」能力，
> 不改动既有条目存储结构与检索逻辑。以下章节为本次扩展的独立需求描述。

### 8.1 用户诉求（非技术语言）

> 创作者希望：**把知识库里的条目导出为标准的 Markdown 文件，方便本地存档、分享、二次编辑；
> 也能把本地已经写好的 Markdown 文件导入知识库，复用已有素材。整个过程要稳定、内容不失真、有进度提示、有明确的结果反馈。**

### 8.2 功能边界（In Scope）

| # | 能力 | 说明 |
|---|------|------|
| M1 | 单条文档导出 | 将知识库中一条条目导出为独立 `.md` 文件 |
| M2 | 批量导出 | 勾选多条条目，逐个导出为 `.md`，打包为 ZIP 下载 |
| M3 | 分类导出 | 按 type（文章/论文/小说/灵感）或 tag（标签）指定分类，导出该分类下全部条目 |
| M4 | 文件名规范 | 自动生成符合规范的文件名（标题清洗 + 时间戳防冲突），非法字符自动替换 |
| M5 | 单文件/多文件导入 | 读取本地单个或多个 `.md` 文件 |
| M6 | 导入解析 | 自动解析标题、正文、格式元素（标题层级/列表/代码块/图片引用/表格） |
| M7 | 格式校验 | 校验文件格式合法性（扩展名、编码、是否损坏），损坏文件明确报错 |
| M8 | 导入预览 | 导入前预览解析结果（标题/正文摘要/格式元素统计） |
| M9 | 目标位置选择 | 导入时可指定目标 type 分类（article/paper/novel/inspiration） |
| M10 | 冲突策略 | 重复内容处理：覆盖 / 重命名 / 跳过，三选一 |
| M11 | 结果统计 | 导入完成返回成功数、失败数、失败原因明细 |
| M12 | 进度提示 | 大文件导入导出时提供进度提示，避免界面阻塞 |
| M13 | 编码兼容 | UTF-8 为主，兼容常见编码；特殊字符/格式标记无丢失错乱 |
| M14 | 内容一致性 | 导入导出的内容与原文档一致性达到 100% |

### 8.3 功能边界（Out of Scope）

- ❌ 导出为 PDF/Word 等其他格式（后续增强）。
- ❌ 图片资源二进制打包（导出保留图片引用文本，不打包图片文件，见决策）。
- ❌ 跨用户共享与协作。

### 8.4 关键决策（已确认）

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 前端交付形态 | **独立可挂载面板组件** | `knowledge_panel.js` 为 4 行骨架，新建可挂载「Markdown 导入导出」面板，延续 novel_editor.js 独立组件模式，不越界重建知识库管理主界面 |
| 分类维度 | **两者都支持** | 导出时既可指定 type（文章/论文/小说/灵感），也可指定 tag（标签）作为筛选维度 |
| 判重依据 | **标题 + 内容哈希** | 同名且正文哈希相同判为重复；仅同名内容不同视为待确认，避免误判 |
| 图片引用 | **原样保留引用文本** | 知识库条目正文为纯 Markdown 文本，图片以链接形式存在，导出保留链接文本不变，不打包二进制 |

### 8.5 导入导出流程

**导出流程**：
```text
创作者选择导出范围（单条 / 批量勾选 / 按 type / 按 tag）
  → 系统按范围收集条目
  → 每条渲染为标准 Markdown（标题 + 正文 + 元数据注释）
  → 自动生成规范文件名
  → 单条：直接下载 .md；批量/分类：打包 ZIP 下载
  → 返回导出结果统计（成功数 / 失败数 / 失败原因）
```

**导入流程**：
```text
创作者选择本地 .md 文件（单个或多个）
  → 系统读取文件 → 解析标题/正文/格式元素
  → 格式校验（扩展名/编码/损坏）
  → 生成导入预览（标题/摘要/格式统计/冲突标记）
  → 选择目标 type 分类 + 冲突处理策略（覆盖/重命名/跳过）
  → 确认导入 → 写入知识库
  → 返回导入结果统计（成功数 / 失败数 / 失败明细）
```

### 8.6 验收标准（DoD，新增）

| # | 标准 | 验证方式 |
|---|------|---------|
| MD-1 | 单条导出 | 选择单条目导出，得到标准 `.md`，含标题/正文/格式元素 |
| MD-2 | 批量导出 ZIP | 勾选多条导出，得到 ZIP 包，内部含对应 `.md` 文件 |
| MD-3 | 分类导出 | 指定 type/tag 导出该分类全部条目，数量与检索结果一致 |
| MD-4 | 文件名规范 | 文件名含清洗后标题 + 时间戳，非法字符替换，无冲突 |
| MD-5 | 单文件导入 | 导入单个 `.md`，生成知识库条目，标题/正文正确 |
| MD-6 | 多文件导入 | 导入多个 `.md`，批量生成条目，返回成功/失败统计 |
| MD-7 | 格式校验 | 非 `.md` 扩展名 / 损坏文件 / 非法编码给出明确报错 |
| MD-8 | 导入预览 | 导入前返回预览（标题/摘要/格式统计/冲突标记） |
| MD-9 | 目标位置选择 | 导入时可指定 type，条目按指定分类入库 |
| MD-10 | 冲突策略三选一 | 覆盖（更新原条目）/重命名（新 id 新文件名）/跳过（不处理）均生效 |
| MD-11 | 结果统计 | 返回成功数、失败数、失败原因明细 |
| MD-12 | 进度提示 | 大文件导入导出时进度提示，界面不阻塞 |
| MD-13 | 编码兼容 | UTF-8/GBK 等常见编码正常，特殊字符/格式标记无丢失错乱 |
| MD-14 | 内容一致性 100% | 导出再导入后正文与原始 `raw_content` 逐字符一致 |

> **实现状态（2026-11-12 同步）**：MD-1~MD-14 均已实现并通过单测（`tests/test_markdown_io.py`，48 用例）
> 与全量回归（145 全过）。落点：引擎 `modules/knowledge_base/knowledge_markdown_io.py`、
> 端点 `routes.py` §9.3、前端 `static/js/knowledge_panel.js`（`StoryForgeKnowledgeMarkdownIO` 可挂载面板）。

### 8.7 异常与边界处理（新增）

| 场景 | 处理 |
|------|------|
| 文件扩展名不支持 | 拒绝，提示仅支持 `.md` |
| 文件损坏/解析失败 | 返回失败明细，明确错误原因，不中断整批导入 |
| 文件编码异常 | 自动尝试 UTF-8 → GBK → 失败报错 |
| 目标条目不存在 | 导出时跳过并记失败，不中断整批 |
| 同名不同内容 | 判为「待确认」，走冲突策略（覆盖/重命名/跳过） |
| 大文件 | 分块处理 + 进度提示，避免界面阻塞 |
| 导出无匹配条目 | 返回空结果 + 提示「该分类下无条目」 |

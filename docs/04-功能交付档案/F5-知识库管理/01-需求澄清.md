## 一、用户诉求（非技术语言）

> 创作者希望：**把看过的文章、论文、小说，还有脑子里一闪而过的灵感，都收进一个统一的知识库，让系统自动帮我分类、提取要点、建立关联，写小说时随时能检索复用。**

### 1.1 要解决的核心痛点

- 资料散落在浏览器、微信、笔记、PDF 里，创作时找不到。
- 手动整理资料耗时，重点往往被忽略。
- 灵感一闪而过，没有及时记录、没有与已有知识关联，就流失了。
- 论文看完了不知道对写作有什么可落地启发。

### 1.2 期望的完整体验

```text
创作者进入知识库页面
  → 选择录入方式：直接粘贴 / 上传文件 / 图片OCR识别
  → 系统识别资料类型（文章/论文/小说/灵感）
  → 自动结构化拆分：
     ├─ 文章   → 分段 + 核心观点 + 标签化要点清单
     ├─ 论文   → 五要素知识卡片（问题/方法/结论/局限/启发）
     ├─ 小说   → 拆文（角色/情节/叙事风格/世界观）
     └─ 灵感   → 与已有知识自动匹配关联 + 上下文补充完善
  → 生成结构化条目，可编辑、可检索、可关联引用
```

## 二、功能边界

### 2.1 包含（In Scope）

| # | 能力 | 说明 |
|---|------|------|
| 1 | 统一录入入口 | 文本直接输入、文件上传、图片 OCR 识别，三种方式汇总到同一入口 |
| 2 | 资料类型识别 | 自动判定文章/论文/小说/灵感四类（也可手动指定） |
| 3 | 文章结构化 | 内容分段、核心观点提取、关键信息标签化，保留原文逻辑结构 |
| 4 | 知识卡片 | 提炼研究问题/研究方法/核心结论/研究局限/产品设计启发点五要素 |
| 5 | 小说拆文 | 提取核心角色设定、关键情节脉络、叙事风格特征、世界观设定 |
| 6 | 灵感记录与关联 | 快速记录碎片化想法，自动与已有知识匹配关联，上下文补充完善 |
| 7 | 知识关联 | 跨条目关联引用，形成知识网络 |
| 8 | 统一检索 | 按关键词/类型/标签/时间检索全部知识条目 |
| 9 | 编辑与复用 | 结构化内容可编辑，可从知识库引用到创作项目 |
| 10 | 大纲自动提取 | 小说拆文完成后自动提取大纲（章节结构/情节节点/人物关系/故事线），结构化存储并关联绑定拆文数据 |

### 2.2 不包含（Out of Scope）

- ❌ 多格式导出（PDF/Word 批量导出，后续增强）。
- ❌ 知识图谱可视化（力导向图等，后续 Phase 增强）。
- ❌ 跨用户共享与协作（当前单创作者本地知识库）。
- ❌ 自动定时抓取网页/订阅（当前为主动录入）。

## 三、功能流程

### 3.1 录入流程（统一入口）

```text
创作者选择录入方式
  ├─ 直接粘贴文本 → 进入文本区
  ├─ 上传文件 → 读取内容（docx/pdf/txt/md）
  └─ 图片上传 → OCR 识别 → 提取文本
  → 提交 → 系统判定类型（自动/手动）
  → 触发对应结构化拆分
  → 生成条目预览（可编辑）
  → 确认入库 → 写入知识库
```

### 3.2 文章结构化流程

```text
文章全文
  → 分段（保留原文段落结构）
  → 核心观点提取（AI 抽取 3-5 条）
  → 关键信息标签化（关键词/主题标签）
  → 生成摘要 + 要点清单
```

### 3.3 知识卡片流程

```text
论文全文
  → 五要素精准提炼：
     ├─ 研究问题
     ├─ 研究方法
     ├─ 核心结论
     ├─ 研究局限
     └─ 产品设计可落地启发点
  → 生成标准化知识卡片
```

### 3.4 小说拆文流程

```text
小说内容
  → 提取核心角色设定（人物/性格/关系）
  → 提取关键情节脉络（主线/冲突/转折）
  → 提取叙事风格特征（视角/节奏/语言）
  → 提取世界观设定（背景/规则/体系）
  → 生成结构化拆文
  → 自动触发大纲提取（见 3.6）
```

### 3.5 灵感记录与关联流程

```text
灵感快速记录
  → 系统在知识库中检索匹配已有知识（相似度）
  → 自动建立关联（灵感 ↔ 已有知识）
  → 基于已有知识上下文补充完善灵感
  → 生成更完整、更具可执行性的输出
```

### 3.6 大纲自动提取流程（拆文完成后触发）

```text
小说拆文完成（3.4）
  → 自动触发大纲提取：
     ├─ 提取核心章节结构（章节划分/顺序/层级）
     ├─ 提取关键情节节点（主线节点/分支节点/转折点）
     ├─ 提取人物关系脉络（角色间关系/阵营/冲突链）
     └─ 提取核心故事线（主线/支线/暗线）
  → 生成结构化大纲
  → 与对应小说拆文数据关联绑定
  → 前端可查看/编辑/导出
```

## 四、验收标准（DoD）

| # | 标准 | 验证方式 |
|---|------|---------|
| 1 | 三种录入方式可用 | 粘贴 / 上传文件 / 图片 OCR 均可提取内容 |
| 2 | 类型自动识别 | 文章/论文/小说/灵感四类判定准确 |
| 3 | 文章结构化输出 | 分段 + 核心观点 + 标签化要点清单齐全 |
| 4 | 论文五要素卡片 | 问题/方法/结论/局限/启发点五要素齐全 |
| 5 | 小说拆文输出 | 角色/情节/叙事风格/世界观四要素齐全 |
| 6 | 灵感自动关联 | 新灵感与已有知识匹配并建立关联 |
| 7 | 灵感上下文补充 | 补充完善后内容更完整、可执行 |
| 8 | 统一检索 | 关键词/类型/标签/时间四维度可查 |
| 9 | 结构化可编辑 | 每条目内容可二次编辑 |
| 10 | 关联引用 | 条目可被创作项目引用复用 |
| 11 | 大纲自动触发 | 小说拆文完成后自动触发大纲提取，无需手动操作 |
| 12 | 大纲四维度齐全 | 章节结构/情节节点/人物关系/故事线四维度要素齐全 |
| 13 | 结构化关联绑定 | 大纲与拆文数据关联绑定，前端可查看/编辑/导出 |
| 14 | 准确率与适配 | 提取准确率符合内容处理质量标准，对不同类型/篇幅小说文本适配 |
| 15 | 单元测试 | 提取逻辑稳定性、结果完整性有单测覆盖，原拆文功能不受影响 |

## 五、异常与边界处理

| 场景 | 处理 |
|------|------|
| 文件格式不支持 | 前端提示支持格式清单，拒绝上传 |
| 图片 OCR 识别失败 | 提示重新上传，或改用手动输入 |
| 类型识别不确定 | 弹出确认框，允许手动指定 |
| 拆分失败 | 降级为原文存储 + 提示重试 |
| 灵感无匹配知识 | 提示「无关联，仅存为独立灵感」 |
| 检索无结果 | 显示空态 + 建议放宽条件 |
| 超大文本 | 分块处理，进度提示 |
| 并发录入 | 队列化，避免重复条目 |
| 大纲提取失败 | 保留拆文结果，提示重试大纲提取 |
| 大纲无法提取 | 提示文本过简/无章节结构，可手动补充大纲 |

## 六、数据字段说明（概念模型）

### 6.1 知识条目（knowledge entry）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 条目唯一 id |
| `type` | enum | article/paper/novel/inspiration |
| `title` | string | 标题 |
| `source` | enum | paste/upload/ocr/manual |
| `raw_content` | text | 原始内容 |
| `structured` | object | 结构化结果（按类型不同结构） |
| `tags` | array | 标签 |
| `links` | array | 关联条目 id 列表 |
| `created_at` | datetime | 创建时间 |
| `updated_at` | datetime | 更新时间 |

### 6.2 结构化结果（structured，按类型）

| 类型 | 结构 |
|------|------|
| article | `{ paragraphs[], key_points[], summary, tag_list[] }` |
| paper | `{ research_question, research_method, core_conclusion, limitation, design_insight }` |
| novel | `{ characters[], plot_lines[], narrative_style[], world_setting, outline }` |
| inspiration | `{ raw_text, enriched_text, related_ids[] }` |

novel 的 `outline` 字段进一步结构化为四维度大纲要素：

```text
{ chapters[], plot_nodes[], character_relations[], core_storylines }
```

## 七、相关依赖与约束

- **依赖**：`coze_client`（调用 Coze 智能体做拆分/提取/关联）；`app.py` 新增知识库路由；`app.js` 知识库面板。
- **约束**：结构化提取走 Coze 智能体（LLM）时需隐藏 Token；OCR 走可用视觉能力或第三方；检索为本地索引，无需外部搜索服务。
- **前置**：需先完成站点设置（F4）以具备 LLM 配置；与角色 Agent 体系（改造路线图 P3）联动，知识库条目可注入角色上下文。

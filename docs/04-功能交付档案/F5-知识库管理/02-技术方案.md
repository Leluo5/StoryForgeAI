## 一、方案概述

本功能是创作端的**素材与灵感底座**：把文章/论文/小说/灵感四类资料统一录入，走 Coze 智能体（LLM）做结构化拆分，建立跨条目关联，提供统一检索与复用。核心是「录入 → 识别 → 拆分 → 关联 → 检索」五段管线。

### 1.1 方案选型

| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 存储 | JSON 文件（`data/knowledge/*.json`） | SQLite | 延续项目 JSON 存储惯例；单创作者本地；条目数可控 |
| 结构化引擎 | 后端调 Coze 智能体 | 前端调 | 隐藏 Token；集中错误处理；可复用已有 coze_client |
| 类型识别 | LLM 自动判定 + 手动指定 | 纯启发式 | 自动判定为主，不确定时人工兜底 |
| 关联引擎 | 向量相似度（本地 TF-IDF 兜底） | 纯关键词 | 需 LLM 嵌入时走 Coze；无外部搜索服务 |
| OCR | 后端调视觉能力 | 前端 OCR 库 | 统一走 Coze 视觉模型，避免前端依赖 |
| 大纲提取 | 拆文后自动触发子任务 | 手动触发 | 满足 DoD #11 自动触发 |

## 二、数据模型（对齐需求澄清 §六）

### 2.1 知识条目 `knowledge_entry`（`data/knowledge/<id>.json`）

```json
{
  "id": "k_01xxx",
  "type": "novel",
  "title": "雾都疑案·拆文",
  "source": "upload",
  "raw_content": "…原文…",
  "structured": { "...按类型见 2.2..." },
  "tags": ["悬疑", "侦探"],
  "links": ["k_02xxx"],
  "created_at": "2026-11-10T10:00:00",
  "updated_at": "2026-11-10T10:05:00"
}
```

### 2.2 结构化结果 `structured`（按 type）

| type | 结构 |
|------|------|
| article | `{ paragraphs[], key_points[], summary, tag_list[] }` |
| paper | `{ research_question, research_method, core_conclusion, limitation, design_insight }` |
| novel | `{ characters[], plot_lines[], narrative_style[], world_setting, outline }` |
| inspiration | `{ raw_text, enriched_text, related_ids[] }` |

`novel.outline` 四维度大纲结构：

```json
{
  "chapters": [{ "title": "第一章", "summary": "...", "order": 1 }],
  "plot_nodes": [{ "id": "pn_1", "label": "初遇", "type": "main|branch|turn" }],
  "character_relations": [{ "a": "林远", "b": "周福", "relation": "敌对", "camp": "..." }],
  "core_storylines": { "main": "...", "branches": ["..."], "hidden": ["..."] }
}
```

### 2.3 索引与检索

- `data/knowledge/index.json`：条目元数据索引（id/type/title/tags/created_at），供列表与四维度检索，避免全量扫描。
- 检索四维度：关键词（raw_content+structured 全文）、类型（type）、标签（tags）、时间（created_at 范围）。

## 三、API 设计

### 3.1 `POST /api/knowledge/entries` — 统一录入

**请求体**：

```json
{
  "source": "paste|upload|ocr|manual",
  "type": "auto|article|paper|novel|inspiration",
  "title": "可选",
  "raw_content": "文本内容（paste/manual）",
  "file_id": "可选（upload/ocr 时先上传）"
}
```

**响应 200**：`{ "id": "k_01xxx", "type": "novel", "structured": {...}, "tags": [...], "status": "preview" }`

> 返回 `preview` 供前端编辑确认，确认后调 3.2 入库。

### 3.2 `POST /api/knowledge/entries/<id>/commit` — 确认入库

**请求体**：`{ "structured": {...修正后...}, "tags": [...], "links": [...] }`

**响应 200**：`{ "id": "k_01xxx", "status": "saved" }`

### 3.3 `POST /api/knowledge/ocr` — 图片 OCR 识别

**请求体**：multipart `{ "file": <binary> }`

**响应 200**：`{ "text": "识别出的文本" }`

### 3.4 `GET /api/knowledge/entries` — 统一检索

**查询参数**：`keyword` / `type` / `tag` / `start_time` / `end_time` / `page` / `page_size`

**响应 200**：`{ "total": n, "items": [{ id, type, title, tags, created_at }] }`

### 3.5 `GET/PUT/DELETE /api/knowledge/entries/<id>` — 详情 / 编辑 / 删除

- `GET`：完整条目（含 structured）。
- `PUT`：`{ "structured", "tags", "title", "links" }` → 更新 + 重建关联。
- `DELETE`：删除条目，并清理其他条目 `links` 中对它的引用。

### 3.6 `POST /api/knowledge/entries/<id>/link` — 建立关联

**请求体**：`{ "target_id": "k_02xxx", "type": "reference|inspiration|conflict" }`

**响应 200**：`{ "id": "k_01xxx", "links": ["k_02xxx"] }`

### 3.7 `POST /api/knowledge/outline/extract` — 大纲自动提取（拆文后触发）

**请求体**：`{ "novel_id": "k_01xxx" }`

**响应 200**：`{ "novel_id": "k_01xxx", "outline": { "chapters": [...], "plot_nodes": [...], "character_relations": [...], "core_storylines": {...} } }`

## 四、核心逻辑

### 4.1 类型识别

```python
def detect_type(raw_content, manual=None):
    if manual in ("article", "paper", "novel", "inspiration"):
        return manual
    # 调 Coze 智能体判定；不确定时抛 TypeUncertain → 前端弹确认框
    return llm_detect(raw_content)
```

### 4.2 拆分引擎（`knowledge_parser.py`）

```python
def parse_entry(entry):
    if entry["type"] == "article":  return parse_article(entry["raw_content"])
    if entry["type"] == "paper":    return parse_paper(entry["raw_content"])
    if entry["type"] == "novel":    return parse_novel(entry["raw_content"])
    if entry["type"] == "inspiration": return parse_inspiration(entry["raw_content"])
```

- 各 `parse_*` 走 Coze 智能体，结构化提取失败 → **降级为原文存储**（需求澄清 §五「拆分失败」）。
- `parse_novel` 成功后**自动触发** `extract_outline(novel_id)`（DoD #11）。

### 4.3 大纲提取引擎（`knowledge_outline.py`）

```python
def extract_outline(novel_id):
    entry = load_entry(novel_id)
    outline = llm_extract_outline(entry["raw_content"])  # 四维度
    entry["structured"]["outline"] = outline
    save_entry(entry)  # 与拆文数据同条目关联绑定
    return outline
```

- 失败：保留拆文结果，返回 `{ "error": "outline_failed" }`（前端提示重试）。
- 无法提取（无章节结构）：返回 `{ "error": "no_chapters" }`（前端提示手动补充）。

### 4.4 关联引擎（`knowledge_linker.py`）

```python
def link_inspiration(inspiration_id):
    # 1) 在已有条目中检索相似度
    candidates = search_similar(inspiration["raw_text"])
    # 2) 建立关联
    for c in candidates[:3]:
        add_link(inspiration_id, c["id"])
    # 3) 基于已有知识上下文补充完善灵感
    enriched = llm_enrich(inspiration["raw_text"], candidates)
    inspiration["structured"] = {"raw_text": ..., "enriched_text": enriched, "related_ids": [...]}
```

- 无匹配：`related_ids=[]`，仅存独立灵感（需求澄清 §五）。
- 相似度：优先 LLM 嵌入，无嵌入服务时 TF-IDF + 余弦兜底。

### 4.5 统一检索

```python
def search_entries(keyword=None, type=None, tag=None, start=None, end=None, page=1, size=20):
    index = load_index()  # data/knowledge/index.json
    results = [e for e in index if match(e, keyword, type, tag, start, end)]
    return {"total": len(results), "items": paginate(results, page, size)}
```

### 4.6 并发与去重

- 录入走**队列化**：同一 `raw_content` 哈希在 `index.json` 中查重，重复返回已有条目（防重复条目）。
- 超大文本：按 8000 字分块，逐块送 LLM，前端进度提示。

## 五、异常处理（对齐需求澄清 §五）

| 场景 | 处理 | 方案落点 |
|------|------|---------|
| 文件格式不支持 | 前端提示支持清单，拒绝上传 | 3.3 上传前校验 MIME |
| OCR 识别失败 | 提示重传或改手动 | 3.3 返回 `{error:"ocr_failed"}` |
| 类型识别不确定 | 弹确认框手动指定 | 4.1 `TypeUncertain` |
| 拆分失败 | 降级原文存储 + 提示重试 | 4.2 `parse_*` 降级 |
| 灵感无匹配知识 | 提示「仅存为独立灵感」 | 4.4 `related_ids=[]` |
| 检索无结果 | 空态 + 建议放宽 | 4.5 返回空 `items` |
| 超大文本 | 分块 + 进度 | 4.6 分块 |
| 并发录入 | 队列化防重复 | 4.6 哈希查重 |
| 大纲提取失败 | 保留拆文 + 提示重试 | 4.3 `outline_failed` |
| 大纲无法提取 | 提示手动补充 | 4.3 `no_chapters` |

## 八、风险与待定

| 风险 | 说明 | 对策 |
|------|------|------|
| LLM 拆分成本 | 每录入一条走一次智能体 | 分块 + 缓存（哈希查重避免重复调） |
| 向量相似度依赖 | 无嵌入服务时 TF-IDF 精度受限 | 本地 TF-IDF 兜底；后续接入嵌入 |
| OCR 视觉模型可用性 | 依赖 Coze 视觉能力 | 失败降级手动输入 |
| 大纲提取准确率 | 不同篇幅/文风差异大 | 分块 + 章节启发式前处理；DoD #14 抽样 |
| JSON 存储扩展性 | 条目增多索引扫描变慢 | index.json 元数据索引，避免全量 |

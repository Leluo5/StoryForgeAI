## 一、功能简介

知识库支持把条目**导出为标准 Markdown 文件**（单条 / 批量 / 分类），也能把本地 Markdown 文件**导入知识库**（单文件 / 多文件，带预览与冲突处理）。

| 能力 | 说明 |
|------|------|
| 导出 | 单条直接下载 `.md`；批量/分类打包为 ZIP 下载；文件名自动规范（标题清洗 + 时间戳） |
| 导入 | 读取 `.md`/`.markdown` 文件，自动解析标题、正文、格式元素；导入前预览；冲突策略三选一 |
| 质量 | UTF-8 为主兼容 GBK；内容一致性 100%；损坏文件明确报错；大文件有进度提示 |

## 二、前置条件（如何挂载面板）

本功能是**独立可挂载面板组件**，不改变知识库主界面。需在页面脚本中挂载入口按钮：

```js
// 方式一：直接挂载面板到容器
StoryForgeKnowledgeMarkdownIO.mount({
  apiBase: '',            // API 前缀（默认空，即相对路径；如部署在子路径则传 '/xxx'）
  onClose: () => {}       // 面板关闭回调（可选）
});

// 方式二：挂载入口按钮，点击后打开面板
StoryForgeKnowledgeMarkdownIO.createButton({
  mountEl: document.getElementById('some-container'),
  apiBase: ''
});
```

> 前提：`static/js/knowledge_panel.js` 已随页面加载（`app.py` 已注册知识库蓝图 `/api/knowledge`）。

## 三、导出功能

### 3.1 操作步骤

1. 打开「Markdown 导入导出」面板，切到 **导出** 标签。
2. 选择 **导出范围**：
   - **单条**：从下拉框选择一条条目 → 点击「导出」，直接下载 `.md` 文件。
   - **批量**：勾选多条条目（列表来自 `/api/knowledge/entries`）→ 点击「导出」，下载 ZIP 包，内含每个条目的 `.md`。
   - **分类**：选择 **type**（文章/论文/小说/灵感）或 **tag**（标签）作为筛选维度 → 点击「导出」，下载该分类下全部条目的 ZIP 包。
3. 下载后本地打开文件，内容为 **元数据注释 + `# 标题` + 原文正文**，格式元素（标题层级/列表/代码块/图片引用/表格）原样保留。

### 3.2 文件名规则

```
{清洗后的标题}_{YYYYMMDD_HHMMSS}.md
```

- 非法字符（`\ / : * ? " < > |` 等）自动替换为 `_`；连续空白压缩；首尾点/空格去除。
- 标题超长截断（上限 80 字符），末尾多余 `_` 去除；空标题回退 `untitled`。
- 批量打包文件名：`knowledge_export_{YYYYMMDD_HHMMSS}.zip`。

### 3.3 无匹配条目

选中范围内无条目时，返回统计为空并提示「该范围下无条目可导出」，不会下载空文件。

## 四、导入功能

### 4.1 操作步骤

1. 切到 **导入** 标签。
2. 选择本地文件（支持 `.md` / `.markdown`，可多选）→ 文件自动读取为文本。
3. 点击「预览」，系统解析每个文件并展示：
   - **标题**（取首个 `#` 或首行非空，≤60 字符，空则回退 `untitled`）
   - **格式统计**：标题数 / 代码块数 / 图片引用数 / 列表数 / 表格数
   - **冲突标记**：⚠ 同名或内容重复时提示
4. 选择 **目标分类** `target_type`：`article`（文章）/ `paper`（论文）/ `novel`（小说）/ `inspiration`（灵感）。
5. 选择 **冲突策略** `conflict_strategy`：
   - **覆盖 overwrite**：内容哈希相同 → 更新原条目；仅同名 → 覆盖标题并更新内容。
   - **重命名 rename**：同名或重复 → 用新 id、文件名加后缀另存为新条目。
   - **跳过 skip**：重复内容 → 不处理，跳过并计入 skipped。
6. 点击「开始导入」，完成后展示结果统计。

### 4.2 结果统计

```json
{
  "total": 3, "success": 2, "failed": 1,
  "failed_items": [{"file_name": "坏文件.md", "reason": "bad_extension"}],
  "created": ["k_xxx"], "updated": ["k_yyy"], "skipped": []
}
```

- **成功**：成功入库条目数（含新增/更新/跳过）；**失败**：失败条目数与失败原因明细。
- 失败原因示例：`bad_extension`（扩展名不支持）、`parse_error`（内容损坏/编码异常）、`empty_content`（空文件）。
- 单文件失败**不中断整批**，其余文件正常导入。

### 4.3 校验端点

`POST /api/knowledge/markdown/import/validate` 可单独校验单文件格式合法性，返回 `{valid, reason}`。前端选择文件时自动调用，非法文件即时报错。

## 五、编码与兼容性

| 项 | 说明 |
|----|------|
| 编码 | 优先 **UTF-8**，失败自动尝试 **GBK**，再失败抛 `EncodingError` → 归入失败明细 |
| 特殊字符 | 导入导出的 Markdown 文本不做转义改写，特殊字符、格式标记原样保留 |
| 内容一致性 | 导出（注释 + H1 + 正文）→ 导入（自动剥离导出头）→ `raw_content` 与原正文**逐字符一致（100%）** |
| 图片引用 | 保留引用文本（如 `![](xxx.png)`），不打包二进制图片（见需求 §8.3 决策） |
| 大文件 | 分块处理 + 前端进度提示，界面不阻塞 |

## 六、常见问题（FAQ）

**Q：导出的 `.md` 文件里的头部注释是什么？**
A：是 `<!-- knowledge-export ... -->` 元数据注释（含 id/type/时间戳），用于再次导入时识别并剥离，保证内容一致性。不影响正常 Markdown 渲染。

**Q：为什么批量/分类导出返回的是 ZIP 而不是多个 `.md`？**
A：单条导出直接下载 `.md`；条目数 >1 时自动打包为 ZIP，避免浏览器触发多次下载。

**Q：导入时提示「同名」但没有内容重复，选哪个策略？**
A：这是「待确认」场景（同名不同内容）。推荐选 **重命名** 保留两个条目；若想用新内容替换旧的选 **覆盖**。

**Q：`identical` 内容重复 + 选「重命名」会怎样？**
A：内容已存在时 `create_entry` 内部哈希查重会命中已有条目而非新建，因此**视为跳过**（内容已存在，无需重复入库），计入 `skipped`。仅「同名不同内容」的 `name_collision` 才会走重命名新建（标题加 `_imported` 后缀）。

**Q：一个文件损坏了，其他文件还能导入吗？**
A：能。失败文件进入 `failed_items` 并给出原因，整批继续。

**Q：面板按钮在哪里？**
A：本组件不自动渲染入口，需按第二节挂载（`mount` 或 `createButton`）。

## 七、相关接口速查

| 方法 | 路径 | 用途 |
|------|------|------|
| POST | `/api/knowledge/markdown/export` | 导出（`scope: single\|batch\|category` + `entry_ids`/`type`/`tag` + `as_zip`） |
| POST | `/api/knowledge/markdown/import/preview` | 导入前预览 |
| POST | `/api/knowledge/markdown/import` | 执行导入（`target_type` + `conflict_strategy`） |
| POST | `/api/knowledge/markdown/import/validate` | 单文件格式校验 |
| GET | `/api/knowledge/entries` | 条目列表（导出选择/批量勾选数据源） |

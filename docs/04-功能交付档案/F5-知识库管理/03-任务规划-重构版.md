## 一、依赖图

```
R-T1 契约schema + 实体 + migration ──→ R-T2 知识库service(CRUD+检索+去重) ──→ R-T5 controller
      │                                                                        ▲
      ├──→ R-T3 引擎层(parser/outline/linker) ─────────────────────────────────┘
      └──→ R-T4 Markdown导入导出引擎 ──→ R-T5 controller
                                              │
                          R-T6 前端client + KnowledgePanel(录入/检索/详情/大纲)
                          R-T7 工作台接入(knowledge tab) + 单元测试
                          R-T8 端到端验收(E2E + 回归)
```

> 分层原则：契约/数据 → service → 引擎 → controller → 前端 → 接入 → 验收。高风险任务 `★` 见 §四。

## 二、任务清单

### 阶段 A · 契约与数据层

**R-T1 契约 schema + 实体 + migration** — 高优先级 · ★
- `packages/contracts/src/knowledge.ts`：`knowledgeEntrySchema`、`createKnowledgeEntryRequestSchema`、`commitKnowledgeEntryRequestSchema`、`updateKnowledgeEntryRequestSchema`、`searchKnowledgeRequest/ResponseSchema`、`linkKnowledgeRequestSchema`、Markdown 导入导出 schema。
- `apps/api/src/database/knowledge-entry.entity.ts`：`KnowledgeEntryEntity`（§2.1，含 `author_id/type/title/source/raw_content/structured/tags/links/content_hash/created_at/updated_at`）。
- `apps/api/src/database/migrations/1760600000000-knowledge-base.ts`：建表 + 索引（`(author_id)`、`(author_id,type)`、`(author_id,created_at)`、唯一 `(author_id,content_hash)`）。
- `packages/contracts/src/index.ts`：`export * from './knowledge'`。
- 完成标准：`pnpm --filter @storyforge/contracts build` 通过；migration 在测试库可跑；schema 单测覆盖必填/枚举/边界。

### 阶段 B · 服务层

**R-T2 知识库 service（CRUD + 检索 + 去重）** — 高优先级 · ★
- `apps/api/src/knowledge/knowledge.service.ts`：`createPreview`（生成 preview 不落库，去重查 `author_id+content_hash`）、`commit`、`getById`、`update`、`delete`（清理他人 links 引用）、`searchEntries`（四维 ILIKE/type/tag/时间 + 分页）、`addLink`、`removeLink`。
- 完成标准：单测覆盖 CRUD/去重/四维检索/分页边界/删除级联清理 links。

### 阶段 C · 引擎层

**R-T3 引擎层（parser/outline/linker）** — 高优先级 · ★
- `apps/api/src/knowledge/knowledge-llm.provider.ts`：`KnowledgeLlmProvider` 接口（`detectType`/`parseEntry`/`extractOutline`/`enrichInspiration`）+ `MockKnowledgeLlmProvider`（确定性输出，M3b 接 Coze）。
- `apps/api/src/knowledge/knowledge-parser.service.ts`：`detectType`（手动兜底）、`parseArticle/parsePaper/parseNovel/parseInspiration`（分块 + 降级原文）、`parseNovel` 后自动触发 `extractOutline`。
- `apps/api/src/knowledge/knowledge-outline.service.ts`：`extractOutline`（四维度，失败 `outline_failed`/`no_chapters`）。
- `apps/api/src/knowledge/knowledge-linker.service.ts`：`linkInspiration`（TF-IDF 余弦相似度 + 前 3 关联 + `enrichInspiration`）。
- 完成标准：单测覆盖四类拆分/降级/分块/自动触发大纲/无匹配关联/四维度大纲。

**R-T4 Markdown 导入导出引擎** — 高优先级 · ★
- `apps/api/src/knowledge/knowledge-markdown.service.ts`：`buildExportMarkdown`（标题 H1 + 正文保原样 + 元数据注释）、`sanitizeFilename`/`buildFilename`、`decodeBytes`（utf-8→gbk）、`parseMarkdownText`、`detectConflict`（identical/name_collision）、`importFiles`（overwrite/rename/skip + 统计）、`buildZip`（jszip）。
- 完成标准：单测覆盖编码/解析/冲突三策略/统计/一致性 100%（导出→导入逐字符比对）。

### 阶段 D · 接口层

**R-T5 controller（3.1~3.9 端点）** — 高优先级 · ★
- `apps/api/src/knowledge/knowledge.controller.ts`：统一录入/commit/检索/详情/编辑/删除/link/大纲提取/Markdown 导入导出四端点。
- `apps/api/src/knowledge/knowledge.module.ts`：注册 controller + service + 引擎，`TypeOrmModule.forFeature([KnowledgeEntryEntity])`；`app.module.ts` 注册 `KnowledgeModule`。
- 完成标准：supertest E2E 覆盖全部端点（含 400/404/401 异常路径）。

### 阶段 E · 表现层

**R-T6 前端 client + KnowledgePanel** — 中优先级
- `apps/web/src/knowledge/knowledge-client.ts`：封装 3.1~3.9 全部端点。
- `apps/web/src/knowledge/knowledge-panel.tsx`：`KnowledgePanel`（录入 Tab + 类型确认 + 条目预览编辑 + 检索四维 + 卡片列表 + 详情编辑 + 大纲四维视图 + Markdown 导入导出子面板）。
- 完成标准：组件单测（渲染/交互/表单）；typecheck/lint 通过。

**R-T7 工作台接入 + 单测** — 中优先级
- `apps/web/src/workbench/workbench-page.tsx`：`PANELS` 加 `'knowledge'`；`context()` 加 tab + body 分支 + import。
- 完成标准：单测验证 knowledge tab 渲染；回归 147+ 全绿。

### 阶段 F · 验收

**R-T8 端到端验收（E2E + 回归）** — 高优先级 · ★
- E2E：登录 → 工作台 → 打开知识库 tab → 录入（paste）→ 预览 → 编辑确认 → 入库 → 检索 → 详情编辑 → 删除；Markdown 导出→导入→一致性。
- 完成标准：全量单测 + E2E 通过；DoD 对照表逐条核对；README 更新为「已交付」。

## 四、高风险任务标注

| 任务 | 风险点 | 对策 |
|------|--------|------|
| R-T1 | migration 唯一索引与既有数据冲突 | 测试库空表，无冲突；唯一 `(author_id,content_hash)` 建索引 |

| R-T8 | DoD 逐条难收口 | 对照表逐条 + 抽样 |

## 五、编码实现指引（对齐 Skill 11）

1. **每任务一阶段**：R-T1 完成并跑通单测，再进 T2，不一口气全做完。
2. **每任务完成即写单测**：通过才进下一任务。
3. **文档同步**：编码完成并单测通过后，更新本档案 README 与总索引为「已交付」。
4. **高风险任务**：R-T1/T2/T3/T5/T8 完成时暂停，人工复核后再继续。
5. **vite 缓存坑**：contracts 新增导出后，需清 `apps/web/node_modules/.vite` 缓存并重启 vite（历史踩坑，见会话记录）。

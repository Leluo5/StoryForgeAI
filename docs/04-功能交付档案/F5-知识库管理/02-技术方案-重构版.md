# 技术方案设计 · F5 知识库管理（重构版）

> 版本：v2.0 · 状态：已交付（2026-11-21）
> 项目：StoryForgeAI —— 专业小说 AI 写作软件
> 类型：功能交付档案（架构迁移）
> 对应需求：[01-需求澄清.md](./01-需求澄清.md)（v1.1，含大纲自动提取 + Markdown 导入导出）
> 迁移背景：原 F5 在旧 Flask 架构（JSON 文件存储 + Coze LLM + `knowledge_panel.js`）已实现并测试通过；
> 当前项目已重构为 **React 19 + NestJS + TypeORM(PostgreSQL) + `@storyforge/contracts`**，知识库功能在重构版中缺失，
> 本方案为**按新架构重写知识库**（非逐行移植旧代码），复用旧 F5 的需求语义与功能范围。

---

## 一、方案概述

本功能是创作端的**素材与灵感底座**：把文章/论文/小说/灵感四类资料统一录入，走 LLM 做结构化拆分，建立跨条目关联，提供统一检索与复用。核心是「录入 → 识别 → 拆分 → 关联 → 检索」五段管线，另含大纲自动提取与 Markdown 导入导出两个增量能力。

### 1.1 架构迁移映射（旧 → 新）

| 旧 Flask 实现 | 新 React/NestJS 落点 | 说明 |
| --- | --- | --- |
| `modules/knowledge_base/knowledge_store.py`（JSON 文件） | `apps/api/src/knowledge/`（TypeORM entity + service） | 存储改 PostgreSQL，结构化结果用 `jsonb` |
| `knowledge_parser.py::detect_type/parse_*`（Coze LLM） | `KnowledgeParserService`（依赖 `AiModelProvider`） | LLM 走 `AiModelProvider` 接口，当前 Mock（M3a），M3b 接 Coze |
| `knowledge_outline.py::extract_outline`（Coze LLM） | `KnowledgeOutlineService`（同上） | 四维度大纲提取 |
| `knowledge_linker.py::link_inspiration`（嵌入+TF-IDF） | `KnowledgeLinkerService`（TF-IDF + 余弦，无嵌入时兜底） | 灵感自动关联 |
| `knowledge_markdown.py` / `knowledge_markdown_io.py` | `KnowledgeMarkdownService`（纯函数） | Markdown 渲染/导入导出 |
| `app.py` 知识库路由 / `routes.py` §9.3 | `apps/api/src/knowledge/knowledge.controller.ts` | REST 端点，前缀 `api/v1/knowledge` |
| `static/js/knowledge_panel.js` | `apps/web/src/knowledge/knowledge-panel.tsx` | React 组件，挂工作台右侧 `knowledge` tab |
| `@storyforge/contracts`（新增 `knowledge.ts`） | — | 前后端共享 zod schema |

### 1.2 方案选型（重构版）

| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 存储 | **TypeORM + PostgreSQL**（`knowledge_entry` 表） | JSON 文件 | 对齐当前重构版架构；结构化用 `jsonb` 存任意结构；与既有 entity 同一事务 |
| 结构化引擎 | **`AiModelProvider` 接口**（当前 Mock，M3b 接 Coze） | 前端调 | 隐藏 Token；集中错误处理；复用既有 AI 基础设施（M3b 无需改知识库） |
| 类型识别 | LLM 自动判定 + 手动指定兜底 | 纯启发式 | 对齐旧 F5 语义；不确定抛 `TypeUncertain` |
| 关联引擎 | 向量相似度（本地 TF-IDF 余弦兜底） | 纯关键词 | 无嵌入服务时 TF-IDF 兜底，与旧 F5 一致 |
| OCR | **降级为手动输入**（当前无视觉模型） | Coze 视觉 | 当前 Mock 无 OCR 能力；预留 `ocr` 字段，M3b 接视觉后启用。**本轮录入方式仅 paste/manual** |
| 大纲提取 | 拆文后自动触发（`parse_novel` 成功后） | 手动触发 | 满足 DoD #11 自动触发 |
| Markdown 导入导出 | 纯函数引擎（服务端）+ React 面板 | — | 对齐旧 F5 §9，正文保原样，内容一致性 100% |
| 作用域 | **全局**（不按作品） | 按作品 | 对齐旧 F5「单创作者本地知识库」；`author_id` 归属 |

> **重要限制**：当前 `AiModelProvider` 为 Mock（M3a），LLM 拆分/大纲提取/类型识别无法真实运行。
> 方案通过 **Mock 确定性输出** 打通闭环（可编辑确认入库），M3b 接入 Coze 时替换 provider 即可，不改知识库业务逻辑。

## 二、数据模型（对齐需求澄清 §六，映射到 TypeORM）

### 2.1 实体 `KnowledgeEntryEntity`（`apps/api/src/database/knowledge-entry.entity.ts`）

| 字段 | 类型（TypeORM） | 说明 |
|------|------|------|
| `id` | `uuid` PK | 条目唯一 id |
| `author_id` | `uuid` FK → authors | 归属作者（全局库，作者级隔离） |
| `type` | `varchar` | `article/paper/novel/inspiration` |
| `title` | `varchar(200)` | 标题 |
| `source` | `varchar` | `paste/manual/upload/ocr/import` |
| `raw_content` | `text` | 原始内容（Markdown 友好） |
| `structured` | `jsonb` | 结构化结果（按类型不同结构，见 2.2） |
| `tags` | `jsonb`（string[]） | 标签 |
| `links` | `jsonb`（string[]） | 关联条目 id 列表 |
| `content_hash` | `varchar(64)` | `sha256(raw_content)` 十六进制，查重用 |
| `created_at` | `timestamptz` | 创建时间 |
| `updated_at` | `timestamptz` | 更新时间 |

索引：`(author_id)`、`(author_id, type)`、`(author_id, created_at)`。`content_hash` 联合 `author_id` 建唯一索引用于查重。

### 2.2 结构化结果 `structured`（按 type，`jsonb`）

与旧 F5 §2.2 完全一致：

| type | 结构 |
|------|------|
| article | `{ paragraphs[], key_points[], summary, tag_list[] }` |
| paper | `{ research_question, research_method, core_conclusion, limitation, design_insight }` |
| novel | `{ characters[], plot_lines[], narrative_style[], world_setting, outline }` |
| inspiration | `{ raw_text, enriched_text, related_ids[] }` |

`novel.outline` 四维度大纲（对齐旧 F5 §2.2）：

```json
{
  "chapters": [{ "title": "第一章", "summary": "...", "order": 1 }],
  "plot_nodes": [{ "id": "pn_1", "label": "初遇", "type": "main|branch|turn" }],
  "character_relations": [{ "a": "林远", "b": "周福", "relation": "敌对", "camp": "..." }],
  "core_storylines": { "main": "...", "branches": ["..."], "hidden": ["..."] }
}
```

### 2.3 契约 schema（`packages/contracts/src/knowledge.ts`）

用 zod 定义与实体一致的输入/输出 schema，前端 `apiRequest(path, schema)` 校验。核心：

- `knowledgeEntrySchema`：完整条目（含 structured `z.record(z.unknown())`，因按类型异构）。
- `createKnowledgeEntryRequestSchema`：`{ source, type: 'auto'|'article'|...|'inspiration', title?, raw_content }`。
- `commitKnowledgeEntryRequestSchema`：`{ structured, tags, links }`。
- `updateKnowledgeEntryRequestSchema`：`{ title?, structured?, tags?, links? }`。
- `searchKnowledgeRequestSchema` / `searchKnowledgeResponseSchema`：四维检索 + 分页。
- `linkKnowledgeRequestSchema`：`{ target_id, type: 'reference'|'inspiration'|'conflict' }`。
- Markdown 导入导出 schema：`importPreviewItemSchema` / `importResultSchema` / `exportResultSchema`（对齐旧 F5 §8.8）。

## 三、API 设计（`api/v1/knowledge/*`，挂 SessionGuard，写操作 + CsrfGuard）

### 3.1 `POST /api/v1/knowledge/entries` — 统一录入（生成预览）

**请求体**：
```json
{ "source": "paste|manual|upload|ocr", "type": "auto|article|paper|novel|inspiration", "title": "可选", "raw_content": "文本内容" }
```
**响应 200**：`{ "id", "type", "structured", "tags", "status": "preview" }`
> 返回 `preview` 供前端编辑确认；**不落库**（preview 态，临时生成）。确认后调 3.2 入库。
> 去重：同一 `author_id + content_hash` 已存在则直接返回已有条目（`status: "saved"`，防重复条目）。

### 3.2 `POST /api/v1/knowledge/entries/:id/commit` — 确认入库

**请求体**：`{ "structured", "tags", "links" }`
**响应 200**：`{ "id", "status": "saved" }`

### 3.3 `GET /api/v1/knowledge/entries` — 统一检索

**查询参数**：`keyword` / `type` / `tag` / `start_time` / `end_time` / `page` / `page_size`
**响应 200**：`{ "total": n, "items": [{ id, type, title, tags, created_at }] }`

### 3.4 `GET /api/v1/knowledge/entries/:id` — 详情

**响应 200**：完整条目（含 structured）。

### 3.5 `PUT /api/v1/knowledge/entries/:id` — 编辑

**请求体**：`{ "title"?, "structured", "tags", "links" }` → 更新 + 重建关联。

### 3.6 `DELETE /api/v1/knowledge/entries/:id` — 删除

删除条目，并清理其他条目 `links` 中对它的引用。

### 3.7 `POST /api/v1/knowledge/entries/:id/link` — 建立关联

**请求体**：`{ "target_id", "type": "reference|inspiration|conflict" }`
**响应 200**：`{ "id", "links": ["k_02xxx"] }`

### 3.8 `POST /api/v1/knowledge/outline/extract` — 大纲自动提取（拆文后触发）

**请求体**：`{ "novel_id" }`
**响应 200**：`{ "novel_id", "outline": { "chapters": [...], "plot_nodes": [...], "character_relations": [...], "core_storylines": {...} } }`

### 3.9 Markdown 导入导出（对齐旧 F5 §9.3）

| 方法/路径 | 用途 | 说明 |
| --- | --- | --- |
| `POST /api/v1/knowledge/markdown/export` | 单条/批量/分类导出 | `{mode:"single"|"batch"|"by_type"|"by_tag", entry_ids?, type?, tag?}`；single 返回 `{content, file_name}`，批量/分类返回 ZIP（base64）+ 统计 |
| `POST /api/v1/knowledge/markdown/import/preview` | 导入预览 | `{files:[{file_name, content}], target_type}` → `{items:[import_preview_item]}`（含冲突标记，不落库） |
| `POST /api/v1/knowledge/markdown/import` | 确认导入 | `{items, target_type, conflict_strategy}` → `{total, success, failed, failed_items, created, updated}` |
| `POST /api/v1/knowledge/markdown/import/validate` | 单文件格式校验 | `{file_name, content}` → `{valid, reason}` |

> 导出 ZIP 用服务端 `jszip` 生成，前端下载 blob；单条直接下载 `.md`。

## 四、核心逻辑（引擎层，`apps/api/src/knowledge/`）

### 4.1 类型识别 `detectType(rawContent, manual?)`

`manual` 非空则直接返回；否则调 `AiModelProvider` 判定；不确定抛 `TypeUncertain` → 前端弹确认框手动指定。

### 4.2 拆分引擎 `parseEntry(type, rawContent)`

按类型分派 `parseArticle/parsePaper/parseNovel/parseInspiration`，全部走 `AiModelProvider`。
- 拆分失败 → 降级为原文存储（`structured = { raw: rawContent }` + 标记 `parse_degraded`）。
- 超大文本（> 6000 字）分块，逐块解析再合并（对齐旧 F5 §4.6 分块规则）。
- `parseNovel` 成功后**自动触发** `extractOutline`（DoD #11）。

### 4.3 大纲提取 `extractOutline(novelId)`

四维度提取（章节/情节/人物关系/核心故事线）。失败返回 `{ error: "outline_failed" }`；无章节结构返回 `{ error: "no_chapters" }`（前端提示手动补充）。结果写入 `structured.outline`。

### 4.4 关联引擎 `linkInspiration(inspirationId)`

1. 在已有条目中检索相似度（TF-IDF + 余弦，无嵌入兜底）；
2. 前 3 名建立关联；
3. 基于已有知识上下文 `llmEnrich` 补充完善灵感。
无匹配 → `related_ids=[]`，仅存独立灵感。

### 4.5 统一检索 `searchEntries(keyword, type, tag, start, end, page, size)`

四维过滤（keyword 匹配 raw_content + structured 全文；type/tag/时间）+ 分页。keyword 用 PostgreSQL `ILIKE` 或 `to_tsvector` 全文检索（中文分词受限，用 ILIKE 兜底）。

### 4.6 并发与去重

录入前查重：`author_id + content_hash` 唯一索引，重复返回已有条目（防重复条目）。超大文本分块 + 前端进度提示。

## 五、异常处理（对齐需求澄清 §五）

| 场景 | 处理 | 方案落点 |
|------|------|---------|
| 文件格式不支持 | 前端提示支持清单（`validate` 返回 `bad_extension`） | 3.9 validate |
| OCR 不可用 | 本轮 OCR 降级手动输入；M3b 接视觉后启用 | 1.2 选型 |
| 类型识别不确定 | 弹确认框手动指定 | 4.1 `TypeUncertain` |
| 拆分失败 | 降级原文存储 + 提示重试 | 4.2 `parse_degraded` |
| 灵感无匹配知识 | 提示「仅存为独立灵感」 | 4.4 `related_ids=[]` |
| 检索无结果 | 空态 + 建议放宽 | 4.5 空 `items` |
| 超大文本 | 分块 + 进度 | 4.6 分块 |
| 并发录入 | 哈希查重防重复 | 4.6 唯一索引 |
| 大纲提取失败 | 保留拆文 + 提示重试 | 4.3 `outline_failed` |
| 大纲无法提取 | 提示手动补充 | 4.3 `no_chapters` |

## 八、风险与待定

| 风险 | 说明 | 对策 |
|------|------|------|
| LLM 依赖 Mock | 拆分/大纲/识别无法真实运行 | Mock 确定性输出打通闭环；M3b 接 Coze 替换 provider |

| jsonb structured 校验 | 按类型异构，zod 难精确 | 用 `z.record(z.unknown())` + 业务层按类型校验 |

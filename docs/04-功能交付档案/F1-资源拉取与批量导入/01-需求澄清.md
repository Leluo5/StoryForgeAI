## 一、用户诉求（非技术语言）

> 创作者希望：**不用一行代码，就把 Coze 智能体导入 Agent 管理，把工作流导入工作流管理，把知识库导入作品管理。**

### 1.1 要解决的核心痛点

- Coze 作品默认只能在 Coze 站内体验，无法嵌入自己的站点。
- 创作者不想把源码/PAT Token 暴露给访客。
- 逐个手工配置作品元信息（名称、简介、参数）太繁琐。

### 1.2 期望的完整体验

```text
创作者登录管理后台
   → 粘贴 PAT Token + 工作空间 ID
   → 点「测试连接」验证可用
   → 平台自动拉取我的 Bot / 工作流 / 知识库列表
   → 按资源类型 Tab 浏览（Bot / 工作流 / 知识库）
   → 勾选要导入的资源 → 点「批量导入」
   → 自动提取元信息（名称/简介/提示词/变量等）
   → Bot 进入「Agent 管理」的全局未分类池
   → 工作流进入「工作流管理」模块
   → 知识库进入「作品管理」
```

## 二、功能边界

### 2.1 包含（In Scope）

| # | 能力 | 说明 |
|---|------|------|
| 1 | PAT 连接测试 | 校验 Token 与 workspace 是否有效，返回连接状态 |
| 2 | 资源列表拉取 | 列 Bot / 工作流 / 知识库，支持类型 Tab 切换 |
| 3 | 资源详情获取 | 拉取单个资源完整元信息（提示词/开场白/变量等） |
| 4 | 批量导入 | 勾选多个资源 → Bot 写入 Agent 池，workflow 写入工作流管理，dataset 写入作品库 |
| 5 | 元信息自动提取 | 名称/简介/开场白/变量/快捷指令 自动填充 |
| 6 | 导入状态反馈 | 每个资源导入成功/失败独立反馈，部分成功不整体回滚 |

### 2.2 不包含（Out of Scope）

- ❌ 编辑 Coze 平台上的资源本体（本平台只读拉取 + 展示，不反向写回 Coze）。
- ❌ 资源在 Coze 侧的删除/下线同步（本平台不监听 Coze 变更）。
- ❌ 知识库内文档内容的在线预览编辑（仅展示元信息）。
- ❌ 多创作者多租户（当前单管理端，单 PAT Token 工作空间）。

## 三、功能流程

### 3.1 连接测试流程

```text
输入 PAT + workspace
      │
      ▼
POST /api/admin/coze/test
      │
      ├─ 成功 → 返回 { ok: true, bots_count, workflows_count }
      └─ 失败 → 返回 { ok: false, error: "<原因>" }
```

### 3.2 资源列表流程

```text
连接成功
  │
  ▼
拉取三类型资源（并行）：
  ├─ GET /v1/bots           → botList
  ├─ GET /v1/workflows      → workflowList
  └─ GET /v1/datasets       → datasetList
  │
  ▼
前端按 currentResourceTab 渲染对应 Tab
（all 合并展示 / bots / workflows / datasets）
```

### 3.3 批量导入流程

```text
勾选资源列表 → POST /api/admin/works/import
      │
      ▼
遍历每个勾选资源：
  ├─ Bot：拉取详情并写入 AgentStore 的 _global 未分类池
  │   └─ 按 bot_id 查重；已存在则更新，不保存 PAT
  ├─ workflow：提取元信息并写入 WorkflowStore 的 _global 未分类池
  │   └─ 按 workflow_id 查重；已存在则更新（幂等）
  └─ dataset：提取元信息并写入 work_manager
      │
      ├─ 成功 → 记录 agent_id / workflow_id / work_id
      └─ 失败 → 记录失败项（不中断整体）
      │
      ▼
返回 { imported: n, failed: [{id, reason}] }
前端提示「成功导入 n 个，失败 m 个」
```

## 四、验收标准（DoD）

| # | 标准 | 验证方式 |
|---|------|---------|
| 1 | PAT 无效时提示明确错误，不进入列表页 | 输入错误 Token → 点测试 → 见错误 toast |
| 2 | 资源列表按类型正确分组，Tab 切换即时生效 | 切 Tab → 列表刷新为对应类型 |
| 3 | Bot 导入后进入 Agent 管理，不生成作品 | 导入 Bot → Agent 管理可见，作品管理无新增 |
| 4 | 工作流进入工作流管理模块 | 导入 workflow → 工作流管理出现对应工作流，作品管理无新增 |
| 5 | 单个资源失败不影响其他成功导入 | 故意传一个无效资源 → 部分成功提示 |
| 6 | Agent 不持久化 PAT，作品不对外暴露 PAT | 检查 Agent JSON 无 pat_token；作品公开响应无 pat_token |
| 7 | 参数自动提取准确（String/Integer/...） | 导入含变量的工作流 → 表单参数类型正确 |
| 8 | 重复导入同资源不产生重复数据 | 同一 Bot 导入两次 → 原 Agent 更新且版本递增 |

## 五、异常与边界处理

| 场景 | 处理 |
|------|------|
| PAT Token 过期/无效 | 返回 401，提示「Token 无效或已过期，请重新获取」 |
| workspace ID 错误 | 返回 400，提示「工作空间不存在」 |
| 网络超时 | 请求超时（如 15s），提示「连接 Coze 超时，请重试」 |
| 某资源详情拉取失败 | 跳过该资源，计入 failed 列表，不中断批量 |
| 重复导入 | 按资源 id 去重（已存在则更新或跳过，给出提示） |
| 空勾选导入 | 前端禁用按钮 + 提示「请至少勾选一个资源」 |
| Coze 返回限流 | 捕获 429，提示「Coze 请求过于频繁，稍后再试」 |

## 六、数据字段说明

### 6.1 资源统一模型（导入前，Coze 侧）

| 字段 | 类型 | 说明 |
|------|------|------|
| `resource_id` | string | Coze 资源唯一 id |
| `resource_type` | enum | bot / workflow / dataset |
| `name` | string | 资源名称 |
| `description` | string | 简介 |
| `opening` | string | 开场白（bot） |
| `params` | array | 参数定义（workflow 变量） |
| `variables` | array | 快捷指令/变量 |
| `bot_list` | array | 快捷指令列表（bot） |

### 6.2 作品模型（workflow / dataset 导入后，本平台）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 作品唯一 id（uuid） |
| `title` | string | 作品标题（默认取资源名） |
| `description` | string | 作品简介 |
| `type` | enum | bot / workflow / dataset |
| `coze_resource_id` | string | 关联 Coze 资源 id |
| `pat_token` | string | ⚠️ 敏感，仅服务端存储 |
| `workspace_id` | string | Coze 工作空间 |
| `access_code` | string | 访问码（可为空=公开） |
| `params` | array | 参数定义 |
| `created_at` / `updated_at` | datetime | 时间戳 |

> `type=bot` 仅用于兼容既有作品数据；新导入 Bot 不再写入该模型。

### 6.3 全局未分类 Agent 模型（Bot 导入后）

| 字段 | 值 / 说明 |
|------|------|
| `project_id` | 固定为 `_global`，不关联小说作品 |
| `kind` / `scope` | `unclassified` / `global` |
| `source` / `platform` | `coze_import` / `coze` |
| `platform_config` | 仅保存 `bot_id`、`workspace_id` 等非敏感配置 |
| `model_config.system_prompt` | Coze Bot 提示词 |
| 归属字段 | 不设置 `role_id`、`tool_name`、`step_order` |

### 6.4 全局未分类工作流模型（workflow 导入后，新增）

> 新增独立工作流管理模块 `modules/workflow_management/`，完全复刻 agent 模块四层结构（types / store / service / routes）。

| 字段 | 值 / 说明 |
|------|------|
| `id` | 工作流唯一 id（uuid） |
| `project_id` | 固定为 `_global`，不关联小说作品 |
| `name` / `description` | 名称 / 简介 |
| `status` | `active` / `disabled` / `archived` |
| `platform` | 固定为 `coze` |
| `platform_config` | 仅保存 `workflow_id`、`workspace_id`，不持久化 PAT/token |
| `params` | 参数定义（list） |
| `llm_config` | `{base_url, api_key, model}`，api_key 为可选敏感字段 |
| `source` | `manual` / `coze_import` |
| `icon_url` | 图标 |
| `version_no` / `versions` | 版本号 / 快照（上限 50 条） |
| `created_at` / `updated_at` / `archived_at` | 时间戳 |

> 工作流按 `platform_config.workflow_id` 唯一（冲突抛 409）；状态机：`active` ↔ `disabled`，`archived` 单向（删除需 force 或先归档）。

## 七、相关依赖与约束

- **依赖**：`coze_client.py`（Coze API）、`AgentService / AgentStore`（Bot 存储）、`WorkflowService / WorkflowStore`（workflow 存储，新增）、`work_manager.py`（dataset 作品存储）、`config_loader.py`（PAT 默认值可选）。
- **约束**：PAT Token 敏感，仅用于当次服务端请求；Agent 与工作流均不落 PAT，作品公开响应必须经 `get_work_public()` 过滤。
- **前置条件**：管理端已通过 `require_admin` 鉴权（当前为空壳实现，需补齐）。
- **存量迁移**：装配时执行 `_bootstrap_workflow_migration()`，把 `work_manager` 中 `coze_meta.type=="workflow"` 且含 `coze_workflow_id` 的存量复制进新模块，幂等可重复。

## 一、方案概述

本功能负责「把 Coze 平台资源拉取到本地并批量导入为作品」。核心是将 `coze_client.py` 现有的拉取能力与 `work_manager.py` 的写入能力衔接，通过统一的导入接口完成。

### 1.1 方案选型

| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 导入方式 | **同步批量**（for 循环逐个处理） | 异步/线程池 | 资源量小（个人作品集），同步更简单可调试；失败可独立捕获 |
| 导入幂等 | **按 coze_resource_id 去重**（已存在则更新） | 跳过 | 重复导入不产生重复作品；更新可同步最新元信息 |
| 部分失败 | **不中断整体**，记录 failed 列表 | 全有全无 | 单个资源失败不应阻塞其余成功项 |
| 元信息提取 | **服务端提取**（导入时落库） | 前端提取 | 数据统一，作品页无需二次请求 Coze |

## 二、API 设计

### 2.1 `POST /api/admin/coze/test` — PAT 连接测试

**请求体**：

```json
{ "pat_token": "pat_xxx", "workspace_id": "12345" }
```

**响应 200**：

```json
{ "ok": true, "bots_count": 3, "workflows_count": 5 }
```

**错误**：400（参数缺）、401（Token 无效）、502（Coze 上游异常）

### 2.2 `POST /api/admin/coze/resources` — 拉取资源列表

**请求体**：`{ "pat_token": "...", "workspace_id": "..." }`

**响应 200**：

```json
{
  "bots": [ { "resource_id": "b1", "name": "出行助手", "type": "bot" } ],
  "workflows": [ { "resource_id": "w1", "name": "订单流程", "type": "workflow" } ],
  "datasets": [ { "resource_id": "d1", "name": "知识库A", "type": "dataset" } ]
}
```

### 2.3 `POST /api/admin/works/import` — 批量导入

**请求体**：

```json
{
  "pat_token": "...",
  "workspace_id": "...",
  "resources": [
    { "resource_id": "b1", "type": "bot" },
    { "resource_id": "w1", "type": "workflow" }
  ]
}
```

**响应 200**：

```json
{
  "imported": 2,
  "failed": [ { "resource_id": "d1", "reason": "资源详情拉取失败" } ]
}
```

## 四、核心逻辑

### 4.1 导入主流程（伪代码）

```python
def import_works(pat, workspace, resources):
    imported, failed = 0, []
    for res in resources:
        try:
            detail = coze_client.get_resource_detail(pat, workspace, res)
            work = build_work_model(detail, pat, workspace)   # 元信息提取
            work_manager.upsert_work(work)                     # 按 coze_resource_id 去重
            imported += 1
        except Exception as e:
            failed.append({"resource_id": res["id"], "reason": str(e)})
    return {"imported": imported, "failed": failed}
```

### 4.2 元信息提取规则

| 资源类型 | 提取字段 |
|---------|---------|
| bot | name / description / opening（开场白）/ prompt（提示词）/ variables / bot_list（快捷指令） |
| workflow | name / description / params（变量定义）/ variables |
| dataset | name / description / file_count |

### 4.3 去重策略

- 以 `coze_resource_id` 为唯一键。
- 已存在 → `update`（刷新元信息 + updated_at）。
- 不存在 → `create`（生成 uuid）。

## 五、异常处理

| 异常 | 处理 |
|------|------|
| `CozeAuthError` | 401「Token 无效」 |
| `CozeRateLimitError` | 429「Coze 限流，稍后再试」 |
| `CozeTimeoutError` | 504「连接 Coze 超时」 |
| 单资源详情失败 | 记入 failed，继续 |
| 文件写入失败 | 记入 failed，不中断 |

所有错误统一 `{"error": "<msg>"}`。

## 七、验收对照

| 需求验收标准 | 方案落点 |
|------------|---------|
| PAT 无效提示明确错误 | 2.1 返回 401 + error 文案 |
| 资源列表按类型分组 | 2.2 返回三数组，前端 Tab 渲染 |
| 导入后大厅立即可见 | 2.3 写入 work_manager，list 即时包含 |
| 单资源失败不中断 | 4.1 独立 try/except，failed 收集 |
| 导入作品不含敏感 Token 对外暴露 | work_manager.get_work_public 过滤 |
| 参数提取准确 | 4.2 按类型提取 params |
| 重复导入不重复 | 4.3 按 coze_resource_id upsert |

## 八、风险与待定

| 风险 | 说明 | 对策 |
|------|------|------|
| PAT Token 落盘 | 作品 JSON 含明文 Token | 生产迁移环境变量/密钥服务（见开发规范 §5） |
| Coze API 字段漂移 | 平台字段可能变化 | coze_client 做字段容错（.get 默认值） |
| 大批量导入 | 资源多时串行慢 | 资源量小可接受；必要时加线程池 |

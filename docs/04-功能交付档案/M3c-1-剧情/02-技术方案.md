## 一、方案概览

### 1.1 设计目标

在现有 TS monorepo（`apps/api` NestJS + `apps/web` React + `packages/contracts` Zod + PostgreSQL）上新增「剧情」能力，满足需求澄清 D1~D25，并保证：

1. 不破坏 M3a 章节 AI 任务链路（`ai_tasks` 扩展后 `scope='chapter'` 行为完全不变）。
2. 复用 M3b 工具注册表、M2 审计、既有鉴权/契约/错误包络。
3. 结构写入全部可校验、可回滚，导入不产生半成品。
4. 推衍走任务队列 + SSE，回写必须人工确认且原子。
5. 前端在不丢弃正文编辑状态的前提下新增中央「剧情」页签。

### 1.2 核心技术决策

| 决策 | 方案 | 理由 |
| --- | --- | --- |
| 树的读取模型 | 整树一次读取（节点 + 关联 + 分组），写操作增量 | 单树 ≤ 500 节点，整树负载可控；避免复杂分页与增量同步 |
| 结构完整性 | 父子链与线性关联均在服务端做环检测 | 客户端校验不可信；导入同样复用同一守卫 |
| 并发控制 | 结构写操作携带 `expected_version`，乐观锁 | 与 M1 章节版本语义一致，冲突返回 409 |
| 拖拽/布局坐标 | 独立批量坐标接口，不推进结构版本 | 需求要求拖拽不触发结构变更 |
| 推衍任务 | 扩展 `ai_tasks`：`chapter_id` 可空 + `scope` 字段 | 复用同一队列表、同一 SSE、同一重连语义 |
| 推衍结果 | 模型 Provider 产出结构化步骤；任务成功写 `derivation_steps` | 步骤与正文修订集解耦，避免污染 M2 修订模型 |
| 回写 | 候选表 + 确认接口 + 单事务写入 | 满足「AI 不直接覆盖」与原子性 |
| 自动建树 | 草稿表 + 预览确认后提交 | 生成结果不直接进入正式树 |
| 搜索 | 前端内存过滤 | 整树已在前端，免去搜索接口与索引成本 |
| 自动布局 | 前端纯函数计算 + 批量坐标持久化 | 布局属于展示逻辑，服务端无需感知算法 |

### 2.2 迁移 `1760300001000-ai-task-plot-scope.ts`

```sql
ALTER TABLE ai_tasks ALTER COLUMN chapter_id DROP NOT NULL;
ALTER TABLE ai_tasks ADD COLUMN scope varchar(16) NOT NULL DEFAULT 'chapter'
  CHECK (scope IN ('chapter','plot'));
CREATE INDEX idx_ai_tasks_scope_status ON ai_tasks(scope, status);
```

影响面：
- 既有行全部落到 `scope='chapter'`，章节链路行为不变；
- `aiTaskSchema.chapter_id` 由 `id` 改为 `id.nullable()`，新增 `scope` 字段；
- `AiModelContext.chapterId`、`baseDocument`、`baseVersion` 仅在 `scope='chapter'` 时必填，剧情分支改用 `PlotStepContext`（见 §五）。

> 不新增 `plot_session_id` 列：会话与步骤归属放在 `derivation_steps.task_id` 上，避免任务表承载业务外键。任务上下文写入 `input_summary`。

### 2.3 迁移 `1760300002000-derivation-session-start-node-no-fk.ts`

```sql
ALTER TABLE derivation_sessions DROP CONSTRAINT derivation_sessions_start_node_id_fkey;
-- down：先清理指向不存在节点的会话，再重建外键
```

原因：`start_node_id` 若保留 `ON DELETE CASCADE`，作者删除起点节点会连带删除整段推衍会话及其步骤，历史丢失且不可解释。改为弱引用后：

- 会话与历史步骤保留，作者仍可查看；
- 候选确认时用 `derivation_candidates.start_node_id`（创建候选时的快照）定位起点，节点已删则返回 `409 PLOT_START_NODE_MISSING`，提示重选起点；
- 服务端在创建会话时仍校验起点属于当前树。

## 三、契约设计（packages/contracts/src/plot.ts）

### 3.1 枚举与基础

```text
plotNodeOriginSchema   = manual | derivation | outline | novel_text | import
plotLinkTypeSchema     = linear | non_linear
plotGroupKindSchema    = group | swimlane
derivationStatusSchema = idle | running | paused | finished | failed
candidateStatusSchema  = pending | confirmed | rejected
placementSchema        = child | sibling
plotTreeSourceSchema   = manual | outline | novel_text | import
```

### 3.2 实体 Schema

- `plotNodeSchema`：`id/tree_id/parent_id(nullable)/sibling_order/title/summary(nullable)/content/attributes/position{x,y}/group_id(nullable)/origin/created_at/updated_at`
- `plotLinkSchema`：`id/tree_id/source_id/target_id/type/label(nullable)/created_at`
- `plotGroupSchema`：`id/tree_id/name/kind/order_index/created_at/updated_at`
- `plotTreeSchema`：`id/work_id/title/source/schema_version/version/created_at/updated_at`
- `plotTreeResponseSchema`：`{ tree, nodes, links, groups }`
- `derivationSessionSchema`、`derivationStepSchema`、`derivationCandidateSchema`

受控字段严格校验（禁任意 JSON 透传）：

| 字段 | Schema |
| --- | --- |
| 节点 `attributes` | `.strict()`：`time_point` ≤ 120、`place` ≤ 120、`status` ≤ 40，均可选 |
| 会话 `characters` | 数组 1~20，元素 `{name ≤ 60, description ≤ 200}` |
| 步骤 `event` | `{title ≤ 120, description ≤ 500}` |
| 步骤 `branches` | 数组 2~4，元素 `{id ≤ 40, label ≤ 120, description ≤ 300}` |
| 候选 `payload` | 1~50 个节点，节点字段复用节点输入 Schema |

### 3.3 请求 Schema 要点

- 所有结构写操作：`expected_version: z.number().int().nonnegative().optional()`
- `position`：`x/y` 为整数，范围 `-1_000_000 ~ 1_000_000`
- 导入：`schema_version` 必须为 1；节点 ≤ 2000、关联 ≤ 4000
- 导入/导出复用 `plotTreeResponseSchema` 的字段，但导出为扁平文件结构 `{ schema_version, exported_at, tree, nodes, links, groups }`
- 推衍发起：`tool` 由服务端固定为 `plot_derivation`，前端不传
- 自动建树：`source='outline'` 时 `text` 必填（10~20000 字）；`source='novel_text'` 时 `chapter_id` 必填

### 3.4 索引补充

`packages/contracts/src/index.ts` 追加 `export * from './plot';`；新增 `plot.test.ts` 覆盖边界值（坐标上下限、属性超长、分支数量、导入版本）。

### 4.4 错误码约定

| 状态 | 场景 |
| --- | --- |
| 401 | 未登录 / 会话失效 |
| 403 | 作品不属于当前作者 |
| 404 | 树/节点/关联/分组/会话/任务不存在 |
| 409 | `PLOT_PARENT_CYCLE`、`PLOT_LINK_CYCLE`、`PLOT_LINK_SELF`、`PLOT_LINK_EXISTS`、`PLOT_GROUP_NAME_EXISTS`、`PLOT_VERSION_CONFLICT`、`PLOT_TREE_EXISTS`、`AI_TOOL_DISABLED`、`PLOT_SESSION_RUNNING`、`PLOT_SESSION_FINISHED`、`PLOT_SESSION_NOT_READY`、`PLOT_STEP_RUNNING`、`PLOT_START_NODE_MISSING`、`PLOT_TREE_MISSING`、`PLOT_CANDIDATE_REJECTED`、`PLOT_CANDIDATE_CONFIRMED` |
| 422 | Zod 校验失败；导入结构非法（`PLOT_IMPORT_INVALID`，`details.reason` 为 `duplicate_id/invalid_parent/invalid_link/parent_cycle/link_cycle/invalid_group/schema_version/node_limit`）；`PLOT_BRANCH_UNKNOWN`、`PLOT_NO_STEPS`、`PLOT_PAYLOAD_INVALID` |

`409` 响应统一携带 `details.current_version`（版本冲突）或 `details.code`（业务冲突），供前端区分提示。

## 五、核心逻辑设计

### 5.1 读取与写入模型

- `GET plot-tree` 单次查询三张表并组装；无树时返回 `{ tree: null, nodes: [], links: [], groups: [] }`，前端据此展示空态。
- 结构写操作统一走 `assertOwnedTree(manager, workId, authorId, lock)`：`plot_trees → works` 联表校验归属；`expected_version` 存在且不等时抛 409。
- 每次结构写入（节点/关联/分组/父级/导入）在事务内 `version = version + 1` 并返回最新 `version`。
- 坐标更新不推进版本；节点不存在时跳过（幂等），返回 `updated` 计数。

### 5.2 环检测 `plot-cycle.ts`

| 检查 | 算法 | 复杂度 |
| --- | --- | --- |
| 父子成环 | 从目标父节点沿 `parent_id` 上溯，若遇到待移动节点则成环；同时禁止 `parent_id === id` | O(深度)，深度通常 < 20 |
| 线性成环 | 在 `type='linear'` 子图上，从 `target` 做递归 CTE 可达性查询，若能到达 `source` 则成环 | O(V+E)，500 节点内可接受 |
| 导入全量校验 | 一次性加载节点/关联，内存 DFS 校验父链与线性 DAG | O(V+E) |

非线性关联不做环检测。所有检测在事务内、加锁后执行，避免并发插入绕过。

### 5.3 删除策略

- 删除节点：依赖 `plot_nodes.parent_id` 的自引用 `ON DELETE CASCADE` 级联删除子树；`plot_links` 两端外键级联删除关联；候选/会话中引用该节点的记录按各自外键级联处理。
- 删除分组：`plot_nodes.group_id ON DELETE SET NULL`，节点保留并回到未分组。
- 前端在发起删除前展示将删除的子树节点数（由已加载数据本地计算），二次确认后才调用。

### 5.4 自动布局 `plot-layout.ts`（前端纯函数）

```text
输入：nodes、groups
步骤：
  1. 按 parent_id 计算深度 depth（根为 0）
  2. 泳道按 order_index 横向分区，每组分配 laneX
  3. 同组/同深度节点按 sibling_order 纵向排布 y = baseY + index * rowGap
  4. 未分组节点放入默认区域
  5. 输出 { nodeId: {x, y} }
输出直接用于画布；用户确认后调用 PUT positions 持久化
```

- 纯函数、无副作用，便于单测（D9）；
- 前端保存布局前坐标快照，点击「撤销布局」用快照反向调用 `PUT positions`；
- 布局不改变父子与关联关系，不推进结构版本。

### 5.5 导入导出 `plot-import.ts`

导出文件结构：

```json
{
  "schema_version": 1,
  "exported_at": "2026-11-18T00:00:00.000Z",
  "tree": { "title": "主线剧情" },
  "nodes": [{ "id": "…", "parent_id": null, "sibling_order": 0, "title": "…", "summary": null, "content": "", "attributes": {}, "position": { "x": 0, "y": 0 }, "group_id": null, "origin": "manual" }],
  "links": [],
  "groups": []
}
```

导入校验顺序（失败即 422，不写库）：

1. `schema_version === 1`；
2. 节点数 ≤ 2000、关联数 ≤ 4000；
3. 节点 id 唯一、父引用存在、分组引用存在、关联两端存在；
4. 父子链无环、线性关联无环；
5. 事务内：删除旧树的节点/关联/分组 → 重建（旧 id 通过映射表替换为新 UUID）→ 更新树标题与 `source='import'` → `version + 1`。

导出为只读，不推进版本。

### 5.6 推衍任务接入

**任务创建**（`POST .../derivations/:sessionId/steps`）：

1. 校验会话属于当前作者、状态允许（`idle/paused`）；
2. 校验工具 `plot_derivation` 在 `ai_tools` 中存在且 `enabled`，否则 409 `AI_TOOL_DISABLED`；
3. 校验同一会话无进行中的步骤任务（`status IN (queued, running)`），否则 409 `PLOT_STEP_RUNNING`；
4. 计算 `step_no = session.step_index + 1`，写入 `input_summary`：`{ session_id, step_no, place, background, time_node, premise_node_ids, related_node_ids, characters, random_enabled, random_character_enabled, history: 最近 5 步摘要 }`；
5. 插入 `ai_tasks`：`scope='plot'`、`chapter_id=null`、`base_version=0`、`tool='plot_derivation'`、`agent_id` 由 M3b 工具绑定解析；
6. 入队，返回 202 + `{ task, session }`。

**处理器分支**（`ai-task.processor.ts`）：

```text
startRunning:
  if task.scope === 'plot':
    → 读取 derivation_sessions（校验存在与归属），构造 PlotStepContext
    → 不读取章节、不使用 ProseMirror 文档
  else:
    → 保持现有章节逻辑不变

process:
  if plot → PLOT_MODEL_PROVIDER.generateStep(ctx)
       → plot-task.handler 事务内写入 derivation_steps
       → 推进 session.status='paused'、step_index=step_no（仅当 step_no 更大）
  else → 保持现有 AI 修订集链路
```

**Provider 端口**：

```text
interface PlotModelProvider {
  generateStep(ctx: PlotStepContext): Promise<PlotStepCandidate>;   // content/event/new_characters/branches
  generateTree(ctx: PlotTreeContext): Promise<PlotTreeDraftPayload>; // 第二阶段
}
```

- `MockPlotModelProvider`：确定性输出（内容含步序号，固定 2 个分支），支持注入延迟/失败，供单测与 E2E；
- 真实模型接入沿用 M3b 可插拔 Provider 思路，本期不接外部厂商。

**SSE**：复用 `AiTaskEventBus`；任务事件通过既有 `/ai-tasks/:taskId/events` 推送。剧情侧只消费 `progress/succeeded/failed`，成功后重新拉取会话详情，避免前端自行拼装步骤数据。

### 5.7 候选生成与人工确认回写

**生成候选**（`POST .../candidates`）：

- 入参 `{ split_by_step: boolean, placement: 'child' | 'sibling' }`；
- 默认 `split_by_step=false`：把会话全部步骤合并为 1 个节点（标题取起点节点标题 + 「推衍」后缀，内容为各步拼接）；
- `split_by_step=true`：每步一个节点，`parent_index` 形成链；
- 写入 `derivation_candidates.payload`，状态 `pending`；同一会话允许多个候选，但同一时刻只有一个 `pending`（再次创建时把旧 pending 置为 `rejected`）。

**确认回写**（事务，`SELECT ... FOR UPDATE` 锁会话行）：

1. 校验候选属于会话、状态 `pending`；若已 `confirmed`，幂等返回已写入节点（200）；
2. 校验起点节点仍存在且属于当前树，否则 409 `PLOT_START_NODE_MISSING`；
3. `placement='child'`：新节点 `parent_id = start_node_id`；`placement='sibling'`：新节点 `parent_id = start.parent_id`，`sibling_order` 插入到起点之后，后续兄弟顺序整体 +1；
4. 多个节点按 `payload` 顺序插入，父引用用临时索引映射；
5. 坐标：以起点节点坐标为基准，向右/向下偏移（`+240` / `+120`）；
6. 更新候选 `status='confirmed'`、`confirmed_node_id`；
7. `plot_trees.version + 1`；
8. 写审计 `plot_candidate_confirm`；
9. 任一步失败整体回滚，候选保持 `pending`。

**拒绝候选**：仅改状态为 `rejected`，不触碰树。

**幂等**：确认接口对已确认候选返回首次结果，不重复建节点；拒绝接口重复调用返回当前状态。

### 5.8 自动建树（第二阶段）

1. `POST generations`：校验工具 `plot_generate` 启用；`outline` 直接写 `input_text`；`novel_text` 读取章节正文快照写入 `input_text`（不建立任何节点-章节关联）；创建草稿并入队，`ai_tasks.scope='plot'`、`tool='plot_generate'`。
2. 处理器调用 `PLOT_MODEL_PROVIDER.generateTree`，结果写 `plot_generation_drafts.payload`，状态 `succeeded`。
3. 前端预览可本地编辑（节点标题/概要/层级），编辑结果通过 `PATCH drafts/:id` 回写 payload。
4. `commit`：
   - `mode='replace'`：事务内清空现有树结构后写入草稿（等价导入）；
   - `mode='append'`：以指定 `parent_node_id`（可空表示根层）挂入草稿根节点；
   - 校验草稿状态为 `succeeded`，写入后置 `committed` 并 `version + 1`；
   - 覆盖模式需前端二次确认（服务端要求 `confirm_overwrite: true`）。
5. `discard`：置 `discarded`，不动正式树。
6. 解析失败：任务与草稿置 `failed`，保留 `input_text`，前端可重试或转手动。

### 6.3 画布交互

- 画布容器 `transform: translate(pan) scale(zoom)`，只作用于一个 `<g>`/内层容器，拖拽与缩放不触发节点重渲染；
- 节点拖拽用 Pointer Events，移动中只更新 CSS transform，`pointerup` 后批量提交坐标；
- 连线：父子为实线、线性关联为带箭头实线、非线性为虚线；三类使用不同 `stroke` 与 `marker-end`；
- 缩放范围 0.25~2，提供「适应视图」「复位」；
- 拖拽越界时坐标钳制在画布逻辑范围（±1,000,000）。

### 6.4 可访问性

- 画布节点使用 `<button>` 语义并带 `aria-label`（标题 + 层级 + 来源）；
- 画布提供 `role="application"` 容器内的方向键选择、`Enter` 打开检查器、`Delete` 触发删除确认；
- 列表视图 `plot-node-list.tsx` 采用 `role="tree"/"treeitem"`，完整键盘操作，作为读屏与纯键盘用户的主路径；
- 推衍面板与检查器使用原生表单控件，错误内联 `aria-describedby`；
- 导入/覆盖/删除使用原生 `<dialog>` + 焦点陷阱 + 关闭后焦点恢复（复用工作台既有模式）；
- 动效尊重 `prefers-reduced-motion`。

### 6.5 性能策略（500 节点目标）

- 节点组件 `React.memo`，仅依赖节点自身字段与选中态；
- 连线由父级一次性计算路径，避免逐节点 setState；
- 平移/缩放走 CSS transform，不重排；
- 搜索为内存过滤 + `useMemo`，命中结果只做高亮与居中；
- 单树超过 800 节点时提示性能风险（本期不做虚拟化，列后续优化）。

### 6.6 错误与冲突

- `409 PLOT_VERSION_CONFLICT`：提示「结构已被更新」，提供「刷新并重试」，不静默覆盖；
- 推衍任务失败：保留已生成步骤与配置，展示错误与重试按钮（同幂等键重试则由后端按任务语义处理）；
- 导入失败：对话框展示 `details.reason` 的中文映射，现有树不变；
- 回写冲突：起点节点已删除时提示重新选择挂接位置，候选保留。

## 七、安全与约束

1. 所有剧情接口按作品归属校验（`works.author_id = 当前作者`），跨作品一律 403/404，不泄露存在性。
2. 请求体全部 Zod 校验；`attributes`、`characters`、`branches`、候选 `payload` 使用 `.strict()` 或显式字段，禁止任意 JSON 透传。
3. 导入文本、节点正文按纯文本处理，前端使用文本节点渲染，不注入 HTML。
4. 审计详情不写正文全文、不写模型密钥。
5. 任务 `input_summary` 只保存必要上下文；不写入作者会话秘密。
6. 单作品请求限流沿用全局策略；导入文件大小上限 2MB（服务端校验）。

## 十、风险与取舍

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| `ai_tasks` 扩展影响 M3a | 章节任务 500/回归失败 | `scope` 默认 `chapter`；处理器分支隔离；M3a e2e 全量回归作为门禁 |
| 画布不可键盘操作 | D20 不达标 | 列表视图作为等价主路径 + 画布方向键 |
| 500 节点渲染性能 | 拖拽卡顿 | memo + transform + 批量坐标；先量测再决定虚拟化 |
| 导入覆盖误操作 | 数据丢失 | 服务端事务 + 前端二次确认 + 导入前自动导出提示 |
| 环检测并发绕过 | 结构损坏 | 事务内加锁后检测 |
| 推衍长会话上下文膨胀 | 生成质量下降/超时 | 仅传最近 5 步摘要；单步任务化，避免一次生成全部 |
| 布局算法争议 | 用户不满意 | 提供撤销一次 + 手动拖拽兜底 |

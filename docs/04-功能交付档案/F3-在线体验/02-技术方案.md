## 一、方案概述

本功能是平台的**核心交互**：访客无需 Coze 账号即可体验作品。按作品交互模式分三条路径，全部由后端代理 Coze API，通过 SSE 流式返回。

### 1.1 方案选型

| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 通信方式 | 后端代理 SSE | 前端直连 Coze | 隐藏 Token；统一鉴权；集中错误处理 |
| 流式 | SSE（`text/event-stream`） | WebSocket | 单向文本流足够，SSE 简单可靠 |
| 工作流运行 | `stream_run` 优先，`run` fallback | 仅 run | 流式体验好，失败降级 |
| 参数转换 | 后端白名单转换 | 前端转换 | 前后端双保险，后端权威 |

## 二、API 设计

### 2.1 `POST /api/works/<id>/chat` — 智能体对话（SSE）

**请求体**：

```json
{ "message": "帮我规划去杭州的路线", "conversation_id": "xxx", "user_id": "visitor_xxx", "access_token": "sess_xxx" }
```

**响应**（`text/event-stream`）：

```text
data: {"delta": "你"}
data: {"delta": "好"}
data: {"done": true, "conversation_id": "new_id"}
```

### 2.2 `POST /api/works/<id>/workflow/run` — 工作流运行

**请求体**：

```json
{
  "params": { "city": "杭州", "days": 3 },
  "access_token": "sess_xxx",
  "stream": true
}
```

- `stream=true` → SSE 增量；`stream=false` → JSON 完整结果。
- 响应（非流式）：`{ "output": "..." }`

### 2.3 `POST /api/works/<id>/upload` — 文件上传（File 参数）

**请求体**：multipart `{ "file": <binary> }`

**响应 200**：`{ "file_id": "file_xxx" }`

## 三、参数类型转换（核心）

### 3.1 类型映射

| Coze 类型 | Python | 前端控件 | 校验 |
|-----------|--------|---------|------|
| String | str | 输入框 | 字符串 |
| Integer | int | 数字框 | `int()` 可转换 |
| Number | float | 数字框 | `float()` 可转换 |
| Boolean | bool | 开关 | `true/false` |
| Time | str | 时间选择 | ISO 格式 |
| Object | dict | JSON 文本域 | `json.loads` 成功 |
| Array | list | JSON 文本域 | `json.loads` 为 list |
| File | str(file_id) | 文件上传 | 已上传返回 file_id |

### 3.2 转换函数（后端）

```python
def convert_param(name, ptype, value):
    try:
        if ptype == "Integer":   return int(value)
        if ptype == "Number":    return float(value)
        if ptype == "Boolean":   return value in (True, "true", "True", 1)
        if ptype == "Object":    return json.loads(value) if isinstance(value, str) else value
        if ptype == "Array":     return json.loads(value) if isinstance(value, str) else value
        return str(value)  # String / Time / File
    except (ValueError, TypeError) as e:
        raise ParamError(f"参数 {name} 类型不合法: {e}")
```

## 四、核心逻辑

### 4.1 chat 流式代理

```python
def chat_stream(work, message, conversation_id, token):
    require_access(work.id, token)          # F2 鉴权
    for event in coze_client.chat_stream(...):  # 逐事件
        if event["type"] == "delta":
            yield f"data: {json.dumps({'delta': event['text']})}\n\n"
        elif event["type"] == "done":
            yield f"data: {json.dumps({'done': True, 'conversation_id': event['id']})}\n\n"
```

### 4.2 会话管理

- 前端在页面会话内生成一次稳定的 `user_id`，每轮请求随 Body 携带并由后端透传，用于隔离 Coze 用户上下文和记忆。
- `conversation_id` 由前端保存，每轮通过本站 API Body 携带；后端调用 Coze `/v3/chat` 时必须放入 **URL Query 参数**，不能放入 Coze 请求 Body（见 [Coze 对话 v3 官方文档](https://docs.coze.cn/developer_guides/chat_v3)）。
- 首次对话无 `conversation_id` → Coze 创建会话并随 `done` 返回，下一轮复用该 ID。
- `conversation_id` 与 `user_id` 均为前端内存态（刷新丢失，符合 F3 边界）。

### 4.3 SSE 协议约束

- 响应头：`Content-Type: text/event-stream; charset=utf-8`、`Cache-Control: no-cache`、`X-Accel-Buffering: no`。
- 事件：`data: {json}\n\n`，结束 `data: {"done": true}\n\n`。
- 客户端断开 → `GeneratorExit` → `finally` 释放上游连接。
- 流式期间发送按钮切换为“停止生成”并保持可点击；点击后通过 `AbortController` 中断请求，主动取消不显示网络错误，已生成内容保留，输入区在 `finally` 中恢复。
- 错误事件：`data: {"error": "..."}`（脱敏，不透传上游原文）。

## 五、异常处理

| 场景 | 处理 |
|------|------|
| 未授权访问 | 403「请先验证访问码」（进入前先调 verify） |
| 参数类型非法 | 400，前端即时拦截 + 后端二次校验 |
| Coze 超时 | 504「连接超时」 |
| SSE 中断 | 前端显示重试按钮，`isStreaming` 复位 |
| 用户主动停止 | 静默取消，不显示“请求失败”；保留已生成内容并恢复输入区 |
| stream 失败 | 自动 fallback 到 run（非流式） |
| 空消息 | 前端禁用发送 |

## 六、前端交互

| 交互模式 | 渲染 | 关键逻辑 |
|---------|------|---------|
| chat | 聊天气泡列表 + 输入框 | 流式逐字追加，`isStreaming` 防重复 |
| form | 参数表单（按 type 渲染控件） | 提交前转换，调 run |
| mixed | 左侧聊天 + 右侧参数面板 | 两路径独立，`conversationId` 共享 |
| 文件 | 上传按钮 → upload → 存 file_id | 表单值提交 file_id |

**渲染函数**：

- `renderChatMode(work)` / `renderFormMode(work)` / `renderMixedMode(work)`
- 参数控件工厂：`buildParamField(param)` → 按 `param.type` 返回 DOM 控件
- 流式处理：`handleStream(reader)` → 解析 SSE → 追加 delta

## 二、任务明细

### 2.1 F3-T1 参数类型转换工具（数据层）

**目标**：实现 8 种 Coze 参数类型的后端白名单转换。

**完成标准**：
- `convert_param(name, ptype, value)`：Integer→int / Number→float / Boolean→bool / Object→json / Array→json / String·Time·File→str。
- 非法转换抛 `ParamError`（含参数名与原因）。
- Boolean 接受 `(True, "true", "True", 1)`；Object/Array 接受字符串或原值。
- 禁止 eval/exec（安全规范 §5）。

**关键点**：白名单类型映射；异常信息含参数名。

### 2.2 F3-T2 SSE 流式代理（chat，接口层，高风险）

**目标**：`POST /api/works/<id>/chat` 后端代理 Coze，SSE 流式返回。

**完成标准**：
- 先 `require_access`（F2）鉴权，未授权 403。
- 响应头：`Content-Type: text/event-stream`、`Cache-Control: no-cache`、`X-Accel-Buffering: no`。
- 事件 `data: {"delta": "..."}\n\n` 逐条，结束 `data: {"done": true, "conversation_id": id}\n\n`。
- 客户端断开 → `GeneratorExit` → `finally` 释放上游连接。
- 错误事件 `data: {"error": "..."}`（脱敏，不透传上游原文）。
- `conversation_id` 首轮无则创建，随 done 返回，前端保存。

**关键点**：SSE 协议规范（开发规范 §2.5）；错误脱敏；断开释放。

### 2.3 F3-T3 工作流运行 + 文件上传（接口层）

**目标**：工作流参数运行 + File 参数上传。

**完成标准**：
- `POST /api/works/<id>/workflow/run`：`stream=true` → SSE 增量；`false` → JSON `{output}`；先 `convert_param` 再调 client。
- 流式失败自动 fallback 到非流式 `run`。
- `POST /api/works/<id>/upload`：multipart 接收 → 调 Coze upload → 返回 `{file_id}`。
- 未授权 403；参数非法 400；上游超时 504。

**关键点**：stream fallback；file_id 透传给参数。

### 2.4 F3-T4 前端三模式渲染 + 流式处理（表现层）

**目标**：chat/form/mixed 三种体验模式 + 流式逐字追加。

**完成标准**：
- `renderChatMode(work)` / `renderFormMode(work)` / `renderMixedMode(work)` 三种渲染。
- 参数控件工厂 `buildParamField(param)`：按 `param.type` 返回输入框/数字框/开关/JSON 文本域/时间/文件上传。
- `handleStream(reader)`：解析 SSE → `delta` 逐字追加；`done` 结束；`error` 显示；`isStreaming` 防重复。
- `conversationId` 共享（mixed 两路径共用）。
- 空消息禁用发送；流式中断显示重试按钮。

**关键点**：流式 `isStreaming` 复位（finally）；动态内容转义（安全 §4）。

### 2.5 F3-T5 单元测试与验证（测试）

**目标**：验证参数转换、SSE 协议、三模式。

**完成标准**：
- 单元测试：`convert_param` 八类型 + 非法抛错；SSE 事件格式（delta/done/error）；未授权 403。
- 手动验证：chat 流式逐字不卡顿；form 提交返回结果；mixed 参数面板 + 聊天独立；File 上传返回 file_id。
- `py_compile` 通过；启动服务走三种模式。

**关键点**：八类型转换、SSE 格式是断言核心。

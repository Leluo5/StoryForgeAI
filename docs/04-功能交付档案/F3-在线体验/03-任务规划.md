## 四、整改任务明细

### 4.1 F3-R1 抽取独立 convert_param + ParamError（数据层，P1）

**目标**：把 execute 内联的八类参数转换抽到独立函数，非法转换抛 `ParamError`，转换失败返回 400 而非透传。

**完成标准**：
- 新增 `convert_param(name, ptype, value)`（建议放 `coze_client.py` 或新建 `param_utils.py`），覆盖 String/Integer/Number/Boolean/Time/Object/Array/File 八类，映射规则同 [技术方案 §3.1](file:///e:/workspace_trae/StoryForgeAI/docs/04-功能交付档案/F3-在线体验/02-技术方案.md)。
- 新增 `ParamError` 异常（含参数名与原因）。
- Integer/Number 转换失败 → 抛 `ParamError`；Object/Array JSON 解析失败 → 抛 `ParamError`（不再静默兜底）。
- 禁止 `eval`/`exec`（安全规范 §5）。
- execute 路由（[L1159-L1225](file:///e:/workspace_trae/StoryForgeAI/app.py#L1159-L1225)）改用 `convert_param`；捕获 `ParamError` → 返回 400（含参数名）。
- `py_compile` 通过。

**关键点**：白名单类型映射；异常信息含参数名；不再保留原值透传。

### 4.2 F3-R4 错误脱敏（接口层，P0 安全）

**目标**：chat 与 execute 的 SSE 异常路径禁止透传上游原文/堆栈/Token。

**完成标准**：
- chat [L1042-L1045](file:///e:/workspace_trae/StoryForgeAI/app.py#L1042-L1045)、execute [L1304-L1307](file:///e:/workspace_trae/StoryForgeAI/app.py#L1304-L1307) 的 `str(e)` 改为脱敏通用提示（如「对话失败，请重试」「执行失败，请重试」）。
- 真实异常（含上游原文）仅写 `app.logger`，不下发前端。
- 建立错误白名单映射（超时→504/「连接超时」；4xx 上游→「请求参数有误」；其余→「服务异常」），不透传 `msg` 原文。
- 测试断言：mock 上游抛含敏感串的异常 → SSE error 事件不含该敏感串。

**关键点**：`logger.exception` 记详情，前端只拿通用文案。

### 4.3 F3-R6 统一鉴权（接口层，P0 安全）

**目标**：execute/upload 与 chat 统一使用 `@require_work_access`，消除鉴权三套不一致与 upload 裸奔。

**完成标准**：

- upload 路由（[L1060](file:///e:/workspace_trae/StoryForgeAI/app.py#L1060)）加 `@require_work_access`，未授权 → 403。
- execute 路由（[L1127](file:///e:/workspace_trae/StoryForgeAI/app.py#L1127)）移除内联 `X-Access-Code` 明文校验（[L1135-L1137](file:///e:/workspace_trae/StoryForgeAI/app.py#L1135-L1137)），改用 `@require_work_access`；通过后从 `request.work_config` 取 work。
- 前端 upload（[app.js#L153](file:///e:/workspace_trae/StoryForgeAI/static/js/app.js#L153)）、execute（[L2216](file:///e:/workspace_trae/StoryForgeAI/static/js/app.js#L2216)）调用携带 `X-Access-Token`（chat 已带，[L129](file:///e:/workspace_trae/StoryForgeAI/static/js/app.js#L129)），需先经 `/verify` 拿到 token。

- 确认 `/api/works/<id>/verify` 返回的 token 如何被前端存储并带入后续请求（与 chat 现有链路一致）。

**关键点**：破坏性——前端鉴权头与 verify 流程联动；需确认设访问码作品的体验端 token 传递链路不回退。

### 4.6 F3-R5 工作流 stream→run 自动降级 fallback（接口层，P1）

**目标**：`stream_run` 失败时自动降级到非流式 `run`，满足需求验收标准 #9。

**完成标准**：

- 降级结果包装为单次 `done` 事件（`{"done":true,"output":"..."}`）下发，前端无需特殊处理即可渲染。
- 降级仅触发一次（避免无限重试）；降级失败 → 走 R4 脱敏 error。
- 测试：mock stream_run 抛异常 → 断言最终下发 `done` 且内容来自 run。

**关键点**：降级后前端 `isStreaming` 正确复位；不重复发起上游请求。

```text
R6(鉴权) ──→ R3(事件契约,改前端) ──→ R7(重试) ──→ R8
```

- **阻塞关系**：R2 依赖 R1；R5 依赖 R2+R3；R7 依赖 R3；R8 依赖 R1–R7；R9 依赖 R8。
- **可并行**：R4 与 R6 互不依赖，可并行（都偏安全，建议最先）。
- **前端冲突规避**：R2/R3/R6/R7 都改 `app.js`，**必须串行**，建议顺序 R6 → R2 → R3 → R7（先鉴权头，再路由字段，再事件格式，最后重试 UI），避免同文件多任务并发冲突。

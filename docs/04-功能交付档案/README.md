## 二、功能档案结构规则

每个功能一个子目录，固定三分册（遵循[文档编写规范 §2.5](../08-工作流规范/文档编写规范.md)）：

| 分册 | 文件名 | 内容 |
| --- | --- | --- |
| 01 | `01-需求澄清.md` | 需求与验收标准 |
| 02 | `02-技术方案.md` | 技术方案设计 |
| 03 | `03-任务规划.md` | 任务拆解与依赖 |

> 【必读】功能上线后，本档案追加"实施记录"与"验证结论"分册（`04-实施记录.md` / `05-验证结论.md`），并在下方登记状态变更。功能上线后本档案整体**冻结**，不再改动，只读归档。

## 三、阅读路径

- **顺序阅读**：`01-需求澄清.md` → `02-技术方案.md` → `03-任务规划.md`（需求 → 方案 → 任务的证据链）。
- **按需跳读**：仅看技术细节 → `02-技术方案.md`；仅看排期 → `03-任务规划.md`。
- **回溯**：需求验收标准与方案逐条核对，见各分册末尾的"验收标准核对"节。

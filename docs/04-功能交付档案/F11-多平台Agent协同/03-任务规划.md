## 一、规划原则

1. 单任务 ≤ 2 小时、单一职责、有明确完成标准。
2. 依赖顺序：数据层 → 服务层 → 接口层 → 前端 → 部署验证。
3. 高风险任务（通道适配、写回事务、撤销冲突、归档投递）单独列出并优先验证。
4. 阻塞任务（契约、迁移）前置，其余任务可并行。
5. 每个任务完成以对应测试通过为门禁，CI 使用 `pnpm run ci`（contracts build → lint → typecheck → test → build）。

## 三、P1 契约与迁移（T01–T05）

### T01 定义协同样板契约

- **内容**：`packages/contracts/src/collab.ts` 定义 `collab-settings`、`collab-readiness`、`role-profile-task`、`writeback`、`archive` 等 Schema。
- **依赖**：无（阻塞任务）。
- **完成标准**：契约单测 `collab.test.ts` 通过；Schema 覆盖 F2 §4.2~§4.4 全部请求/响应结构。

### T02 定义 Agent 通道配置扩展

- **内容**：`packages/contracts/src/agent-config.ts` 扩展 `agentPlatformSchema`（增加 `flowise`）、新增 `agentPlatformConfigSchema`（仅 `flowise_chatflow_id`）。
- **依赖**：无（阻塞任务）。
- **完成标准**：契约单测通过；`platform_config` 拒绝 URL、令牌、任意键。

### T03 创建五张新表实体

- **内容**：`collab-setting.entity.ts`、`role-profile-writeback.entity.ts`、`role-profile-writeback-field.entity.ts`、`agent-task-citation.entity.ts`、`agent-archive-outbox.entity.ts`。
- **依赖**：无（阻塞任务）。
- **完成标准**：实体与 F2 §3.2 列定义、索引、约束一致；`pnpm run typecheck` 通过。

### T04 创建迁移 1760700000000-collab-base.ts

- **内容**：5 张新表 + `ai_tasks.channel` 列与检查约束；注册到 `data-source.ts`。
- **依赖**：T03。
- **完成标准**：迁移可升可降；回滚按依赖逆序删表并删列。

### T05 扩展 ai_tasks 作用域

- **内容**：迁移 `1760700001000-ai-task-role-profile-scope.ts` 扩展 `scope` 检查约束为 `chapter/plot/character/role_profile`。
- **依赖**：T04。
- **完成标准**：迁移可升可降；`role_profile` 任务可创建，原有作用域不受影响。

## 四、P2 配置与就绪（T06–T08）

### T06 实现协同设置服务

- **内容**：`collab-settings.service.ts` 实现 `get/put`，校验作品归属、角色归属、Agent 归属、白名单字段集合。
- **依赖**：T04、T05。
- **完成标准**：服务单测覆盖合法/非法配置；`collab_settings` 默认 `enabled=false`。

### T07 实现就绪检查服务

- **内容**：`collab-readiness.service.ts` 返回通道、检索、归档就绪布尔值与缺失项名称。
- **依赖**：T06。
- **完成标准**：就绪接口只返回布尔值与名称，不返回地址、密钥或上游原始错误。

### T08 扩展 Agent 更新接口

- **内容**：`agent.service.ts` 更新白名单支持 `platform`、`platform_config`；`PATCH /ai-agents/:agentId` 校验 `flowise` 与 Chatflow 标识。
- **依赖**：T02。
- **完成标准**：更新 Agent 触发版本快照与审计；`platform_config` 校验通过。

## 五、P3 通道与检索（T09–T11）

### T09 定义通道端口与注册表

- **内容**：`channel/agent-channel.port.ts`、`channel/agent-channel.registry.ts`；`AgentChannel` 接口与按 `name` 注入的注册表。
- **依赖**：T02。
- **完成标准**：端口单测通过；任务处理器只依赖端口，无厂商分支。

### T10 实现 Flowise 与 Coze 适配器

- **内容**：`channel/flowise.channel.ts` 调用 `POST {FLOWISE_BASE_URL}/api/v1/prediction/{chatflowId}`；`channel/coze.channel.ts` 调用 `POST {COZE_API_BASE}/open_api/v3/chat` 并按 `chat_id` 轮询。
- **依赖**：T09。
- **完成标准**：替身测试通过；上游错误映射为 `CollabUpstreamError`（含 `retryable` 与脱敏 `code`）；超时用 `COLLAB_HTTP_TIMEOUT_MS`。

### T11 实现 FastGPT 客户端与引用映射

- **内容**：`retrieval/fastgpt.client.ts` 调用 `POST {FASTGPT_BASE_URL}/api/core/dataset/searchTest`；`retrieval/citation.mapper.ts` 截断、兜底与上限控制。
- **依赖**：T04。
- **完成标准**：零引用抛 `COLLAB_NO_CITATION`；引用先入库再生成；snippet 截断 500 字、上限 `COLLAB_MAX_CITATIONS`。

## 六、P4 编排与写回（T12–T14）

### T12 扩展任务处理器分支

- **内容**：`ai-task.processor.ts` 增加 `scope='role_profile'` 分支：构建上下文 → 检索 → 通道调用 → 结果校验 → 写回。
- **依赖**：T10、T11。
- **完成标准**：`role_profile` 任务走完整链路；非 `role_profile` 作用域行为不变；幂等键复用 `ai_tasks.idempotency_key`。

### T13 实现结果校验器

- **内容**：`collab-result.validator.ts` 解析 JSON（去代码围栏）、校验字段集合与长度、拒绝空白/超长/额外键。
- **依赖**：无（阻塞任务，可并行 T12）。
- **完成标准**：合法/非法结果单测通过；字段键集合必须等于请求字段集合；`identity≤80`、`personality≤2000`、`experience≤20000`。

### T14 实现自动写回事务

- **内容**：`collab-writeback.service.ts` 单事务：锁角色行 → 复查设置与白名单 → 记录 before_value → 更新字段 + `version+1` → 写写回单与字段行 → 写 outbox → 置 `succeeded`。
- **依赖**：T12、T13。
- **完成标准**：写回原子性单测通过；重复写回被 `role_profile_writebacks.task_id` 唯一约束阻止；失败不产生部分写回。

## 七、P5 撤销与归档（T15–T17）

### T15 实现逐字段撤销

- **内容**：`collab-revert.service.ts` 锁角色行与字段行 → 值比对 `after_value` → 恢复 `before_value` + `version+1` → 置 `reverted` → 重算写回单状态。
- **依赖**：T14。
- **完成标准**：撤销单测通过；冲突返回 `409 COLLAB_FIELD_CONFLICT` 并保留当前值；重复撤销幂等。

### T16 实现归档 outbox 投递

- **内容**：`collab-archive.service.ts` 调用 `POST {N8N_ARCHIVE_WEBHOOK_URL}` 带 `Idempotency-Key: storyforge-archive-{task_id}`；成功记 `external_id` 并置 `delivered`。
- **依赖**：T14。
- **完成标准**：投递单测通过；载荷不含凭据、作者邮箱、其他角色或正文；失败不触碰任务与写回单。

### T17 实现独立归档重试队列

- **内容**：`collab-archive.queue.ts`、`collab-archive.processor.ts`；独立 `collab-archive` 队列，指数退避，最多 `COLLAB_ARCHIVE_MAX_ATTEMPTS`。
- **依赖**：T16。
- **完成标准**：重试单测通过；超限置 `failed` 并写审计；重复重试返回当前状态，不新增记录。

## 十、风险与回归范围

| 风险 | 关联任务 | 应对 |
| --- | --- | --- |
| Coze 最小适配器缺失 | T10 | 就绪接口显式暴露缺失，不阻塞 Flowise 主链路 |
| Flowise 输出格式漂移 | T13 | 严格 Schema + 失败关闭，不做宽松兜底 |
| n8n 工作流配置错误 | T16/T17 | outbox 保留载荷，可修复后重试，不影响写回 |
| 自动写回误改正式角色 | T14/T15 | 只允许配置的测试角色；M3c-2 既有链路不改动 |
| 引用包含恶意指令 | T13/T14 | 资料视为数据 + 服务端白名单与结构校验 |
| 外部模型数据泄露 | T10/T11 | 私有部署 + 上下文最小化 + 凭据不落库 |

回归范围：M3a（正文待审）、M3b（Agent 配置）、M3c-2（角色版图）接口不因 `ai_tasks`/`ai_agents` 扩展而破坏；`pnpm run ci` 全绿为合并门禁。

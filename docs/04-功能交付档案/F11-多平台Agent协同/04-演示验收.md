## 一、演示前置条件

> 对应 F1 §2.3 演示前置条件。以下 5 项全部就绪后，方可按 A01~A12 执行。

| 编号 | 前置条件 | 就绪判定 |
| --- | --- | --- |
| C1 | 已准备一个专用测试角色，不关联正式作品的正文或剧情树写回 | `collab_settings.test_character_id` 指向该角色；该角色 `status='active'` |
| C2 | 已准备独立 FastGPT 演示知识库，内含可识别的演示资料 | `FASTGPT_DATASET_ID` 配置的 dataset 内已有 ≥1 条可检索资料 |
| C3 | 测试角色至少选择两个普通资料字段进入写回白名单，以验证逐字段撤销 | `collab_settings.whitelist_fields` 长度 ∈ [2,3] |
| C4 | Flowise、FastGPT、n8n 均可通过项目私有环境访问，Coze 原通道仍可使用 | 三组件 Compose 健康；`coze` 通道凭据齐备 |
| C5 | 演示使用真实三组件链路 | 不使用测试替身执行本演示 |

### 1.1 启动协同组件

```bash
# 先启动主 compose（提供 postgres 与 storyforge_default 网络）
docker compose -f infra/docker-compose.yml up -d postgres

# 按需启动协同组件（所有服务带 collab profile，不影响主链路）
docker compose --profile collab -f infra/docker-compose.collab.yml up -d

# 校验配置（T21 门禁）
docker compose --profile collab -f infra/docker-compose.collab.yml config --quiet

# 观察就绪
docker compose --profile collab -f infra/docker-compose.collab.yml ps
```

### 1.2 就绪检查（界面入口）

作者登录后进入「角色详情 → AI 协同」页签，面板展示各通道 `configured` 状态：

- Flowise / FastGPT / n8n / Coze 均为 `已就绪` 或 `已配置`。
- 任一通道 `未就绪` 时，对应能力在就绪接口返回 `configured: false`，且面板给出引导。

## 二、验收场景 A01~A12

> 每个场景给出「操作步骤 → 预期结果」，以可观察现象或留存记录为证据。

### A01 正常闭环：测试角色 → FastGPT 检索 → Flowise 生成

**操作**：

1. 打开测试角色的「AI 协同」页签，确认执行通道显示 `Flowise`。
2. 勾选至少两个白名单字段（如 `identity`、`personality`），填写指令，点击「发起任务」。
3. 观察任务进度：`已入队 → 执行中 → 检索中 → 生成中 → 已完成`。

**预期**：返回指定字段内容与引用资料；实际执行通道记录为 `Flowise`；任务详情 `citations` 含 ≥1 条引用，`task.channel='flowise'`。

### A02 自动写回只更新白名单字段

**操作**：

1. 完成 A01 后，打开该角色的资料页。
2. 对比任务发起前/后的角色字段。

**预期**：仅 `whitelist_fields` 内的字段值更新；正文、剧情树、非白名单字段及正式作品数据均不变；写回单 `status='applied'`。

### A03 同一任务写回两个字段后撤销其中一个

**操作**：

1. 在「AI 协同」页签打开「写回记录」。
2. 对某一字段行点击「撤销」，确认弹窗，点击「确认撤销」。

**预期**：目标字段恢复为写回前值（`before_value`）；另一字段保持写回后值；该字段行 `status='reverted'`，写回单状态重算为 `partially_reverted`。

### A04 写回后再次修改某字段，再撤销较早写回

**操作**：

1. 在 A03 之后，手动修改一个已写回且未撤销的字段（如把 `personality` 改成新值，角色 `version` 自增）。
2. 回到「AI 协同」页签，对该字段的较早写回点击「撤销」。

**预期**：显示「字段冲突」，当前新值不被旧值覆盖；字段行保持 `applied`；错误码 `COLLAB_FIELD_CONFLICT`。

### A05 n8n 归档可追踪

**操作**：

1. 完成任务后，打开「任务详情 → 归档」区域。
2. 记录 `external_id`，在 n8n 执行历史中反查该任务。

**预期**：归档 `status='delivered'`，`external_id` 与 n8n 执行标识一致；载荷可关联来源任务、测试角色、实际通道、生成结果、写回字段及版本、引用资料标识与摘录。

### A06 模拟 n8n 不可用后恢复，再执行归档重试

**操作**：

1. 停止 n8n 容器，发起一个任务。
2. 确认任务写回成功但归档 `status='failed'`，界面显示「已写回但归档未完成」。
3. 恢复 n8n，在「写回记录/任务详情」点击「重试归档」。

**预期**：已写回字段不重复更新（无新版本）；仅补齐一次归档，`status='delivered'`，`attempts` 递增。

### A07 Flowise 任务执行中切回 Coze，再发起新任务

**操作**：

1. 发起一个 Flowise 任务并让其进入 `running`。
2. 在「Agent 管理」把该 Agent 的 `platform` 改为 `coze`。
3. 再发起一个新任务。

**预期**：原任务保持 `channel='flowise'`；新任务 `channel='coze'`；历史写回单与归档记录通道不被改写。

### A08 FastGPT 无有效引用

**操作**：

1. 构造检索条件使 FastGPT 返回 0 条有效引用（或清空演示库）。
2. 发起任务。

**预期**：任务标记失败，提示「资料不足」；不进入自动写回；角色字段保持原值。

### A09 生成失败 / 非法结果 / 写回失败

**操作**：

1. 分别构造三种失败：Flowise 返回错误、结果缺少字段或格式非法、写回事务失败。
2. 发起任务并观察。

**预期**：失败环节清楚可识别（错误码区分）；原字段值保留；无静默部分写回；角色版本不产生新值。

### A10 重复投递同一完成结果并重复归档重试

**操作**：

1. 用同一 `Idempotency-Key` 重复发起任务。
2. 对已投递的归档重复点击「重试归档」。

**预期**：重复投递返回同一任务（`created:false`），不重复写字段版本；重复归档不产生重复归档记录，只返回既有记录。

### A11 测试角色、其他角色与演示知识库的数据边界

**操作**：

1. 对非测试角色发起任务（或直接调用接口）。
2. 核对其他角色、正式作品、演示知识库。

**预期**：非测试角色请求被拒绝（`COLLAB_TEST_ROLE_MISMATCH`）；其他角色与正式作品数据不变；FastGPT 演示库无正式作品数据；外部上下文仅含当前任务必需数据，无无关角色/作品信息。

### A12 部署、界面提示、日志与归档

**操作**：

1. 检查三组件运行方式与访问边界。
2. 查看界面错误提示、API 日志与归档记录。

**预期**：三组件在私有环境运行，仅本机 `127.0.0.1` 可访问；敏感凭据不明文暴露（文档/前端/日志仅出现变量名）；错误提示含脱敏错误码，不含令牌或响应体明文。

## 三、部署手册登记

> 对应 F2 §6 部署方案与 §6.1 镜像标签锁定（禁止 `latest`）。

### 3.1 组件与镜像标签

| 服务 | 镜像 | 作用 | 持久化 | 依赖 |
| --- | --- | --- | --- | --- |
| `flowise` | `flowiseai/flowise:2.2.7` | 执行 Chatflow | 独立卷 + Postgres `flowise` 库 | Postgres（主 compose） |
| `fastgpt` | `labring/fastgpt:v4.8.11` | 检索与演示知识库 | 独立卷 | `fastgpt-mongo`、`fastgpt-pg` |
| `fastgpt-mongo` | `mongo:7` | FastGPT 元数据 | 独立卷 | 无 |
| `fastgpt-pg` | `pgvector/pgvector:pg16` | 向量存储 | 独立卷 | 无 |
| `n8n` | `n8nio/n8n:1.75.1` | 归档工作流 | 独立卷 + Postgres `n8n` 库 | Postgres（主 compose） |

所有镜像标签已锁定，禁止使用 `latest`。三组件不接入现有 `storyforge` 库；FastGPT 使用独立 `fastgpt-pg`。

### 3.2 端口绑定（仅本机）

| 服务 | 容器端口 | 宿主机绑定 |
| --- | --- | --- |
| `flowise` | 3000 | `127.0.0.1:3000` |
| `fastgpt` | 3000 | `127.0.0.1:3001` |
| `n8n` | 5678 | `127.0.0.1:5678` |

禁止 `0.0.0.0` 绑定；API 容器通过内部网络 `storyforge_default` 访问，不暴露公网。

### 3.3 环境变量（API 侧）

| 变量 | 用途 | 必填 |
| --- | --- | --- |
| `FLOWISE_BASE_URL` | Flowise 地址 | 使用 Flowise 时 |
| `FLOWISE_API_KEY` | Flowise 凭据 | 使用 Flowise 时 |
| `FASTGPT_BASE_URL` | FastGPT 地址 | 启用检索时 |
| `FASTGPT_API_KEY` | FastGPT 凭据 | 启用检索时 |
| `FASTGPT_DATASET_ID` | 演示知识库标识 | 启用检索时 |
| `COZE_API_BASE` | Coze Open API 地址 | 使用 Coze 时 |
| `COZE_PAT` | Coze 凭据 | 使用 Coze 时 |
| `COZE_BOT_ID` | Coze Bot 标识 | 使用 Coze 时 |
| `N8N_ARCHIVE_WEBHOOK_URL` | 归档 Webhook | 启用归档时 |
| `N8N_ARCHIVE_TOKEN` | Webhook 鉴权 | 启用归档时 |
| `COLLAB_HTTP_TIMEOUT_MS` | 上游超时，默认 120000 | 否 |
| `COLLAB_MAX_CITATIONS` | 引用上限，默认 8 | 否 |
| `COLLAB_ARCHIVE_MAX_ATTEMPTS` | 归档重试上限，默认 5 | 否 |

凭据只从环境变量读取，不落库、不返回、不写日志；`.env.example` 只写键与说明。

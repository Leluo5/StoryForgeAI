## 一、需求结论

### 1.1 背景

StoryForgeAI 已具备角色、创作流程、Agent 配置和 Coze 调用基础，但角色内容的检索、生成、写回与归档仍需要更清晰的平台分工。本功能引入 Flowise、FastGPT 与 n8n，在不推翻现有角色体系和创作规则的前提下，形成一个可演示、可撤销、可追踪、可回退的单角色闭环。

本功能不是把创作数据主权移交给外部平台。StoryForgeAI 始终负责角色身份、任务边界、字段写回、版本与撤销；外部组件只承担各自明确的工作。

### 1.2 核心目标

| 目标 | 需求结论 |
| --- | --- |
| 多平台协同 | Flowise 执行角色 Agent，FastGPT 提供资料检索，n8n 归档结果与引用资料 |
| 单角色先行 | 首期只启用一个专用测试角色，验证完整链路后再考虑扩展 |
| 自动写回可撤销 | 合格结果无需逐次人工确认即可写回白名单字段，每个字段可独立撤销 |
| 双通道可回退 | Flowise 与 Coze 并存，按 Agent 切换；切换只影响新任务 |
| 结果可追踪 | 生成结果、引用资料、写回字段与执行通道能够关联追查 |
| 创作边界不变 | 章节正文与剧情树不进入自动写回，正文仍遵守既有待审修订规则 |

### 1.3 已确认决策

| 决策点 | 结论 |
| --- | --- |
| 组件组合 | Flowise + FastGPT + n8n |
| 部署方式 | 三个组件统一私有部署，纳入现有 Docker 运维体系 |
| 模型使用 | 允许按 Agent 配置合规的外部模型服务，复用现有可用模型凭据 |
| 首期范围 | 一个专用测试角色的最小闭环，不操作正式作品 |
| Coze 关系 | 并存而非一次性替换，按 Agent 逐步切换且可回退 |
| 写回方式 | AI 结果自动写回，无需人工确认后才写回 |
| 撤销粒度 | 按字段撤销，不按任务批次整体撤销 |
| 归档职责 | n8n 自动归档写回结果及 FastGPT 引用资料 |
| 知识库边界 | 首期使用独立 FastGPT 演示知识库，不替换或同步 M3c-3 内部知识库 |
| 验收方式 | 功能演示通过即可，不设置连续运行次数、成功率或响应时间硬指标 |

## 二、用户与核心场景

### 2.1 目标用户

| 用户 | 核心诉求 | 首期使用边界 |
| --- | --- | --- |
| 创作者 | 用检索资料辅助生成角色内容，写回后仍能按字段反悔 | 只操作专用测试角色 |
| 管理员或运维人员 | 配置执行通道与模型，排查归档失败，必要时切回 Coze | 使用项目控制的私有环境与既有凭据 |
| 验收人员 | 按可重复步骤核对生成、写回、撤销、归档和回退 | 以功能现象和留存记录为证据 |

### 2.2 首期完整体验

```text
选择专用测试角色并发起角色资料生成任务
  → StoryForgeAI 只准备当前任务所需的角色上下文
  → FastGPT 从独立演示知识库检索资料并返回引用
  → Flowise 基于角色上下文与引用资料生成指定字段内容
  → StoryForgeAI 校验结果后自动写回白名单字段
  → 保留每个字段写回前后的值、版本与任务关联
  → n8n 归档生成结果、写回信息及引用资料
  → 用户撤销其中一个字段，其他字段保持不变
  → 用户把该 Agent 的执行通道切回 Coze，并发起新任务验证回退
```

### 2.3 演示前置条件

1. 已准备一个专用测试角色，不关联正式作品的正文或剧情树写回。
2. 已准备独立 FastGPT 演示知识库，内含可识别的演示资料。
3. 测试角色至少选择两个普通资料字段进入写回白名单，以验证逐字段撤销。
4. Flowise、FastGPT、n8n 均可通过项目私有环境访问，Coze 原通道仍可使用。
5. 演示使用真实三组件链路；测试替身不能替代本次真实功能演示。

## 三、功能边界

### 3.1 首期包含

1. 一个专用测试角色的任务发起、执行过程展示与结果查看。
2. 按 Agent 配置 Flowise 或 Coze 执行通道，并允许配置合规外部模型服务。
3. FastGPT 演示知识库检索与引用资料返回。
4. Flowise 基于当前任务上下文生成指定角色资料字段。
5. 合格结果自动写回白名单字段，并保留写回前后值与版本关系。
6. 每个写回字段独立撤销，以及撤销时的后续变更冲突保护。
7. n8n 自动归档生成结果、写回信息和引用资料。
8. 归档失败后的可识别状态与仅归档重试，不重复生成或写回。
9. 从 Flowise 切回 Coze 后发起新任务，保留历史任务的原通道记录。
10. 关键环节的审计、异常提示、角色数据隔离与敏感信息保护。

### 3.2 首期不包含

| 不包含项 | 边界说明 |
| --- | --- |
| 多角色并行协同 | 不扩展为多个角色同时生成、交叉写回或角色间编排 |
| 正式作品试用 | 不操作正式作品，不以正式章节或剧情数据做演示 |
| 正文与剧情树自动写回 | 章节正文继续走 M3a 待审修订；剧情树不在本功能写回范围 |
| Coze 一次性替换或下线 | 不批量迁移既有 Agent，不删除 Coze 配置与历史记录 |
| FastGPT 替换 M3c-3 | 不做双向同步、自动导入、统一检索或内部知识库迁移 |
| M3c-3 联动扩张 | 不因本功能新增角色上下文注入、角色 Agent 写知识库等能力 |
| Trae Agent 接入 | 现有协议桩不代表可用通道，本功能不承诺 Trae 执行能力 |
| 长期归档运营 | 不定义长期保留周期、跨项目归档检索或归档数据仓库 |
| 量化稳定性验收 | 不设置连续运行轮数、成功率、并发量或响应时间门槛 |
| 旧模块退场 | 不裁定 `modules/novel_creation/` 删除，不改变 M0–M5 路线依赖 |

### 3.3 与既有能力的关系

| 既有能力 | 本功能的关系 |
| --- | --- |
| M3a AI 创作基座 | 复用任务与审计思维，但正文待审规则不被自动写回覆盖 |
| M3b Agent 与工具、F10 智能体管理 | 延续 Agent 配置与管理职责，新增的是执行通道选择，不重建角色体系 |
| M3c-2 角色版图 | 角色资料是写回对象的业务来源；首期只使用测试角色，不扩张角色版图需求 |
| M3c-3 知识库 | 与 FastGPT 演示库相互独立，各自检索和存储边界不混用 |
| Coze 现有链路 | 作为可回退执行通道继续保留，历史任务不修改通道归属 |
| 旧角色 Agent 与流程实现 | 作为现状与兼容性参考，不因本档案直接删除或迁移 |

## 四、核心流程与功能需求

### 4.1 主闭环规则

1. **任务限定**：一次任务只服务一个测试角色和一组明确的白名单字段。
2. **资料检索**：FastGPT 返回生成所需内容及其引用来源，不能只返回无法追踪的摘抄。
3. **角色生成**：Flowise 只基于当前任务提供的角色上下文、用户指令与引用资料生成。
4. **结果校验**：只有结构可识别、目标字段合法且引用关系完整的结果才能进入自动写回。
5. **自动写回**：白名单字段直接更新，同一任务的字段写回要么全部成功，要么全部不写回。
6. **版本留痕**：每个字段分别记录原值、新值、来源任务、执行通道与写回时间。
7. **结果归档**：n8n 将结果与引用资料归档到项目控制的私有存储，并能反查来源任务。
8. **字段撤销**：用户可只撤销一个字段，其他字段和既有归档不受影响。
9. **通道回退**：切换到 Coze 后的新任务使用 Coze，进行中的任务不中途换道。

### 4.2 功能需求清单

| 编号 | 需求 | 完成判定 |
| --- | --- | --- |
| R01 | 指定专用测试角色 | 只能向该测试角色发起本功能演示任务 |
| R02 | 配置执行通道与模型 | 每个 Agent 可选择 Flowise 或 Coze，并按需选择已授权模型 |
| R03 | 检索演示知识库 | FastGPT 返回与任务相关的资料和可识别引用 |
| R04 | 生成角色字段 | Flowise 输出与请求字段对应的内容，不生成越权写回目标 |
| R05 | 自动写回白名单字段 | 合格结果无需人工确认即可写回，非白名单字段不变 |
| R06 | 保存字段级版本关系 | 每个字段均可查看写回前后值及来源任务 |
| R07 | 按字段撤销 | 撤销单个字段不影响同任务其他字段 |
| R08 | 撤销冲突保护 | 字段在写回后又被修改时，旧版本撤销不得覆盖新值 |
| R09 | 自动归档 | n8n 归档结果、引用资料、写回字段和通道等追踪信息 |
| R10 | 归档独立重试 | 归档失败只重试归档，不再次生成或写回 |
| R11 | Coze 回退 | 切换后的新任务走 Coze，原任务与历史记录保持原通道 |
| R12 | 审计与异常可见 | 能识别失败环节、查看脱敏错误并核对关键操作记录 |

## 五、写回、撤销与通道切换

### 5.1 自动写回规则

- 自动写回只适用于本功能专用测试角色的白名单资料字段，不构成全系统默认行为。
- 演示至少写回两个字段；缺少合法目标字段、字段越权或结果无法解析时不得写回。
- 同一任务涉及多个字段时，不允许出现一部分字段已更新、另一部分字段未更新且无明确失败结果的情况。
- 写回前必须保留各字段原值；写回后能区分每个字段的版本，不得只保存整份角色快照来替代字段撤销能力。
- 章节正文、剧情树节点、正式作品数据及未列入白名单的角色字段必须保持不变。
- 重复完成通知或重复重试不得把同一任务结果重复写回。

### 5.2 按字段撤销规则

- 撤销对象是「某字段的一次写回」，不是整个任务，也不是整个角色。
- 撤销成功后，该字段恢复到本次写回前的值；同任务其他字段及其版本记录不变。
- 若字段在写回后已被用户或更新任务修改，旧写回不可直接覆盖当前值，必须显示冲突并保留当前值。
- 撤销不删除 n8n 已保存的原始结果与引用资料，也不篡改历史任务的执行通道。
- StoryForgeAI 必须记录撤销操作及其结果；归档撤销事件不是首期闭环的必要条件。

### 5.3 Flowise 与 Coze 切换规则

- 通道配置按 Agent 生效，不做全平台强制切换。
- 切换只决定新任务的执行通道；已排队或执行中的任务继续使用启动时的通道。
- 切回 Coze 不应要求删除 Flowise 配置，也不应重写历史任务记录。
- 每次任务都应保留实际执行通道，便于核对结果来源和排查问题。
- 通道不可用不能成为覆盖角色原数据的理由，失败时仍须保留写回前状态。

## 六、平台职责与数据约束

### 6.1 职责分工

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| StoryForgeAI | 角色身份、任务上下文、字段白名单、写回、字段版本、撤销、通道配置与审计 | 不把外部平台返回内容直接视为无条件可信 |
| Flowise | 执行角色 Agent，生成指定字段结果 | 不直接修改 StoryForgeAI 角色数据 |
| FastGPT | 从独立演示知识库检索资料并返回引用 | 不替代或同步 M3c-3，不直接写角色字段 |
| n8n | 接收并归档结果、写回信息及引用资料 | 不作为角色字段的事实来源，不重复触发写回 |
| Coze | 作为既有可切换执行通道完成新任务 | 不因接入 Flowise 被强制下线 |
| 外部模型服务 | 按 Agent 配置提供模型生成能力 | 不接收完整知识库、无关角色数据或项目密钥 |

### 6.2 上下文最小化

1. 外部模型只接收当前任务所需的用户指令、测试角色上下文和 FastGPT 引用资料。
2. 不发送其他角色信息、正式作品内容、完整知识库、会话凭据、访问令牌或内部配置。
3. FastGPT 演示库只放项目允许用于演示的资料，不上传正式作品或敏感素材。
4. 归档位于项目控制的私有存储，访问边界与现有私有运维体系一致。

### 6.3 归档内容

归档记录至少能够关联：来源任务、测试角色、实际执行通道、生成结果、写回字段及版本、FastGPT 引用资料标识与摘录、执行时间、处理状态和脱敏错误信息。

归档记录用于追踪，不替代 StoryForgeAI 中的角色当前值与字段版本。归档失败不能抹掉已经成功且可撤销的字段写回。

## 七、异常与边界规则

| 场景 | 期望行为 | 数据要求 |
| --- | --- | --- |
| FastGPT 无有效资料 | 明确提示资料不足，不进入自动写回 | 角色字段保持原值 |
| FastGPT 不可用 | 标记检索失败并允许后续重试 | 不产生字段新版本 |
| Flowise 或外部模型失败 | 标记生成失败，保留脱敏错误 | 不自动写回 |
| 生成结果缺少字段或格式非法 | 拒绝该结果并显示原因 | 不写白名单之外的字段，不产生部分更新 |
| 引用关系缺失 | 结果不得进入自动写回 | 保留失败信息供排查 |
| 写回失败 | 明确标记写回失败 | 同一任务字段不出现无标记的部分写回 |
| n8n 归档失败 | 写回结果保留，显示「已写回但归档未完成」的可观察状态 | 仅重试归档，不新增角色字段版本 |
| 重复完成通知或归档重试 | 识别为同一任务结果 | 不重复写回，不生成重复归档记录 |
| 撤销时字段已有新值 | 提示冲突并阻止旧值覆盖 | 当前值保持不变 |
| 任务执行中切换通道 | 原任务继续原通道，新任务使用新配置 | 历史通道记录不被重写 |
| 越权字段或非测试角色请求 | 拒绝执行 | 正式作品及其他角色数据不变 |

## 八、非功能需求

| 类别 | 要求 | 验收口径 |
| --- | --- | --- |
| 私有部署 | Flowise、FastGPT、n8n 纳入现有 Docker 运维体系 | 能在项目私有环境启动、访问与排查 |
| 凭据安全 | 复用现有可用模型凭据，不明文写入文档、前端或日志 | 演示记录与归档中不出现密钥明文 |
| 数据隔离 | 只使用专用测试角色与独立演示知识库 | 正式作品和其他角色无变化 |
| 最小披露 | 外部模型只接收当前任务必需上下文 | 可核对发送范围，无无关项目数据 |
| 正确性 | 写回、撤销、通道归属与归档关联必须一致 | 各验收场景结果可重复核对 |
| 可追踪性 | 失败环节、实际通道、引用来源和字段版本可追查 | 无需查看密钥或内部敏感配置即可定位 |
| 可恢复性 | 归档失败可独立重试，撤销冲突不覆盖新值 | 不发生重复写回或数据倒退 |
| 兼容性 | 不改变 M3a 正文待审规则和既有 Coze 通道 | 正文仍需接受修订后才变更 |
| 可理解性 | 用户能区分检索、生成、写回、归档和撤销的结果 | 失败不会被静默吞掉 |

本期不设置响应时间、吞吐量、连续运行次数或成功率硬指标；该取舍不免除正确性、数据隔离、安全和可撤销性的验收。

## 九、功能演示验收标准

### 9.1 验收场景

| 编号 | 演示操作 | 预期结果 |
| --- | --- | --- |
| A01 | 对测试角色发起任务，经 FastGPT 与 Flowise 完成生成 | 返回指定字段内容与引用资料，实际通道记录为 Flowise |
| A02 | 核对自动写回前后数据 | 仅白名单字段更新，正文、剧情树、非白名单字段及正式作品不变 |
| A03 | 在同一任务写回两个字段后撤销其中一个 | 目标字段恢复写回前值，另一字段保持不变 |
| A04 | 写回后再次修改某字段，再撤销较早写回 | 显示冲突，当前新值不被旧值覆盖 |
| A05 | 打开 n8n 归档并反查任务 | 结果、引用资料、字段版本、角色和通道可关联追踪 |
| A06 | 模拟 n8n 不可用后恢复，再执行归档重试 | 已写回字段不重复更新，只补齐一次归档 |

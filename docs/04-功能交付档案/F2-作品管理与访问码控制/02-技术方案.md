## 一、方案概述

本功能提供作品的 CRUD + 访问码验证 + 敏感字段过滤。核心是 `work_manager.py` 的持久化与 `get_work_public` 脱敏，配合 app.py 的公开/管理两组路由。

### 1.1 方案选型

| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 存储 | JSON 文件（每作品一个文件） | SQLite | 个人规模、零运维、易备份 |
| 敏感过滤 | `get_work_public()` 白名单字段 | 黑名单删除 | 白名单更安全，漏加字段不泄露 |
| 访问码 token | 进程内存 dict | 签名 JWT | 单机演示够用；JWT 适合多实例（增强） |
| 密码对比 | `==` 比较（现状） | `hmac.compare_digest` | 增强防时序攻击 |

## 二、API 设计

### 2.1 公开端

| 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|
| GET | `/api/works` | 公开作品列表 | 无 |
| GET | `/api/works/<id>` | 公开作品详情 | 无（过滤敏感） |
| POST | `/api/works/<id>/verify` | 访问码验证 | 无 |

**verify 请求**：`{ "access_code": "xxx" }`

**verify 响应 200**：`{ "token": "sess_xxx", "work_id": "id" }`

### 2.2 管理端

| 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|
| GET | `/api/admin/works` | 完整作品列表 | 需 require_admin |
| PUT | `/api/admin/works/<id>` | 更新作品 | 需 require_admin |
| DELETE | `/api/admin/works/<id>` | 删除作品 | 需 require_admin |

**PUT 请求体**（可部分字段）：

```json
{
  "title": "新标题",
  "description": "新简介",
  "access_code": "newcode",
  "params": [ { "name": "city", "type": "String" } ]
}
```

## 三、存储设计

### 3.1 作品文件

沿用 F1 的 JSON 结构（每作品一个文件 `data/works/<id>.json`）。

### 3.2 脱敏白名单（get_work_public）

```python
PUBLIC_FIELDS = {
    "id", "title", "description", "type", "coze_resource_id",
    "opening", "params", "variables", "has_access_code", "created_at"
}

def get_work_public(work):
    return {k: work[k] for k in PUBLIC_FIELDS if k in work}
```

- `has_access_code` = `bool(access_code)`，**绝不返回 access_code 明文**。
- `pat_token`、`workspace_id` 永不进公开响应。

### 3.3 访问码会话

```python
access_tokens = {}   # { work_id: { token, expires } }
```

## 四、核心逻辑

### 4.1 访问码验证

```python
def verify_access(work_id, code):
    work = work_manager.get_work(work_id)
    if not work:
        raise NotFound("作品不存在")
    if not work.get("access_code"):
        return {"token": "public", "work_id": work_id}   # 公开免验证
    if code != work["access_code"]:
        raise Unauthorized("访问码错误")
    token = secrets.token_urlsafe(24)
    access_tokens[work_id] = {"token": token, "expires": now + TTL}
    return {"token": token, "work_id": work_id}
```

### 4.2 体验鉴权（供 F3 调用）

```python
def require_access(work_id, token):
    sess = access_tokens.get(work_id)
    if not sess or sess["token"] != token or expired(sess):
        raise Unauthorized("请先验证访问码")
```

## 五、异常处理

| 异常 | 处理 |
|------|------|
| 作品不存在 | 404「作品不存在」 |
| 访问码错误 | 401，不提示作品是否存在 |
| 删除文件失败 | 500，提示稍后重试 |
| 更新非法字段 | 400，列出非法字段 |
| 未授权管理操作 | 401（需补齐 require_admin） |

## 六、前端交互

| 交互 | 实现 |
|------|------|
| 编辑弹窗 | 表单预填当前值 → PUT → 刷新列表 |

## 七、验收对照

| 需求验收标准 | 方案落点 |
|------------|---------|
| 公开列表不含敏感键 | 3.2 白名单过滤 |
| 编辑后前台即时生效 | 2.2 PUT + 前端刷新 |
| 删除后文件移除 | 2.2 DELETE + work_manager.remove |
| 未验证无法进入体验 | 4.2 require_access |
| 正确访问码进入 | 4.1 发放 token |
| 公开作品免验证 | 4.1 无 access_code 直接 public |
| 公开作品列表可见 | 2.1 GET /api/works |
| 卡片显示正文字数 | Work 契约 `word_count` 字段；`WorkService.list` 聚合 `chapters.document` 文本节点非空白字符数，`toWork` 默认 0 |

## 八、风险与待定

| 风险 | 说明 | 对策 |
|------|------|------|
| 访问码暴力破解 | 无限次尝试 | 增加限流（5 次/分钟） |
| 时序攻击 | `==` 比较 | 用 `hmac.compare_digest` |
| token 内存丢失 | 重启失效 | 单机演示可接受；多实例用 JWT |
| require_admin 空壳 | 管理接口无鉴权 | 生产必须补齐（开发规范 §5.1） |

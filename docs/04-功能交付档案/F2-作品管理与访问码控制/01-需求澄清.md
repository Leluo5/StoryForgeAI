## 一、用户诉求（非技术语言）

> 创作者希望：**我能管理已导入的作品（改名字、改描述、设访问码、删掉不想要的），同时访客要看某些作品时需要先通过访问码验证。**

### 1.1 要解决的核心痛点

- 导入后作品元信息可能不准确（名字乱、简介缺失），需要能编辑。
- 部分作品只给特定人看，不想公开。
- 访客体验时不能看到别人的敏感信息。

### 1.2 期望的完整体验

```text
【管理端】
  管理后台 → 作品列表 → 编辑/删除/设置访问码
  编辑：改标题/简介/参数/访问码
  删除：确认后移除（连同本地 JSON）

【体验端】
  访客点击作品卡片
     → 若需访问码 → 弹出验证框
     → 输入正确 → 发放 token → 进入体验
     → 输入错误 → 提示重试
```

## 二、功能边界

### 2.1 包含（In Scope）

| # | 能力 | 说明 |
|---|------|------|
| 1 | 作品列表 | 管理端/公开端均可获取，公开端过滤敏感字段 |
| 2 | 作品详情 | 单个作品完整信息（公开端经 `get_work_public` 过滤） |
| 3 | 作品编辑 | 改标题/简介/访问码/参数等 |
| 4 | 作品删除 | 删除本地作品 JSON 文件 |
| 5 | 访问码验证 | 校验访问码，通过发放一次性/会话 token |
| 6 | 敏感字段过滤 | 任何公开响应不含 pat_token / access_code 明文 |

### 2.2 不包含（Out of Scope）

- ❌ 作品版本历史 / 回滚。
- ❌ 多用户权限体系（仅单管理员）。
- ❌ 作品评论 / 点赞 / 访问统计（后续增强）。
- ❌ Coze 侧资源删除联动（本平台不删 Coze 资源）。

## 三、功能流程

### 3.1 作品列表流程

```text
【公开端】GET /api/works
  → work_manager.list_works()
  → 每条经 get_work_public() 过滤
  → 返回 [{id, title, description, type, ...}]  // 无 pat_token

【管理端】GET /api/admin/works
  → require_admin 校验
  → work_manager.list_works(include_sensitive=true)
  → 返回完整字段（含 pat_token，仅管理端可见）
```

### 3.2 作品编辑流程

```text
管理端编辑表单（标题/简介/访问码/参数）
  → PUT /api/admin/works/<id>
  → 校验字段 → work_manager.update_work(id, data)
  → 返回更新后作品
  → 前端刷新列表
```

### 3.3 访问码验证流程

```text
访客打开需访问码作品
  → 弹窗输入 access_code
  → POST /api/works/<id>/verify  { access_code }
  → 校验：
      ├─ 匹配 → 生成 token → 存 accessTokens[workId] → 进入体验
      └─ 不匹配 → 401 → 提示「访问码错误」→ 重新输入
```

## 四、验收标准（DoD）

| # | 标准 | 验证方式 |
|---|------|---------|
| 1 | 公开列表不含 pat_token/access_code | 请求 GET /api/works → 响应字段无敏感键 |
| 2 | 编辑后前台即时生效 | 改标题 → 返回大厅 → 新标题显示 |
| 3 | 删除后前台消失且本地文件移除 | 删除 → 大厅无该卡片 → data/works 无该 json |
| 4 | 设访问码后，未验证无法进入体验 | 设码 → 前台点击 → 弹出验证框 → 无验证不渲染体验 |
| 5 | 正确访问码可进入，错误提示 | 输对→进入；输错→401 提示 |
| 6 | 公开作品（无码）免验证直接进入 | 无访问码作品 → 点击直接进入体验 |
| 7 | 访问码为空的公开作品列表可见 | 公开作品出现在大厅卡片 |
| 8 | 作品卡片显示正文字数 | 卡片 meta 行显示「N 字」，N = 全作品章节 document 非空白字符数，无正文为 0 |

## 五、异常与边界处理

| 场景 | 处理 |
|------|------|
| 作品 id 不存在 | GET/PUT/DELETE 均返回 404「作品不存在」 |
| 编辑非法字段 | 返回 400，列出非法字段名 |
| 访问码错误 | 返回 401，不提示「作品是否存在」（防枚举） |
| 访问码连续错误 | 可增加简单限流（如 5 次后锁 1 分钟，后续增强） |
| 删除时文件占用/失败 | 返回 500，提示稍后重试，不静默失败 |
| 删除已导入的 Coze 资源 | 仅删本地作品，提示「Coze 侧资源未删除」 |
| 访问码为空字符串 | 视为公开（无码） |

## 六、数据字段说明

### 6.1 公开作品（get_work_public 输出）

| 字段 | 说明 |
|------|------|
| `id` | 作品 id |
| `title` | 标题 |
| `description` | 简介 |
| `type` | bot / workflow / dataset |
| `coze_resource_id` | Coze 资源 id |
| `params` | 参数定义 |
| `has_access_code` | bool，是否需访问码 |
| `created_at` | 创建时间 |

### 6.2 管理端作品（含敏感）

公开字段 + `pat_token`、`workspace_id`、`access_code`。

### 6.3 访问码会话

| 字段 | 说明 |
|------|------|
| `token` | 验证通过后发放（进程内存 `accessTokens[workId]`） |
| `work_id` | 关联作品 |
| `expires` | 有效期（当前为会话级） |

## 七、相关依赖与约束

- **依赖**：`work_manager.py` 提供 CRUD + `get_work_public`。
- **约束**：`access_code` 对比须用常数时间比较（防时序攻击，后续增强）；公开响应永不泄露敏感键。
- **前置**：管理端接口需 `require_admin` 鉴权（当前为空壳，需补齐）。

## 六、新架构迁移说明（2026-11-25）

> 本节记录 `1d3064e` 将 F2 从 Python 旧架构迁移至 TS 新架构后的**实际落点**，取代上文第 1~5 节中与新实现不一致的描述。上文保留作历史记录。

**作品管理（登录态）**：
- 数据层：作品存 PostgreSQL `WorkEntity`（`works` 表），含 `title`/`description`/`status`/`is_public`/`access_code`/Coze 绑定字段/`project_id`。
- 管理 API：`/works`（SessionGuard），CRUD + 更新（含 `is_public`、`access_code` 读写）。

**访问码控制（体验侧）**：
- 体验者访问：`/experience/works`（公开无登录），设访问码作品需 `X-Access-Token`（`verify` 校验后颁发签名 token）。
- 访问码存储：`access_code` 字段（`1760800000000-work-access-code` 迁移新增），未设码作品 `granted=true, token=null`。

**契约校验**：请求/响应经 `packages/contracts/src/works.ts`（管理侧）+ `experience.ts`（体验侧）Zod schema 校验。

**前端**：`apps/web/src/works/works-page.tsx`（管理）+ `experience-page.tsx`（体验），对应旧 `work_manager.py`/`app.js`。

**差异摘要**：存储由 JSON 文件迁 PostgreSQL；管理/体验 API 分离（`/works` 登录态 vs `/experience/works` 公开）；新增 Zod 契约。

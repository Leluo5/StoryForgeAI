## 一、用户诉求（非技术语言）

> 创作者希望：**设定一个剧情发生的场所和背景，把角色拉进聊天室，然后一步步看着剧情自己长出来——每走一步，系统可能触发意外事件、可能跑进来新角色，走到一步我可以停下来改一改、选个方向，还能同时开好几个聊天室互不打扰。**

### 1.1 要解决的核心痛点

- 剧情写到一半卡住，不知道下一步该发生什么。
- 凭感觉推剧情，容易逻辑跳、人设崩、前后矛盾。
- 想同时试几个剧情走向，但一个工具只能跑一条线，没法并行。
- 剧情推进后难以回头调整，一旦生成就不好改。

### 1.2 期望的完整体验

```text
创作者进入剧情推衍聊天室
  → 设置基础配置：故事场所 / 核心剧情背景 / 当前时间节点 / 重要前置剧情 / 关联剧情
  → 把剧情参与角色手动拉入聊天室
  → 点击「开始推衍」：
     ├─ 生成第 1 步剧情内容
     ├─ 随机度系统掷骰：
     │    ├─ 可能触发随机意外事件（改写当前步）
     │    └─ 可能随机入场新角色（追加到聊天室）
     └─ 生成后自动暂停，进入「一步一断」交互
  → 用户可修改/调整剧情内容，或从多个剧情分支选项中选择后续走向
  → 点「下一步」继续推衍，循环
  → 可同时创建多个独立聊天室（多线程），切换流畅无卡顿
```

## 二、功能边界

### 2.1 包含（In Scope）

| # | 能力 | 说明 |
|---|------|------|
| 1 | 基础配置模块 | 故事场所、核心剧情背景、当前时间节点（剧情节点）、重要前置剧情（可多个）、关联剧情（可多个）可自定义设定 |
| 2 | 角色管理 | 手动将指定剧情参与角色拉入聊天室；支持随机触发新角色拉入机制 |
| 3 | 步骤化剧情推衍 | 以步骤化方式逐步推进当前剧情发展，每步生成一段剧情内容 |
| 4 | 随机度生成系统 | 内置随机度生成系统，含随机意外事件触发、新角色随机入场等随机化逻辑 |
| 5 | 多线程支持 | 同时创建并运行多个独立剧情推衍线程，各线程数据隔离互不干扰 |
| 6 | 一步一断交互 | 每完成一步推衍后自动暂停，开放剧情内容修改、调整，并提供多个剧情分支选项供选择 |
| 7 | 配置实时编辑 | 所有配置项（基础配置/角色/随机度/分支）可实时编辑调整 |

### 2.2 不包含（Out of Scope）

- ❌ 跨线程剧情合并（多线程各自独立，暂不自动合成主线）。
- ❌ 成书级导出（全文导出，后续增强）。
- ❌ 长对话持久化到数据库（当前为会话级，服务重启即失）。
- ❌ 语音 / 音视频推衍（当前为文本剧情）。

## 三、功能流程

### 3.1 基础配置流程

```text
创作者打开聊天室
  → 填写故事场所（如「雾都旅馆大厅」）
  → 填写核心剧情背景（如「侦探受雇调查失踪案」）
  → 设定当前时间节点（如「第三夜 23:00」）
  → 可添加重要前置剧情（多个，如「旅馆老板失踪」「血字留信」）
  → 可添加关联剧情（多个，如「警局封锁令」「老宅密道」）
  → 保存配置 → 进入角色管理
```

### 3.2 角色管理流程

```text
从作品角色库中浏览
  → 勾选要拉入的剧情参与角色（可多选，如「侦探·林远」「旅馆老板·周福」）
  → 确认拉入聊天室
  → （可选）开启随机入场机制：推衍中随机触发新角色入场
```

### 3.3 步骤化推衍流程（含随机系统）

```text
点击「开始推衍」/「下一步」
  → 推衍引擎基于：当前配置 + 聊天室角色 + 前序剧情历史
     ├─ 生成当前步剧情内容
     └─ 随机度系统掷骰：
          ├─ 触发随机意外事件 → 改写当前步剧情（如「突然停电，走廊传来脚步声」）
          └─ 触发新角色随机入场 → 追加角色到聊天室（如「神秘女郎·苏晚推门而入」）
  → 生成步结果（剧情内容 + 事件标记 + 新角色 + 分支选项）
  → 自动暂停 → 进入一步一断交互
```

### 3.4 一步一断交互流程

```text
步结果生成后自动暂停
  → 用户可：
     ├─ 修改/调整本步剧情内容（自由编辑文本）
     ├─ 从多个剧情分支选项中选择后续走向（如 A 追问线索 / B 按兵不动 / C 引蛇出洞）
     └─ 调整角色/随机度/配置后继续
  → 确认 → 点击「下一步」→ 回到 3.3 推衍下一步
```

### 3.5 多线程流程

```text
创建聊天室 A（侦探线）
创建聊天室 B（反派线）
创建聊天室 C（并行支线）
  → 三个独立线程同时推衍
  → 各线程数据隔离：配置/角色/剧情历史/步序号互不共享
  → 切换聊天室标签 → 流畅恢复各自状态
```

## 四、验收标准（DoD）

| # | 标准 | 验证方式 |
|---|------|---------|
| 1 | 基础配置可保存 | 填写场所/背景/时间节点/前置剧情/关联剧情 → 保存成功并回显 |
| 2 | 前置剧情可多选 | 添加多个重要前置剧情，列表可增删 |
| 3 | 角色手动拉入 | 从角色库勾选 → 拉入聊天室成功 |
| 4 | 随机入场可触发 | 开启随机机制后，推衍中有概率出现新角色入场 |
| 5 | 步骤化推进 | 点「下一步」生成递增步序号剧情，历史保留 |
| 6 | 随机意外事件触发 | 推衍中概率触发意外事件，并改写当前步剧情 |
| 7 | 多线程独立 | 同时开 3 个聊天室，各自动态推进，切换无串扰 |
| 8 | 一步一断暂停 | 每步生成后自动暂停，未点「下一步」不自动推进 |
| 9 | 剧情可修改 | 暂停后编辑本步剧情文本，保存生效 |
| 10 | 分支选项可用 | 每步提供多个分支选项，选择后影响下一步走向 |
| 11 | 配置实时编辑 | 推衍中可调整随机度/角色，不中断线程 |
| 12 | 逻辑上下文一致 | 随机事件/新角色入场符合背景与角色设定，无逻辑跳变 |

## 五、异常与边界处理

| 场景 | 处理 |
|------|------|
| 未填必填配置 | 前端提示补充故事场所/核心剧情背景，禁止开始 |
| 聊天室无角色 | 提示先拉入至少 1 名角色 |
| 随机入场角色已存在 | 跳过重复，不重复拉入 |
| 推衍引擎调用失败 | 提示重试，保留当前步编辑内容 |
| 多线程超限 | 提示已达上限，建议先关闭闲置线程 |
| 切换线程时未保存 | 提示确认，未确认不丢弃 |
| 分支选项冲突 | 提示重新选择，不自动兜底 |
| 剧情历史超长 | 分页/折叠展示，不阻塞交互 |

## 六、数据字段说明（概念模型）

### 6.1 聊天室配置（story room config）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 聊天室唯一 id |
| `name` | string | 聊天室名称 |
| `place` | string | 故事场所 |
| `background` | text | 核心剧情背景 |
| `time_node` | string | 当前时间节点（剧情节点） |
| `premise_plots` | array | 重要前置剧情（可多个） |
| `related_plots` | array | 关联剧情（可多个） |
| `characters` | array | 当前聊天室角色 id 列表 |
| `random_enabled` | bool | 是否开启随机度系统 |
| `step_index` | integer | 当前步序号 |
| `status` | enum | idle/running/paused/finished |

### 6.2 单步结果（step result）

| 字段 | 类型 | 说明 |
|------|------|------|
| `step_no` | integer | 步序号 |
| `content` | text | 本步剧情内容（可编辑） |
| `event_triggered` | object/null | 随机意外事件（如有） |
| `new_character` | string/null | 随机入场新角色 id（如有） |
| `branches` | array | 可选剧情分支选项列表 |
| `created_at` | datetime | 生成时间 |

## 七、相关依赖与约束

- **依赖**：`coze_client`（调用 Coze 智能体生成剧情内容/意外事件/分支）；`app.py` 新增聊天室路由与线程管理；`app.js` 聊天室面板与多线程切换。
- **约束**：多线程数据隔离必须做到实例级隔离（配置/角色/历史/步序号独立），禁止共享可变状态；随机度系统概率可配置，事件与角色须符合背景上下文；SSE 或轮询实现推衍进度反馈。
- **前置**：需先完成角色 Agent 体系（改造路线图 P3）以具备角色库来源；知识库（F5）条目可作为剧情背景补充来源；站点设置（F4）提供 LLM 配置。

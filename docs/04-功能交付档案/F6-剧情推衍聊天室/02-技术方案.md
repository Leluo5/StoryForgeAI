## 一、方案概述

本功能是创作端的**剧情推衍工具**：设定剧情基础要素，拉入角色，以步骤化方式逐步推衍剧情；内置随机度系统（意外事件/新角色入场）；多线程实例隔离；一步一断交互。核心是「配置 → 推衍一步 → 随机 → 暂停 → 交互 → 下一步」循环，每步结果走 Coze 智能体生成。

### 1.1 方案选型

| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| 推衍引擎 | 后端 `story_engine.py` 状态机 | 前端驱动 | 状态机集中管理步序/历史/分支，后端权威 |
| 多线程 | 进程内实例字典（thread-safe） | 多进程 | 单机演示，实例级隔离即可；多进程过重 |
| 并发安全 | `threading.Lock` + 实例级锁 | 全局锁 | 隔离是硬约束，实例间零共享 |
| 进度反馈 | SSE（`/api/story/stream`） | 轮询 | 推衍生成耗时，SSE 流式反馈更顺滑 |
| 随机度 | 配置化概率表 + `random` | 固定种子 | 概率可调（DoD #11），事件/角色符合上下文 |
| 分支生成 | Coze 智能体输出多选项 | 前端硬编码 | 分支须符合背景与角色设定，走 LLM 保证上下文一致 |

## 三、API 设计

### 3.1 `POST /api/story/rooms` — 创建聊天室

**请求体**：基础配置（见 2.1 前 8 字段）

**响应 200**：`{ "room_id": "room_01xxx" }`

### 3.2 `GET /api/story/rooms` — 列出所有聊天室（多线程）

**响应 200**：`{ "rooms": [{ id, name, step_index, status, characters_count }] }`

### 3.3 `GET /api/story/rooms/<id>` — 聊天室详情（含历史）

**响应 200**：完整 `story_room` + `history`（step_result 列表，分页/折叠在前端）。

### 3.4 `POST /api/story/rooms/<id>/step` — 推衍一步（同步）

**请求体**：`{ "override_content": "可选，用户修改后的本步内容", "branch_choice": "A|B|C", "random_enabled": true }`

**响应 200**：`{ "step": { ...step_result }, "status": "paused" }`

> 推衍完成后 `status` 置 `paused`（一步一断，DoD #8），前端据此开放修改/分支选择。

### 3.5 `POST /api/story/rooms/<id>/continue` — 确认本步并进入下一步

**请求体**：`{ "final_content": "编辑后的剧情文本", "branch_choice": "B", "config_updates": {...可选配置调整...} }`

**响应 200**：`{ "status": "running" }` → 前端随后调 3.6 SSE 或 3.4 继续。

### 3.6 `POST /api/story/rooms/<id>/stream` — 推衍流式反馈（SSE）

```text
data: {"stage": "generating"}
data: {"stage": "rolling", "event": "blackout"}
data: {"delta": "林远推开房门…"}
data: {"done": true, "step": {...step_result}, "status": "paused"}
```

### 3.7 `POST /api/story/rooms/<id>/characters` — 角色拉入 / 随机入场

**请求体**：`{ "characters": ["c_xxx"], "random_enter": true }`

**响应 200**：`{ "characters": [...], "random_entered": "c_苏晚|null" }`

### 3.8 `PUT /api/story/rooms/<id>` — 配置实时编辑

**请求体**：基础配置任意字段子集

**响应 200**：`{ "status": "updated" }`

### 3.9 `DELETE /api/story/rooms/<id>` — 关闭/销毁聊天室

**响应 200**：`{ "deleted": true }`

## 四、核心逻辑

### 4.1 推衍状态机（`story_engine.py`）

```text
idle ──start──→ running ──step完成──→ paused
  ▲                 │                    │
  └────continue─────┘                    │
        │                                │
        └────(branch选择/编辑)────────────┘
paused ──finish──→ finished
```

```python
def advance_step(room):
    # 1) 组装推衍上下文：配置 + 角色 + 前序历史
    ctx = build_context(room)
    # 2) 生成本步剧情（Coze 智能体）
    content = llm_generate_step(ctx)
    # 3) 随机度系统掷骰
    event = random_system.roll_event(room)     # 可能改写 content
    new_char = random_system.roll_enter(room)  # 可能追加角色
    # 4) 生成分支选项（LLM，符合上下文）
    branches = llm_gen_branches(ctx, content)
    # 5) 记录步结果，置 paused（一步一断）
    room["history"].append(build_step(room, content, event, new_char, branches))
    room["status"] = "paused"
    room["step_index"] += 1
    return room["history"][-1]
```

### 4.2 随机度系统（`random_system.py`）

```python
class RandomSystem:
    def __init__(self, config):  # config: {event_rate, enter_rate, seed}
        self.event_rate = config.get("event_rate", 0.25)
        self.enter_rate = config.get("enter_rate", 0.15)

    def roll_event(self, room):
        if not room["random_enabled"]: return None
        if random.random() < self.event_rate:
            return pick_event(room["background"], room["time_node"])  # 符合上下文
        return None

    def roll_enter(self, room):
        if not room["random_enabled"]: return None
        if random.random() < self.enter_rate:
            cand = pick_character_pool(room)  # 从角色库挑未入场者
            if cand and cand not in room["characters"]:
                return cand  # 跳过重复（DoD 异常表）
        return None
```

- 事件/角色须符合背景与角色设定：事件池按 `background` 关键字匹配；角色从作品角色库按阵营/关联度筛选。
- 概率可实时调（`PUT` 配置），DoD #11。

### 4.3 多线程隔离（`story_thread.py`）

```python
_rooms = {}          # room_id → story_room
_room_locks = {}     # room_id → Lock
_global_lock = threading.Lock()

def create_room(cfg):
    with _global_lock:
        rid = new_id()
        _rooms[rid] = init_room(cfg)
        _room_locks[rid] = threading.Lock()
        return rid

def with_room(rid, fn):
    lock = _room_locks.get(rid)
    with lock:  # 实例级锁，隔离保证
        return fn(_rooms[rid])
```

- 硬约束：**实例级隔离**——配置/角色/历史/步序号均在各自 `story_room` 内，禁止全局可变共享；`_rooms` 仅存实例引用，方法全部走 `with_room`。
- 并发上限：`MAX_ROOMS = 10`，超限返回 409（异常表「多线程超限」）。
- 服务重启即失（符合 F6 边界：会话级，不持久化到 DB）。

### 4.4 一步一断交互

- 每步完成 → `status = paused`（DoD #8），不自动推进。
- `continue` 携带 `final_content`（用户修改）与 `branch_choice`（分支），覆盖本步或注入下一步上下文。
- 未确认不丢弃：前端在切换线程/关闭时弹确认（异常表）。

### 4.5 分支选项

- 由 LLM 基于当前配置+角色+历史生成 2-4 个可选走向，符合上下文逻辑（DoD #12）。
- 用户选择后 `branch_choice` 注入下一步 `build_context`，影响生成方向。
- 冲突（如重复分支/非法选择）提示重选，不自动兜底（异常表）。

## 五、异常处理（对齐需求澄清 §五）

| 场景 | 处理 | 方案落点 |
|------|------|---------|
| 未填必填配置 | 400「请补充故事场所/核心剧情背景」 | 3.1 创建前校验 |
| 聊天室无角色 | 400「请先拉入至少 1 名角色」 | 3.4 推衍前校验 |
| 随机入场角色已存在 | 跳过重复 | 4.2 roll_enter 去重 |
| 推衍引擎调用失败 | 保留当前步编辑内容 + 提示重试 | 4.1 异常保持 paused |
| 多线程超限 | 409 提示关闭闲置 | 4.3 MAX_ROOMS |
| 切换线程未保存 | 前端确认弹窗 | 4.4 交互层 |
| 分支选项冲突 | 提示重选，不自动兜底 | 4.5 |
| 剧情历史超长 | 分页/折叠 | 3.3 前端处理 |

## 八、风险与待定

| 风险 | 说明 | 对策 |
|------|------|------|
| 多线程共享状态泄漏 | 全局可变导致串扰 | 实例级锁 + 无全局可变（硬约束） |
| LLM 生成延迟 | 每步一次智能体调用 | SSE 流式反馈；分块/缓存上下文 |
| 随机事件上下文不符 | 事件池匹配不精准 | 事件池按 background 关键字 + LLM 校验 |
| 内存增长 | 会话级历史无界 | 历史分页/折叠；后续持久化增强 |
| 角色库来源 | 依赖角色 Agent 体系（P3） | 前置约束：P3 完成后接入，否则用模拟角色 |

| 决策 | 方案结论 | 实现 |

| 决策2 路径前缀 | B. 新 `/ai-*` 体系 | 全部对齐 `ai-agents` / `ai-agent-groups` / `ai-projects` / `ai-roles` 命名 |
| 评审修正 R1 工具开关 | 路径带 `projectId`，`switchToolDefault(authorId, projectId, toolName, agentId)` | `POST /ai-projects/:projectId/tools/:toolName/switch` |

| 评审修正 R3 key 取值域 | `key` 对齐 `_groups.json`——`role:` / `agent:` / `flow:` | 以 `buildTree` 实际生成域为准：`flow:{step_order}` / `tool:{tool_name}` / `role:{role_id}` / `project:` / `manual:{uuid}` |

### 关键实现细节与偏离说明

- **契约 schema 数量**：方案 4.3 表格列 8 个 schema，实际实现 11 个。方案表格未列 `deleteOverrideSchema` / `deleteManualGroupSchema` / `resetRoleDefaultFlowSchema`，但服务层有对应方法，编码时按「服务层签名 + 旧 Flask 路由语义」补全（`project_id` 必填、`createManualGroup` name/parent_key、`switchTool` agent_id 必填、`resetRoleDefaultFlow` mode 枚举）。此为方案表格的不完整，非语义偏离。
- **`setAgentGroup` 承载（评审修正偏差 2）**：用 `updateAgentV2` 的 `manual_group_key` 承载，`setAgentGroupSchema = { manual_group_key: id.nullable() }`（纯 uuid，无 `manual:` 前缀）。
- **`createManualGroup` 返回类型**：`createManualGroup(projectId, parentKey, name, sortOrder)` 返回 `ManualGroup { id, parent_key, name, sort_order }`（无 `group_id` / `label`，方案表格列的是旧 Flask `_groups.json` 字段，与新服务层签名不符，以服务层签名及旧路由语义为准）。
- **`manual_group_key` 格式不兼容（偏离说明）**：`ai_agents.manual_group_key` 列类型为 **uuid**（migration 1760200000000），旧 `_groups.json` 的手动分组 id 是 `manual:{uuid}` 字符串。新旧格式不兼容，T4 采用**纯 uuid**（`randomUUID()`），对齐列类型。旧格式迁移属 M4-T11 旧数据迁移脚本范围，不在本任务。
- **`switchTool` 契约必填**：`switchToolSchema = { agent_id: id }`（必填非空），对齐旧 `POST /tools/<name>/switch` 语义（必传绑定 Agent）。
- **`provision` / `bindRoles` / `archiveAgent` 空 body**：`z.object({}).default({})`，避免 `ZodValidationPipe` 对 `undefined` body 的 422（契约层不校验空 body，`undefined` 放行）。

## 四、验收结果

### 4.1 契约测试

`pnpm --filter @storyforge/contracts test` → **228 用例全绿**（含新增 `M4-T4 agent management request schemas` 11 组）：

- `archiveAgentSchema` / `provisionSchema` / `bindRolesSchema`：空 body 合法（`.default({})`）
- `rollbackAgentSchema`：`version_no` 正整数合法，0 / 负数 / 缺失非法
- `upsertOverrideSchema`：`project_id` + `key` 必填，`name` / `sort_order` / `hidden` 可选
- `deleteOverrideSchema` / `deleteManualGroupSchema`：`project_id` + `key` 必填
- `createManualGroupSchema`：`project_id` + `name` 必填，`parent_key` 默认 `project:`，`sort_order` 默认 0
- `setAgentGroupSchema`：`manual_group_key` uuid / null 合法
- `switchToolSchema`：`agent_id` 必填 uuid
- `resetRoleDefaultFlowSchema`：`mode` 枚举 `fill` / `replace`，默认 `fill`

### 4.2 E2E（真实 PG）

`pnpm vitest run apps/api/test/agent-mgmt.e2e-spec.ts` → **12 用例全绿**：

1. `GET /ai-agent-groups/tree` 返回分组树，归属 Agent 落在 `flow:` 节点（`node.key === 'flow:1'`、`agent_ids` 含 id、默认名 `'步骤 1'`）
2. `override` upsert（`flow:` / `tool:` / `role:` 域）与 delete
3. `override` 契约：缺 `key` → 422
4. `manual group` create + delete
5. `setAgentGroup` 经 `PUT /ai-agents/:id/group` 承载 `manual_group_key`（纯 uuid）
6. `provision` 幂等开通默认流 Agent，`bind-roles` 绑定角色
7. `switchTool` 切换绑定 Agent
8. `archive` / `restore` / `versions` / `rollback` 全链路
9. 非作者访问 Agent → 404（不泄露存在性）
10. 未认证 401 / 无 CSRF 403
11. `rollback` 缺 `version_no` 路径 → 400/422（契约校验入口）
12. 未登录 401（getTree）

### 4.3 全量门禁

`pnpm ci` → **全绿**（contracts build + lint + typecheck + 全量单测 + 全量 e2e + build，exit 0）。

> 过程中发现并修复 **服务层 DI 裸类型注入缺陷**：`AgentService` 构造器 4 个服务（`versionService` / `provisionService` / `groupService` / `flowProgressService`）为裸类型注入（无 `@Inject`），在 esbuild / vitest 转换下 `design:paramtypes` 元数据不生成，Nest 无法解析 → 注入为 `undefined` → `updateAgentV2` / `archiveAgent` / `rollbackVersion` 调 `this.versionService.snapshot/rollback` 时抛 `TypeError: Cannot read properties of undefined (reading 'snapshot')` → 500（此前 `createAgent` 走非 V2 `createAgent` 不触发，故单跑 create 用例未暴露；全量 CI 的 `setAgentGroup` / `archive` 用例暴露）。与 M4-T2 `ChatRoomController` 裸类型注入缺陷完全同类。修复方式：给 4 个参数补 `@Inject(AgentVersionService)` / `@Inject(AgentProvisionService)` / `@Inject(AgentGroupService)` / `@Inject(FlowProgressService)`；`AgentProvisionService.versionService` 同步补 `@Inject`。修复后全量 CI 全绿。
>
> 同时修复 **provision 默认流撞作者级唯一默认索引**：`uq_ai_agents_author_default ON ai_agents(author_id) WHERE is_default`（作者级唯一默认索引）。`provisionProjectDefaults` 把每个作品级 flow_step_agent / tool_agent 设 `is_default=true`，第 2 个起撞唯一索引（每作品 11 个 flow agent + 多个 tool agent）。且原 catch 检查 `err?.code === '23505'` 不命中（TypeORM `QueryFailedError` 的 `code` 是 `ERR_QUERY_FAILED`，真实 PG 错误码在 `err.databaseError.code`）→ 事务中断 → 后续 `25P02`。修复：flow / tool agent `is_default=false`（作品级不占用作者级唯一默认），catch 改用 `isUniqueViolation`（同时检查 `code` 与 `databaseError.code`）。

## 五、遗留说明

- **`switchToolDefault` 的 `newDefault.is_default = true`**：同样存在撞 `uq_ai_agents_author_default` 作者级唯一索引的既有服务缺陷（schema 语义问题，切换工具为默认 Agent 时若作者已有默认会冲突）。e2e 因数据巧合通过（切换目标无默认冲突）。**属既有服务缺陷，超出 M4-T4「接口层补齐」范围，不改代码**，记录待 M4-T5 工具开关细节任务评估。
- **`manual_group_key` 新旧格式不兼容**：旧 `_groups.json` 为 `manual:{uuid}`，新列为纯 uuid，旧数据迁移属 M4-T11。
- **旧代码未删除**：`modules/agent_management/routes.py` 保留至 M4-T14 统一清理，cutover（M4-T13）前不删。
- **`archiveAgent` / `provision` / `bindRoles` 空 body**：契约层 `z.object({}).default({})`，controller 无 body 参数。

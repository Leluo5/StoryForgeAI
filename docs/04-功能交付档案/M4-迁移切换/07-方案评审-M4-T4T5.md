## 四、评审意见（修正项）

### 🔴 R1（必改）：`switchToolDefault` 缺 projectId 来源

**问题**：T4 端点 `POST /ai-tools/:toolName/switch` 的路径参数只有 `toolName`，但服务方法签名 `switchToolDefault(authorId, projectId, toolName, agentId)` 需要 `projectId`。controller 无法从路径解析 projectId，导致调用缺参。

**建议**：二选一——
- **A**：端点改 `POST /ai-projects/:projectId/tools/:toolName/switch`（路径带 projectId，对齐 `provision` 的 projectId 体系）；
- **B**：服务方法签名改为 `switchToolDefault(authorId, toolName, agentId)`，内部由 `tool_agent` 表的 `project_id` 反查（工具本身归属 project）。
推荐 **A**（显式传参，避免隐式反查）。

### 🔴 R2（必改）：`getProgress` / `resetProgress` 缺 projectId 来源

**问题**：T4 端点 `GET /ai-roles/:roleId/progress`、`POST /ai-roles/:roleId/progress/reset` 路径只有 `roleId`，但 `FlowProgressService.getProgress(projectId, roleId)` / `resetProgress(projectId, roleId)` 需要 `projectId`。同理缺参。

**建议**：服务方法签名改为 `getProgress(authorId, roleId)` / `resetProgress(authorId, roleId)`，内部由 role → project 反查归属（role 必属 project），controller 透传 `request.author.id` 作归属校验。

### 🟡 R3（建议改）：T4 分组覆盖键与旧语义核对

**问题**：T4 `POST /ai-agent-groups/override`（upsertOverride）key 唯一，但旧 `_groups.json` 的 override 键语义（role 名/agent 名）未在方案中明确，可能覆盖范围理解偏差。

**建议**：方案补充 `override.key` 的取值域说明（对齐旧 `_groups.json` 键），并在 T4 §4.3 schema 注释明确。

### 🟡 R4（建议改）：T5 版本清理与查询的并发边界

**问题**：T5 `appendVersion` 内 `DELETE` 清理旧版本，但 `listVersions` 查询与清理可能并发（查询读到清理前状态），且清理条件 `version_no < current - 50` 依赖 current 已更新。

**建议**：清理与查询在同一事务（清理后查询）；`DELETE` 条件改为 `version_no <= (SELECT MAX(version_no) FROM agent_version WHERE agent_id=?) - 50`，保证清理只删确实超出 50 的旧行。

## 一、评审结论

**评审结论：有条件通过（Conditional Pass）**——收尾四任务的门禁链（T12→T13→T14→T15）设计正确、风险应对合理，但存在 **7 处需修正项**（4 项必改、3 项建议改）。

其中 **R2 为实质缺陷**：T13 的「双写比对 + 回滚开关」在新架构**无实现基础**（新侧从未写 JSON，`LEGACY_WRITE_ENABLED` 机制在代码库中不存在），须重写该阶段语义，否则编码时会造出一个永远无法触发的开关。

## 四、修正项

| # | 级别 | 任务 | 问题 | 修正 |
|---|---|---|---|---|
| **R1** | 🔴 必改 | T12 | `legacy-verify.ts` 运行参数未定义；`--source ./data` 抄自 T11 迁移脚本参数表，校验脚本自身 CLI 契约缺失 | 补 T12 校验脚本参数表：`--source <旧 data 目录>`（必填）、`--report <输出 md 路径>`（默认）、`--strict`（任一差异即 exit 1，供 CI 门禁）；并声明 exit code 语义（0=通过 / 1=有差异 / 2=执行错误） |
| **R2** | 🔴 必改 | T13 | **双写比对与回滚开关无实现基础**：新侧从未写 JSON，`LEGACY_WRITE_ENABLED` 在代码库不存在；且「不可逆操作」与「秒级回滚」语义自相矛盾 | 重写 P2/P3 语义：**取消「双写」**，改为「P0 冻结旧 Flask 写入进程 → P1 新侧只读 PG + 旧侧只读 JSON 抽样比对 → P2 前端全量切新端点、旧服务降为只读 → P3 关停旧服务 → P4 观察」。回滚**不是开关**：定义为「重启旧 Flask 服务 + 旧 JSON 快照（T14 前保留）回切」，并**明示代价 = 迁移窗口内新增 PG 数据丢失**，回滚仅适用于观察期早期且须人工授权 |
| **R3** | 🔴 必改 | T14 | 「`app.py`（旧 Nest 入口）」事实错误——`app.py` 是旧 **Flask** 入口 | 更正为「`app.py`（旧 Flask 主入口，1570+ 行）」；删除清单须含 `app.py` 本身 + 其 `app.register_blueprint` 注册块 |
| **R4** | 🔴 必改 | T14 | 删除清单不全，且「分支级删除」判断错误 | ① 删除清单补齐：`app.py`、`modules/`（7 蓝图整目录）、`run_70_workflow` 所在 `modules/novel_creation/routes.py` 随目录一并删除、`data/*.json` **运行时读取代码**（保留 `.json` 文件作快照备份）；② 更正判断依据：新架构为 TS，无法 import Python 模块 → `work_manager.py` / `coze_client.py` **整文件删除**，无需「迁移复用分支」（复用须先迁到 TS） |
| **R5** | 🟡 建议 | T13 | P1「灰度读」缺**分流主体**定义：新旧是两套独立进程，无统一流量入口，「灰度」由谁分流未定义 | 明确灰度主体 = **前端路由开关**（React 按用户白名单指向新 API 或旧 API），灰度期间新旧同时可读但**仅新侧接受写入**；灰度粒度为「用户级」，非「请求级」 |
| **R6** | 🟡 建议 | T12 | 「抽样 key 字段比对 100% 一致」未定义抽样范围与比例，无法执行、无法复现 | 定义：**全量比对**主键映射域（`work_id`/`agent_id`/`character_id`/`chapter_id`）；抽样比对非主键字段（title/content 长度、model_config），比例 10% 且**固定随机种子**保证可复现；报告须列种子值 |
| **R7** | 🟡 建议 | T13 | P0「旧服务停止接受写入，停止旧后台任务」缺执行步骤与责任人，实际落地会卡在「谁停机」 | 补 P0 执行步骤：① 公告停机窗口 → ② 停旧 Flask 进程 → ③ 停旧后台任务（定时任务/队列消费者）→ ④ 确认 `data/` 目录最后写入时间不再变化（校验方式）→ ⑤ 记录停机时刻到验收报告。须指定执行人与回切授权人 |

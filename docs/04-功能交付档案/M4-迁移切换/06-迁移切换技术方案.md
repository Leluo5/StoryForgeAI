## 一、目标

## 二、现状与约束分析

### 2.1 旧实现语义（agent_store.py / agent_service.py）

| 能力 | 旧实现 | 关键语义 |
|---|---|---|
| 版本号 | `version_no` 递增，创建=1 | 每次变更 +1 |
| 版本列表 | `versions` 数组，`_snapshot(agent, action, note)` | 含 action/note/时间戳 |
| 版本上限 | `versions[-MAX_VERSIONS:]`（MAX_VERSIONS=50） | 保留最近 50 |
| 归档 | `status='archived'` + `archived_at` | 版本快照 action=archive |
| 恢复 | `archived_at=None` + `status='active'` | 版本快照 action=restore |
| 回滚 | 找 `version_no` 目标 → 覆盖当前配置 → 写新版本（`action=rollback`） | **回滚写新版本，不覆盖原版本** |
| 工具开关 | `switch_tool_default` 设 `is_default=true`，同 tool_name 其他置 false | **互斥**：同工具同时只有一个默认 |

### 2.2 硬约束

1. **版本保留上限**：`versions` 保留最近 50，超出截断（`slice(-50)`）。
2. **回滚写新版本**：回滚产生新 `version_no`，历史不丢失（回滚点可再回滚）。
3. **工具默认互斥**：同一 `tool_name` 同时只有一个 `is_default=true`。
4. **快照不可变**：`snapshot` 字段不随 agent 变更（历史留痕）。

## 三、设计决策（多方案对比）

### 决策 1：版本存储 —— 单表 jsonb vs 独立版本表

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. `agent.versions` jsonb 数组（复刻旧） | 简单、对齐旧语义 | 大文档、并发写整表 | ○ 折中 |
| **B. 独立 `agent_version` 表** | **版本历史独立、可查询、并发友好** | 需迁移/查询逻辑 | **✅ 推荐** |

**推荐 B**：新建 `agent_version` 表（每版本一行），`agent` 表保留当前配置 + `current_version_no`。回滚/归档/恢复/更新均插入新版本行，`agent.current_version_no` 指向最新。查询版本列表直接查表。

### 决策 2：回滚语义 —— 覆盖当前 vs 写新版本

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 覆盖当前配置 | 简单 | 回滚点丢失 | ✗ |
| **B. 写新版本（复刻旧）** | **回滚点可再回滚、历史完整** | 版本数增长 | **✅ 推荐** |

**推荐 B**：回滚 = 读目标版本 snapshot → 写为新 `agent_version` 行（action=rollback）+ 更新 `agent.current_version_no`。与原版本不冲突。

### 决策 3：工具开关互斥 —— 应用层 vs DB 约束

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 应用层事务内更新（复刻旧） | 简单 | 并发下竞态 | ○ 折中 |
| **B. 应用层事务 + 部分唯一索引** | **DB 层防并发双默认** | PG 部分索引 `WHERE is_default` | **✅ 推荐** |

**推荐 B**：`tool_agent` 表加部分唯一索引 `(tool_name) WHERE is_default AND kind='tool_agent'`，DB 层保证同工具单默认；事务内先清旧默认再设新默认。

| 字段 | 类型 | 必填 | 说明 |

### 4.3 核心逻辑（AgentVersionService）

#### 快照写入（所有版本变更共用）

```ts
async appendVersion(agentId, action, note, snapshot): Promise<AgentVersionEntity> {
  return this.dataSource.transaction(async (tx) => {
    // 1. 取当前最大 version_no + 1（agent 内递增）
    const last = await tx.getRepository(AgentVersionEntity).createQueryBuilder('v')
      .select('MAX(v.version_no)', 'max').where('v.agent_id = :agentId', { agentId }).getRawOne();
    const nextNo = (last?.max ?? 0) + 1;
    // 2. 插入新版本行（snapshot 不可变）
    const version = await tx.getRepository(AgentVersionEntity).save({
      agent_id: agentId, version_no: nextNo, action, note, snapshot
    });
    // 3. 更新 agent.current_version_no = nextNo
    await tx.getRepository(AgentEntity).update(agentId, { current_version_no: nextNo });
    return version;
  });
}
```

#### 回滚（写新版本，决策 2）

```ts
async rollback(agentId, targetVersionNo): Promise<AgentVersionEntity> {
  return this.dataSource.transaction(async (tx) => {
    // 1. 读目标版本 snapshot（不存在 404）
    const target = await tx.getRepository(AgentVersionEntity).findOne({
      where: { agent_id: agentId, version_no: targetVersionNo }
    });
    if (!target) throw new NotFoundException(`版本不存在: ${targetVersionNo}`);
    // 2. 目标 snapshot 写回 agent 当前配置
    await tx.getRepository(AgentEntity).update(agentId, {
      ...target.snapshot, current_version_no: target.version_no
    });
    // 3. 写新版本（action=rollback，note 标记目标）
    return this.appendVersion(agentId, 'rollback', `rollback to ${targetVersionNo}`, target.snapshot);
  });
}
```

#### 版本保留上限（决策 1）

> 评审修正 R4：清理与查询在同一事务（清理后查询，避免并发读到清理前状态）；清理条件改为 `version_no <= (SELECT MAX(version_no) FROM agent_version WHERE agent_id=?) - 50`，保证只删确实超出最近 50 的旧行（不依赖 current 更新时序）。

`appendVersion` 后清理：删除该 agent 超出最近 50 的旧版本行（`DELETE WHERE agent_id AND version_no <= (SELECT MAX(version_no) FROM agent_version WHERE agent_id=?) - 50`）。用独立表 + 上限清理，替代旧 `versions[-50:]` 数组截断。

#### 工具开关互斥（决策 3）

```ts
async switchToolDefault(projectId, toolName, agentId): Promise<void> {
  return this.dataSource.transaction(async (tx) => {
    // 1. 同 tool_name 全部清 is_default=false
    await tx.getRepository(ToolAgentEntity).update(
      { tool_name: toolName, kind: 'tool_agent' }, { is_default: false });
    // 2. 目标置 is_default=true（部分唯一索引兜底防并发双默认）
    await tx.getRepository(ToolAgentEntity).update(agentId, { is_default: true });
  });
}
```

## 五、边界与安全

| 项 | 处理 |
|---|---|
| 版本上限 | 独立表 + 上限清理（保留最近 50），替代旧数组截断 |
| 回滚幂等 | 每次回滚写新版本，回滚点不丢失；`version_no` 目标不存在 404 |
| 快照不可变 | snapshot 写入后只读，agent 变更不修改历史行 |
| 工具互斥 | 部分唯一索引 `(tool_name) WHERE is_default`，DB 层防并发双默认 |
| 归属校验 | 沿用 agent 服务（authorId → project → agent 归属），controller 透传 |
| 鉴权 | `SessionGuard` + 写操作 `CsrfGuard` |
| 输入校验 | `rollbackAgentSchema`（version_no）/ `switchToolSchema`（agent_id） |

## 七、验收标准

| # | 验收项 | 通过标准 |
|---|---|---|
| 1 | 版本快照 | 创建/更新/归档/恢复/回滚均产生版本行，snapshot 不可变 |
| 2 | 版本上限 | 版本数 > 50 时仅保留最近 50（单元测试：51 次变更后 50 行） |
| 3 | 回滚写新版本 | 回滚后 version_no+1，回滚点可再回滚，原版本不丢失 |
| 4 | 工具互斥 | 同 tool_name 切默认后仅一个 `is_default=true`；并发切默认不产生双默认（DB 索引兜底） |
| 5 | 归档/恢复 | archive 后 status=archived，restore 后 active，均产生版本行 |
| 6 | 契约层 | `rollbackAgentSchema`/`switchToolSchema` 测试通过 |
| 7 | 回归 | 单元 + E2E（PG）通过，CI 全绿 |

## 八、风险与应对

| 风险 | 应对 |
|---|---|
| 独立表迁移复杂 | M4-T11 处理旧 `versions` 数组 → 表行；本任务仅新表结构 |
| 部分唯一索引并发 | 事务内清旧设新 + 索引兜底，冲突捕获返回 409 重试 |
| 版本清理边界 | 上限清理在 `appendVersion` 事务内，防并发超限（`DELETE` 条件 `version_no < current - 50`） |
| 快照不可变被误改 | snapshot 列只读（应用层不更新），查询仅 select |

## 三、设计决策落地核对

| 决策 | 方案结论 | 实现 |
|---|---|---|
| 决策1 pull 数据源 | B. 经 `ChatRoomService` 读 history | `getHistory` + `getCreatedAt`，按 `step_no` 过滤去重 |
| 决策2 push 语义 | B. 返回节点 + 注入 `chat_room.context` | `updateContext` 写 `context.context_node_ids`；返回 `{injected, context_nodes}` |
| 决策3 去重键 | B. room_id + step_no 复合键（评审 R3） | `attributes.sync_room_origin = sync-room:${roomId}:${stepNo}` 判重 |

### 关键实现细节

- **origin 存储位置偏离（须说明）**：评审 R3 要求 pull 回写节点 `origin = sync-room:${roomId}:${step_no}` 全标记写入 `plot_nodes.origin` 列，但该列为 `varchar(16)` 且带 CHECK 约束 `CHECK (origin IN ('manual','derivation','outline','novel_text','import'))`，全标记无法写入。**最小侵入方案**：`origin` 列保留枚举值 `'derivation'`，全标记改存 `attributes.sync_room_origin`（jsonb，已扩展 `plotNodeAttributesSchema` 支持 `sync_room_origin: z.string().trim().max(200).optional()`，schema 保持 `.strict()`）。
- **非法 action 判定下沉 service**：验收标准 5 要求「非法 action → 400」，而 `ZodValidationPipe` 对 schema 校验失败返回 422。`syncRoomSchema.action` 用宽松 `z.string().trim().min(1).max(16)`（契约层只做格式校验），另导出 `syncRoomActionSchema = z.enum(['push','pull'])`，由 `PlotRoomSyncService` 用 `safeParse` 二次判定，非法值抛 `BadRequestException('联动动作非法，允许：push / pull')`（对齐旧语义 400）。
- **push 语义**：`context_node_ids` 缺失节点抛 409（`getNodesByIds` 校验）；注入用 `updateContext`（房间行锁事务内写 `context.context_node_ids`），不阻塞 LLM。
- **pull 去重键**：以 `attributes.sync_room_origin = sync-room:${roomId}:${stepNo}` 判重，规避房间 history 清空重建（step_index 归零）后 step_no 复用误判——评审修正 R3。
- **批量回写父环校验**：`batchCreateSyncNodes` 中回写节点统一挂到同一父节点下，新增边本身不构成环（本批节点尚无 id），但若父节点父链自身成环（脏数据），沿链上溯会无限循环——用 `seen` 集合沿父链上溯判环，成环抛 `UnprocessableEntityException({ code: 'PLOT_PARENT_CYCLE' })`（422）；父节点缺失抛 `NotFoundException('父节点不存在')`（404）。
- **pull 单事务批量回写**（评审 R5）：`batchCreateSyncNodes` 在单事务内完成「判重查询 → 父环校验 → 顺序创建 → 版本递增 → 审计」，失败整体回滚，避免半写。
- **树与作品 1:1**：新架构树与作品 1:1，controller 端点用 `works/:workId/plot-tree/sync-room/:roomId`，`treeId` 传空字符串由 `assertTreeOwned` 按作品定位（对齐 T2 端点风格）。

## 四、验收结果

### 4.1 契约测试

`pnpm --filter @storyforge/contracts test` → **15 用例全绿**（含新增 2 个）：

- `syncRoomActionSchema`：`'push'` / `'pull'` 合法，`'explode'` 非法
- `syncRoomSchema`：合法 push/pull 负载通过；契约层宽松（action 语义由 service 判定）
- `plotNodeAttributesSchema` 严格模式接受 `sync_room_origin`（≤200），超长拒绝

### 4.2 E2E（真实 PG）

`pnpm vitest run apps/api/test/plot-room-sync.e2e-spec.ts` → **7 用例全绿**：

1. push 注入 context nodes 并更新房间 context
2. push 缺失 context node → 409 且不注入
3. pull 回写 history 步骤为新节点（含 `sync_room_origin` 全标记）
4. pull 按 `sync_room_origin` 去重（重复 pull 不重建）
5. 非法 action → 400
6. 跨作者作品 → 404
7. 未认证 401 / 无 CSRF 403

### 4.3 全量门禁

`pnpm ci` → **全绿**（contracts build + lint + typecheck + 全量单测 + 全量 e2e + build，exit 0；单测 201 文件 / 1877 用例全过）。

> 过程中发现并修复 **T2 遗留 DI 装配缺陷**：`ChatRoomController` 构造器用裸类型注入（`private readonly chatRoomService: ChatRoomService`，无 `@Inject`），导致 `createRoom` HTTP 端点的 `chatRoomService` 注入为 `undefined`（`TypeError: Cannot read properties of undefined (reading 'createRoom')`，e2e 创建房间 500）。T2 单测走 `new ChatRoomService(...)` 不经 DI 容器，故未暴露。为与全库一致，给 `ChatRoomController` 构造器参数补 `@Inject(ChatRoomService)` / `@Inject(ChatRoomSseService)` 后，全部 e2e 恢复绿。

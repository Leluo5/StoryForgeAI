> 版本：v1.0 · 状态：与实现同步（2026-11-27）
> 项目：StoryForgeAI —— 专业小说 AI 写作软件
> 所属里程碑：M4 迁移切换｜任务：M4-T11（旧数据映射迁移脚本，数据层）
> 对应方案：[13-迁移切换技术方案.md](./13-迁移切换技术方案.md)
> 实现依据：`apps/api/src/database/legacy-mappers/*.ts`（本表与代码字段一一对应）
> 说明：本表以**真实数据源**为准（用户已确认「按真实数据实现」）。旧数据源顶层扁平 `_agents.json`/`_roles.json`/`_relations.json`/`_knowledge_base.json`/`_workflows.json` 等**均不存在**，实际分布在 `data/projects/`、`data/agents/`、`data/workflows/`、`data/works/`。

## 〇、全局映射规则

### 0.1 ID 映射（核心：保证跨表关联完整）

| 旧 ID 形态 | 新 ID 生成方式 | 说明 |
|---|---|---|
| 合法 UUID（8-4-4-4-12 连字符） | 直接沿用 | 无需映射 |
| 非 UUID（本项目全部为 32 位 hex，如 `31601c93...`） | `uuidFromHash(\`${domain}:${legacyId}\`)` | SHA-256 前 16 字节 → UUID v5 风格，确定性稳定 |

所有新旧 ID 映射落 `legacy_id_map(domain, legacy_id, new_id)` 表，`(domain, legacy_id)` 唯一。**该表迁移后保留**，用于审计与追溯。

> 关键点：旧 `project.id`、`role.id`、`plot.id`、`agent.id`、`workflow.id` 均为 **32 位 hex 非 UUID**，统一走 `uuidFromHash` 确定性路径。domain 隔离同名旧 ID（如 `character` 与 `work` 的 32 位 hex 不同域互不冲突）。

### 0.2 域清单（迁移顺序 = 父域先迁）

| 顺序 | 域 | 旧数据源 | 新表 |
|---|---|---|---|
| 0 | author（兜底） | 无旧数据，创建迁移专用作者 | `author` |
| 1 | work | `data/projects/*.json`（作品本体）+ `data/works/*.json`（Coze bot 配置回挂） | `work`（volume/chapter 数据源为空，不产生行） |
| 2 | agent | `data/agents/<projectId>/*.json` | `ai_agents` + `agent_version` |
| 3 | character | `data/projects/*.json` 的 `roles[]` + `roles[].relations[]` | `characters` + `character_relations` + `character_relation_types`（补种） |
| 4 | plot | `data/projects/plot/*.json` | `plot_trees` + `plot_nodes`（links 兼容，实际为空） |
| 5 | workflow | `data/workflows/_global/*.json` | `ai_workflows` |

### 0.3 幂等规则（全域统一）

- 每个实体写入前先 `resolveNewId(tx, domain, legacyId)` 得到新 UUID，再按该 UUID 查目标表。
- 已存在 → `skipped`（不重复插入），**不覆盖**旧数据。
- 迁移脚本可重复执行：重复运行只补漏，不产生重复数据。

### 0.4 关系类型归一（M3c-2 默认种子）

| 旧 `relation_type` | 新 `code` | 说明 |
|---|---|---|
| `ally` | `camp_ally` | 结盟 |
| `enemy` | `camp_hostile` | 敌对 |
| 其他未识别 | 原值（若命中种子则用，否则跳过） | 不落孤儿外键 |

## 一、author 域（兜底作者）

**旧数据无 author 概念**（`project.author` 为空字符串）。`work.author_id`/`agent.author_id`/`workflow.author_id` 均非空必填，故迁移时创建**一个**迁移专用兜底作者并复用其 id（幂等，按 `email` 查重）。

| 新表字段 | 值 | 说明 |
|---|---|---|
| `author.id` | `resolveNewId('author', 'author:legacy-migrate')` | 确定性 UUID |
| `author.email` | `legacy-migrate@local` | 查重键，幂等 |
| `author.display_name` | `迁移用户` | 标识迁移来源 |
| `author.password_hash` | `!legacy-migrate!` | 不可登录哨兵（非真实密码） |

## 五、plot 域

### 5.1 数据源

`data/projects/plot/<id>.json`（剧情树，1 个）。**无显式 `work_id`/外键**，需按 project 关联推断归属。

### 5.2 归属推断规则（`inferPlotWorkId`）

1. 遍历 `data/projects/*.json`；若 plot 任一 `nodes[].role_id` 命中某 project 的 `roles[].id` → 归属该 project。
2. 否则若全局**唯一** project → 归属之。
3. 仍无法判定 → `undetermined`（跳过，**不落孤儿外键**）。

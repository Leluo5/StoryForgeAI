## 五、实现过程中的关键问题与解决

### 问题 1：`agent_version already exists`（跨测试文件残留）

**现象**：`agent.service.test.ts` 29/30 失败，迁移 `AgentVersionTable1761300000000` 报 `relation "agent_version" already exists`。

**根因**：`dropWritingAndAuthTables`（`test-database.ts`）未将新增 `agent_version` 表加入 DROP 列表 → 跨测试文件残留 → 重跑 `runMigrations()` 时 `CREATE TABLE` 撞已存在表。

**解决**：
1. `test-database.ts` 在 `DROP TABLE IF EXISTS ai_agents CASCADE` 前加 `DROP TABLE IF EXISTS agent_version CASCADE`（FK 依赖，先删引用表）；
2. 迁移 up 的 `CREATE TABLE`/`CREATE INDEX` 加 `IF NOT EXISTS` 幂等保险。

### 问题 2：provision / rollback 事务内 FK violation 或读不到快照

**现象**：`agent-mgmt.e2e-spec.ts` 2 失败——provision 500（FK violation）、rollback 404（快照读不到）。

**根因**：`appendVersion`/`getSnapshot` 用 `this.dataSource.transaction` 开**独立新事务**；而 provision/rollback 调用方已在外层 `manager` 事务内，独立新事务读不到外层**未提交**的 `ai_agents` 行 → FK violation；rollback 同理读不到同事务内刚写的版本行。

**解决**：`appendVersion`/`getSnapshot` 增加可选 `EntityManager` 参数，传入则复用该事务（不新开）。全部 6 处业务调用方（create/update/archive/restore/rollback/provision×3）均传外层 `manager`。

### 问题 3：旧 `createAgent` 不写初始版本 → 回滚 404

**现象**：rollback 到 v1 返回 404（`getSnapshot` 为 null）。

**根因**：e2e `createAgent` helper 走旧 `POST /ai-agents` → 旧 `createAgent` 方法，未接入 `appendVersion`，故无 v1 版本行。

**解决**：旧 `createAgent` 补 `agent.version_no = 1` + `appendVersion(..., 'create', ...)`（与 V2 创建语义一致）。同时 `agent.service.test.ts` 的 mock 构造注入真实 `AgentVersionService`（原为裸 `{}` mock，会因新调用抛错）。

## 六、迁移说明（`1761300000000-agent-version-table`）

`up`：
1. `CREATE TABLE IF NOT EXISTS agent_version`（FK `agent_id → ai_agents(id) ON DELETE CASCADE`，`uq_agent_version_agent_no (agent_id, version_no)` 唯一，`idx_agent_version_agent_created (agent_id, created_at)`）；
2. DO $$ 块遍历旧 `ai_agents.versions` jsonb 数组 → 插 `agent_version` 行（`ON CONFLICT DO NOTHING`，`action=COALESCE(change_type,'update')`）；
3. 重建 `uq_ai_agents_author_default` → `(author_id) WHERE is_default AND kind='legacy'`；
4. `ALTER TABLE ai_agents DROP COLUMN IF EXISTS versions`。

`down`：加回 `versions` jsonb（聚合回数组）+ 恢复旧索引（`WHERE is_default`）+ `DROP TABLE IF EXISTS agent_version`。

> 旧 `versions` 数组数据在 up 中迁移为独立表行，`agent.version_no` 对齐各 agent 最新行。

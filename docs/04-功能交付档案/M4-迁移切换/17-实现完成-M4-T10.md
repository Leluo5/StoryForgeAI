## 一、交付概览

将旧架构 `coze_client.get_workflow_list`（`modules/workflow_management/workflow_service.import_coze_workflow`）的 Coze 工作流导入能力迁移到新 NestJS 架构：
`GET /v1/workflows`（拉取列表）、`POST /admin/coze/workflows`（列表端点）、`POST /admin/coze/import-workflow`（导入端点，落 `WorkflowEntity`）。

F1 已迁移 bot/dataset 两类资源，本任务补齐工作流资源线，实现 Coze 三类资源（bot/dataset/workflow）导入全齐。

## 二、关键实现决策

| # | 决策点 | 落地 |
|---|---|---|
| 1 | client 方法名 | **`get_workflows`**（snake_case，对齐旧 `coze_client.get_workflow_list` 与任务规划完成标准字面），非 `listWorkflows` |
| 2 | 列表端点语义 | `/admin/coze/workflows` 调 `listWorkflowResources`（**仅触发 `/v1/workflows`**，不调用 bot/dataset），避免 `listResources` 三路合并导致无关 Coze 请求 |
| 3 | 导入幂等 | 按 `platform_config->>'workflow_id'` + `author_id` + `archived_at IS NULL` 查重（jsonb 操作符），已存在 → `duplicate` 不落库；未命中列表 → `not_found` |
| 4 | 导入列表拉取 | `get_workflows` 按作者全量拉取（不限定 Coze workspace）；导入时挂到本地作品 `work_id`（可空），复用 F1 的 `work_id` 语义 |
| 5 | 响应包装 | 新端点 + 顺带修复 F1 端点均用 `ok()` 包装 `{data, request_id}`（对齐项目标准；F1 原为裸对象，前端 `apiRequest` 读 `json.data` 会拿 undefined） |
| 6 | 状态码 | POST 默认 **201**（与 F1 既有端点一致，无 `@HttpCode` 覆盖） |
| 7 | DI 注入 | 构造参数 `client` / `agentService` 显式 `@Inject`（本 tsconfig 无 `emitDecoratorMetadata` 可靠反射，裸注入 undefined → 500，同 M4-T7 问题 1 / T9 根因） |

## 五、实现过程中的关键问题与解决

### 问题 1：`CozeImportService` 注入 undefined → 500（e2e 首次 5 失败）

**现象**：e2e 首次运行 5 个用例报 500，堆栈 `Cannot read properties of undefined (reading 'listBots'/'get_workflows')`。

**定位**：`CozeImportService` 构造参数 `client` / `agentService` 为裸注入（无 `@Inject`），本 tsconfig 无 `emitDecoratorMetadata` 可靠反射 → 注入 undefined（同 M4-T7 问题 1 / T9 根因）。

**解决**：构造参数补显式 `@Inject(CozeImportClient)` + `@Inject(AgentService)`（import `Inject`）。重跑 e2e 通过。

### 问题 2：`/workflows` 端点误触发 bot/dataset 的 Coze 请求

**现象**：`lists only workflow resources` 报 500，`CollabUpstreamError: Coze 请求失败: Cannot read properties of undefined (reading 'ok')`——`/workflows` 端点复用 `listResources`（三路合并），而 e2e 只 mock 了 1 次 fetch，bot/dataset 未 mock 返回 undefined。

**定位**：`/workflows` 复用 `listResources` 会触发 bot/dataset 的 Coze 请求，不符合「只拉工作流」语义。

**解决**：新增 `listWorkflowResources`（仅调 `get_workflows`），controller `/workflows` 端点改用之。

### 问题 3：POST 默认 201 与 e2e 断言 200 冲突

**现象**：`imports selected workflows` 等 4 用例报 `expected 200, got 201`。

**定位**：`/import-workflow` 端点无 `@HttpCode`，POST 默认 201（与 F1 既有 `list`/`import` 一致）。

**解决**：e2e 断言改为 201（保持与 F1 一致，不新增 `@HttpCode(200)`）。

### 问题 4：F1 端点裸对象响应缺陷（用户确认顺带修复）

**现象**：F1 既有 `/admin/coze/list`、`/admin/coze/import` 端点直接返回裸对象（`{resources}` / `{total,imported,results}`），未用 `ok()` 包装；前端 `apiRequest` 读 `json.data` 拿到 undefined → Coze 导入面板实际失效。

**定位**：F1 技术方案文档约定裸对象响应，与项目标准（`ok()` 包装 `{data, request_id}`）不一致。

**解决**：经用户确认，顺带修复 F1 `list`/`import` 端点加 `ok()` 包装；同步更新 F1 技术方案响应约定（见 §六）。

## 二、关键实现决策

| # | 决策点 | 落地 |
|---|---|---|
| 1 | 运行执行语义 | **本地实体 + ai-task 队列**（用户决策，非 Coze 透传）。`POST /ai-workflows/:workflowId/run` 创建 `scope='workflow_run'` 任务并入队，202 返回 `aiTaskId` |
| 2 | 运行端点归属 | **作者级 `ai_workflows` 域**（用户决策）：`/ai-workflows/:workflowId/run`，非任务规划 §2.7 字面的 `/works/:workId/workflow/run` |
| 3 | 作品归属 | **`ai_workflows` 表加 `work_id` 列**（用户决策，改表），迁移新增可空列；运行任务携带 `work_id`，无作品为空 |
| 4 | 上游配置来源 | **`platform_config.workflow_id`**（方案 v1.1 引用的 `node_ids`/`order` 列实体不存在，v1.2 修正）。缺失 → 409 |
| 5 | 上游调用 | `CozeImportClient.runWorkflow` → `POST /v1/workflow/run`（非流式），`code!==0` → `upstreamFailedError`（不可重试，防死循环） |
| 6 | 失败语义 | 上游错误映射 `CollabUpstreamError`；processor `markFailed` 将其 `code/retryable` 落库并写 failed 事件 |
| 7 | 上传存储 | **内存存储**（`memoryStorage`，范本 knowledge）+ 落盘 `uploads/works/<workId>/`，临时文件写后 `rename` |
| 8 | 上传校验 | 白名单 20 类扩展名 / 5MB 上限（`buffer.length` 判定）/ 防路径穿越；非法类型 400、超限 413、空名 400 |
| 9 | 上传响应 | `202` 返回 `{work_id, count, files:[{name,path,size,ext}]}`（同 knowledge 上传范式） |
| 10 | DI 注入 | 构造参数 `DataSource`/业务 service 一律显式 `@Inject(...)`（本文件无 `emitDecoratorMetadata`，缺注会注入 undefined → 500） |

## 五、实现过程中的关键问题与解决

### 问题 1：`DataSource`/业务 service 注入 undefined → 500（两处）

**现象**：e2e 首运行用例与隔离运行用例报 500，堆栈 `Cannot read properties of undefined (reading 'getRepository')` / `(reading 'createWorkflowRunTask')`。

**定位**：`WorkflowRunService` 构造参数 `dataSource`、`aiTaskService` 均未加 `@Inject`。本 tsconfig 无 `emitDecoratorMetadata` 可靠反射，构造参数类型对 `DataSource`/业务 service 不可靠，缺 `@Inject` 注入为 undefined。

**解决**：两处补显式 `@Inject(DataSource)` / `@Inject(AiTaskService)`。重跑 e2e 15/15 全绿。

### 问题 2：无上游 `platform_config.workflow_id` 未校验

**现象**：实现最初未校验上游配置，缺配置也放行入队，与方案「缺失 → 409」不符。

**解决**：`runWorkflow` 补 `typeof platformConfig.workflow_id !== 'string' || trim()===''` → 409；binds work_id / status 流两测试用例补 `platform_config.workflow_id` 后通过。

### 问题 3：迁移 down SQL 语法错误

**现象**：`DROP INDEX IF EXISTS idx_ai_workflows_work ON ai_workflows(work_id)` 语法错误（PostgreSQL 不接受 `ON` 子句）。

**解决**：修复为 `DROP INDEX IF EXISTS idx_ai_workflows_work`；直接调用迁移类 up/down/up 验证通过，最终库为 up 态。

### 问题 4：typecheck 类型传播（work_id 可空）

**现象**：`work_id` 改 `string | null` 后，多处需 string 的位置报类型错误。

**解决**：`BaseProcessContext.workId` 移除、各具体 context 自行声明（`workflow_run` 为 `string | null`）；各分支补 `if (!task.work_id) throw` 断言；audit `work_id` 传 `?? undefined`；`plot-derivation` `AiTaskView.work_id` 兼容可空。

### 问题 5：e2e 上传用例 WorkEntity 创建

**现象**：上传用例需真实 `work` 记录，`save(create({...}))` 未设必填字段导致失败。

**解决**：用 `repo.save(repo.create({id, author_id, title, status:'active'}))` 完整字段。

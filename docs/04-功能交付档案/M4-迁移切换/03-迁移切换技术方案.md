## 一、目标

将旧 `plot/routes.py` 的 `sync-room` 双向联动端点（`POST /trees/<tree_id>/sync-room/<room_id>`，action=push/pull）迁移到新 NestJS 架构，使剧情树 ↔ 聊天室房间数据同步在新侧闭环。

**迁移后**：剧情树与 F6 聊天室房间（M4-T2 的 `chat_room` 表）的双向联动完全在新架构运行，不再依赖旧 Flask 进程。

---

## 二、现状与约束分析

### 2.1 旧实现（plot/routes.py §3.9 + plot_tree.py）

| 能力 | 旧实现 | 问题 |
|---|---|---|
| push | 树 → 推衍上下文注入：选择 `context_node_ids` 节点返回，实际注入由前端/聊天室完成 | 只返回节点，注入逻辑散落前端 |
| pull | 聊天室已提交推衍步骤 → 回写为新节点（去重） | 依赖 `story_thread.with_room` 内存房间，读取 `history` |
| 去重 | `pull_from_room` 内部去重（按 step_no） | 与新 PG 房间历史需重新对齐 |
| 校验 | 环路校验 + 原子性（先校验后写入） | 需复用新 `plot-cycle.ts` |

### 2.2 硬约束

1. **环路校验**：回写新节点必须保证线性无环 + 父环无环（`assertLinearAcyclic` / `assertParentAcyclic`）。
2. **原子性**：先校验后写入，失败不产生脏节点。
3. **去重**：pull 回写时同一 `step_no` 不重复创建节点。

### 2.3 新架构依赖（M4-T2）

- 房间数据已迁到 `chat_room` 表（含 `history` jsonb 承载已提交推衍步骤）。
- 房间操作经 `ChatRoomService`（`FOR UPDATE` 行锁），pull 读取房间 `history` 需经服务层或直接查表。

## 三、设计决策（多方案对比）

### 决策 1：pull 数据源 —— 直读 chat_room 表 vs 经 ChatRoomService

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 直读 `chat_room` 表 | 简单、少一层依赖 | 绕过服务层校验、跨模块耦合表结构 | ✗ |
| **B. 经 ChatRoomService 读 history** | **复用归属校验、封装表结构** | 需跨模块依赖 | **✅ 推荐** |

**推荐 B**：plot 模块依赖 `ChatRoomService`（模块导入 `ChatRoomModule`），pull 时调用其 `getHistory(roomId)` 获取已提交步骤，经服务层校验归属。

### 决策 2：push 语义 —— 只返回节点 vs 真正注入房间上下文

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 复刻旧：只返回 context 节点 | 简单、前端兼容 | 注入逻辑仍散落前端，未真正迁移 | ✗ |
| **B. 返回节点 + 注入 chat_room.context** | **上下文注入真正在新侧闭环** | 需扩展房间 context 更新 | **✅ 推荐** |

**推荐 B**：push 不仅返回 `context_node_ids` 对应节点，还通过 `ChatRoomService.updateContext(roomId, context_node_ids)` 将上下文节点 ID 注入房间 `context` 字段（对齐 M4-T2 `chat_room.context` 语义），前端不再自行拼装注入逻辑。

### 决策 3：去重键 —— step_no vs 内容 hash

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. step_no（复刻旧） | 简单 | step_no 可能跨房间冲突 | ○ 需 room 限定 |
| **B. room_id + step_no 复合键** | **跨房间不冲突** | 需复合查询 | **✅ 推荐** |

**推荐 B**：pull 去重按 `origin` 全标记（**评审修正 R3**：`sync-room:${roomId}:${step_no}`）判重。相比纯 `(room_id, step_no)` 复合键，origin 全标记在 `plot_node.origin` 唯一约束下判重更稳——房间 `history` 清空重建（`step_index` 归零）后同一 `step_no` 会被误判已存在，origin 全标记 + `created_at` 校验可规避（pull 仅回写房间创建后的步骤）。

## 四、模块设计

### 4.1 模块结构

复用现有 `plot` 模块，新增文件：

```

├── plot-room-sync.service.test.ts
└── plot-room-sync.controller.test.ts
```

依赖注入：`PlotRoomSyncService` 注入 `PlotOwnerService`（归属校验）+ `ChatRoomService`（读 history / 更新 context）+ `PlotTreeService`（节点写入）。`plot.module.ts` 导入 `ChatRoomModule`。

### 4.2 核心逻辑（PlotRoomSyncService）

#### push（树 → 房间上下文注入）

> 评审修正 R5：push 为「读节点 + 更新 context」单短事务（读操作 + 一次 context 更新，无长耗时不持锁）。

```ts
async push(authorId, workId, treeId, roomId, dto): Promise<PushRoomResult> {
  return this.dataSource.transaction(async (tx) => {
    // 1. 归属校验：tree ∈ work ∈ author + room ∈ work，否则 404
    await this.owner.assertOwnedTree(tx, authorId, workId, treeId);
    await this.chatRoom.assertOwnedRoom(tx, authorId, workId, roomId);
    // 2. 加载 context_node_ids 对应节点（存在性校验）
    const nodes = await this.treeService.getNodesByIds(tx, treeId, dto.context_node_ids);
    if (nodes.length !== dto.context_node_ids.length) throw new NotFoundException('上下文节点不存在');
    // 3. 注入房间 context（对齐 M4-T2 chat_room.context）
    await this.chatRoom.updateContext(tx, roomId, dto.context_node_ids);
    // 4. 返回节点（供前端渲染选择上下文）
    return { nodes: nodes.map(toNodeView) };
  });
}
```

#### pull（房间已提交步骤 → 回写为新节点）

```ts
async pull(authorId, workId, treeId, roomId, dto): Promise<PullRoomResult> {
  // 评审修正 R5：整体为「读 history + 批量回写」单事务（batchCreateNodes 内已含事务，复用其原子性）
  return this.dataSource.transaction(async (tx) => {
    // 1. 归属校验
    await this.owner.assertOwnedTree(tx, authorId, workId, treeId);
    await this.chatRoom.assertOwnedRoom(tx, authorId, workId, roomId);
    // 2. 读取房间已提交步骤（经 ChatRoomService，含归属校验；仅回写房间创建后的步骤）
    const history = await this.chatRoom.getHistory(roomId);
    const roomCreatedAt = await this.chatRoom.getCreatedAt(roomId);
    // 3. 转换为回写步骤（origin 全标记，R3：room+step_no，规避房间重建后 step_no 复用误判）
    const steps = history
      .filter(h => new Date(h.created_at) >= roomCreatedAt)
      .map(h => ({
        id: `sync-room:${roomId}:${h.step_no}`,
        label: `推衍第${h.step_no}步`,
        content: h.content,
        origin: `sync-room:${roomId}:${h.step_no}`
      }));
    // 4. 去重回写（origin 全标记判重，已存在跳过）
    const result = await this.treeService.batchCreateNodes(tx, treeId, dto.parent_node_id, steps, {
      dedupeBy: 'origin',
      // 环路校验：assertLinearAcyclic + assertParentAcyclic（复用 plot-cycle.ts）
      validate: this.cycleValidator
    });
    return { created: result.created, skipped: result.skipped };
  });
}
```

### 4.3 API 契约

复用 `plot.ts` 契约，新增 schema：

| 方法 | 路径 | 说明 | Zod schema |
|---|---|---|---|
| POST | `/trees/:treeId/sync-room/:roomId` | 双向联动（body: `{ action, context_node_ids?, parent_node_id? }`） | `syncRoomSchema` |

`schema`：
```ts
export const syncRoomSchema = z.object({
  action: z.enum(['push', 'pull']),
  context_node_ids: z.array(z.string()).optional(),
  parent_node_id: z.string().nullable().optional()
});
export type SyncRoomInput = z.infer<typeof syncRoomSchema>;
```

非法 action 抛 400「联动动作非法，允许：push / pull」（对齐旧语义）。

## 五、边界与安全

| 项 | 处理 |
|---|---|
| 归属校验 | tree 与 room 双归属校验（room ∈ work ∈ author），否则 404 |
| 环路校验 | 回写节点先 `assertLinearAcyclic` / `assertParentAcyclic`，失败不写入 |
| 去重 | `(room_id, step_no)` 复合键，已存在跳过（不抛错） |
| 注入一致性 | updateContext 与节点返回在同一事务，失败回滚 |
| 输入校验 | `ZodValidationPipe` + `syncRoomSchema` |
| 鉴权 | `SessionGuard` + `CsrfGuard`（写操作） |
| 幂等 | pull 重复调用不重复创建（origin 判重） |

## 七、验收标准

| # | 验收项 | 通过标准 |
|---|---|---|
| 1 | push 注入 | push 返回 context 节点 + 房间 `context` 更新为 `context_node_ids`（E2E） |
| 2 | pull 回写 | 房间 history 回写为新节点，`origin` 标记 `sync-room:${roomId}:${step_no}` |
| 3 | 去重 | 重复 pull 不重复创建（skipped > 0，created 不增长） |
| 4 | 环路校验 | 回写导致环 → 抛 422，无脏节点残留 |
| 5 | 非法 action | action 非 push/pull → 400 |
| 6 | 归属校验 | 非作者访问 → 404（E2E） |
| 7 | 契约层 | `syncRoomSchema` + 类型导出，contracts 测试通过 |
| 8 | 回归 | 单元 + E2E（PG）通过，CI 全绿 |

## 八、风险与应对

| 风险 | 应对 |
|---|---|
| 跨模块依赖 plot → ChatRoom | 模块导入 `ChatRoomModule`，`ChatRoomService` 显式导出 |
| 去重键跨房间冲突 | `(room_id, step_no)` 复合键 + origin 标记，避免撞键 |
| 环路校验失败致部分写入 | `batchCreateNodes` 事务内校验，失败回滚（复用 plot-tree.service 原子性模式） |
| 旧前端依赖旧 sync_room 响应格式 | 新端点响应结构对齐旧 `_ok(result)` 形态，前端渐进切换 |

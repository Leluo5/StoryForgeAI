## 一、目标

为已实现但无 HTTP 入口的服务层补齐端点，使 Agent 项目管理面（旧 `agent_management/routes.py` 23 端点）在新架构有对应入口。

**迁移后**：Agent 分组、版本回滚、工具开关、provision 默认流、进度追踪等能力在新侧可调用，不依赖旧 Flask。

1. **服务层不复写**：仅补入口，业务逻辑复用已有服务方法（AgentGroupService / AgentProvisionService / FlowProgressService）。

3. **契约层同步**：新增 schema + 类型需导出到 `packages/contracts`。

## 三、设计决策（多方案对比）

### 决策 1：端点组织 —— 复用 agent.controller vs 新建 controller

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 全部塞进 agent.controller | 文件少 | controller 过大（16+7 端点），职责杂 | ✗ |
| **B. 按域拆分 controller** | **职责清晰、可测** | 多文件 | **✅ 推荐** |

**推荐 B**：按域拆 3 个 controller——`AgentLifecycleController`（归档/恢复/版本/回滚）、`AgentGroupController`（分组树/覆盖/手动分组/设分组）、`AgentProvisionController`（provision/bind-roles/reset-default/progress/switch-tool）。现有 `AgentController`（7 端点）保持不动。

### 决策 2：路径前缀 —— 沿用旧 `/api` vs 新 `/ai-` 体系

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 沿用旧路径 | 前端零改动 | 与新 `/ai-*` 体系不一致 | ✗ |
| **B. 新 `/ai-*` 体系** | **契约统一、前端切新** | 前端需改 | **✅ 推荐** |

**推荐 B**：对齐现有 `ai-agents` / `ai-tools` 命名体系，新端点用 `/ai-agent-groups`、`/ai-projects/:projectId/...` 等，前端一次性切新（旧端点 cutover 前保留）。

## 四、模块设计

### 4.1 模块结构

```
apps/api/src/agent/
├── agent-lifecycle.controller.ts   # 归档/恢复/版本/回滚（AgentLifecycleController）
├── agent-group.controller.ts       # 分组树/覆盖/手动分组/设分组（AgentGroupController）
├── agent-provision.controller.ts   # provision/bind-roles/reset-default/progress/switch-tool（AgentProvisionController）
├── agent-lifecycle.controller.test.ts
├── agent-group.controller.test.ts
└── agent-provision.controller.test.ts
```

`agent.module.ts` 注册 3 个新 controller，并确保 `AgentGroupService` / `AgentProvisionService` / `FlowProgressService` 已导出（供注入）。

### 4.2 端点映射

| POST | `/ai-agents/:agentId/versions/:versionNo/rollback` | rollback | 版本回滚（写 `versions` 历史，保留最近 50） |

#### AgentGroupController

| 方法 | 路径 | 服务方法 | 说明 |
|---|---|---|---|

#### AgentProvisionController

| 方法 | 路径 | 服务方法 | 说明 |
|---|---|---|---|
| POST | `/ai-projects/:projectId/provision` | provisionProjectDefaults | provision 默认流 |

## 五、边界与安全

| 项 | 处理 |
|---|---|
| 归属校验 | 各服务方法内已含（authorId → 资源归属），controller 透传 `request.author.id` |
| 鉴权 | 全部 `SessionGuard`，写操作 `CsrfGuard` |
| 输入校验 | `ZodValidationPipe` + 对应 schema |
| 版本回滚幂等 | 回滚写新版本（不覆盖当前），`versions` 保留最近 50（数据结构设计 §3.7） |
| 分组一致性 | `setAgentGroup` 校验 group 存在，`upsertOverride` key 唯一 |
| 服务层复用 | 仅补入口，零业务逻辑重写（防「服务已实现无路由」陷阱误判） |

## 六、与 M4 其他任务的关系

- **依赖 M4-T5**：本任务补 Agent 入口，M4-T5 再迁工具开关 / 版本回滚的**具体端点**（`switch-tool` / `rollback` 已在本文档 4.2 列出，M4-T5 聚焦其细节）。实际上本任务与 M4-T5 部分重叠，编码时协同：本任务补全分组/provision/progress 面，M4-T5 聚焦工具开关 + 版本回滚。
- **M4-T1（缺口清点）**：本任务范围来自 M4-T1 缺口清单。
- **旧代码保留**：旧 `agent_management/routes.py` 保留至 M4-T13 cutover，前端先切新端点。

## 八、风险与应对

| 风险 | 应对 |
|---|---|
| 「服务已实现无路由」误判 | 按路由装饰器核对（M4-T1），本文档按服务方法逐项映射，不按服务类存在性 |
| 新 controller 与既有冲突 | 路径前缀 `/ai-*` 不与既有 `/ai-agents` 主路径冲突；`agent.module.ts` 注册顺序确认 |
| 服务层签名与 controller 参数不匹配 | 编码前逐方法核对签名（authorId, projectId 顺序），以服务方法实际签名为准 |
| 前端切新端点遗漏 | 每端点同步更新 React 调用，旧端点 cutover 前保留 |

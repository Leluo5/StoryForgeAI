## 二、任务明细

### 2.1 M4-T1 缺口清点（前置）✅ 已完成（2026-11-28，产出物 [M4-缺口清单.md](./M4-缺口清单.md)）

**目标**：对旧架构全部端点（`app.py` + 7 个 `modules/*/routes.py`）与新增点（`apps/api/src/**/*.controller.ts`）逐项比对，输出**精确未迁移缺口清单**，作为后续所有任务的范围依据。

**完成标准**：
- 用脚本/手工枚举旧架构所有 `@app.route` 与 Blueprint 路由（`app.py` 25 处 + `modules/` 各蓝图），登记到 `M4-缺口清单.md`。
- 与新增点 controller 逐项匹配，标注每个旧端点的状态：`已迁移` / `部分迁移` / `未迁移` / `弃用（设计变更）`。
- 输出缺口清单含：端点路径、方法、旧蓝图、功能归属、建议迁移目标 controller/service、风险等级。
- 重点核对**服务层已实现但无 HTTP 入口**的模块（AgentGroupService / FlowProgressService / AgentProvisionService）——按路由装饰器实际存在性判定，而非服务类是否存在。

**关键点**：清单是 M4-T2~T10 的唯一定义来源；漏一处 = 切换后丢一个功能。F6 聊天室（rooms CRUD/step/continue/stream，9 端点）是最大单项债务，需明确标注。

### 2.2 M4-T2 F6 聊天室房间模型迁移（数据层）✅ 已完成（2026-11-27，见 [17-实现完成-M4-T2.md](./17-实现完成-M4-T2.md)）

**目标**：把旧 `story_thread.py` / `plot sync-room` 的**房间模型**（rooms 的 CRUD / step / continue / stream，9 端点）迁入新架构，作为 M4 前置的最优先对象（它牵动 plot 同步 + novel_creation 协作多线）。

**完成标准**：
- 新架构新增 `chat-room` 模块：`chat-room.entity.ts`（房间表）+ `chat-room.service.ts`（CRUD / step / continue / stream 逻辑）+ `chat-room.controller.ts`（HTTP 入口）。
- 房间模型字段与旧 JSON 结构对齐：`id` / `project_id` / `roles[]` / `random_seed` / `step_index` / `branch[]` / `context` / `status`（running/paused/done）。
- stream 走 SSE（参考 `ai-task.sse.ts` 实现），逐步推进一步一断，支持 `continue` 续跑。
- 旧 `story_thread.py` 的房间逻辑被新 service 替代；旧代码保留（切换验证通过前不删）。

**关键点**：F6 房间是「一点阻塞多线」的最大项；stream 必须兼容旧前端长连接语义。

### 2.3 M4-T3 plot sync-room 端点迁移（接口层）✅ 已完成（2026-11-27，见 [17-实现完成-M4-T3.md](./17-实现完成-M4-T3.md)）

**目标**：把旧 `plot/routes.py` 的 `sync-room/<room_id>`（push_to_room / pull_from_room）迁入新架构，使剧情树与聊天室房间数据同步在新侧闭环。

**完成标准**：
- 新架构 `plot-tree` 模块新增 `sync-room` 端点：`POST /trees/:treeId/sync-room/:roomId`（push）+ `POST /trees/:treeId/pull-from-room/:roomId`（pull）。

**关键点**：此端点迁移后，plot ↔ room 数据同步完全在新侧运行，不再依赖旧 Flask 进程。

### 2.7 M4-T7 作品上传 / 工作流运行迁移（接口层）✅ 已完成（2026-11-27，见 [17-实现完成-M4-T7.md](./17-实现完成-M4-T7.md)）

**目标**：迁移 `works/<work_id>/upload`（作品上传）与 `works/<work_id>/workflow/run`（工作流运行）。

**完成标准**：
- 新架构新增 `POST /works/:workId/upload`（作品目录文件上传，参考 `knowledge` 上传实现）+ 工作流运行端点 `POST /ai-workflows/:workflowId/run`（作者级工作流域）。
- 工作流运行接入新 `WorkflowRunService`（经 ai-task 队列 scope=`workflow_run`，本地实体 + 队列执行，非 Coze 透传），替换旧 `workflow/run` 链路。
- 上传做类型 / 大小校验，错误 400/413（非法类型 400 `WORK_UPLOAD_TYPE_UNSUPPORTED`、超限 413 `WORK_UPLOAD_FILE_TOO_LARGE`）。
- 工作流运行：归档 409、未配置上游 workflow_id 409、非作者 404、返回 `aiTaskId` 入队。

**关键点**：upload 涉及文件落盘与访问码，需确认存储路径与权限模型；运行端点归属 ai_workflows 域（作者级），work_id 经 ai_workflows.work_id 列关联作品。

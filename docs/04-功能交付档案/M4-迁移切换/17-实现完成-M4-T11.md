## 二、关键实现决策

| # | 决策点 | 落地 |
|---|---|---|
| 1 | 数据源假设修正 | 技术方案假设的顶层扁平 `_agents.json`/`_roles.json`/`_relations.json`/`_knowledge_base.json`/`_workflows.json` 等**均不存在**；用户确认「按真实数据实现」，映射器以 `data/projects/`、`data/agents/<pid>/`、`data/workflows/_global/`、`data/works/` 为准 |
| 2 | ID 映射 | 决策 2 方案 A：旧 ID 若是合法 UUID 直接沿用，否则 `uuidFromHash(\`${domain}:${legacyId}\`)` 确定性生成并落 `legacy_id_map`（本项目旧 ID 全为 32 位 hex，统一 hash 路径） |
| 3 | 迁移执行方式 | 决策 1 方案 B：独立幂等脚本 `migrate-legacy-data.ts`（tsx 直接运行），不注册进 data-source migrations（结构迁移与数据迁移分离） |
| 4 | 旧数据无 author | 创建迁移专用兜底作者（`legacy-migrate@local`，`password_hash='!legacy-migrate!'` 不可登录哨兵），`ensureLegacyAuthor` 幂等按 email 查重 |
| 5 | plot 归属推断 | plot 文件无显式 `work_id`；`inferPlotWorkId` 按任一 `nodes[].role_id` 命中 `project.roles`，否则全局唯一 project 兜底，仍无法判定则跳过（不落孤儿） |
| 6 | 关系类型归一 | `RELATION_TYPE_MAP = { ally:'camp_ally', enemy:'camp_hostile' }`，每作品先 `seedCharacterRelationTypes`（幂等 ON CONFLICT DO NOTHING）补种 23 类，按 `code→type_id` 索引 |
| 7 | 迁移顺序 | 父域先迁：author（兜底）→ work → agent → character → plot → workflow |
| 8 | dry-run 事务 | dry-run 用**单事务执行全部域后统一回滚**（跨域 FK 引用需在回滚前可见，否则 character 域 seed 引用 work_id 失败），仅统计不写库 |
| 9 | 校验开关 | `verifyMigration(ds, sourceDir, compareRows)`：dry-run 传 `!opts.dryRun`（false）跳过行数对比（库未写入必然不匹配），仅查引用完整性 |
| 10 | 可测试性 | `migrate(opts, dataSource=AppDataSource)` 注入 DataSource，测试用 `createDataSource(testDatabaseUrl())` 独立实例 |

## 五、实现过程中的关键问题与解决

### 问题 1：Driver not Connected（集成测试首次失败）

**现象**：`migrate()` 内部使用 `AppDataSource` 单例，而测试用 `createDataSource(testDatabaseUrl())` 独立实例未连接。

**定位**：主脚本默认参数绑定单例，测试无法注入。

**解决**：`migrate(opts, dataSource=AppDataSource)` 增加注入参数，测试全部改为 `migrate(opts, ctx.ds)`。

### 问题 2：dry-run 角色域 FK 失败（`character_relation_types_work_id_fkey` 违反）

**现象**：dry-run 各域独立事务回滚，character 域 seed 引用 work_id，但 work 域已回滚导致 FK 失败。

**定位**：dry-run 需跨域 FK 引用在回滚前可见。

**解决**：dry-run 改为**单事务执行全部域后统一回滚**（抛 `{__rollback:true, results}` 强制回滚并携带统计）。

### 问题 3：id 保持原值断言失败（测试假设错误）

**现象**：测试期望 32 位 hex 旧 ID 原样沿用，但 `isUuid` 要求 8-4-4-4-12 连字符格式，32 位 hex 非 UUID → 实际走 hash 路径。

**定位**：实现正确（所有旧 ID 为 32 位 hex 非 UUID，统一走 `uuidFromHash` 确定性路径），测试假设错误。

**解决**：测试断言修正为 `roleA.id === uuidFromHash(\`character:${ROLE_A}\`)`。

### 问题 4：dry-run verify.ok 可能为 false

**现象**：dry-run 库空，行数对比必然不匹配。

**定位**：校验函数未区分 dry-run。

**解决**：`verifyMigration(ds, sourceDir, compareRows=true)` 增加开关，dry-run 传 `!opts.dryRun`（false）跳过行数对比，仅查引用完整性。

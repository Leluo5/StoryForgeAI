## 四、评审意见（修正项）

### 🔴 R1（必改）：T7 工作流运行与 T10 工作流导入的范围重叠

**问题**：T7 §一目标包含「作品导入」，T10 专做「Coze 工作流导入」，两者在「工作流导入写 `workflow` 实体」上重叠，编码时易产生两套导入路径。

**建议**：明确边界——
- **T10** 负责**从 Coze 拉取**工作流（`importWorkflows`，`source_type=workflow`）；
- **T7** 只负责**工作流运行**（`runWorkflow`，运行已有 `workflow` 实体）；
- T7 §一「作品导入」目标**删除**，移入 T10（T7 只保留工作流运行 + 运行进度查询）。

### 🔴 R2（必改）：T6 max_tokens 的 Zod boolean 校验不可达

**问题**：T6 §4.2 用 `z.number().int()...refine(v => typeof v !== 'boolean')`，但 Zod 的 `z.number()` 对 JSON 中的 `true`/`false` 会直接判 fail（`expected number, received boolean`），`refine` 永不可达，且报错信息不含「须为整数」语义。

**建议**：改用 `z.number().int().min(1).max(32768)` 直接依赖 Zod 原生校验（boolean 输入已被 `z.number()` 拦截）；如需明确报错，用 `z.number({ invalid_type_error: 'max_tokens 须为整数' })`。移除不可达的 `refine`。

### 🔴 R3（必改）：T8 commit 写图的目标实体未指明

**问题**：T8 §4.3 `commit` 调用 `writeGraph(authorId, work_id, input)`，但未指明写 `character` 表还是 `character_view_node` 表。旧 role_map 的「图谱」对应新架构 `character`（角色）+ `character_relation`（关系）+ `character_view_node`（版图节点），三表写入范围不明。

**建议**：明确 commit 写入范围——
- `characters[]` → `character` 表（角色实体）
- `relations[]` → `character_relation` 表（角色关系）
- `character_view_node` 仅在「版图可视化节点」需要时同步（可选）
在 T8 §4.3 补三表映射，避免编码歧义。

### 🟡 R4（建议改）：T9 detect-type 置信度阈值需对齐既有实现

**问题**：T9 §4.3 用 `rule.confidence < 0.6` 触发 LLM 兜底，但既有 `classify.ts` 的 `ClassifyResult` 是否含 `confidence` 字段未确认，且 0.6 阈值与既有 F5 知识库判定语义可能不一致。

**建议**：编码前核对 `classify.ts` 的 `ClassifyResult` 结构——若无 `confidence` 字段，改用「规则未命中（返回 `other`）」作为 LLM 兜底触发条件，而非硬编码阈值。T9 方案补此对齐说明。

### 🟡 R5（建议改）：T10 工作流编排节点映射 `mapWorkflowNodes` 未定义

**问题**：T10 §4.2 调用 `this.mapWorkflowNodes(detail)`，但 Coze 工作流编排（graph/nodes/edges）到平台 `workflow.node_ids` 的映射规则未定义，属关键转换逻辑缺口。

**建议**：补充映射规则——Coze `graph.nodes` → 平台节点（按 `node.type` 映射），`graph.edges` → `workflow.order`/依赖；无法映射的节点类型记 warning 并跳过。T10 §4.2 补此转换说明。

### 🟡 R6（建议改）：T11 迁移顺序与 T13 cutover 的冻结窗口需明确

**问题**：T11 §八提到「迁移期间只读旧数据」，但未与 T13 P0（冻结）衔接；若 T11 执行期间旧服务仍在写入，迁移数据会不一致。

**建议**：明确 T11 正式执行必须在 **T13 P0 冻结之后**（旧服务停止写入），dry-run 可在冻结前。T11 §二补充此时序约束，与 T13 P0 对齐。

## 一、目标

将旧架构「角色版图 AI 建图」能力完整迁移到新 NestJS 架构。旧能力含：源文本抽取角色/关系、预览确认、提交落库、AI 进度追踪。

**迁移后**：新侧可经 LLM 抽取角色与关系，三阶段（extract → preview → commit）确认式落库，不依赖旧 Flask。

---

## 二、现状与约束分析

### 2.1 旧实现语义（role_map_ai.py + routes_role_map.py）

| 阶段 | 旧端点 | 关键语义 |
|---|---|---|
| **extract** | `POST /api/role-map/ai/generate` | 源文本 → LLM 抽取 `characters[]`/`relations[]`，后台线程异步，返回 `task_id`（202） |
| **progress** | `GET /api/role-map/ai/progress` | 返回 `{stage, percent, done}`，stage 含 `extracting/previewing/committing/done/failed` |
| **commit** | `POST /api/role-map/ai/commit` | preview 确认后写库 + 置 `ai_generated=true` |

**抽取契约**（LLM 返回 JSON）：
- `characters[]`：`name/identity/nationality/faith/camp/race/profession/age/gender/attributes`
- `relations[]`：`from/to/relation_type/note`，**from/to 必须在 characters 中存在**（缺失丢弃 + warning）
- `characters` 至少 1 个，否则冲突（"AI 未识别到角色"）

**进度契约**（`role_map.ai_progress`）：`stage`/`percent`/`done`；`stage=done` 时置 `ai_generated` + `generated_at`。

### 2.2 硬约束

1. **三阶段确认式**：extract（异步）→ preview（待确认，不落库）→ commit（写库 + `ai_generated`）。
2. **关系完整性**：relations 的 from/to 必须在 characters 中，缺失边丢弃并记 warning。
3. **归属校验**：图谱属 `project_id`/`work_id`，经 `authorId` 归属校验。
4. **异步非阻塞**：extract 经后台线程/队列，返回 task_id。

## 三、设计决策（多方案对比）

### 决策 1：异步执行 —— 后台线程 vs ai-task 队列

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. Node `setImmediate` 后台线程（复刻旧） | 简单 | 多实例失效、进程重启丢任务 | ✗ |
| **B. ai-task 队列（复用）** | **跨实例、持久化、进度可查、SSE 推送** | 接队列成本 | **✅ 推荐** |

**推荐 B**：抽取经 ai-task 队列（kind=`role_map_extract`），`ai_progress` 复用 `FlowProgressService`，前端经 SSE 消费进度。对齐 M4-T7 工作流运行的队列模式。

### 决策 2：preview 存储 —— 内存 vs 持久化草稿表

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 内存（旧 `task_id → result`） | 简单 | 多实例/重启失效 | ✗ |
| **B. 持久化草稿表（`role_map_ai_draft`）** | **跨实例、可重连、可二次编辑** | 需建表 | **✅ 推荐** |

**推荐 B**：抽取结果存 `role_map_ai_draft` 表（draft 状态：`extracting/pending_confirm/committed/failed`），支持二次编辑后 commit。

### 4.2 数据模型

#### RoleMapAiDraftEntity（`role_map_ai_draft` 表）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | uuid PK | 是 | 草稿 ID（对齐 task_id） |
| `work_id` | uuid FK→work | 是 | 作品归属（author 校验） |
| `source_text` | text | 是 | 抽取源文本 |
| `source_label` | varchar | 否 | 来源标签 |
| `status` | enum | 是 | `extracting`/`pending_confirm`/`committed`/`failed` |
| `characters` | jsonb | 是 | 抽取角色数组 |
| `relations` | jsonb | 是 | 抽取关系数组 |
| `warnings` | jsonb | 否 | 丢弃边的 warning |
| `ai_progress` | jsonb | 是 | `{stage, percent, done}` |
| `ai_generated` | bool | 是 | commit 后置 true |
| `generated_at` | timestamptz | 否 | commit 时间 |
| `created_at`/`updated_at` | timestamptz | 是 | |

索引：`(work_id, status)`。

### 4.3 核心逻辑（RoleMapAiService）

#### extract（异步，决策 1）

```ts
async extract(authorId: string, workId: string, input: { source_text: string; source_label?: string })
  : Promise<{ draftId: string }> {
  const work = await this.assertOwnedWork(authorId, workId); // 归属校验
  if (!input.source_text?.trim()) throw new BadRequestException('抽取源文本不能为空');
  // 创建草稿（status=extracting）+ 创建 ai-task 入队
  const draft = await this.createDraft(workId, input);
  const task = await this.aiTaskService.create({
    kind: 'role_map_extract', draft_id: draft.id,
    payload: { source_text: input.source_text, source_label: input.source_label }
  });
  await this.aiTaskQueue.addJob(task.id);
  return { draftId: draft.id };
}
```

ai-task handler（`role-map-ai.task.ts`）：调 LLM → 解析 → 校验 characters/relations → 更新 draft（`characters`/`relations`/`warnings`）→ `status=pending_confirm` + `ai_progress.stage=done`。

#### commit（写库 + ai_generated，决策 2）

```ts
async commit(authorId: string, draftId: string, input: { characters; relations }): Promise<{ ok: true }> {
  const draft = await this.assertOwnedDraft(authorId, draftId);
  if (draft.status !== 'pending_confirm') throw new ConflictException('草稿不可提交');
  // 评审修正 R3：明确写库三表范围（避免编码歧义）——
  //   input.characters[]  → character 表（角色实体，复用既有 character.service）
  //   input.relations[]  → character_relation 表（角色关系，复用既有 character-relation.service）
  //   character_view_node 仅在「版图可视化节点」需要时同步（可选，不强制写）
  await this.writeGraph(authorId, draft.work_id, input);
  draft.status = 'committed'; draft.ai_generated = true; draft.generated_at = new Date();
  await this.saveDraft(draft);
  return { ok: true };
}
```

### 4.4 端点（role-map-ai.controller.ts）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/ai-role-maps/ai/generate` | extract，返回 `draftId`（202） |
| GET | `/ai-role-maps/ai/drafts/:draftId/progress` | 进度 `{stage, percent, done}` |
| GET | `/ai-role-maps/ai/drafts/:draftId` | 预览抽取结果（二次编辑） |

## 五、边界与安全

| 项 | 处理 |
|---|---|
| 关系完整性 | relations from/to 缺失则丢弃 + 记 warning（对齐旧语义） |
| characters 至少 1 | 空则冲突（"AI 未识别到角色"） |
| LLM JSON 解析 | 失败 → `status=failed`（"AI 返回格式不合法"） |
| 异步 | ai-task 队列，跨实例、进度经 SSE |
| preview 不落库 | 仅 `pending_confirm` 草稿存库，未 commit 不写图谱实体 |
| 归属校验 | `work_id` → author 归属 |
| 鉴权 | `SessionGuard` + 写操作 `CsrfGuard` |

## 八、风险与应对

| 风险 | 应对 |
|---|---|
| LLM 返回非 JSON | `_parse_llm_json` 移植 + 失败置 `failed`，可重试 |
| 多实例进度丢失 | ai-task 队列 + 持久化草稿，进度存 `ai_progress` jsonb |
| 二次编辑丢失 | draft 存库，可重连二次编辑 |
| commit 重复提交 | `status` 状态机（仅 `pending_confirm` 可 commit），重复 → 409 |
| 既有图谱服务签名 | 编码前核对 character/character-relation 服务方法签名 |

## 三、设计决策落地核对

| 决策 | 方案结论 | 实现 |
|---|---|---|
| 决策1 存储 | C. PG 表 + SSE 流 | `chat_rooms` / `chat_room_events` 表 + `ChatRoomSseService` |
| 决策2 隔离 | B. PG 行锁 `FOR UPDATE` | `lockRoom` 用 `setLock('pessimistic_write')`，同房间串行 / 跨房间并行 |
| 决策3 流式 | B. SSE 复用事件总线 | `ChatRoomEventBus`（key=`room:${roomId}`）+ PG 事件表 + Last-Event-ID 补取 |

### 关键实现细节

- **容量上限（DoD #10）**：`CHAT_ROOM_MAX_PER_WORK = 10`，创建时 `COUNT(*)` 校验，超限抛 409「聊天室容量已满」；按作品分域（每 work 最多 10，非全局 10）。
- **step 一步一断**：`step` 仅允许 `idle/running`，每次推衍只走一步；`continue` 仅允许 `paused`，否则抛 409「房间未暂停，无法续跑」。
- **随机种子确定性**：客户端可不传 `random_seed`，服务端 `deriveSeed(workId, roomKey)` 用 FNV-1a 派生；同 room_key 重试得同种子（幂等重试安全）。
- **三阶段避免长事务**：短事务锁读（`FOR UPDATE`）→ 事务外调 LLM Provider → 短事务乐观写回 + 事件追加，避免持锁调用 LLM 阻塞其他房间。
- **事件序号单调**：`event_seq` 在房间行锁事务内 `max+1` 推进，`(room_id, event_seq)` 唯一约束兜底（`isUniqueViolation` 错误码 `23505`），SSE 按游标补取不丢序。
- **幂等创建**：`(work_id, room_key)` 唯一约束 + `save` 冲突回退 `findOneByOrFail`，重复 `createRoom` 返回既有房间。
- **列表摘要**：`listRooms` 不返回 `history` / `context` 大字段（省带宽）。
- **Model Provider 抽象**：`ChatRoomLlmProvider` + `MockChatRoomLlmProvider`（同种子同输入→同输出），后续接真实 LLM 仅替换 DI 绑定；避免 T2 阻塞在真实 LLM 接入。

## 四、验收结果

### 4.1 单元测试（真实 PG fixture）

`pnpm --filter @storyforge/api test -- src/chat-room` → **16 个用例全绿**，覆盖：

- 确定性种子派生（同 room_key 重试同种子）
- room_key 幂等创建（重复返回既有房间）
- 第 11 个房间 409「聊天室容量已满」
- 按作品分域容量（每 work 独立 10 上限）
- step 一步一断 + continue 续跑
- 同种子确定性推衍内容
- 并发隔离（同房间串行 / 跨房间并行）
- 非 paused continue 拒绝「房间未暂停，无法续跑」
- 跨 work / 跨 author 404
- 删除释放容量
- 跨 author 创建拒绝
- 列表摘要降序且不含 history/context
- context_node_ids 写入 context
- 事件序号单调

### 4.2 全量门禁

`pnpm ci` → **全绿**（contracts build + lint + typecheck + 全量单测 + 全量 e2e + build，exit 0）。

> 过程中发现并修复：`ChatRoomService` 构造器 `DataSource` 参数缺 `@Inject(DataSource)` 装饰器且用 `import type`，导致 e2e 的 `app.init()` 抛 DI 解析错误（16 个 e2e 文件 beforeAll 失败）。改为值导入 + `@Inject(DataSource)` 后，全部 e2e 恢复绿。

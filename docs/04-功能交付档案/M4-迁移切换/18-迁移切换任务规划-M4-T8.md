### T8-5 · CharacterMapTaskHandler（建图执行核心）

- **涉及文件**：[apps/api/src/character/character-map.handler.ts](../../../apps/api/src/character/character-map.handler.ts)（**新建**）
- **改动**：新增 `CharacterMapTaskHandler`，`handle({ taskId, authorId, workId, tool, inputSummary })`：
  1. 读已入库角色（`character` 表 where work_id，过滤 `status != 'archived'`）；不足 2 个 → 直接成功，`summary={ skipped:'insufficient_characters' }`。
  2. `seedCharacterRelationTypes(executor, workId)` 幂等补种；读 `character_relation_types`。
  3. 调 `CharacterMapModelProvider.generateCharacterMap(input)`。
  4. 解析 relations[]：
     - from/to 引用解析（按 name 或 id 精确匹配；匹配不到 → 跳过该边，计入 `summary.skipped`，**不报错**，D3）。
     - 自环（from===to）→ 跳过。
     - 无向边去重：`computePairKey(a,b)` 重复 → 跳过。
     - 类型归一：`relation_type` 匹配 code 或 label → type 实体；匹配不到 → fallback 第一个类型（复刻 `confirmRelationItem` L496-550）。
     - 调 `CharacterRelationService.create(authorId, workId, { source_id, target_id, type_id, directed, label, tag, origin:'ai' })`——幂等重复返回 `created=false`，不报错。
  5. 返回 `summary { generated, created, skipped, typeFallbacks }`。
- **异常语义**：LLM 失败 → 抛 `AiModelError`（retryable）；单边非幂等落库失败 → 整体抛错（事务回滚，任务 failed）。
- **完成标准**：
  1. 单测：角色 < 2 → succeeded，`summary.skipped==='insufficient_characters'`。
  2. 单测：from/to 含不存在角色 → 跳过该边，任务仍 succeeded，`summary.skipped>0`（D3）。
  3. 单测：自环边 → 跳过不落库。
  4. 单测：无向边 A-B / B-A 重复 → 仅落一条（`computePairKey` 去重）。
  5. 单测：`relation_type` 匹配 code/label 成功；匹配不到 → fallback 第一个类型（`typeFallbacks` 计数）。
  6. 单测：落库行 `origin==='ai'`；重复建边 `created=false` 不重复写。
  7. 单测：LLM 抛错 → 任务 failed，error 含 `retryable`。
  8. `pnpm -F api test` 该模块单测通过。
- **依赖**：T8-3（provider 接口）
- **风险**：**高**（核心业务逻辑，覆盖所有跳过/归一/幂等分支）

## 一、目标

将旧架构「Coze 工作流导入」能力迁移到新架构：从 Coze 平台拉取工作流详情，转换为平台智能体/工作流（挂作者归属），与既有 `importBots`/`importDatasets` 并列。

**迁移后**：Coze 资源（智能体/知识库/工作流）完整导入新侧，不依赖旧 Flask。

## 三、设计决策（多方案对比）

### 决策 1：工作流导入归属 —— 智能体 vs 工作流实体

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 工作流 → 智能体（旧语义） | 对齐旧、复用 agent 表 | 语义混淆 | ○ 折中 |
| **B. 工作流 → `workflow` 实体（`source_type=workflow`）** | **语义清晰、与 M4-T7 工作流运行打通** | 需建 workflow 记录 | **✅ 推荐** |

**推荐 B**：导入的 Coze 工作流写 `workflow` 实体（非智能体），挂 `author_id`，`node_ids` 由工作流编排映射。与 M4-T7「工作流运行」打通（导入即可运行）。

### 决策 2：调用路径 —— 直连 Coze vs ai-proxy

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 直连 Coze | 简单 | PAT 暴露后端 | ✗ |
| **B. 经 ai-proxy（复用）** | **PAT 透传、统一代理** | 依赖 proxy | **✅ 推荐** |

**推荐 B**：复用 `listResources`/`importBots` 的 ai-proxy 调用模式，工作流详情经 `GET /workflows/{id}`。

### 4.2 importWorkflows（对齐 importBots 结构）

```ts
async importWorkflows(authorId: string, pat: string, workflowIds: string[], workId?: string)
  : Promise<CozeImportResultItem[]> {
  const results: CozeImportResultItem[] = [];
  for (const workflowId of workflowIds) {
    // 1. 幂等检查：(author_id, source_type='workflow', coze_id) 已存在 → 返回已导入
    const existing = await this.findExisting(authorId, 'workflow', workflowId);
    if (existing) { results.push({ coze_id: workflowId, ok: true, skipped: true, ... }); continue; }
    // 2. 经 ai-proxy 拉取工作流详情（GET /workflows/{id}）
    const detail = await this.fetchWorkflowDetail(pat, workflowId);
    // 3. 映射 workflow.node_ids（工作流编排 → 平台节点）
    const nodeIds = this.mapWorkflowNodes(detail);
    // 4. 写 workflow 实体（source_type=workflow，挂 author_id/work_id）
    const wf = await this.createWorkflowEntity(authorId, workId, workflowId, nodeIds, detail);
    results.push({ coze_id: workflowId, ok: true, workflow_id: wf.id });
  }
  return results;
}
```

### 4.3 `mapWorkflowNodes` 映射规则（评审修正 R5）

Coze 工作流返回 `graph`（`nodes[]` + `edges[]`），映射到平台 `workflow.node_ids` + `order`：

| Coze 侧 | 平台侧 | 规则 |
|---|---|---|
| `graph.nodes[]`（每个 node） | `node_ids[]`（节点 ID 列表） | 按 `node.id` 建映射；`node.type` 识别节点类别 |
| `graph.edges[]`（依赖边） | `workflow.order`（执行顺序） | 拓扑排序得出线性顺序 |
| 无法映射的 `node.type` | 记 warning，跳过该节点 | 不阻断整体导入 |

```ts
private mapWorkflowNodes(detail: CozeWorkflowDetail): { nodeIds: string[]; order: string[] } {
  const nodeIds: string[] = [];
  const warnings: string[] = [];
  const supportedTypes = new Set(['start', 'end', 'llm', 'code', 'http', 'tool', 'condition']);
  for (const node of detail.graph?.nodes ?? []) {
    if (!supportedTypes.has(node.type)) { warnings.push(`跳过不支持节点类型: ${node.type}`); continue; }
    nodeIds.push(node.id);
  }
  const order = topologicalSort(nodeIds, detail.graph?.edges ?? []);
  return { nodeIds, order };
}
```

### 4.4 端点扩展

`import` 端点（`POST /coze/import`）`source_type` 支持 `workflow`，分流到 `importWorkflows`（对齐 `bot`/`dataset` 既有分流）。

### 4.4 契约扩展（packages/contracts/src/coze-import.ts）

`CozeImportRequest` 的 `source_types` 增 `workflow` 枚举值；`CozeImportResultItem` 增 `workflow_id` 字段（可空）。

## 五、边界与安全

| 项 | 处理 |
|---|---|
| PAT 透传 | 经 ai-proxy，不经手用户 PAT |
| 幂等 | `(author_id, source_type, coze_id)` 唯一，重复导入返回 `skipped:true` |
| 归属 | 导入挂 `author_id`（BUG-2026-121-01），可指定 `work_id` |
| 来源标记 | `source_type=workflow`，区别于 `agent`/`dataset` |
| 工作流编排映射 | `mapWorkflowNodes` 映射节点；节点缺失 → warning，不阻断 |
| Coze 拉取失败 | 单个工作流失败记 `ok:false` + error，不中断批量 |
| 鉴权 | `SessionGuard` + 写操作 `CsrfGuard` |
| 输入校验 | `ZodValidationPipe` + schema（`workflow_ids` 非空、`source_types` 枚举） |

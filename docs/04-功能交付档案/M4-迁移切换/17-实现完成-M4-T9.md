## 二、关键实现决策

| # | 决策点 | 落地 |
|---|---|---|
| 1 | 类型判定来源 | **复用 `classify.ts` 的 `classifyEntryType`**（4 类：paper/novel/inspiration/article + setting 经 manual），非 11 类枚举（11 类含 `other`，既有 classify.ts 从不返回 `other`，用户决策不新建）。detect-type 响应扩展为 `{type, confidence, reasons, warnings}`（对齐 `ClassifyResult`） |
| 2 | 相似检索 | **`cosineSimilarity` 自行排序**（非 `findSimilar`，因其 `reason='inspiration_auto'` 固定、语义为灵感召回；T9 需任意类型条目检索）。目标条目 embedding 与同库（同 owner + 同 scope + 未删除 + 排除自身）候选向量余弦 Top-N，`score>0` 过滤，`score` 保留 4 位小数 |
| 3 | 相似降级 | 目标无 embedding / 候选为空 / 查询向量全零 → 返回空 `items`（不报错） |
| 4 | 路由前缀 | **统一 `/knowledge`**（方案 4.2 字面 `/ai-knowledge`，但任务规划 §2.9 与既有 `entries.controller` 均用 `/knowledge`，用户决策统一 `/knowledge`）。`GET /knowledge/entries/:entryId/similar` |
| 5 | markdown-render | **TS 重写**（非 Python 桥接）：`MarkdownIt({html:false, linkify:false, breaks:true})`。`html:false` 禁内联 HTML（等价旧 safe 剔除 script/on*），`breaks:true` 对齐旧 `nl2br`；纯渲染预览，不落库 |
| 6 | markdown-render 路径 | 任务规划 §2.9 字面 `POST /knowledge/:id/markdown-render`，但旧端点为 `POST /markdown/render`（无 id）；按旧语义实现为 `POST /knowledge/markdown/render`（纯文本→HTML，非条目级） |
| 7 | DI 注入 | 构造参数 `DataSource` 一律显式 `@Inject(DataSource)`（本 tsconfig 无 `emitDecoratorMetadata` 可靠反射，缺注会注入 undefined → 500，同 M4-T7 问题 1） |

## 五、实现过程中的关键问题与解决

### 问题 1：`DataSource` 注入 undefined → 500（similar 三个用例）

**现象**：e2e 的 similar 三个用例（空 items / cosine top-N / 404）均报 500，堆栈 `Cannot read properties of undefined (reading 'getRepository')` 于 `KnowledgeToolsService.similar` L53。

**定位**：`KnowledgeToolsService` 构造参数 `dataSource` 未加 `@Inject(DataSource)`。本 tsconfig 无 `emitDecoratorMetadata` 可靠反射，构造参数类型对 `DataSource` 不可靠，缺 `@Inject` 注入为 undefined（同 M4-T7 问题 1）。

**解决**：构造参数补显式 `@Inject(DataSource)`（import `Inject`）。重跑 e2e 8/8 全绿，单测 11/11 回归通过，typecheck 通过。

### 问题 2：service 单测 embedding 维度强约束

**现象**：`similar` 单测首次用 2/3 维向量，插入 `knowledge_entry_embeddings` 报 `QueryFailedError: expected 1024 dimensions, not 2`——`embedding` 列是 `vector(1024)` DB 强约束维度。

**解决**：测试 `addEmbedding` 补零到 1024 维、`dim:1024`。重跑通过。

### 问题 3：service 单测 far 向量正交导致过滤

**现象**：`similar 返回余弦 Top-N` 期望 2 项实际 1 项——`far` 用 `[0,1,0]` 与查询 `[1,0,0]` 正交（余弦=0），被 `score>0` 过滤。

**解决**：`far` 改 `[0.3,0.95,0]`（小正余弦，仍 < close 的 0.99 余弦）。重跑通过。

### 问题 4：service 单测 WorkEntity 字段误用

**现象**：曾用 `workRepo.create({cover, tags})`，但 `WorkEntity` 无这些字段（仅 id/author_id/title/...）。

**解决**：改为 `{id, author_id, title}` + import `WorkEntity`。

### 问题 5：typecheck exactOptionalPropertyTypes 类型传播

**现象**：`exactOptionalPropertyTypes: true` 下 `detectType` 参数 `manual?: string` 与契约 `manual?: KnowledgeEntryType` 不符，controller 传 `input` 类型不匹配。

**解决**：service `detectType(input: KnowledgeDetectTypeRequest)` 签名改为契约类型，import `KnowledgeDetectTypeRequest`。typecheck 通过。

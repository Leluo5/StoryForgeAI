## 一、技术选型

| 项 | 选择 | 备选 | 理由 |
| --- | --- | --- | --- |
| 头像生成方式 | AI 图像工具（用户已确认） | 程序化 SVG/Canvas | 用户明确选 AI 图像工具 |
| 图像生成接口 | 新增 Coze 文生图工作流调用 | 外部文生图 API | 复用现有 `coze_client.run_workflow`，无新增 SDK 依赖 |
| 确定性一致性 | 特征哈希 → prompt 缓存（`avatar_{hash}.png`） | 后端查重表 | 同特征 → 同 prompt → 同图，满足 F9-02 确定性 |
| 头像存储 | 本地文件 `data/avatars/<project>/<hash>.png` + Role.avatar 存路径 | base64 内嵌 | 避免 data 膨胀，JSON 只存引用 |
| 形象特征模型 | Role 新增结构化字段 `visual_features`（对象） | 复用 appearance 字符串 | 需求按维度（性别/发型/发色/面部/服饰）生成，需结构化 |
| 连线颜色 | 唯一色池 + 对比度校验（哈希分配） | 按 relation_type 固定色 | 需求要求每条连线随机唯一，非按类型固定 |
| 同步机制 | 事件总线 `storyforge:role-avatar-updated`（DOM CustomEvent） | 轮询 | 实时同步多展示位，无延迟 |

## 二、形象特征模型（Role 扩展）

### 2.1 新增字段

| 字段 | 类型 | 说明 | 来源 |
| --- | --- | --- | --- |
| `visual_features` | object | 形象特征（结构化，头像生成依据） | 新增 |
| `visual_features.hair_style` | string | 发型（如 长发/短发/马尾/盘发/寸头…） | 新增，默认 `""` |
| `visual_features.hair_color` | string | 发色（如 黑/棕/金/银/红…） | 新增，默认 `""` |
| `visual_features.face_features` | string | 面部特征（如 剑眉星目/温和/冷峻…） | 新增，默认 `""` |
| `visual_features.outfit_style` | string | 服饰风格（如 侠客/书生/贵族/军装…） | 新增，默认 `""` |
| `visual_features.expression` | string | 表情/神态（可选） | 新增，默认 `""` |
| `avatar` | string | 头像文件路径（`/api/role-map/avatar/<hash>`） | 新增，默认 `""` |

> 特征维度可扩展（未来增 `ear_shape`/`eye_color` 等，仅扩展字段池即可，满足边界 §3.2）。字段池配置在 `config/role_visual_pools.json`，与 F8 随机生成字段池同构。

### 2.2 确定性一致性策略（F9-01/02）

- **特征规范化**：将 `visual_features` 各维度按固定顺序拼接为特征签名 `sig = JSON.stringify([gender, hair_style, hair_color, face_features, outfit_style, expression])`。
- **确定性哈希**：`hash = sha256(sig)`（前 16 位十六进制）。
- **prompt 构造**：由特征签名映射到固定 prompt 模板（确定性），非随机。
- **缓存**：`data/avatars/<project>/<hash>.png` 若存在 → 直接返回，不再调用 AI（幂等，同特征同图）。
- **AI 调用**：仅缓存未命中时调用文生图，成功后落盘。
- **满足**：F9-01（特征强关联）、F9-02（同特征同图，确定性）。

## 三、AI 图像工具实现

### 3.1 现状与目标
- 现状：`gen_character_image` 为 stub（`tool_registry.py:116` → `_stub_handler`），无真实逻辑；`coze_client` 无图像方法。
- 目标：实现真实工具，接入文生图工作流。

### 3.2 方案（推荐）

1. **`coze_client.py` 新增 `generate_character_image(workflow_id, prompt)`**：复用 `run_workflow` 调用 Coze 文生图工作流，返回图像 URL/文件。
2. **`tool_registry.py` 替换 `_stub_handler` 为真实处理器 `_gen_character_image_handler`**：读取 `context.role.visual_features` → 构造特征签名 → 查缓存 → 命中直接返回；未命中调 `generate_character_image` → 落盘 `data/avatars/<project>/<hash>.png` → 写回 `role.avatar`。
3. **配置**：`config_loader` 新增 `image_workflow_id`（Coze 文生图工作流 ID），从全局配置读取。

### 3.3 备选方案（不推荐）
- **外部文生图 API（如 SD/即梦）**：需新增 SDK 与密钥配置，破坏「复用现有 coze 工作流」的一致性；仅当 Coze 无文生图工作流时考虑。
- **程序化 SVG/Canvas**：确定性最强、零外部依赖，但用户已明确选 AI 图像工具，不作为主选。

## 四、头像同步机制（F9-03/04）

### 4.1 事件总线
- 头像字段更新后，派发 DOM CustomEvent `storyforge:role-avatar-updated`，`detail = {roleId, avatarPath}`。
- 监听方：角色详情侧滑面板（`role_map_panel.js`）、角色导入预览（`novel_editor.js`）、角色版图节点（`role_map_panel.js`）。
- 各监听方收到事件 → 更新对应 `<img>` src / 节点头像，**无延迟**（同步事件派发）。

### 4.2 展示位接入
| 展示位 | 文件 | 接入点 |
| --- | --- | --- |
| 角色详情侧滑面板 | `role_map_panel.js` | 头部新增 `<img class="rmp-avatar">` |
| 角色导入预览 | `novel_editor.js` | 预览卡片新增 `<img>` |
| 角色版图节点 | `role_map_panel.js` | 节点渲染叠加头像（若可用） |

> 版图节点当前为 `<circle>` + `<text>`（`role_map_panel.js:536`）。叠加头像采用「节点中心叠加 `<image>` 裁剪为圆形」方案，头像缺失时回退为现有色点节点。

## 五、连线颜色分配（F9-05/06/07）

### 5.1 颜色池设计
- 预定义**唯一色池**：一组高对比度、深浅色背景均清晰的颜色（HSL 均匀分布，亮度/饱和度约束保证对比度达标），如 24 色。
- **分配**：`role_map_service.add_edge()` 时，为新连线从色池取**未占用**颜色（按 `edge.id` 哈希取模 + 冲突探测）；删除连线时回收颜色。
- **持久化**：`edge` 新增 `color` 字段（与 F8 现有 5 字段并存），服务端分配后写库，前端直接读 `edge.color` 渲染，保证唯一。

### 5.2 对比度保证
- 色池选色时按 **WCAG 对比度 ≥ 4.5:1**（对浅底 `#fff`）与 **≥ 3:1**（对深底 `#1e293b`）双重校验筛选，只保留达标色。
- 前端 `.rmp-link` stroke 由硬编码 `#94a3b8` 改为 `edge.color`（或按 `--link-color` CSS 变量）。

### 5.3 与筛选高亮兼容
- 现有「匹配高亮 `.matched` → `#f59e0b`」逻辑保留；高亮优先级高于唯一色（高亮时覆盖，恢复时还原 edge.color）。

## 七、异常处理与边界

| 场景 | 处理 |
| --- | --- |
| 特征全空 | 返回占位头像（默认灰底），不调 AI（避免无意义生成） |
| AI 图像调用失败 | 返回 502 + 明确错误；保留旧头像，不覆盖 |
| 缓存未命中且 AI 不可用 | 回退占位头像，记录警告 |
| 连线颜色池耗尽（>24 边） | 进入第二圈色（加深/减淡变体），仍保证唯一与对比度 |
| 头像文件缺失 | 前端回退色点节点 + 占位图 |

## 八、性能与约束

- 头像生成是**低频操作**（用户主动触发），缓存命中 O(1)，不阻塞图谱加载。
- 连线颜色分配 O(1)（哈希取模），不重排全图。
- 头像文件按项目分目录，避免单目录文件过多。
- 兼容现有交互：不改动新增/编辑/删除/关联/筛选/跳转既有流程，仅新增字段与渲染叠加。

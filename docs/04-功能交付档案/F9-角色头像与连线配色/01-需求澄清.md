## 一、用户诉求（非技术语言）

> 创作者希望：**每个角色都有一张符合他/她人设的专属头像**——男的女的、什么发型发色、长什么样、穿什么风格，头像都要对得上；我用「生成角色形象」工具做好/改好一个角色形象后，这个角色的头像要立刻在所有地方同步更新（角色列表、角色版图里的节点，一处更新处处更新）。同时，角色版图里人物之间的每一根关系线，都要有一根**不重样、看得清**的颜色，盟友、敌人、师徒……一眼就能分辨是哪条关系，不能好几根线一个颜色让人分不清。**

## 二、功能范围（做什么）

### 2.1 角色头像随机生成

- 根据角色的**各项特征属性**生成匹配的个性化头像。特征维度**包括但不限于**：性别、发型、发色、面部特征、服饰风格等。
- 特征组合与头像**强关联**：**相同特征组合应生成一致的头像**（确定性）。
- 头像以**图像**形式呈现（用户已确认采用 AI 图像工具生成方式）。

### 2.2 头像同步更新

- 调用**角色形象生成工具**完成角色形象**创建或修改**后，自动同步更新对应角色的**头像展示**。
- 头像更新**实时同步至所有展示该角色的界面位置**和**角色版图展示**，无延迟或不同步问题。

### 2.3 关系连线颜色分配

- 角色人际关系连线功能需为**每一条关系连线**分配**随机生成的唯一颜色**。
- 确保**不同角色之间的关系连线**具备清晰可区分的视觉效果，**避免连线颜色重复**导致的关系识别混淆。
- 连线随机颜色需具备**足够对比度**，在**深色和浅色背景**下均清晰可见。

### 2.4 兼容既有交互

- 所有功能**兼容现有角色管理界面的交互逻辑**，不影响原有操作流程（新增/编辑/删除/关联/筛选/跳转等）。

## 三、功能边界（不做什么 / 允许什么 / 条件触发）

### 3.1 不做什么（禁止）

| 禁止 | 说明 |
| --- | --- |
| 不修改现有角色管理主流程 | 新增/编辑/删除/关联/筛选/跳转等原有操作逻辑保持不变 |
| 不改变角色数据模型主键/基础字段 | 仅**新增**头像与形象特征字段，不动 id/project_id/name/age/gender 等既有字段 |
| 不重写角色版图渲染引擎 | 仅在现有 d3-force + SVG 渲染上做「连线着色 + 节点头像叠加」，不换引擎 |
| 不做头像手动上传 | 头像由 AI 工具生成，不提供用户自选图片上传（避免与确定性要求冲突） |
| 不依赖外部固定图片资源 | 头像必须由特征驱动生成，不使用预置图片库 |

### 3.2 允许什么

| 允许 | 说明 |
| --- | --- |
| 角色形象特征维度可扩展 | 除性别/发型/发色/面部/服饰外，未来可增维度，扩展字段池即可 |
| 头像在角色列表/详情/版图多处展示 | 同一头像数据源，多界面同步引用 |
| 连线颜色按需重算 | 增删连线/角色后，重新分配保证唯一性 |

### 3.3 条件触发

| 条件 | 触发动作 |
| --- | --- |
| 调用角色形象生成工具（创建/修改） | 生成头像 → 写入角色 avatar 字段 → 广播同步更新所有展示位 |
| 新增角色 | 自动生成一套特征 + 头像（若该角色首次生成形象） |
| 新增/删除关系连线 | 为新增连线分配唯一颜色，回收删除连线的颜色 |
| 切换深浅色主题 | 连线颜色保证在两种背景下均清晰（对比度校验） |

## 四、交互与流程

### 4.1 角色头像生成流程

```
选择角色 → 点击「生成角色形象」→ 工具按特征（性别/发型/发色/面部/服饰）生成图像 → 保存头像到角色 → 头像出现在角色列表 + 详情 + 版图节点
```

### 4.2 角色形象修改流程

```
打开角色形象编辑 → 调整特征（如改发色/服饰）→ 重新生成头像 → 保存 → 所有展示位同步更新头像
```

### 4.3 头像同步更新流程

```
头像字段更新（创建或修改）→ 触发同步事件 → 角色列表刷新头像 / 角色版图节点刷新头像 → 全界面一致
```

### 4.4 连线颜色分配流程

```
新增关系连线 → 从「唯一颜色池」分配未占用颜色 → 连线以该颜色渲染 → 增删时颜色池动态回收/补充 → 无重复
```

## 五、验收标准（可量化）

| 编号 | 标准 | 判定方法 |
| --- | --- | --- |
| F9-01 | 头像根据特征（性别/发型/发色/面部/服饰）生成，特征与头像强关联 | 自动化断言：相同特征组合生成一致头像 |
| F9-02 | 相同特征组合生成一致头像（确定性） | 自动化断言：两次生成同特征 → 同头像 |
| F9-03 | 调用形象工具创建/修改后，头像自动更新 | 自动化 + 手动 |
| F9-04 | 头像实时同步至所有展示位（角色列表/详情/版图），无延迟 | 浏览器验证：更新一处 → 多处同步 |
| F9-05 | 每条关系连线分配随机唯一颜色 | 自动化断言：edges 颜色无重复 |
| F9-06 | 连线颜色在深色/浅色背景下均清晰可见（对比度） | 自动化断言对比度 + 手动视觉 |
| F9-07 | 连线颜色具备足够对比度区分不同关系 | 自动化断言两两色差 |
| F9-08 | 兼容现有角色管理交互（新增/编辑/删除/关联/筛选/跳转不受影响） | 回归测试全量通过 |

## 六、风险与依赖

| 项 | 说明 |
| --- | --- |
| 依赖 AI 图像工具 | 需先实现/接入「生成角色图像」真实工具（现为 stub 占位） |
| 依赖角色数据模型 | 需新增 avatar + 形象特征字段（发型/发色/面部/服饰），现仅 gender |
| 依赖 F8 角色版图 | 连线着色、节点头像叠加在 F8 图谱渲染上增量实现 |
| 一致性保证 | 相同特征组合生成一致头像，需确定性（缓存/哈希）策略 |
| 对比度保证 | 深浅色背景均清晰，需预定义对比度达标色池 |

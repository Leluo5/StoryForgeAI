## 二、任务清单

### 阶段 A · 数据层

**M3b-B1 数据模型与迁移（`database/migrations/<epoch>-agent-config-base.ts` + `database/agent.entity.ts` + `database/ai-tool.entity.ts`）** — 高优先级 · ★
- 建 2 张表：`ai_agents`、`ai_tools`（手写 SQL，沿用 M1/M2/M3a 模式）。
- 写 2 个 TypeORM 实体：`AgentEntity`、`AiToolEntity`。
- 关键约束：`UNIQUE(author_id, name)`（Agent 名称唯一）、唯一部分索引 `WHERE is_default`（同作者仅一个默认）、`UNIQUE(tool_id)`、`CHECK IN (...)`（status）、`REFERENCES ... ON DELETE CASCADE/SET NULL`、索引。
- **种子数据**（幂等 `ON CONFLICT DO NOTHING`）：插入 4 个工具（`continue`/`polish`/`expand`/`rewrite`）+ 1 个默认 Mock Agent（`platform='mock'`、`model_id='mock-continue-v1'`、`is_default=true`），4 工具绑定该默认 Agent。
- 完成标准：`migration:run` 幂等；实体注册进 DataSource；种子在空库与重复执行下均正确。

### 阶段 B · 契约层

**M3b-B2 契约层（`packages/contracts/src/agent-config.ts` + `index.ts` 聚合）** — 高优先级 · ★
- 定义全部请求/响应 Zod Schema：`createAgentRequestSchema`、`updateAgentRequestSchema`、`agentSchema`、`aiToolSchema`、`listAgentsResponseSchema`、`listToolsResponseSchema`、`updateToolRequestSchema`。
- 导出 `z.infer` 类型（单 schema 双端复用，沿用 M1/M2/M3a）。
- 完成标准：contracts 构建通过；前后端 import 同一 schema 类型一致。

### 阶段 C · 服务层

**M3b-B3 Agent 服务（`agent/agent.service.ts`）** — 高优先级 · ★
- `createAgent`：同作者名称唯一校验 + 默认互斥（事务内清除其他默认）+ 创建 + 审计 `agent_create`。
- `updateAgent`：归属校验 + 默认互斥 + 状态合法 + 审计 `agent_update`。
- `deleteAgent`：软删（status='disabled'）+ 绑定工具 agent_id 置空 + 审计。
- `listAgents`：按作者查询 + 模型参数概要 + 绑定工具数。
- 完成标准：单测覆盖创建/默认互斥/更新/软删/归属校验；404/409 边界。

**M3b-B4 工具绑定与启停（`agent/agent.service.ts` 工具方法 + 修改 M3a `ai-task.service.ts` 发起解析）** — 高优先级 · ★
- `listTools`：全部工具 + 绑定 Agent 概要 + 状态。
- `updateTool`：工具存在校验 + 绑定 Agent 存在且 active 校验 + 更新 + 停用附「进行中任务不受影响」提示 + 审计 `tool_update`。
- **M3a 接入（`ai-task.service.ts`）**：`createTask` 步骤 0 按 `tool` 查 `ai_tools` → 不存在 404 / 停用 409 / 未绑定 422；步骤 2.5 写入 `ai_tasks.agent_id`。
- 完成标准：单测覆盖工具查询/绑定/停用校验 + 发起任务解析（404/409/422/写入 agent_id）。

### 阶段 D · 接口层

**M3b-B5 接口层（`agent/agent.controller.ts` + `agent/agent.module.ts`）** — 高优先级 · ★
- 实现 §3.1–§3.2 全部路由：Agent 创建/列表/更新/删除 + 工具列表/更新。
- 统一 `SessionGuard` + `CsrfGuard` + `ZodValidationPipe` + `ok()` 包装。
- 注册进 `AppModule`。
- 完成标准：路由单测覆盖全部端点（含 401/403/404/409/422）。

### 阶段 E · 表现层

**M3b-B6 前端管理面板（`apps/web/src/agent/`）** — 高优先级 · ★
- `agent-client.ts`：listAgents/createAgent/updateAgent/deleteAgent/listTools/updateTool。
- `agent-panel.tsx/css`：工具清单（名称/绑定 Agent/状态徽章/配置按钮）+ 配置表单（Agent 下拉/模型参数/启用开关/设默认）+ Agent 列表（新增/编辑/软删/设默认）。
- `workbench-page.tsx`：接入「Agent 管理」tab + 深链 `?panel=agent`。
- 完成标准：浏览器验证查看/配置/启停/设默认；375/768/1024/1440；键盘/读屏。

### 阶段 F · 验收

**M3b-B7 单元与集成测试（`src/agent/*.test.ts` + `apps/api/test/agent-config.e2e-spec.ts`）** — 高优先级 · ★
- 单测：Agent 服务/工具绑定/发起任务解析全部覆盖（§八 方案对照表）。
- 集成：真实 PostgreSQL + supertest：Agent 创建/默认互斥/更新/软删 + 工具绑定/停用 + 发起任务解析 404/409/422/写入 agent_id + 审计。
- 完成标准：全部单测 + 集成通过；无回归（M0/M1/M2/M3a 基线全绿）。

**M3b-B8 E2E 与验收（`tests/e2e/*.spec.ts` + DoD 核对）** — 高优先级 · ★
- E2E：打开 Agent 管理面板 → 配置工具 Agent → 发起任务写入 agent_id → 停用工具发起 409。
- DoD #D1~#D11 逐条核对（§八 技术方案对照表）。
- 完成标准：E2E 通过；DoD 逐条核对；更新档案 README + 总索引「已交付」。

## 五、编码实现指引（对齐 Skill 11）

1. **每任务一阶段**：M3b-B1 完成并跑通迁移与种子，再进 B2，不一口气全做完。
2. **每任务完成即写单测**：通过才进下一任务。
3. **高风险任务暂停**：M3b-B1/B2/B3/B4/B5/B7/B8 完成时暂停，人工复核后再继续。
4. **文档同步**：编码完成并单测通过后，更新本档案 README 与总索引为「已交付」。
5. **M3a 兼容**：B4 修改 `ai-task.service.ts` 后必须跑 M3a 全链路回归（种子数据保证缺配置时不中断）。
6. **外部模型边界**：本期不接真实模型厂商，`ai-model.provider.ts` 不变；Coze Provider 留接口待 M3b 后续段。

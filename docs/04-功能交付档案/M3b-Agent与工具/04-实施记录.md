## 四、与方案的两处偏差（已同步文档）

| 偏差 | 方案原描述 | 实际实现 | 原因 |
|------|-----------|---------|------|
| 默认 Agent 预置 | 迁移种子同时插入默认 Mock Agent | 迁移仅插 4 工具；默认 Agent 由 `ensureDefaultAgent` 懒创建 | `ai_agents.author_id` 为作者级非空外键，空库无作者可挂 |
| 工具未绑定 Agent | 发起任务返回 422 | 回退 `ensureDefaultAgent` 默认 Agent 兜底 | 避免 M3a 既有任务链路因缺配置中断 |

### 5.3 过程中发现并修复的问题

| 问题 | 现象 | 根因 | 处置 |
|------|------|------|------|
| Agent 面板数据加载失败 | 「创作工具」空白，面板顶部红字 `Cannot read properties of undefined (reading 'parse')` | Vite 预构建缓存 `.vite/deps/@storyforge_contracts.js` 生成于 `agent-config` 模块加入之前，bundle 中不含 `agentSchema` / `listAgentsResponseSchema` | 删除 `apps/web/node_modules/.vite` 并重启 dev server，缓存重建后验证通过 |
| 单测 `relation "ai_agents" already exists` | 单测建表冲突 | `test-database.ts` 的 `dropWritingAndAuthTables` 未删 M3b 新表 | 补删 `ai_tools` / `ai_agents`（按 FK 依赖倒序） |
| e2e 全部 404 工具不存在 | 每用例后工具种子被清空 | `TRUNCATE ... authors CASCADE` 沿 FK 链递归截断 `ai_agents → ai_tools` | 将两表纳入主 TRUNCATE 并在其后重新预置 4 工具种子 |
| e2e 依赖注入失败 | `Nest can't resolve dependencies of the SessionGuard` | `AgentModule` 未 import `AuthModule` | imports 补 `AuthModule` |

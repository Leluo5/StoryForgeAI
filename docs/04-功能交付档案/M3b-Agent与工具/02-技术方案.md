## 一、方案概述

本功能为创作端 **Agent 配置与管理**：让作者为每个 AI 创作工具指定执行 Agent 与模型参数，配置变更即生效、可审计，发起 AI 任务时按工具解析出执行 Agent 并写入 M3a 的 `ai_tasks.agent_id` 预留字段。核心是「Agent 配置实体 → 工具注册表 → 工具 ↔ Agent 绑定 → 发起任务解析 Agent」四层，全部落在 NestJS `/api/v1` 资源体系，沿用 M0/M1/M2/M3a 的 SessionGuard + CsrfGuard + ZodValidationPipe + `ok()` 响应包装模式，并复用 M2 审计服务记录配置变更。

### 1.1 方案选型

| 决策点 | 选择 | 备选 | 理由 |
|--------|------|------|------|
| Agent 配置持久化 | `ai_agents` 表（DB） | 配置文件 JSON | 需按作者/作品隔离、可审计、CRUD，DB 是权威；配置文件不适合多实例 |
| 工具注册表持久化 | `ai_tools` 表（DB） | 前端硬编码 / 配置文件 | 服务端权威，工具可绑定 Agent、可启停、可审计；前端从 API 拉取 |
| 工具 ↔ Agent 绑定 | `ai_tools.agent_id` 外键 | 独立绑定表 | 本期一对一（一工具一 Agent），外键列足够；后续需多 Agent 再拆绑定表 |
| 默认 Agent | `ai_agents.is_default`（唯一部分索引） | 应用层判重 | DB 唯一约束保证同刻仅一个默认，防并发竞争 |
| 模型参数 | `ai_agents.model_config` jsonb（受控字段） | 任意 JSON | 本期受控字段（温度/最大 token），防任意 JSON 注入；Zod 校验 |
| 平台 | `ai_agents.platform` varchar（本期 `mock`） | 枚举 | `coze` 留待 M3b 后续段，不用数据库迁移即可扩展 |
| 契约复用 | `@storyforge/contracts`（Zod） | 双端各写 | 单一 schema 双端复用，M1/M2/M3a 已验证 |
| 鉴权 | SessionGuard + 服务层 author 过滤 | 独立 AuthorGuard | 沿用 M1/M2/M3a 模式 |
| 审计 | 复用 M2 审计服务 | 新建审计 | 沿用 M2 `audit_logs`，配置变更可追溯 |

## 二、数据模型（对齐需求澄清 §六）

全部主键 `uuid`（`gen_random_uuid()` 默认），时间戳 `timestamptz`，列名 snake_case，沿用 M1/M2/M3a 手写 SQL 迁移模式。

### 2.1 Agent `ai_agents`（迁移 `agent-config-base`）

| 列 | 类型 | 约束 | 说明 |
|----|------|------|------|
| `id` | uuid | PK | Agent 标识（`agent_id`） |
| `author_id` | uuid | REFERENCES authors(id) ON DELETE CASCADE | 所属作者 |
| `name` | varchar(80) | 非空 | Agent 名称（如「标准续写 Agent」） |
| `platform` | varchar(24) | 非空 DEFAULT 'mock' | 模型平台（本期 `mock`；`coze` 留待后续） |
| `model_id` | varchar(80) | 非空 | 模型标识（如 `mock-continue-v1`） |
| `model_config` | jsonb | 非空 DEFAULT '{}' | 模型参数（温度/最大 token 等受控字段） |
| `status` | varchar(16) | CHECK IN ('active','disabled') DEFAULT 'active' | 状态 |
| `is_default` | boolean | DEFAULT false | 是否默认 Agent |
| `created_at` | timestamptz | DEFAULT now() | 创建时间 |
| `updated_at` | timestamptz | DEFAULT now() | 最后变更 |

**约束**：`UNIQUE(author_id, name)`（同一作者内 Agent 名称唯一）；唯一部分索引 `CREATE UNIQUE INDEX ... ON ai_agents(author_id) WHERE is_default`（同作者同刻仅一个默认 Agent）。
**索引**：`idx_ai_agents_author ON ai_agents(author_id, created_at DESC)`、`idx_ai_agents_status ON ai_agents(author_id, status)`。

### 2.2 创作工具注册表 `ai_tools`（迁移 `agent-config-base`）

| 列 | 类型 | 约束 | 说明 |
|----|------|------|------|
| `id` | uuid | PK | 工具行标识 |
| `tool_id` | varchar(40) | 非空 | 工具标识（如 `continue` 续写、`polish` 润色） |
| `name` | varchar(80) | 非空 | 工具展示名 |
| `description` | varchar(255) | 可空 | 工具说明（可选） |
| `agent_id` | uuid | REFERENCES ai_agents(id) ON DELETE SET NULL | 当前绑定执行 Agent |
| `enabled` | boolean | DEFAULT true | 是否启用 |
| `created_at` | timestamptz | DEFAULT now() | 创建时间 |
| `updated_at` | timestamptz | DEFAULT now() | 最后变更 |

**约束**：`UNIQUE(tool_id)`（工具标识唯一，服务端权威）。
**索引**：`idx_ai_tools_enabled ON ai_tools(enabled)`。

**初始化种子**：迁移时仅插入 M3a 已支持的 4 个工具（`continue` 续写 / `polish` 润色 / `expand` 扩写 / `rewrite` 改写，幂等 `ON CONFLICT (tool_id) DO NOTHING`）。**默认 Mock Agent 不随迁移预置**——因 `ai_agents.author_id` 为作者级非空外键，空库无作者可挂；改为服务层 `ensureDefaultAgent` 在首次发起任务时懒创建（`name='默认创作 Agent'`、`platform='mock'`、`model_id='mock-default'`、`is_default=true`），并绑定全部启用工具，保证 M3a 既有任务链路在 M3b 落地后不因缺配置而中断。并发安全由唯一部分索引 `uq_ai_agents_author_default` 兜底。

## 三、API 设计（`/api/v1`）

统一沿用：`SessionGuard` + `CsrfGuard` + `ZodValidationPipe` + `ok(request, data)` 包装。错误码：401/403/404/409/422。

### 3.1 Agent 配置

- `POST /api/v1/ai-agents` — 创建 Agent（`name`、`platform`、`model_id`、`model_config`、可选 `is_default`）。校验 author 归属；若设 `is_default=true` 则先清除该作者其他默认。响应 `{ agent }`。
- `GET /api/v1/ai-agents` — 列出当前作者的 Agent（含模型参数概要、绑定工具数）。
- `PATCH /api/v1/ai-agents/:agentId` — 更新 Agent（`name`/`model_id`/`model_config`/`status`/`is_default`）。校验归属；不能改 `author_id`。响应 `{ agent }`。
- `DELETE /api/v1/ai-agents/:agentId` — 软删 Agent（`status='disabled'`，不物理删除；绑定工具 `agent_id` 置空）。响应 `{ ok: true }`。

### 3.2 工具注册表

- `GET /api/v1/ai-tools` — 列出全部工具（含绑定 Agent 概要、状态）。
- `PATCH /api/v1/ai-tools/:toolId` — 更新工具（`agent_id`/`enabled`/`name`/`description`）。校验：绑定的 Agent 须存在且 `active`；若停用某工具，返回时附「进行中任务引用」提示（不阻断）。响应 `{ tool }`。

### 3.3 发起任务接入（M3a 修改）

- 修改 M3a `POST /api/v1/works/:workId/chapters/:chapterId/ai-tasks` 的服务层：发起任务前按 `tool` 查 `ai_tools`，若 `enabled=false` → 409「该创作工具已停用」；否则取 `agent_id` 写入 `ai_tasks.agent_id`。

## 四、核心逻辑

### 4.1 Agent 创建与默认（`agent.service.ts`）

```ts
// 创建 Agent：同作者名称唯一 + 默认互斥
async createAgent(authorId, input): Promise<{ agent: Agent }> {
  // 1. 校验：同作者下 name 唯一（UNIQUE(author_id, name) 兜底）
  // 2. 若 input.is_default → 事务内先 UPDATE 清除该作者其他默认
  // 3. 创建 ai_agents(status='active', is_default=input.is_default ?? false)
  // 4. 审计 action='agent_create'
  // 5. 返回 { agent }
}

// 更新 Agent：默认互斥 + 状态合法
async updateAgent(authorId, agentId, input): Promise<{ agent }> {
  // 1. 归属校验（author_id === authorId，否则 404）
  // 2. 若设 is_default=true → 事务内清除其他默认
  // 3. 更新字段；status ∈ {active, disabled}
  // 4. 审计 action='agent_update'
}
```

### 4.2 工具绑定与启停（`agent.service.ts`）

```ts
// 更新工具绑定
async updateTool(authorId, toolId, input): Promise<{ tool }> {
  // 1. 查 ai_tools（tool_id 存在，否则 404）
  // 2. 若 input.agent_id：校验 Agent 存在且 active（否则 404/409）
  // 3. 更新 agent_id / enabled / name / description
  // 4. 若停用（enabled=false）→ 附提示「有进行中任务引用时不受影响」
  // 5. 审计 action='tool_update'
}

// 停用默认 Agent 保护：默认 Agent 不能停用（否则无默认执行者）
// 默认 Agent 被软删/停用 → 需先转移默认，或拒绝操作
```

### 4.3 发起任务解析 Agent（修改 M3a `ai-task.service.ts`）

```ts
// 在 createTask 步骤 1（归属校验）与步骤 2（幂等检查）之间插入：
async createTask(authorId, workId, chapterId, input) {
  // 0. 按 input.tool 查 ai_tools：
  //      - 不存在 → 404「创作工具不存在」
  //      - enabled=false → 409「该创作工具已停用」
  // 0.5. 解析执行 Agent：工具已绑定 → 用其 agent_id；未绑定 → ensureDefaultAgent 懒创建默认 Agent 兜底
  //      默认 Agent 同时绑定全部启用工具（缺配置不中断）
  // 1. 悲观锁章节行 + 归属校验（复用 M2 assertOwnedChapter 模式）
  // 2. 幂等键检查（原逻辑）
  // 2.5. 写入 ai_tasks.agent_id = 解析出的 agent_id（M3a 预留字段接入）
  // 3~7. 创建任务 / 写事件 / 入队 / 审计（原逻辑）
}
```

### 4.4 配置变更即生效语义

| 场景 | 行为 |
|------|------|
| 保存工具绑定新 Agent | 后续新任务按新 agent_id 执行；已入队/执行中任务保持原配置 |
| 停用工具 | 后续新任务 409；进行中任务不受影响 |
| 停用 Agent | 绑定该 Agent 的工具在下次解析时校验失败（404/409） |
| 设默认 Agent | 同作者仅一个默认；默认 Agent 被停用前必须转移默认 |

## 五、异常处理（对齐需求澄清 §五）

| 场景 | 异常 | 状态码 | 响应体 |
|------|------|--------|--------|
| 未登录 | UnauthorizedException | 401 | `{ error, request_id }` |
| 无权限/归属不符 | NotFoundException | 404 | `{ error, request_id }` |
| 工具不存在 | NotFoundException | 404 | `{ error, request_id }` |
| 绑定不存在 Agent | NotFoundException | 404 | `{ error, request_id }` |
| 绑定停用 Agent / 停用工具仍发起 | ConflictException | 409 | `{ error, details }` |
| 非法输入（缺 name/缺 model_id/非法 model_config） | ZodValidationPipe | 422 | `{ error, fields }` |
| 同作者 Agent 名称重复 | ConflictException | 409 | `{ error, details: { name } }` |
| 默认 Agent 设为停用 | ConflictException | 409 | `{ error, details }` |

## 六、前端设计（`apps/web/src/agent/`）

### 6.1 Agent 管理面板

- **触发入口**：写作工作台右侧面板新增「Agent 管理」tab（深链 `?panel=agent`）。
- **工具清单**：每个工具一行，显示名称/绑定 Agent/状态徽章（启用/停用）/「配置」按钮。
- **配置表单**：选择目标 Agent（下拉，来自 `GET /ai-agents` 的 active 列表）、模型参数（温度/最大 token 受控字段）、启用开关、设默认按钮。
- **Agent 列表**：当前作者的 Agent 列表，支持新增/编辑/软删/设默认。
- **变更即生效**：保存后刷新工具清单，后续发起任务按新配置执行。

### 6.2 交互与可访问性

- 状态徽章使用文字标签（启用/停用），禁止 Emoji。
- 表单字段均以可见 label 关联；焦点流：工具行 → 配置按钮 → 表单字段 → 保存。
- 面板容器 `role=tabpanel` + `aria-labelledby`，与既有 tab 语义一致（沿用 M3a A9 模式）。

## 九、部署与运行

1. **迁移自动执行**：`agent-config-base` 迁移随 `pnpm --filter @storyforge/api start:dev` 自动执行；种子仅 4 工具（幂等 `ON CONFLICT (tool_id) DO NOTHING`），默认 Mock Agent 由 `ensureDefaultAgent` 在首次发起任务时懒创建（原因见 §2.2）。
2. **与 M3a 兼容**：M3b 落地后，M3a 既有任务链路因种子数据而保持可用；前端仍从 API 拉取工具清单（移除硬编码 4 工具）。
3. **无新增外部依赖**：本期不接真实模型厂商，`ai-model.provider.ts` 不变，仅复用 M3a Mock Provider。
4. **审计复用**：`agent_create`/`agent_update`/`tool_update` 写入 `audit_logs`，沿用 M2 审计服务。

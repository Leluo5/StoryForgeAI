## 一、用户诉求（非技术语言）

### 1.1 要解决的核心痛点

M3a 交付后，作者可以发起 AI 创作任务并看到进度，但任务执行者的配置方式仍存在三类困扰：

1. **执行者不可配置**：M3a 用 1 个固定 Mock 模型打通闭环，作者无法选择「这个创作任务由哪个 Agent 执行、用什么模型参数」。
2. **工具与执行者耦合**：AI 创作工具（续写/润色/扩写等）的标识在 M3a 是前端硬编码的 4 个选项，服务端不感知「哪个工具该配哪个 Agent」。
3. **配置无界面**：作者或管理员想调整某工具的执行 Agent、模型参数，没有可视化管理入口，只能改代码或改配置文件。

### 1.2 期望的完整体验

作者（或管理员）在写作工作台中打开「Agent 管理」后：

1. **看到工具清单**：系统列出所有已注册的 AI 创作工具，每个工具显示当前绑定的执行 Agent 与模型参数概要。
2. **配置执行 Agent**：对某个创作工具，作者可以指定其执行 Agent（如「续写用 Agent 甲、润色用 Agent 乙」），并能设置模型参数（如温度、最大 token）。
3. **启停与默认**：可以启用/停用某个工具 Agent，并设置一个默认 Agent；停用后发起任务时给出明确提示。
4. **变更即生效**：配置保存后，后续发起的新任务按新配置执行；进行中的任务不受影响。
5. **安全可审计**：配置变更写入审计日志，作者知道谁在何时改了哪个工具的 Agent 配置。

### 1.3 核心目标（与 M3 验收门槛一致）

| 目标 | 说明 |
| --- | --- |
| 工具与 Agent 解耦 | 创作工具标识由服务端注册表管理，不再前端硬编码；工具可绑定任意可用 Agent |
| Agent 可配置 | 每个工具可指定执行 Agent 与模型参数，配置持久化、变更即生效 |
| 配置有管理界面 | 写作工作台提供「Agent 管理」入口，支持查看/配置/启停/默认 |
| 变更可审计 | Agent 配置的创建/修改/启停/默认切换写入审计日志 |
| 与 M3a 无缝衔接 | 发起 AI 任务时按工具解析出执行 Agent，写入 `ai_tasks.agent_id` |

## 二、功能边界

### 2.1 包含（In Scope）

1. **Agent 配置实体**：Agent（执行者）的创建、查询、更新、启停、删除（软删），字段含名称/平台/模型标识/模型参数/状态。
2. **工具注册表**：AI 创作工具（续写/润色/扩写/大纲/剧情推衍等）的服务端注册表，含工具标识、展示名、默认 Agent、启停。
3. **工具 ↔ Agent 绑定**：为每个创作工具指定执行 Agent，支持默认 Agent、停用校验、配置变更即生效。
4. **前端管理面板**：写作工作台右侧面板新增「Agent 管理」tab，支持查看工具清单、配置 Agent、启停、设默认。
5. **发起任务接入**：M3a 发起 AI 任务时，按工具解析执行 Agent 并写入 `ai_tasks.agent_id`；工具停用时拒绝发起。
6. **审计日志**：Agent/工具配置的创建、更新、启停、默认切换写入审计日志（复用 M2 审计服务）。

### 2.2 不包含（Out of Scope）

1. **AI 创作工具全集**（M3b 后续段）：具体工具的执行逻辑、上下文注入、提示词模板不在本期；本期只建「Agent 配置 + 工具注册 + 绑定」的管理骨架，仍沿用 M3a 的 Mock 模型执行。
2. **Coze Provider 接入**（M3b 后续段）：真实外部模型厂商（Coze）的 API 对接、Token 计费、密钥管理不在本期；`ai-model.provider.ts` 保留可插拔接口，本期继续用 Mock Provider 验证配置链路。
3. **角色 Agent / 流程 Agent**（M3b 后续）：角色版图 Agent、多步流程 Agent 的类型注册不在本期；本期聚焦「创作工具 Agent」一类。
4. **剧情树 / 角色版图 / 知识库**（M3c）：创作工具的专用上下文能力不在本期。
5. **多人协同与权限分级**：本期 Agent 配置对所有登录作者可见可改；若后续需区分管理员与作者权限，另行评估。
6. **外部模型参数面板**：模型参数（温度等）本期以受控字段表单配置，不做任意 JSON 高级编辑器。

## 三、功能流程

### 3.1 查看工具清单与 Agent 绑定

```
作者打开「Agent 管理」面板
  → 前端请求工具注册表（含每个工具当前绑定 Agent、状态、模型参数概要）
  → 服务端返回工具清单 + 可用 Agent 列表
  → 面板渲染：每个工具一行，显示名称/绑定 Agent/状态/「配置」按钮
```

### 3.2 配置工具的执行 Agent

```
作者点击某工具的「配置」
  → 表单预填当前绑定 Agent 与模型参数
  → 选择目标 Agent、填写模型参数
  → 提交保存（含工具标识、agent_id、model_config、enabled）
  → 服务端校验：Agent 存在且启用、工具存在
  → 写入配置，写审计日志
  → 返回更新后的工具清单
```

### 3.3 启停工具与设默认

```
作者点击某工具的「停用」
  → 服务端校验：若该工具正在进行中的任务引用，则允许停用但提示「已在进行任务不受影响」
  → 工具状态=停用，写审计日志
  → 作者点击「设为默认」
  → 同一时刻仅一个默认 Agent（默认 Agent 必须处于启用状态）
```

### 3.4 发起任务时解析执行 Agent（M3a 接入）

```
作者在「AI 创作」面板发起任务（携带工具标识）
  → 服务端读取工具注册表，解析该工具的当前绑定 Agent
  → 若工具已停用 → 返回 409，提示「该创作工具已停用」
  → 否则写入 ai_tasks.agent_id = 解析出的 Agent 标识
  → 任务进入 M3a 队列正常执行（本期仍用 Mock Provider）
```

### 3.5 配置变更即生效

```
作者保存配置后
  → 后续新发起任务按新配置解析执行 Agent
  → 已入队/执行中任务保持原配置，不受影响
  → 前端面板立即反映最新配置状态
```

| # | 验收标准 | 验证方式 |

## 五、异常与边界处理

| 场景 | 系统行为 | 用户反馈 |
| --- | --- | --- |
| 未登录/无作品权限 | 拒绝访问配置，401/403 | 提示登录或权限说明 |
| 工具标识不存在 | 404 | 提示工具不存在 |
| 绑定不存在的 Agent | 422 | 提示 Agent 不存在 |
| 绑定停用的 Agent | 409 | 提示该 Agent 已停用 |
| 工具已停用仍发起任务 | 409 | 提示「该创作工具已停用」 |
| 设默认 Agent 但目标已停用 | 409 | 提示不能设停用 Agent 为默认 |
| 配置保存时模型参数非法 | 422，字段错误内联展示并聚焦首个错误 | 表单错误提示 |
| 进行中任务引用被停用工具 | 允许停用，进行中任务不受影响 | 提示「已在进行任务不受影响」 |
| 并发配置冲突 | 以最后一次保存为准，写入审计 | 无感知（乐观） |

## 六、数据字段说明（概念模型）

### 6.1 Agent（执行者）

| 字段 | 说明 |
| --- | --- |
| `agent_id` | Agent 标识（不可猜解 UUID） |
| `name` | Agent 名称（如「标准续写 Agent」） |
| `platform` | 模型平台（本期 `mock`；`coze` 留待后续） |
| `model_id` | 模型标识（如 `mock-continue-v1`） |
| `model_config` | 模型参数（温度、最大 token 等，受控字段） |
| `status` | `active / disabled` |
| `is_default` | 是否默认 Agent（同刻仅一个） |
| `created_at` / `updated_at` | 时间戳（UTC 存储，界面按上海时区显示） |

### 6.2 创作工具（注册表）

| 字段 | 说明 |
| --- | --- |
| `tool_id` | 工具标识（如 `continue` 续写、`polish` 润色） |
| `name` | 工具展示名 |
| `agent_id` | 当前绑定执行 Agent |
| `enabled` | 是否启用 |
| `description` | 工具说明（可选） |
| `created_at` / `updated_at` | 时间戳 |

## 七、相关依赖与约束

1. **复用 M3a AI 任务**：`ai_tasks.agent_id`（uuid 可空）已预留，本期从「发起任务时按工具解析 Agent」接入。
2. **复用 M2 审计服务**：Agent/工具配置变更写入 `audit_logs`。
3. **复用契约模式**：前后端从 `@storyforge/contracts` 复用 Zod Schema（沿用 M1/M2/M3a 模式）。
4. **复用鉴权模式**：`SessionGuard` + `CsrfGuard` + `ZodValidationPipe` + `ok()` 包装（沿用 M1/M2/M3a）。
5. **工具注册表服务端权威**：创作工具标识由服务端注册表管理，前端从 API 拉取，禁止前端硬编码工具清单。
6. **外部模型不接真实厂商**：本期仍用 M3a 的 Mock Provider 验证配置链路；`ai-model.provider.ts` 保留可插拔接口，Coze 接入属 M3b 后续段。
7. **安全**：模型参数只存服务端；配置 API 不做任意 JSON 透传，受控字段 Zod 校验，防止注入。

# 子图注入 Agent 的 Prompt 策略

> 版本：v1.0 · 状态：设计探讨（2026-11-25）  
> 项目：StoryForgeAI —— 专业小说 AI 写作软件  
> 类型：Prompt 工程 / Agent 上下文设计  
> 关联：[角色关系图谱算法探讨](./角色关系图谱算法探讨.md)、[角色档案字段设计深入探讨](./角色档案字段设计深入探讨.md)、[知识库结构化字段详细定义](./知识库结构化字段详细定义.md)  
> 说明：讨论如何将「角色关系子图」及关联人设，稳定、省 token 地注入角色 Agent、对话生成与剧情推衍。

---

## 一、目标与约束

### 1.1 要解决的问题

| 不注入子图时的典型失败 | 注入后的期望 |
|------------------------|--------------|
| 角色认错人、叫错关系 | 关系称谓与立场正确 |
| 宿敌突然亲密 | 敌对/同盟边界清晰 |
| 忽略师徒、血缘等硬约束 | 行为符合既有关系 |
| 把整库人设塞进 Prompt | 只带**当前决策相关**的人 |

### 1.2 硬约束

1. **Token 预算有限**：子图 + 人设摘要通常应控制在总上下文的一小块（建议 **300–800 中文字符**量级可调）。  
2. **禁止编造**：只允许图谱与 character 档案中已有信息。  
3. **权威源**：人设以独立 `character` 条目为准，不以小说拆文快照覆盖。  
4. **可解释**：必要时能向用户展示「本次用了哪些关系」。

## 二、子图选取策略（先选对，再写进 Prompt）

按任务选择不同的子图，而不是永远「主角 2 跳全图」。

### 2.1 策略对照

| 策略 | 定义 | 适用场景 | Token | 风险 |
|------|------|----------|-------|------|
| **A. 场景出场星型** | 以「本章/本场出场角色集合 S」为种子，取 S 的诱导子图（只保留 S 内部边） | 对话生成、场景续写 | 低 | 场外关键关系可能缺失 |
| **B. 自我中心 k 跳** | 以单角色 c 为中心，距离 ≤ k 的邻居（k=1 默认，复杂动机用 k=2） | 单角色 Agent、内心戏 | 中 | k=2 时边数上升快 |
| **C. 成对路径** | 角色 A 与 B 之间的最短路径（及路径上节点的人设摘要） | 双人对手戏、关系对质 | 低 | 多路径时需择一或列前 2 条 |
| **D. 阵营切片** | 同 camp / 同 faction 边诱导的子图 | 多人对峙、站队 | 中 | 依赖阵营标注质量 |
| **E. 混合（推荐默认）** | 出场集合诱导子图 ∪ 每个出场角色的 1 跳「硬关系」（血缘/师徒/宿敌）即使对方未出场 | 大多数写作场景 | 中 | 实现稍复杂，效果最好 |

**产品默认建议：策略 E（混合）。**

### 2.2 边的优先级过滤

注入前对边排序/截断，避免噪声：

| 优先级 | 关系类型（归一后） | 说明 |
|--------|--------------------|------|
| P0 | family / mentor / romance | 强约束，几乎总应注入 |
| P1 | enemy（宿敌级） | 防止立场写崩 |
| P2 | ally / faction | 有预算再加 |
| P3 | other | 最后；可只保留 weight 高的 |

截断规则示例：

- 最多 **N 条边**（如 12）  
- 最多 **M 个邻接角色**（如 8）  
- 同优先级按 `weight` 或与主角的关联度排序  

### 2.3 节点人设摘要截断

每个相关角色不必注入完整 `CharacterStructured`，而用 **压缩卡**：

```text
[角色] 姓名｜identity｜personality 前 3 条｜speech_style 一句｜与中心的关系标签
```

P0 字段优先：`name, identity, personality, speech_style`；`background/arc` 仅在「动机相关任务」时附加一句。

## 三、序列化格式（怎么写进 Prompt）

LLM 对结构化短文本敏感。推荐 **固定模板**，少用大型 JSON（费 token 且易被模型复读）。

### 3.1 格式一：关系列表式（默认）

```text
【关系约束】（仅使用下列已设定关系，勿发明新关系）
- 林远 —[敌对/宿敌]→ 贺兰策
- 林远 —[师徒]→ 陈墨（林远为徒）
- 苏晚 —[名义婚约]→ 燕王萧景
```

### 3.2 格式二：人设卡片式

```text
【在场角色人设】
- 林远｜青云城少年｜隐忍、护短｜对白短句
- 贺兰策｜前边军少帅·北境修罗｜冷峻、简言｜与林远：宿敌，实为未相认兄长
```

### 3.3 格式三：路径说明式（对手戏）

```text
【二者关系链】
林远 —敌对→ 贺兰策（宿敌；档案注：未相认兄长）
无更短路径。
```

### 3.4 格式四：禁止清单式（强约束）

在列表后再加一行硬规则：

```text
【硬禁止】
- 不得让林远与贺兰策表现为主动同盟或亲密无防
- 不得改变已列出的师徒方向
```

**组合建议**：`人设卡片` + `关系列表` +（可选）`硬禁止`。路径式仅在双人焦点时使用。

## 四、注入位置与 Prompt 结构

典型 Agent 消息结构：

```text
[System]
你是写作助手 / 角色扮演「{name}」。必须遵守人设与关系约束，不得编造未提供的人物关系。

[关系与人设块]   ← 子图序列化结果放这里（system 后半或独立 system）
【在场角色人设】
...
【关系约束】
...

[任务块]
当前场景目标：...
用户指示：...

[最近正文 / 对话历史]
...
```

### 4.1 放置原则

| 原则 | 说明 |
|------|------|
| 靠近任务说明 | 关系块紧挨「请续写/请以某某口吻回复」，减少被长历史冲淡 |
| 与人设同一块 | 避免关系在 system 顶、人设在 user 底导致不一致 |
| 重复关键约束 | 对 P0 敌对/血缘，可在任务块再点名一次（一句话） |
| 不塞全图 | 禁止把全局版图所有边注入 |

### 4.2 角色扮演 vs 上帝视角推衍

| 模式 | 子图中心 | 人设注入 |
|------|----------|----------|
| **单角色 Agent** | 该角色 ego k=1（+ 硬关系） | 详写中心角色，邻居只保留 identity+关系 |
| **场景续写（多角色）** | 出场集合混合策略 E | 出场者均等压缩卡 |
| **剧情推衍** | 相关情节节点上的角色集合 | 可加 arc 一句，强调动机变化 |

## 五、动态组装流程（实现视角）

```text
输入：taskType, focusCharacterIds[], sceneCharacterIds[], chapter?
    ↓
1. 解析图谱快照（已 name→id 对齐的边表）
    ↓
2. 按 taskType 选策略 A/B/C/E
    ↓
3. 边过滤（relationType 优先级 + 上限 N）
    ↓
4. 拉取 character 档案 → 生成压缩卡（字段白名单）
    ↓
5. 序列化为固定中文模板字符串
    ↓
6. 计入 token 估算；超预算则先丢 P3 边，再缩短 personality
    ↓
7. 填入 Agent Prompt 槽位 {{relation_subgraph}}
```

### 5.1 伪接口

```ts
type SubgraphInjectParams = {
  taskType: 'roleplay' | 'scene_write' | 'plot_derive' | 'duet';
  focusIds?: string[];       // 中心角色
  sceneIds: string[];        // 出场
  maxEdges?: number;         // default 12
  maxNodes?: number;         // default 8
  includeArc?: boolean;
};

function buildRelationPromptBlock(params: SubgraphInjectParams): string;
```

## 六、Prompt 策略细则

### 6.1 指令层（减少幻觉）

在关系块前后使用明确指令：

```text
以下「关系约束」与「人设」来自作者知识库，是当前最高优先级事实。
- 只能使用已列出的人物与关系。
- 若需引入未列出的人物，必须当作路人，不得赋予与主角的深层关系。
- 若对话与约束冲突，以约束为准，并调整对白。
```

### 6.2 冲突消解

当正文历史与图谱不一致时（作者改了关系但旧章未改）：

| 策略 | 做法 |
|------|------|
| **图谱优先（默认）** | Prompt 写明「以关系约束为准」 |
| **正文优先** | 适合修文模式，需用户显式选择 |
| **提示用户** | UI 显示「检测到关系与近文不一致」 |

### 6.3 温度与采样

- 强关系约束场景：temperature **0.4–0.7**，避免过飘  
- 纯文笔润色、关系已锁死：可略升  

### 6.4 少样例（可选）

一般**不必**在关系注入场景再加长 few-shot；关系块本身已是约束。若模型仍乱认亲戚，加 **1 条负例**：

```text
错误示范：林远对贺兰策说「好兄弟咱们一起走」——违反「敌对/宿敌」约束。
```

## 七、Token 预算与降级

| 阶段 | 动作 |
|------|------|
| 超 100% 预算 | 删除 P3 边 |
| 仍超 | 邻居 personality 改为最多 2 词 |
| 仍超 | 去掉未与 focus 直接相连的节点卡，只留边列表 |
| 仍超 | 仅保留 P0 边 + 中心角色卡 |

监控指标：注入块字符数、边数、模型「编造新关系」的人工抽检率。

## 八、评测维度（上线前）

| 维度 | 方法 |
|------|------|
| 关系遵守率 | 给定敌对/师徒设定，生成 10 段对话，人工或规则检查违规 |
| 称谓正确率 | 检查「师父/兄长/殿下」等是否与 relation 一致 |
| 编造率 | 是否出现未注入人物的深度关系 |
| 文笔损伤 | 注入后是否明显变说明书口吻（需调模板语气） |
| 延迟 | 子图组装是否 < 50ms（本地图） |

## 九、反例与对策

| 反例 | 原因 | 对策 |
|------|------|------|
| 注入全局 80 人关系 | 信息过载，模型抓不住重点 | 策略 E + 硬上限 |
| 只注入名字不注入关系类型 | 模型自由脑补 | 边必须带标签 |
| JSON 大段 dump | 浪费 token、易复读 | 中文列表模板 |
| 更新了档案但 Prompt 仍用旧缓存 | 数据不同步 | 图谱版本号 / updated_at |
| 多义关系「亦敌亦友」 | 单标签不够 | relationLabel 保留原文 + type=other 或双标签 |

## 十、推荐默认策略（可写进实现）

1. **任务默认用混合策略 E**：出场诱导子图 + 每名出场角色的 P0/P1 一跳硬关系。  
2. **序列化**：`【在场角色人设】` + `【关系约束】` + 简短 `【硬禁止】`（由 P0 边自动生成）。  
3. **上限**：≤8 节点、≤12 边；超出按优先级裁。  
4. **单角色扮演**：中心角色完整压缩卡（可含 speech_style），邻居仅一行。  
5. **双人焦点**：追加最短路径句。  
6. **权威声明**：图谱与人设高于聊天历史中的即兴关系。

## 十一、示例：完整注入块

```text
【在场角色人设】（来自知识库，请严格遵守）
- 林远｜青云城少年，玄天体持有者｜隐忍、对认定者护短｜对白短句
- 贺兰策｜前边军少帅·北境修罗｜冷峻、复仇心重｜对白极简

【关系约束】
- 林远 —[敌对/宿敌]→ 贺兰策（档案注：实为未相认兄长，当面仍为敌对立场）
- 林远 —[师徒]→ 陈墨（陈墨为师；本场未出场，仅作立场参考）

【硬禁止】
- 不得写成林远与贺兰策已和解或并肩同盟
- 不得否认二者战场敌对现状

请基于以上约束续写雨夜对峙的对白，保持各自语气。
```

## 十二、结论

子图注入的关键不是「图算法有多炫」，而是：

1. **选少、选准**（出场 + 硬关系）  
2. **序列化可读**（短列表，非大 JSON）  
3. **优先级裁剪**（家族/师徒/宿敌优先）  
4. **权威与禁止句**（降低幻觉）  
5. **与 character 权威源一致**  

按此策略，角色 Agent 与推衍可在可控 token 内明显减少关系类错误。

## 一、需求背景与目标

### 1.1 背景

现有 `StoryForgeAI` 是一个「Coze 作品展示与在线体验平台」，能力边界停留在**单一作品在线体验**：访客浏览作品大厅、选择单个作品、以 `chat` / `form` / `mixed` 模式与智能体对话或运行工作流。

该形态对**小说创作**场景存在明显缺口：

| 缺口 | 现状 | 影响 |
| --- | --- | --- |
| 无角色身份体系 | 每次体验都是独立会话，角色无身份归属 | 无法让 AI 稳定扮演同一角色 |
| 无记忆连续性 | 会话不跨请求保留角色记忆 | 角色前后言行不一致 |
| 无多角色协同 | 同一作品只允许单一智能体交互 | 无法模拟多人场景、多线叙事 |
| 无专业写作工具 | 仅在线聊天，无大纲/章节/校对等工具 | 无法完成完整创作流程 |

### 1.2 改造定位

将 StoryForgeAI 改造为**专业小说 AI 写作软件**，核心是把「单一作品在线体验」升级为「角色驱动的小说创作工作台」。改造不推倒既有架构，而是叠加四块新能力：

1. **角色专属 cozeAgent 分配机制**：为每个小说角色独立配置、绑定、管理独立 cozeAgent 实例，保证角色身份一致性、记忆连续性、行为逻辑独立性；支持单角色绑定多个 cozeAgent 按预设流程有序调用。
2. **写作工具集成**：完整集成 14 个写作工具模块，与角色 Agent 体系深度联动，无功能断点、无调用延迟。
3. **多角色协同写作**：多个角色 Agent 在同一小说项目下协同推进情节，数据流转规则清晰。
4. **创作工具模块扩展**：在既有 14 个写作工具之上，新增知识库管理（F5，含小说大纲自动提取）、剧情推衍聊天室（F6）、剧情树（F7）三个创作工具模块，与角色 Agent 体系双向联动。

### 1.3 改造成功衡量标准（概要）

| 指标 | 目标值 |
| --- | --- |
| 角色 Agent 调用成功率 | ≥ 99.5%（连续 7 天，按调用次数统计） |
| 接口响应时间（非流式 API） | ≤ 200ms（P95） |
| 流式首包时间 | < 500ms（P95） |
| 角色一致性命中率 | 100% |
| 记忆连续性 | 100% |
| 写作工具可用率 | 100%（14 个工具全部可调用） |
| 多角色协同无冲突 | 100% |
| 并发承载 | ≥ 50 并发 |
| 数据丢失率 | 0% |
| 创作工具模块可用率 | 100%（F5/F6/F7 全部可调用） |
| 剧情推衍多线程隔离 | 100% |
| 剧情随机上下文符合率 | 100% |
| 剧情树回写一致性 | 100% |

> 完整量化口径与判定方法见 [验收标准](./验收标准.md)。

## 二、目标用户与使用场景

### 2.1 目标用户

| 用户 | 诉求 | 解决方式 |
| --- | --- | --- |
| **小说创作者** | 让 AI 扮演有稳定身份的角色，辅助完成从大纲到章节的完整创作 | 角色 Agent 体系 + 14 个写作工具 |
| **写作团队 / 协同创作者** | 多人、多角色在同一小说项目下协同推进情节 | 多角色协同写作 + 项目级数据流转 |
| **剧情推衍爱好者** | 基于已有角色/剧情上下文做随机推衍、分支探索 | 剧情推衍聊天室（F6）+ 剧情树（F7） |
| **知识管理用户** | 沉淀角色设定、世界观、素材库，供创作时引用 | 知识库管理（F5） |

### 2.2 核心使用场景（P1-T1 场景调研结论）

**场景 A · 单角色辅助创作**

1. 创作者创建小说项目，设定书名、题材、世界观。
2. 创建主要角色，配置角色年龄、性别、性格、经历。
3. 为角色绑定 ≥ 1 个 cozeAgent，按 11 步预设流程（外貌 → 个性 → … → 情节发展）有序调用。
4. 调用「生成小说大纲」工具，多角色协同产出大纲。
5. 调用「生成章节内容」工具，按情节发展步骤调用角色 Agent 产出章节。
6. 使用一致性检查、情感分析等工具打磨章节。

**场景 B · 多角色协同写作**

1. 同一小说项目下创建 ≥ 2 个角色，各自绑定独立 Agent。
2. 开启协同写作，项目获得写锁。
3. 各角色 Agent 依序调用，可并行读取、串行写入。
4. 各角色输出写入独立上下文，汇总到章节。

**场景 C · 剧情推衍 + 剧情树联动**

1. 在剧情推衍聊天室（F6）拉入角色，配置随机系统参数。
2. 剧情树（F7）节点作为推衍起始上下文。
3. 每步推衍后自动暂停（一步一断），开放用户修改与分支选择。
4. 推衍结束自动将结果作为新剧情节点回写剧情树（原子性 + 环路检测）。

**场景 D · 知识库支撑**

1. 录入角色设定、世界观、素材等资料（多类型：文本/链接/文件）。
2. 结构化拆分、知识关联。
3. 小说拆文完成后自动触发大纲自动提取（四维度：章节结构/情节节点/人物关系/故事线）。
4. 知识库条目可只读注入角色上下文，角色不可写知识库。

## 三、核心创作流程

### 3.1 总体创作流程（P1-T2 结论）

```text
创建项目 → 配置世界观 → 创建角色 → 绑定角色 Agent → 生成大纲
  → 生成章节 → 一致性检查 / 情感分析 → 版本管理 → 长篇小说 / 有声书 / 导出
```

### 3.2 角色 Agent 11 步预设流程（P1-T3 结论）

| 步骤 | 名称 | 说明 | 触发工具联动 |
| --- | --- | --- | --- |
| 1 | 外貌特征 | 角色外观设定 | 生成角色图像 |
| 2 | 个性特点 | 性格特质 | — |
| 3 | 思维方式 | 认知模式 | — |
| 4 | 个人能力 | 技能特长 | — |
| 5 | 情感状态 | 当前情绪 | 情感分析 |
| 6 | 文化背景 | 出身文化 | — |
| 7 | 信仰道德 | 价值观与信念 | — |
| 8 | 成长线 | 成长弧线 | — |
| 9 | 经历沉淀 | 过往经历 | — |
| 10 | 人际关系 | 社交网络 | — |
| 11 | 情节发展 | 参与剧情 | 生成章节内容、剧情推衍 |

> 规则：step_order 1-11 完整、可重排、可增删；单角色绑定多 Agent 时按 step_order 排序，命中当前步骤或此前步骤即调用。

### 3.3 角色身份三原则

| 原则 | 要求 |
| --- | --- |
| 身份一致性 | 每次调用携带 `role_id` 作为系统提示词前缀（`你扮演角色<role_id>，保持身份一致`）；会话 key = `f"{role_id}:{agent_id}"`，禁止跨角色复用 |
| 记忆连续性 | Agent 会话存 `memory_state`（JSON），跨会话恢复；角色记忆按 role_id 独立命名空间 |
| 行为逻辑独立性 | 每个角色 Agent 绑定独立 `agent_id`，不共享上下文；多角色并行用 `project_id` 写锁防写冲突 |

### 4.2 三个新增创作工具模块（P1-T4 扩展）

| 模块 | 编号 | 注册名 | 功能描述 | 角色联动 | 关键能力 |

| Agent 绑定管理 | 绑定/更新/列出/启停 | 独立管理接口 |

## 五、功能边界（概要）

### 5.1 角色 Agent 能力边界

| 规则类别 | 定义 |
| --- | --- |
| 禁止项 | 跨角色读写、篡改项目元数据、访问管理端 API、删除章节/版本 |
| 允许项 | 读写本角色上下文、读取项目元数据（只读）、调用绑定工具、追加本角色生成章节 |
| 条件触发项 | 生成情节发展内容（step 11）、多角色协同写作（需写锁）、长耗时工具（需队列） |

### 5.2 明确不做

| 事项 | 说明 |
| --- | --- |
| 不做付费/账号体系 | 保持个人规模，无注册登录（管理端除外） |
| 不做实时多人编辑 | 协同为角色 Agent 协同，非真人实时协作 |
| 不做移动端 App | 仅 Web，桌面主场景 |
| 不做外部发布 | 仅本地/内网部署，不接公网托管 |

> 完整三类规则与数据流转见 [功能边界定义](./功能边界定义.md)。

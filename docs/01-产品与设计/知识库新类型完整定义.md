## 一、类型总览（新增）

| 类型代码 | 中文名 | 优先级 | 核心定位 |
|----------|--------|--------|----------|
| `character` | 角色档案 | P0 | 单个或一组角色的详细设定与弧光 |
| `plot_template` | 情节模板 | P0 | 可复用的情节结构与节拍 |
| `reference_work` | 对标作品 | P1 | 对已有作品的拆解与学习笔记 |
| `technique` | 写作技法 | P1 | 具体可执行的写作方法与示范 |
| `reader_feedback` | 读者反馈 | P2 | 读者评论与数据洞察 |
| `timeline` | 时间线 | P2 | 故事或创作相关的时间事件序列 |

## 二、character（角色档案）

### 2.1 判定规则

**判定特征（满足任意 2 项即可倾向判定为 character）：**
- 以单一或少数角色为描述中心
- 重点在性格、背景、外貌、能力、说话方式、成长弧光
- 包含关系描述，但主体不是完整故事情节
- 常见形式：人物小传、角色卡、人设文档

**排除特征：**
- 有完整情节推进与多场景叙事 → 倾向 `novel`
- 以世界规则、力量体系为主 → 倾向 `setting`
- 碎片化一句话想法 → 倾向 `inspiration`

### 2.2 结构化字段

```ts
interface CharacterStructured {
  name: string;                          // 主角色名（必填）
  aliases?: string[];                    // 别名/绰号
  identity: string;                      // 身份定位（一句话）
  personality: string[];                 // 性格关键词或描述
  background: string;                    // 背景故事摘要
  appearance?: string;                   // 外貌
  abilities?: string[];                  // 能力/特长
  arc?: string;                          // 人物弧光（成长/堕落路径）
  speech_style?: string;                 // 对白风格与用词习惯
  relationships: RelationItem[];         // 重要关系
  key_quotes?: string[];                 // 代表性台词
  notes?: string;                        // 其他补充
}

interface RelationItem {
  target: string;                        // 对方名称
  relation: string;                      // 关系类型与说明
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | 是 | 主角色姓名 |
| `identity` | 是 | 一句话身份定位 |
| `personality` | 是 | 性格要点 |
| `background` | 是 | 背景摘要 |
| `relationships` | 是 | 可为空数组 |
| 其余 | 否 | 按原文丰富程度填充 |

### 2.3 Few-shot 判定示例

```text
【示例】
正文：林远，表面是青云城普通少年，实则拥有上古玄天体。性格坚毅隐忍，不善言辞，但对认定的人极度护短。幼时父母被神秘势力所杀……对白习惯用短句，很少比喻。
输出：
{"type":"character","confidence":0.94,"reason":"以单一角色为中心，描述性格、背景、能力与说话方式，非完整叙事"}
```

### 2.4 Few-shot 结构化提示词（核心部分）


## 三、plot_template（情节模板）

### 3.1 判定规则

**判定特征（满足任意 2 项即可）：**
- 描述的是情节结构、节拍、套路、冲突升级路径，而非具体故事
- 可被套用到不同作品（具有抽象性与可复用性）
- 常见词：三幕、英雄之旅、节拍、反转、爽点、节奏

**排除特征：**
- 具体人物 + 具体事件推进 → `novel`
- 纯世界观规则 → `setting`
- 写作文笔技巧 → `technique`

### 3.2 结构化字段

```ts
interface PlotTemplateStructured {
  structure_name: string;                // 模板名称（如「英雄之旅」「爽文节拍」）
  description: string;                   // 整体说明
  beats: Beat[];                         // 节拍列表
  applicable_genres?: string[];          // 适用题材
  conflict_pattern?: string;             // 冲突模式摘要
  example_usage?: string;                // 使用示例或注意事项
}

interface Beat {
  name: string;                          // 节拍名称
  order: number;
  description: string;                   // 该节拍要完成的叙事任务
  purpose?: string;                      // 目的（制造悬念/释放情绪等）
}
```

### 3.3 Few-shot 判定示例

```text
【示例】
正文：经典三幕结构：第一幕建立日常与激励事件；第二幕对抗升级与中点转折；第三幕高潮与解决。适用于大多数商业故事。
输出：
{"type":"plot_template","confidence":0.95,"reason":"描述抽象可复用的情节结构，而非具体故事"}
```

### 3.4 Few-shot 结构化提示词（核心）

```text
你是情节模板结构化助手。请提取可复用的结构信息，输出严格 JSON。

输出格式：
{
  "structure_name": "模板名称",
  "description": "整体说明",
  "beats": [
    {"name":"节拍名","order":1,"description":"叙事任务","purpose":"目的"}
  ],
  "applicable_genres": ["玄幻","都市"],
  "conflict_pattern": "冲突模式摘要",
  "example_usage": "使用注意"
}

===== 示例 =====
输入：爽文常见节拍——装逼遭打、证明实力、打脸反派、获得认可、埋下更大危机。
输出：
{
  "structure_name": "爽文经典节拍",
  "description": "通过反复「被压制→反转打脸」制造阅读快感",
  "beats": [
    {"name":"装逼遭打","order":1,"description":"主角被轻视或羞辱","purpose":"积累情绪"},
    {"name":"证明实力","order":2,"description":"展现隐藏能力或底牌","purpose":"反转"},
    {"name":"打脸反派","order":3,"description":"当众击败或羞辱对方","purpose":"释放爽感"},
    {"name":"获得认可","order":4,"description":"旁人态度转变","purpose":"巩固地位"},
    {"name":"埋下更大危机","order":5,"description":"引出更强敌人或隐患","purpose":"保持追更"}
  ],
  "applicable_genres": ["玄幻","都市","系统"],
  "conflict_pattern": "弱→强的反复打脸循环",
  "example_usage": "单节拍不宜过长，打脸后需快速进入下一危机"
}
```

## 四、reference_work（对标作品）

### 4.1 判定规则

**判定特征：**
- 主体是对另一部已有作品（小说/影视/游戏）的分析、拆解、优缺点总结
- 目的是学习或对标，而非讲述新故事
- 常见词：拆解、复盘、对标、学习、为什么火、节奏分析

**排除特征：**
- 作品原文或大量引用原文叙事 → `novel`
- 纯技法教学无具体作品 → `technique`

### 4.2 结构化字段

```ts
interface ReferenceWorkStructured {
  work_title: string;                    // 被分析作品名
  genre?: string[];                      // 题材
  strengths: string[];                   // 优点
  weaknesses: string[];                  // 不足
  key_techniques: string[];              // 值得学习的手法
  takeaways: string[];                   // 可落地的创作启发
  target_audience?: string;              // 目标读者
  notes?: string;
}
```

### 4.3 Few-shot 判定 + 结构化要点

判定示例：
```text
正文：分析《诡秘之主》为什么能做到长期追更：信息差控制极好，每卷都有明确阶段目标……
输出：{"type":"reference_work","confidence":0.92,"reason":"对已有作品进行结构化拆解与学习总结"}
```

结构化提示词核心字段要求：`work_title` 必填；`strengths` / `weaknesses` / `takeaways` 至少各有 1 条。

## 五、technique（写作技法）

### 5.1 判定规则

**判定特征：**
- 核心是「如何写」的具体方法、步骤、示范
- 可直接指导某一类段落或技巧的练习
- 常见：对话技巧、环境描写、悬念制造、文笔节奏

**排除特征：**
- 宏观结构套路 → `plot_template`
- 一般观点文章 → `article`

### 5.2 结构化字段

```ts
interface TechniqueStructured {
  technique_name: string;                // 技法名称
  description: string;                   // 说明
  steps: string[];                       // 可执行步骤
  examples: string[];                    // 正反示例
  common_mistakes: string[];             // 常见错误
  applicable_scenes?: string[];          // 适用场景
}
```

### 5.3 Few-shot 要点

判定示例：
```text
正文：如何写好对话——少用形容词，多用动作与潜台词；每人说话要有辨识度……
输出：{"type":"technique","confidence":0.93,"reason":"教授具体可执行的写作方法"}
```

## 六、reader_feedback（读者反馈）与 timeline（时间线）

### 6.1 reader_feedback

**判定**：来源为读者评论汇总、数据报告、追更/弃坑分析。  
**结构化建议**：
```ts
{
  source: string;                        // 来源说明
  positive_points: string[];             // 读者喜欢的点
  negative_points: string[];             // 弃坑或槽点
  data_insights?: string[];              // 数据洞察
  action_suggestions: string[];          // 对作者的改进建议
}
```

### 6.2 timeline

**判定**：以时间顺序排列的事件序列（故事内或创作相关）。  
**结构化建议**：
```ts
{
  title: string;
  events: [
    { date_or_order: string; event: string; importance?: "high"|"medium"|"low" }
  ];
  scope: "story_world" | "creation" | "other";
}
```

## 七、统一判定提示词（含新类型的完整版）

将原有五类 + 新类型合并后的类型列表更新为：

```text
可选类型：
- article：文章
- paper：论文
- novel：小说
- inspiration：灵感
- setting：设定集
- character：角色档案（以单一/少数角色为中心的人设与弧光）
- plot_template：情节模板（可复用的结构与节拍）
- reference_work：对标作品（对已有作品的拆解与学习）
- technique：写作技法（具体可执行的写作方法）
- reader_feedback：读者反馈
- timeline：时间线
```

判定时仍遵循「主要表达目的优先」原则，低置信度弹出人工确认。

## 八、落地建议

1. **先上 P0**：`character` 与 `plot_template`，与现有角色版图、剧情树联动价值最高。
2. **同步工作**：每上一个新类型，必须同步更新：
   - 分类规则文档
   - 结构化字段定义
   - 判定 + 拆分提示词（含 Few-shot）
   - 前端类型选择器与详情渲染模板
   - 测试用例
3. **数据迁移**：提供「将旧 setting/novel 中的角色向 character 迁移」的辅助工具（可选）。
4. **标签补充**：新类型内部仍用 tags 区分细类（如 character 的「主角/反派/配角」）。

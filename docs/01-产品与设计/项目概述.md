## 一、项目定位

**StoryForgeAI** 是一款面向**网络小说创作者**的专业级 AI 写作辅助工具。它以「角色驱动的 AI 创作工作台」为核心形态，帮助作者完成从大纲设定、人设刻画到章节续写的完整创作闭环，同时提供知识沉淀、剧情推衍、剧情树等专业创作模块，让 AI 真正成为小说创作的可靠协作伙伴，而非泛用聊天机器人。

它提供：

- 一套**角色 Agent 体系**：每个小说角色独立配置、绑定专属 AI Agent，保证身份一致性、记忆连续性、行为逻辑独立性；
- 一个**写作工具集**：大纲生成、章节续写、人设设定、风格匹配、润色优化等专业模块，与角色体系深度联动；
- 一组**创作支撑模块**：知识库管理、剧情推衍聊天室、剧情树，覆盖从设定沉淀到多线叙事探索的进阶场景。

### 1.1 一句话描述

> 让网络小说作者拥有一套懂角色、有记忆、能协同的专业 AI 写作工作台，从大纲到章节全程辅助。

## 三、核心价值主张

### 3.1 小说创作专属能力

区别于泛用 AI 助手，StoryForgeAI 围绕**小说创作场景**构建能力：

- **角色身份体系**：为每个角色绑定专属 Agent，AI 稳定扮演同一角色，杜绝「对话漂移」；
- **记忆连续性**：角色记忆跨会话保留，前后言行一致，长线叙事不断档；
- **多角色协同**：同一小说项目下多个角色 Agent 协同推进情节，可并行读取、串行写入；
- **11 步角色流程**：外貌、个性、思维、能力、情感、文化、信仰、成长、经历、人际、情节，全链路角色塑造。

### 3.2 创作效率提升

- **从大纲到章节一键贯通**：创建项目 → 配置世界观 → 创建角色 → 绑定 Agent → 生成大纲 → 生成章节，流程化推进；
- **批量产出能力**：长篇小说批量生成、有声书合成，长任务异步队列不阻塞主流程；
- **版本管理**：章节 / 项目快照，随时回滚对比，迭代不丢稿。

### 3.3 内容质量优化

- **一致性检查**：自动校验章节前后设定、角色言行一致性；
- **情感分析**：分析章节情感走向与角色情绪，辅助打磨节奏；
- **风格匹配**：按作者设定风格续写，保持全文文风统一。

## 四、核心功能清单

### 4.1 角色 Agent 体系（核心）

- **单角色多 Agent**：一个角色可绑定 ≥ 1 个 AI Agent，按 11 步预设流程有序调用；
- **Agent 绑定管理**：绑定 / 更新 / 列出 / 启停，独立管理接口；
- **角色上下文**：按 `role_id` 独立命名空间，身份一致、记忆连续、行为独立；
- **多角色协同**：项目写锁 + 串行写 + 时间戳冲突检测。

### 4.2 专业写作工具集（14 个）

| 模块 | 注册名 | 说明 |
| --- | --- | --- |
| 生成小说大纲 | `gen_outline` | 多角色协同产出大纲 |
| 生成章节内容 | `gen_chapter` | 按情节发展步骤调用角色 Agent |
| 一致性检查 | `consistency_check` | 设定 / 言行一致性校验 |
| 情感分析 | `emotion_analysis` | 章节情感走向与角色情绪 |
| 风格匹配 / 润色 | `run_70_workflow` | 70 步预设工作流，风格统一与润色 |
| 生成角色图像 | `gen_character_image` | 按外貌特征生成角色形象 |
| 生成世界地图 | `gen_world_map` | 按世界观生成地图 |
| 生成长篇小说 | `gen_novel` | 批量生成完整长篇小说 |
| 生成有声书 | `gen_audiobook` | 章节合成有声书 |
| 创建 / 导出 / 版本 | `new_project` / `open_project` / `export_novel` / `create_version` | 项目与版本管理 |
| 站点设置 | `open_settings` | 打开站点 / 项目设置面板 |

### 4.3 创作支撑模块（F5-F8）

- **知识库管理（F5）**：多类型资料录入、结构化拆分、知识关联、统一检索、**小说大纲自动提取**（四维度：章节结构 / 情节节点 / 人物关系 / 故事线）；
- **剧情推衍聊天室（F6）**：剧情基础配置、角色拉入 + 随机入场、步骤化推衍 + 随机系统、多线程隔离、一步一断；
- **剧情树（F7）**：两种生成模式、节点可视化、线性 / 非线性关联、拖拽 / 缩放 / 搜索 / 导出导入、版本管理、分支管理；
- **角色版图（F8）**：角色生成词库与角色版图服务。

### 4.4 既有底座功能（沿用）

- **作品展示大厅**：公开作品卡片式浏览；
- **在线体验**：`chat` / `form` / `mixed` 三种交互模式；
- **站点设置**：站点名、主题、全局 LLM 配置。

## 六、系统架构

```text
StoryForgeAI/                        # 项目根（源码 + 文档）
├── app.py            # Flask 主应用：全部 API 路由 + SSE 流式代理

│   ├── plot/             # 剧情：剧情树/剧情推衍/角色版图
│   ├── knowledge_base/   # 知识库管理（F5）
│   └── common/           # 公共：DTO/错误/存储/映射
├── data/            # 运行时数据（项目/知识库/锁，不入库）
├── static/          # 前端资源（css/js）
├── templates/       # 单页应用
├── tests/           # pytest 测试套件
```

### 6.2 后端分层


## 八、安全注意事项（重要）

1. **管理接口鉴权需补齐**：生产部署前必须实现会话校验（见 [04-安全与数据规范 §二](../02-技术与架构/开发规范/04-安全与数据规范.md)）。
2. **敏感凭据托管**：管理密码与 API Token 建议迁移至环境变量 / 密钥服务，避免明文落盘。
3. **角色 Agent 越权拦截**：角色 Agent 禁止跨角色读写、篡改项目元数据、访问管理端 API，违反即拦截 + 审计告警（见 [功能边界定义](./功能边界定义.md)）。

## 九、项目边界与后续建议

### 9.1 当前能力边界

- 单机、单进程 Flask 部署，非高可用。
- JSON 文件存储，非关系型数据库，适合个人 / 中小团队规模。
- AI 服务依赖创作者提供的 Token 与服务连通性。

### 9.2 后续可选增强

- [ ] 补齐管理接口鉴权（JWT / Session + 密码哈希）
- [ ] 敏感凭据迁移至环境变量 / 密钥服务
- [ ] JSON 存储迁移至 SQLite / MySQL（如需扩展）
- [ ] 增加作品访问量统计、作品排序与检索

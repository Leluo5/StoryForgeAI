## 一、项目定位

**StoryForgeAI** 是一个帮助创作者把 **Coze（扣子）平台** 上的智能体（Bot）、工作流、知识库批量导入并对外展示的 Web 应用。它提供：

- 一个**前台展示大厅**，访客无需登录 Coze 即可浏览作品并直接在线体验；
- 一个**管理后台**，创作者通过 PAT Token 拉取自己的 Coze 资源，一键批量导入为可展示作品；
- 一套**作品级访问控制**，可用访问码限制体验权限。

### 1.1 一句话描述

> 让不懂代码的创作者，也能把 Coze 智能体 / 工作流变成一个可分享、可体验、可控制的展示页面。

## 二、目标用户

| 用户 | 诉求 | 解决方式 |
|------|------|---------|
| **Coze 创作者** | 把自己做的智能体/工作流展示给他人，且不希望暴露源码/Token | 管理后台批量导入 + 公开作品页 |
| **访客 / 体验者** | 无需注册 Coze，直接与智能体对话或运行工作流 | 前台大厅 + 在线体验页（聊天/表单/mixed） |
| **站点运营者** | 统一管理站点名称、主题、访问权限 | 站点设置页（主题/访问码/全局 LLM 配置） |

## 三、核心功能清单

### 3.1 管理端（Admin）

- **PAT 连接测试**：校验 Coze PAT Token 与工作空间是否可用。
- **Coze 资源拉取**：列出智能体（Bot）/ 工作流（Workflow）/ 知识库（Dataset），支持按资源类型 Tab 筛选。
- **批量导入作品**：勾选多个资源一键导入，自动提取提示词、开场白、变量、快捷指令等元信息。
- **参数编辑器**：支持 Coze 的 8 种参数类型（String / Integer / Number / Boolean / Time / Object / Array / File），支持 JSON 导入，以及**AI 识别截图生成参数结构**（调用 LLM 视觉模型）。
- **作品管理**：查询 / 更新 / 删除已导入作品。
- **站点设置**：站点名、站点描述、主题（浅色 / 深色）、管理密码、全局 LLM 配置。

### 3.2 体验端（Public）

- **作品大厅**：浏览全部公开作品，卡片式展示，支持访问码校验。
- **在线体验**：三种交互模式——
  - `chat`：纯对话（智能体走 `/v3/chat` SSE 流式对话）；
  - `form`：参数表单（用于工作流，走 `/v1/workflow/run` 或 `stream_run` 流式）；
  - `mixed`：对话 + 参数面板混合。
- **参数类型转换**：前端输入自动按 Coze 参数类型转换后提交。
- **访问码控制**：作品级访问码，验证通过后发放会话 token。

## 四、技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 后端框架 | **Flask** | Python 3，单应用承载全部路由 |
| 网络请求 | **requests** | 调用 Coze Open API（/v1/bots、/v1/workflows、/v1/workflow/run、/v1/workflow/stream_run、/v1/files/upload、/v3/chat 等） |
| 跨域 | **flask-cors** | 前后端分离/开发调试支持 |
| 前端 | **原生 JavaScript（IIFE）** | 单文件约 2337 行，SPA 单页应用 |
| 样式 | **原生 CSS** | 单文件约 1403 行，支持浅/深主题 |
| 模板 | **Jinja2（index.html）** | 单页应用壳，四种页面视图 |
| 存储 | **JSON 文件** | `data/global_config.json` + `data/works/*.json`（每作品一个文件），无数据库 |

### 4.1 依赖清单（requirements.txt）

```text

```

## 五、系统架构

### 5.1 目录结构

```text
StoryForgeAI/                        # 项目根（源码 + 文档）
├── app.py            # Flask 主应用：全部 API 路由 + SSE 流式代理（约1193行）
├── config_loader.py  # 全局配置读写（站点名/密码/主题/LLM配置）
├── coze_client.py    # Coze API 客户端（bot/workflow/dataset 拉取与执行）
├── work_manager.py   # 作品管理（导入/查询/更新/删除，JSON 文件存储）
├── data/
│   ├── global_config.json
│   └── works/        # 每个作品一个 JSON 文件
├── static/
│   ├── css/style.css   # 1403 行，主题样式
│   └── js/app.js       # 2337 行，单页应用逻辑
├── templates/
│   └── index.html      # 单页应用（首页/体验页/管理后台/访问码弹窗）
├── requirements.txt
└── start.bat / start.sh  # 一键启动脚本
```

### 5.2 后端分层

```text
app.py（路由层）
  ├── 管理员 API：/api/admin/* （导入/管理作品、站点配置、Coze 资源拉取）
  ├── 体验者 API：/api/works/* （公开列表、作品详情、访问码校验、在线体验）
  ├── 工具函数：构建 Coze 请求体、参数类型转换
  └── 依赖
        ├── coze_client.py   # Coze Open API 封装
        ├── work_manager.py  # 作品 JSON 持久化（get_work_public 过滤敏感字段）
        └── config_loader.py # 站点全局配置
```

### 5.3 前端状态机（SPA）

- **三种交互模式**：`chat`（对话）/ `form`（表单）/ `mixed`（混合）
- **四种页面视图**：`home`（大厅）/ `work`（体验）/ `admin`（后台）/ 访问码弹窗
- **核心状态**：`works`、`currentWork`、`adminToken`、`accessTokens`、`conversationId`、`isStreaming`、`botList`、`workflowList`、`datasetList`

## 七、安全注意事项（重要）

1. **管理接口鉴权为空壳**：`app.py` 中的 `require_admin` 装饰器当前为占位实现，管理 API 实际未强制鉴权。生产部署前必须补齐。
2. **管理密码明文存储**：`data/global_config.json` 中的管理密码为**明文**，建议改用环境变量或加密存储。
3. **PAT Token 落盘**：每个作品的 JSON 文件中包含 Coze PAT Token（前端已通过 `get_work_public` 过滤，但服务端文件本身含敏感凭据）。建议生产环境改为服务端密钥托管（如环境变量 / 密钥管理服务）。
4. **会话仅存内存**：`_gen_tasks`、`_admin_sessions` 为进程内存字典，多进程或重启即失效，适合单机演示场景。

## 八、项目边界与后续建议

### 8.1 当前能力边界

- 单机、单进程 Flask 部署，非高可用。
- JSON 文件存储，非关系型数据库，适合中小规模作品集。
- Coze 在线体验依赖创作者提供的 PAT Token 与 Coze Open API 连通性。

### 8.2 后续可选增强

- [ ] 补齐管理接口鉴权（JWT / Session + 密码哈希）
- [ ] 敏感凭据迁移至环境变量 / 密钥服务
- [ ] JSON 存储迁移至 SQLite / MySQL（如需扩展）
- [ ] 增加作品访问量统计、作品排序与检索
- [ ] 接入真实 LiveKit / WebRTC 类实时能力（如后续扩展语音场景）

## 一、核心物理隐喻

力导向布局（Force-Directed Placement / Force-Directed Layout）把图想象成一个物理系统：

- **节点** = 带电荷的粒子（或质量点）
- **边** = 弹簧（或引力绳）

系统通过迭代模拟「力」的作用，最终趋向能量最低的稳定状态。理想结果是：

1. 相连的节点彼此靠近（边不太长）
2. 不相连的节点彼此远离（减少重叠与交叉）
3. 整体分布相对均匀、可读性好

这套隐喻从 1984 年 Eades 的弹簧模型开始，经过 Fruchterman-Reingold（1991）、Kamada-Kawai（1989）、ForceAtlas2（2014）等不断演化，至今仍是知识图谱、社交网络、依赖关系可视化的主流方法。

---

## 二、基础力模型

几乎所有经典算法都围绕两种力展开：

### 2.1 吸引力（Attractive Force）

只作用于**有边相连**的节点对。

最常见形式来自胡克定律（弹簧）：

\[
F_a(d) = k \cdot (d - L)
\]

或 Fruchterman-Reingold 常用的平方形式：

\[
F_a(d) = \frac{d^{2}}{k}
\]

其中 \( d \) 是当前距离，\( L \) 或 \( k \) 是理想边长。

**作用**：把直接关联的知识条目拉近。

### 2.2 排斥力（Repulsive Force）

作用于**所有节点对**（或近似计算）。

常用库仑定律形式：

\[
F_r(d) = -\frac{k^{2}}{d}
\]

或更强的 \( -\frac{k^{2}}{d^{2}} \)。

**作用**：防止节点重叠，让图「舒展」开。

### 2.3 其他常见附加力

| 力类型 | 作用 | 典型用途 |
|--------|------|----------|
| **重力 / 中心引力** | 把所有节点拉向画布中心 | 防止连通分量飞散 |
| **碰撞力（Collision）** | 节点之间保持最小距离 | 避免标签重叠 |
| **链接强度差异** | 不同边赋予不同弹簧系数 | 强关联边更短、更紧 |
| **度加权排斥** | 高度节点产生更强排斥 | ForceAtlas2 特色，让枢纽更突出 |

## 三、经典算法对比

### 3.1 Fruchterman-Reingold（FR，1991）

**核心思想**：
- 吸引力：\( F_a = d^2 / k \)
- 排斥力：\( F_r = -k^2 / d \)
- 使用「温度」概念做模拟退火：早期允许大步移动，后期逐渐降温锁定位置。

**特点**：
- 实现简单，效果稳定
- 对中小图（几百到一两千节点）表现优秀
- 计算复杂度每轮 \( O(|V|^2 + |E|) \)（可用网格近似优化）
- d3-force、react-force-graph 的默认模型很大程度上基于它

**适合知识库**：局部图谱、中等规模全局图的首选基础算法。

### 3.2 Kamada-Kawai（KK，1989）

**核心思想**：
把图论距离（最短路径）直接映射为理想弹簧长度。所有节点对之间都有弹簧，理想长度 = 图距离 × 系数。然后最小化系统总能量（常用牛顿法）。

**特点**：
- 全局结构保持更好（路径长度反映在几何距离上）
- 计算更重，通常用于中小图或作为初始布局
- 对稠密图效果好，稀疏图有时不如 FR 自然

**适合知识库**：可作为高质量初始布局，再交给 FR 精修。

### 3.3 ForceAtlas2（FA2，2014，Gephi 默认）

**核心改进**：
- 排斥力按节点度加权（高度节点推得更开）
- 吸引力更接近 LinLog 模型（对密集区域更友好）
- 持续运行（continuous），支持实时交互调整
- 内置重力、缩放、防重叠等实用参数

**特点**：
- 社区结构更清晰
- 对社交网络、知识网络视觉效果通常优于经典 FR
- 在 Gephi 中被广泛验证

**适合知识库**：全局图谱、希望突出「枢纽条目」时优先考虑。许多现代库（包括 reagraph 的部分布局）受其影响。

### 3.4 现代变体（简述）

- **t-FDP**：用 Student’s t 分布定义有界短程力，邻域保持更好，支持实时调参。
- **多层级（Multilevel）**：先粗化图 → 布局 → 细化，大幅提升大图速度与质量。
- **GPU / 负采样加速**：把排斥力近似为采样计算，可支持更大图。

对 StoryForgeAI 当前规模（≤2000 节点），经典 FR + FA2 风格已足够，无需上最复杂的加速方案。

## 四、关键参数及其影响（调优核心）

以 d3-force / react-force-graph 常见参数为例（其他库名称略有差异，原理相通）：

| 参数 | 典型含义 | 调大效果 | 调小效果 | 知识库建议 |
|------|----------|----------|----------|------------|
| **charge / strength**（排斥） | 节点间排斥强度 | 图更分散，节点间距大 | 图更紧凑，易重叠 | 中等偏强，避免标签挤在一起 |
| **linkDistance** | 理想边长 | 关联节点离得更远 | 关联节点贴得更近 | 80–120px（视画布而定） |
| **linkStrength** | 边的弹簧刚度 | 关联更「硬」，不容易被拉开 | 关联更柔和 | 0.6–1.0，强关联可更高 |
| **gravity / center** | 向中心的拉力 | 整体更聚拢，防止飞散 | 连通分量易散开 | 必须开启，尤其有多个孤立组时 |
| **collisionRadius** | 碰撞检测半径 | 节点之间强制留白 | 允许更近 | 建议开启，半径 ≈ 节点半径 + 文字预留 |
| **alpha / alphaDecay** | 初始能量与衰减 | 收敛慢但更细致 | 收敛快但可能早停 | 局部图可较快衰减，全局图稍慢 |
| **velocityDecay** | 速度阻尼 | 移动更「粘滞」 | 更「滑」 | 0.4 左右较平衡 |

**实践经验**：
- 稀疏知识图（边少）→ 适当加大排斥 + 保持中等 linkDistance，否则容易出现「长面条」。
- 有明显枢纽（被很多灵感关联的条目）→ 可尝试度加权排斥（FA2 风格）。
- 每次数据变化后重新布局时，建议保留上一次的节点位置作为初始值，减少「跳动感」。

## 五、针对知识库场景的算法选择建议

### 5.1 局部图谱（Ego Graph，1–2 跳）

- **推荐算法**：经典 Fruchterman-Reingold 或 d3-force 默认
- **原因**：节点少（通常 < 50），收敛极快，稳定性高
- **参数倾向**：较强排斥 + 明确 collision，保证可读性
- **额外技巧**：把中心节点固定（fx/fy），只让邻居移动

### 5.2 全局图谱（≤ 2000 节点）

- **推荐算法**：ForceAtlas2 风格 或 增强版 FR
- **原因**：能更好分离社区，突出高度节点
- **必要措施**：
  - 开启重力
  - 使用近似排斥（Barnes-Hut 或网格）降低 \( O(n^2) \) 压力
  - 初始布局可用随机 + 短时间预热，或复用上次结果
- **性能目标**：60fps 交互优先于「完美收敛」

### 5.3 小说角色关系子图

- 可复用同一套力导向
- 额外可给「关系类型」不同的 linkStrength 或边颜色
- 若关系是层次性的，可混合层次布局作为初始

## 六、常见问题与对策

| 问题 | 原因 | 对策 |
|------|------|------|
| 每次打开位置大变 | 随机初始化 + 未固定种子 | 缓存节点坐标；或固定随机种子；提供「重置布局」 |
| 节点挤成一团 | 排斥太弱或重力太强 | 加大 charge，减小 gravity |
| 边交叉严重 | 图本身稠密或布局未充分迭代 | 增加迭代次数；对稠密区域用 FA2；接受一定交叉 |
| 孤立节点飞到角落 | 缺少重力或中心力 | 必须加 gravity / center force |
| 标签重叠 | 只考虑了节点圆，没考虑文字 | 加大 collisionRadius，或做标签避让后处理 |
| 动画卡顿 | 每帧全量计算 + 重绘 | 使用 Canvas/WebGL；降低 tick 频率；节点多时用近似算法 |

## 七、与推荐库的对应关系

| 库 | 底层主要算法 | 可调性 | 备注 |
|----|--------------|--------|------|
| **react-force-graph** | d3-force（FR 系） | 高 | 最容易上手，参数与 d3 几乎一致 |
| **reagraph** | 自研 + d3-force-3d 等 | 高 | 内置多种布局，含 ForceAtlas2 风格 |
| **Cytoscape.js** | 多种（含 cose、cola、fcose 等） | 极高 | 图算法丰富，适合后期分析增强 |
| **Sigma.js** | 需配合 Graphology 布局 | 中 | 大规模渲染强，布局常外部计算 |

## 八、实施建议（简版）

1. **先做局部图谱**：用 react-force-graph + 固定中心节点，快速验证价值。
2. **参数做成可配置**：至少暴露 charge、linkDistance、gravity，方便产品和设计调视觉。
3. **位置持久化**：对同一批数据尽量复用上次布局结果，减少用户「迷路」。
4. **监控性能**：节点 > 800 时关注帧率，必要时切换近似排斥或降低更新频率。
5. **后续可演进**：局部图验证通过后，再引入 FA2 风格做全局视图。

## 九、总结

力导向布局的本质是「用物理模拟把关系翻译成空间距离」。  
对 StoryForgeAI 知识库而言：

- **局部探索**用经典 FR 足够且稳定
- **全局概览**更适合 ForceAtlas2 风格（社区分离更好）
- 参数调优的核心是「排斥 vs 吸引 vs 重力」的三角平衡
- 用户体验上，**位置稳定性**往往比「数学上更优的布局」更重要

# 知识库可新增类型推荐

> 版本：v1.0 · 状态：建议稿（2026-11-25）  
> 项目：StoryForgeAI —— 专业小说 AI 写作软件  
> 类型：产品建议  
> 关联：[知识库条目分类规则](./知识库条目分类规则.md)、[知识库结构化字段详细定义](./知识库结构化字段详细定义.md)  
> 说明：当前已有五类（article / paper / novel / inspiration / setting）。本文档评估后续可扩展的新类型，供产品决策。

---

## 一、现有类型覆盖评估

| 现有类型 | 主要解决的问题 | 覆盖缺口 |
|----------|----------------|----------|
| article | 观点、资讯、技巧文章 | 偏「输入」素材 |
| paper | 学术研究与启发 | 使用频率相对较低 |
| novel | 完整/片段虚构叙事 | 已较强 |
| inspiration | 碎片点子 | 已较强 |
| setting | 世界观与规则设定 | 已较强 |

**主要缺口**：  
- 角色相关的深度材料（人物小传、关系网之外的「角色档案」）  
- 情节/结构模板与节拍参考  
- 对标作品的拆解与竞品分析  
- 写作技法与风格参考（比普通 article 更聚焦）  
- 读者反馈与数据洞察

---

## 二、推荐新增类型（按优先级）

### 优先级 P0（强烈建议考虑）

#### 1. `character`（角色档案）

| 项 | 说明 |
|----|------|
| **定位** | 专门存放单个或一组角色的详细设定、背景、弧光、对白风格等 |
| **与现有区别** | setting 偏世界观规则；novel 是叙事文本；character 聚焦「人」本身 |
| **典型来源** | 人物小传、角色卡、对白样本、成长弧线笔记 |
| **结构化建议** | name、identity、personality、background、arc、speech_style、relationships、key_quotes[] |
| **创作价值** | 直接支撑角色 Agent、角色版图、对话生成，复用率极高 |
| **判定特征** | 以单一/少数角色为中心，描述性格、经历、关系、说话方式，而非完整故事或世界规则 |

**推荐理由**：小说创作中「角色」是高频核心资产，单独成类能显著提升引用与 Agent 注入效率。

---

#### 2. `plot_template`（情节模板 / 节拍参考）

| 项 | 说明 |
|----|------|
| **定位** | 可复用的情节结构、节拍表、套路模板、冲突升级路径 |
| **与现有区别** | novel 是具体故事；plot_template 是抽象可套用的结构 |
| **典型来源** | 三幕结构、英雄之旅、爽文节拍、反转设计笔记 |
| **结构化建议** | structure_name、beats[]（name + description + purpose）、applicable_genres[]、example_usage |
| **创作价值** | 写大纲、推衍剧情时直接调用，降低结构重复劳动 |
| **判定特征** | 描述的是「结构/节奏/套路」，而非具体人物事件 |

**推荐理由**：与现有「剧情树」「推衍」功能天然互补，是结构化创作的重要素材。

---

### 优先级 P1（有明显价值，可排期）

#### 3. `reference_work`（对标作品 / 拆解）

| 项 | 说明 |
|----|------|
| **定位** | 对已有小说/影视的结构化拆解（优缺点、节奏、人设、套路分析） |
| **与现有区别** | novel 是作品本身；reference_work 是对作品的分析与学习笔记 |
| **典型来源** | 竞品分析、名著拆解、爆款复盘 |
| **结构化建议** | work_title、genre、strengths[]、weaknesses[]、key_techniques[]、takeaways[] |
| **创作价值** | 帮助作者「站在巨人肩膀上」，避免重复踩坑 |
| **判定特征** | 主体是对另一部作品的评价、拆解或学习总结 |

---

#### 4. `technique`（写作技法）

| 项 | 说明 |
|----|------|
| **定位** | 具体可执行的写作技巧、修辞、叙事手法、文笔示范 |
| **与现有区别** | article 范围更广；technique 更聚焦「怎么写」的可操作方法 |
| **典型来源** | 文笔练习、对话技巧、环境描写方法、悬念制造 |
| **结构化建议** | technique_name、description、steps[]、examples[]、common_mistakes[] |
| **创作价值** | 写作过程中可快速调用「如何写好某一段」 |
| **判定特征** | 核心是教授或示范一种具体写作方法 |

---

### 优先级 P2（可选，视用户反馈）

#### 5. `reader_feedback`（读者反馈与数据）

| 项 | 说明 |
|----|------|
| **定位** | 读者评论精选、数据洞察、追更点/弃坑点分析 |
| **价值** | 帮助作者理解市场与读者心理 |
| **判定特征** | 来源为评论、数据报告或读者反馈汇总 |
| **注意** | 需考虑隐私与版权，建议仅支持作者自己导入的反馈 |

#### 6. `timeline` / `chronicle`（时间线 / 大事记）

| 项 | 说明 |
|----|------|
| **定位** | 故事世界或现实创作相关的时间线事件 |
| **价值** | 辅助长篇连载的时间一致性管理 |
| **与 setting 关系** | 可视为 setting 的子类，也可独立以获得更好时间轴展示 |

## 三、不建议新增的类型（及原因）

| 候选 | 不建议原因 |
|------|------------|
| `dialogue`（纯对话） | 可归入 character 或 novel 片段，单独成类收益低 |
| `outline`（大纲） | 小说类型已包含 outline 字段，重复 |
| `prompt`（提示词） | 属于工具配置，不宜进入知识库主分类 |
| `image` / `media` | 当前知识库以文本为核心，媒体适合另建资源库 |
| 过细的流派类型（玄幻设定、都市设定…） | 应用标签解决，而非增加 type |

---

## 四、扩展原则建议

1. **克制新增**：每增加一个 type，都要同步完成判定规则、结构化字段、前端渲染模板、提示词、测试用例。成本不低。
2. **优先高频刚需**：角色档案与情节模板对「边写边用」场景价值最高。
3. **用标签补充细节**：流派、视角、时代等用 `tags` 解决，避免 type 爆炸。
4. **可逆性**：新类型上线后应支持「迁移到已有类型」的工具，防止历史数据僵化。
5. **与现有模块联动**：新类型最好能直接服务角色 Agent、剧情树、推衍或写作工作台，而不是孤立存在。

---

## 五、推荐落地路径

| 阶段 | 动作 |
|------|------|
| 短期 | 保持现有五类稳定，收集用户真实分类痛点 |
| 中期 | 优先评估并落地 **character（角色档案）** |
| 后续 | 根据使用数据决定是否增加 plot_template 与 reference_work |
| 长期 | 再考虑 technique 等更细分类型 |

---

## 六、结论

**最值得增加的两个新类型**：

1. **`character`（角色档案）** — 与产品核心（角色 Agent、角色版图）契合度最高  
2. **`plot_template`（情节模板）** — 直接提升大纲与推衍效率  

其余类型可按实际用户反馈与开发带宽再决定。

---

*本文档为产品建议，不构成立即实施承诺。若确认新增某一类型，需同步更新分类规则、结构化字段定义与提示词。*

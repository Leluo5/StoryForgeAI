## 一、流程总览

```text
┌─────────────┐
│ 写作任务触发 │  scene_write / roleplay / plot_derive / duet
└──────┬──────┘
       ▼
┌─────────────┐
│ 上下文采集   │  sceneIds, focusIds, workId, taskType, budget
└──────┬──────┘
       ▼
┌─────────────┐
│ 图谱快照加载 │  nodes + edges（已 name→id，含 relationType）

┌─────────────┐

└──────┬──────┘

┌─────────────┐

└──────┬──────┘
       ▼
┌─────────────┐
│ 人设压缩     │  character 档案 → 压缩卡
└──────┬──────┘
       ▼
┌─────────────┐

└──────┬──────┘
       ▼
┌─────────────┐
│ 预算校验     │  超限则降级裁剪

└─────────────┘
```

端到端目标延迟：**本地图 < 50ms**；含一次 DB 拉取时 **< 150ms**（不含 LLM）。

## 二、触发与输入契约

### 2.1 触发点

| 触发场景 | taskType | 典型输入来源 |
|----------|----------|--------------|
| 工作台续写 / 扩写 | `scene_write` | 编辑器当前章出场标注、最近 N 句出现的角色名 |
| 角色 Agent 对话 | `roleplay` | 当前扮演的 characterId |
| 双人对手戏生成 | `duet` | 用户点选的两个角色 |
| 剧情推衍 | `plot_derive` | 情节节点关联角色、冲突双方 |
| 手动「带关系续写」 | 任意 | 用户勾选角色 |

### 2.2 输入参数（建议接口）

```ts
interface BuildSubgraphInjectInput {
  workId: string;
  taskType: 'scene_write' | 'roleplay' | 'plot_derive' | 'duet';
  /** 本场出场角色 entry id */
  sceneIds: string[];
  /** 焦点角色（roleplay 中心、duet 双方） */
  focusIds?: string[];
  /** token/字符预算，默认 600 中文字符约数 */
  maxChars?: number;
  maxNodes?: number;   // default 8
  maxEdges?: number;   // default 12
  /** 是否附带 arc 一句 */
  includeArc?: boolean;
  /** 图谱数据版本，用于缓存 */
  graphVersion?: string;
}
```

### 2.3 输出

```ts
interface BuildSubgraphInjectOutput {
  promptBlock: string;           // 可直接填入槽位
  meta: {
    strategy: 'A' | 'B' | 'C' | 'E';
    nodeIds: string[];
    edgeIds: string[];
    truncated: boolean;
    chars: number;
  };
}
```

`meta` 可供 UI「本次使用的关系」面板与评测日志使用。

## 三、阶段详解

### 阶段 0：图谱快照准备（可异步预热）

**时机**：作品打开、character 保存、关系编辑后。

**步骤**：

1. 加载该 `workId` 下所有 `type=character` 条目  
2. 解析 `relationships[]`：`target` 字符串 → entry id（name/aliases 对齐）  
3. `normalizeRelationType(relation)` → `relationType`（见《关系类型归一规则表》）  
4. 生成内存/缓存结构：

```ts
{
  nodes: Map<id, { name, identity, personality, speech_style, arc?, tags? }>,
  edges: Array<{ id, source, target, relationLabel, relationType, weight }>,
  nameIndex: Map<normalizedName, id>,
  version: string  // hash(updated_at max) 或递增版本
}
```

5. 悬空 target：生成 `orphan` 占位或丢弃边并记 `unresolvedTargets[]`

**缓存键**：`relationGraph:{workId}:{version}`  
**失效**：任一 character 的 structured/relationships/name/aliases 变更。

---

### 阶段 1：上下文采集（运行时）

自动化程度从高到低：

| 来源 | 自动化 | 说明 |
|------|--------|------|
| 用户显式勾选出场 | 高可靠 | 优先 |
| 章节元数据 `cast[]` | 高 | 若产品有出场表 |
| NER / 规则从近文抽人名 | 中 | 与 nameIndex 匹配 |
| 仅 focusIds | 保底 | roleplay 至少有中心 |

**合并规则**：`sceneIds = unique(显式 ∪ 元数据 ∪ 文本匹配)`，再与 focusIds 取并集作为种子。

若 `sceneIds` 与 `focusIds` 皆空 → **跳过注入**（输出空块或短提示「无关系上下文」），不报错阻断写作。

---

### 阶段 2：策略选择

```text
if taskType == 'duet' && focusIds.length >= 2:
    strategy = C  // 最短路径 + 两端人设
elif taskType == 'roleplay' && focusIds.length == 1:
    strategy = B  // ego k=1，可升级 k=2 若边过少
elif taskType in ('scene_write', 'plot_derive'):
    strategy = E  // 混合默认
else:
    strategy = E
```

允许输入覆写 `strategy`（高级选项）。

---

### 阶段 3：子图抽取算法

#### 3.1 策略 E（默认混合）— 伪代码

```text
seed = set(sceneIds ∪ focusIds)
nodes = set(seed)
edges = []

# ① 诱导子图：两端都在 seed 内的边
for e in allEdges:
  if e.source in seed and e.target in seed:
    edges.append(e)

# ② 硬关系一跳：seed 中每个点的 P0/P1 边（对端可未出场）
HARD = {family, mentor, romance, enemy}
for n in seed:
  for e in incidentEdges(n):
    if e.relationType in HARD:
      edges.append(e)
      nodes.add(e.source)
      nodes.add(e.target)

edges = unique(edges)
```

#### 3.2 策略 B（自我中心）

```text
center = focusIds[0]
nodes = {center} ∪ neighbors(center, k=1)
edges = edges within nodes
# 可选：若 edges < 2，扩展 k=2，但仍受 maxNodes 限制
```

#### 3.3 策略 C（成对路径）

```text
a, b = focusIds[0], focusIds[1]
path = BFS_shortest_path(a, b)  # 无路径则仅两点无边
nodes = set(path)
edges = consecutive edges on path
# 附加：a、b 的 P0/P1 边各最多 2 条，防止只有路径中间人
```

#### 3.4 策略 A（纯出场诱导）

仅阶段 3.1 的 ①，不含硬关系一跳。

---

### 阶段 4：过滤与截断

1. **去重边**（同一对节点同 type 可合并，保留更长 label）  
2. **按优先级排序**：P0 → P1 → P2 → P3，同级按 weight、再按与 focus 的距离  
3. **截断**：取前 `maxEdges`；节点若仅因被截断边出现则移除  
4. **保证 focus/scene 种子节点不被删**（可只删纯邻居）  
5. **标记** `truncated=true` 若发生截断  

排序键示例：

```text
score(e) =
  typePriority(e.relationType) * 1000
  + (e.weight || 1) * 10
  + (incidentToFocus(e) ? 5 : 0)
```

---

### 阶段 5：人设压缩

对 `nodes` 中每个 id 拉档案（已在快照中则内存读取）：

```text
压缩卡 =
  name
  + "｜" + identity
  + "｜" + join(personality[0..2], "、")
  + (speech_style ? "｜" + speech_style短句 : "")
  + (includeArc && arc ? "｜弧光：" + 截断(arc, 40字) : "")
```

**中心角色**（focus）：personality 可放到 5 条，保留 speech_style。  
**邻居**：personality 最多 2 条，可省略 speech_style。

缺失档案的悬空节点：仅输出 `name（未建档）`，不编造人设。

---

### 阶段 6：序列化模板

固定三块（空块可省略标题）：

```text
【在场角色人设】（来自知识库，请严格遵守）
- {card_1}
- {card_2}
...

【关系约束】
- {name_s} —[{relationLabel}]→ {name_t}
...

【硬禁止】
- {auto_rules}
```

#### 6.1 硬禁止自动生成规则

| 条件 | 生成句 |
|------|--------|
| 任一边 type=enemy | `不得将「{A}」与「{B}」写成已和解或主动同盟（除非用户剧情明确要求）` |
| type=mentor 且能判方向 | `不得颠倒「{师}」与「{徒}」的师徒方向` |
| type=romance 且任务非告白改写 | `不得无依据地取消已列出的爱慕/伴侣关系` |
| 无 P0/P1 边 | 可省略【硬禁止】整块 |

同一对 enemy 只生成一条，避免重复。

---

### 阶段 7：预算校验与降级

```text
chars = len(promptBlock)
if chars <= maxChars: return

降级阶梯（依次执行直到满足预算）：
1. 去掉所有 type=other 边
2. 去掉 type=faction 边
3. 去掉 type=ally 边
4. 邻居 personality 改为仅 1 词 / 去掉 speech_style
5. 去掉非 seed 节点的人设卡，仅保留边列表中的姓名
6. 仅保留 P0 边 + focus 人设卡
7. 仍超限：只保留 focus 人设，关系块改为「（关系过多已省略，请仅按人设写作）」
```

每次降级后重序列化；`meta.truncated = true`。

---

### 阶段 8：写入 Agent Prompt

编排层模板示例：

```text
{{system_base}}
{{relation_subgraph}}    ← promptBlock
{{task_instruction}}
{{recent_context}}
```

**空块策略**：`promptBlock === ''` 时不插入标题，避免干扰模型。

**日志**：异步写入 `inject_log(workId, taskType, meta, hash(promptBlock))` 便于评测关系遵守率。

## 四、时序图（场景续写）

```text
用户点击「续写」
    → Gateway/API: BuildSubgraphInjectInput
        → RelationGraphService.getSnapshot(workId)
            → hit cache? 是 → snapshot
            → 否 → rebuild from DB → cache
        → SubgraphBuilder.build(input, snapshot)
            → strategy E → filter → cards → serialize → budget
        → 返回 promptBlock + meta
    → AgentOrchestrator.composeMessages(promptBlock, ...)
    → LLM
```

## 五、模块划分建议

| 模块 | 职责 |
|------|------|
| `RelationGraphSnapshotService` | 构建/缓存/失效图谱快照 |
| `RelationTypeNormalizer` | 规则表 + 可选 LLM 兜底 |
| `SubgraphSelector` | 策略 A/B/C/E 抽取 |
| `SubgraphRanker` | 优先级排序与截断 |
| `PersonaCompressor` | 档案 → 压缩卡 |
| `RelationPromptSerializer` | 模板序列化 + 硬禁止 |
| `SubgraphInjectFacade` | 对外 `build(input)` 一站式 |

前端可不感知内部阶段，只消费 `promptBlock` 与可选 `meta` 展示。

## 六、失败与降级策略

| 情况 | 处理 |
|------|------|
| 图谱缓存未命中且 DB 超时 | 跳过注入，写作不阻断；打告警 |
| 全部 target 无法对齐 | 仅注入 seed 人设卡，无关系边 |
| character 档案缺失 structured | 用 title + raw 截断 50 字作 identity 降级 |
| 循环依赖边、自环 | 构建快照时丢弃自环；平行边合并 |
| 用户关闭「关系辅助」开关 | 整段 pipeline short-circuit 返回空 |

**原则：注入失败不得导致续写失败。**

---

## 七、缓存与一致性

| 层级 | 内容 | TTL / 失效 |
|------|------|------------|
| L1 进程内 | snapshot by workId+version | 条目变更时主动失效 |
| L2 Redis（可选） | 同上 | 同左；多实例共享 |
| 运行时 | 单次请求内 selector 结果不二次缓存 | — |

**版本计算**：`max(character.updated_at)` + relationships 内容 hash，避免漏失效。

**与写作请求并发**：允许短暂旧版本；强一致要求下可在保存 character 后 `await invalidate`。

## 九、MVP 裁剪范围

**必须有**：

1. 快照构建（规则归一，无 LLM 兜底也可）  
2. 策略 E + 过滤截断  
3. 压缩卡 + 三块模板  
4. 预算降级阶梯前 4 步  
5. 失败跳过  

**可二期**：

- 策略 C 最短路径  
- 文本 NER 自动出场  
- LLM 关系归一兜底  
- Redis L2、完整 inject 评测看板

## 十、端到端示例

**输入**：

- taskType: `scene_write`  
- sceneIds: [林远, 贺兰策]  
- 边：林远—宿敌/未相认兄长—贺兰策；林远—师徒—陈墨  

**输出 promptBlock（示意）**：

```text
【在场角色人设】（来自知识库，请严格遵守）
- 林远｜青云城少年｜隐忍、护短｜对白短句
- 贺兰策｜前边军少帅·北境修罗｜冷峻、简言

【关系约束】
- 林远 —[宿敌，实为未相认兄长]→ 贺兰策
- 林远 —[师徒]→ 陈墨

【硬禁止】
- 不得将「林远」与「贺兰策」写成已和解或主动同盟（除非用户剧情明确要求）
- 不得颠倒师徒方向（涉及陈墨时）
```

`meta.strategy = 'E'`，`truncated = false`。

## 十一、结论

自动化构建流程的关键控制点是：

1. **快照与对齐**（正确性基础）  
2. **策略 E 默认**（出场 + 硬关系，兼顾省 token 与防崩）  
3. **类型优先级截断**（与归一规则表一致）  
4. **固定模板序列化**（模型稳、可测）  
5. **失败降级不阻断写作**（产品可用性）  

按上述阶段实现 `SubgraphInjectFacade.build()`，即可与现有 Agent 编排槽位对接。

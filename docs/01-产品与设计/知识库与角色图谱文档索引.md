## 三、推荐阅读顺序

### 路径 1：只做知识库录入与拆分

1. 知识库条目分类规则  
2. 知识库结构化字段详细定义  
3. 知识库提示词 Few-shot 增强版（或 knowledge-prompts 代码）  
4. 方案 C / D（若做 UI）

### 路径 2：角色档案 → 版图 → Agent

1. 角色档案字段设计深入探讨 + 结构化字段中 character 节  
2. 关系类型归一规则表  
3. 角色关系图谱算法探讨  
4. 子图注入 Prompt 策略 → 自动化构建流程  
5. 多 Agent 图谱共享 → 实时更新策略 → 双角色并行时序  

### 路径 3：可视化 / 布局专项

1. 知识图谱可视化方案探索  
2. 力导向图布局算法深入探讨  
3. 角色关系图谱算法探讨（角色图专用约束）

## 五、已锁定的产品/技术决策（摘要）

| 决策点 | 结论 |
|--------|------|
| 全局知识库 UI | 方案 **C** 全页管理 |
| 工作台知识库 | 方案 **D** 抽屉 |
| 条目类型 | 核心 5 类 + 扩展（P0：character、plot_template）→ **2026-11-25 已裁决扩至全部 11 类**，落地设计见 [M3c-3 06-设计更新](../../04-功能交付档案/M3c-3-知识库/06-设计更新-11类扩展与判定重构.md) |
| character 权威 | 独立档案优先于小说拆文快照 |
| 关系 target | 允许字符串；对齐后再变 id |
| 关系类型 | 7 类归一；原文保留为 label |
| 子图默认策略 | **E**（出场诱导 ∪ 硬关系一跳） |
| 多 Agent 共享 | L0 权威 / L1 会话快照 / L2 每 Agent 切片 |
| 会话刷新 | 默认 **S2**（编排边界对齐 version） |
| 并行双角色 | 同 version 锁 → 并行 inject+LLM → merge |
| 注入失败 | **不阻断**写作（降级空块） |

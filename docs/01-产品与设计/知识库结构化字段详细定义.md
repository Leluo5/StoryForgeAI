# 知识库结构化字段详细定义

> 版本：v1.2 · 状态：生效（2026-11-25）  
> 项目：StoryForgeAI —— 专业小说 AI 写作软件  
> 类型：数据模型 / 业务规则文档  
> 适用范围：知识库录入后的结构化拆分结果、存储、展示、编辑、检索与导出  
> 关联：[知识库条目分类规则](./知识库条目分类规则.md)、[知识库新类型完整定义](./知识库新类型完整定义.md)、[角色档案字段设计深入探讨](./角色档案字段设计深入探讨.md)  
> 权威口径：本文档为 `structured` 字段的唯一详细定义。系统实现、LLM 提示词、前端渲染模板均须与此保持一致。

---

## 一、通用条目字段（所有类型共享）

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `id` | string (UUID) | 是 | 条目唯一标识 |
| `author_id` | string (UUID) | 是 | 归属作者 |
| `type` | enum | 是 | 见下方完整枚举 |
| `title` | string (≤200) | 是 | 标题 |
| `source` | enum | 是 | `paste` \| `upload` \| `ocr` \| `manual` \| `import` |
| `raw_content` | text | 是 | 原始全文（Markdown 友好） |
| `structured` | object | 是 | **按类型不同的结构化结果** |
| `tags` | string[] | 否 | 用户或系统生成的标签 |
| `links` | string[] | 否 | 关联的其他条目 id 列表 |
| `content_hash` | string (sha256) | 是 | 原文内容哈希，用于查重 |
| `created_at` | datetime | 是 | 创建时间 |
| `updated_at` | datetime | 是 | 最后更新时间 |

**type 完整枚举：**  
`article` \| `paper` \| `novel` \| `inspiration` \| `setting` \| `character` \| `plot_template` \| `reference_work` \| `technique` \| `reader_feedback` \| `timeline`

`structured` 为 **JSONB**，结构随 `type` 变化。

## 二、文章（article）

```ts
interface ArticleStructured {
  paragraphs: Paragraph[];
  key_points: string[];         // 3–8 条
```

## 七、角色档案（character）【扩展】

**用途**：支撑角色 Agent、角色版图与对话生成，聚焦「人」本身。独立 `character` 条目为角色的权威数据源；小说拆文中的 `characters[]` 仅为文本内快照。

**权威依据**：[角色档案字段设计深入探讨](./角色档案字段设计深入探讨.md)

```ts
interface CharacterStructured {
  name: string;                          // 主角色名（P0 必填）
  aliases?: string[];                    // 别名/绰号（P2）
  identity: string;                      // 一句话身份定位（P0 必填）
  personality: string[];                 // 性格关键词或短句，建议 3–8 条（P0 必填）
  background: string;                    // 背景故事摘要，建议 100–400 字（P0 必填）
  appearance?: string;                   // 外貌（P2）
  abilities?: string[];                  // 能力/特长（P1）
  arc?: string;                          // 人物弧光：成长/堕落路径（P1）
  speech_style?: string;                 // 对白风格与用词习惯，对 Agent 极重要（P1）
  relationships: {                       // P0 必填，允许空数组
    target: string;                      // 对方名称（允许尚未建档的字符串）
    relation: string;                    // 关系说明
  }[];
  key_quotes?: string[];                 // 代表性台词，建议 ≤5 条（P2）
  notes?: string;                        // 其他补充（P2）
}
```

| 优先级 | 字段 | 必填 | 说明 |
|--------|------|------|------|
| **P0** | `name` | 是 | 主角色姓名；检索与版图主标识 |
| **P0** | `identity` | 是 | 一句话身份，列表/版图/Agent 第一眼定位 |
| **P0** | `personality` | 是 | 数组，3–8 条为宜；便于 Agent 约束与筛选 |
| **P0** | `background` | 是 | 过去已发生的背景摘要；与 arc 区分 |
| **P0** | `relationships` | 是 | 可为空数组；`target` 用字符串，降低冷启动成本 |
| **P1** | `speech_style` | 否 | 对角色 Agent 生成对话约束最直接 |
| **P1** | `arc` | 否 | 人物变化路径（成长/堕落） |
| **P1** | `abilities` | 否 | 该角色具体能力；体系规则仍归 setting |
| **P2** | `appearance` / `aliases` / `key_quotes` / `notes` | 否 | 按题材与作者习惯补全 |

**设计约束（正式口径）**：
- `relationships.target` 使用字符串而非强制 entry id，允许对方尚未建档；后续可通过对齐工具回写 `target_id`。
- 创建档案时产品可仅强制 P0；P1/P2 用完整度引导逐步补全。
- 禁止编造原文未出现的能力、关系或台词。
- 同一角色的小说内快照与独立档案并存时，Agent 与角色版图**优先读独立 character 条目**。

## 八、情节模板（plot_template）【扩展】

**用途**：可复用的结构与节拍，直接服务大纲与剧情推衍。

```ts
interface PlotTemplateStructured {
  structure_name: string;                // 模板名称
  description: string;
  beats: {
    name: string;
    order: number;
    description: string;                 // 该节拍的叙事任务
    purpose?: string;                    // 目的（悬念/爽感/转折等）
  }[];
  applicable_genres?: string[];
  conflict_pattern?: string;
  example_usage?: string;
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `structure_name` | 是 | 如「英雄之旅」「爽文经典节拍」 |
| `description` | 是 | 整体说明 |
| `beats` | 是 | 至少 1 个节拍 |
| 其余 | 否 | — |

## 十三、字段通用约束与处理规则

1. **空值处理**：必填字段结构化失败时降级为仅保存 `raw_content` + 类型；空集合用 `[]`，不用 `null`。
2. **长度建议**：摘要 100–300 字，单条观点/要点 ≤ 100 字为宜；超长内容保留在 `raw_content`。
3. **可编辑性**：所有结构化字段支持事后编辑，编辑后更新 `updated_at`。
4. **类型变更**：修改 `type` 后提示是否重新生成 `structured`。
5. **与顶层字段关系**：`tags` 可由各类型的 `tag_list` 初始化；inspiration 的 `related_ids` 与顶层 `links` 保持同步。
6. **版本兼容**：新增字段向后兼容；禁止随意删除或重命名已有字段。

## 十四、前端渲染建议

| 类型 | 推荐展示形式 |
|------|--------------|
| article | 分段列表 + 观点卡片 + 摘要折叠 |
| paper | 五要素知识卡片 |
| novel | 角色列表 + 情节脉络 + 可折叠四维大纲树 |
| inspiration | 原始 vs 完善对比 + 关联链接 |
| setting | 分段 + 要点 + 可选设定条目表格 |
| character | 人设卡片（identity 置顶）+ personality 标签 + 关系列表 + speech_style/arc 折叠区 + 台词；展示完整度（P0/P1 填充率） |
| plot_template | 节拍时间轴或有序列表 + 适用题材标签 |
| reference_work | 优缺点对照 + 启发清单 |
| technique | 步骤列表 + 正反示例 + 常见错误 |
| reader_feedback | 正负点分栏 + 行动建议 |
| timeline | 纵向时间轴 |

存储：`structured` 使用 PostgreSQL `jsonb`。

## 一、统一错误码

所有后端接口统一返回 `{"code": <int>, "data": <any>, "message": "<可读>"}`。前端以 `code !== 0` 判定失败。

| code | 语义 | 典型场景 |
|------|------|---------|
| `0` | 成功 | 正常响应 |
| `400` | 参数错误 | 缺参、类型不符、非法值（如空标题、不支持扩展名） |
| `401` | 未授权/鉴权失败 | PAT Token 缺失或无效 |
| `403` | 禁止访问 | 权限不足（如 access_code 错误） |
| `404` | 未找到 | 条目/作品 id 不存在 |
| `409` | 冲突 | 同名条目、重复导入、状态非法转移 |
| `500` | 服务器内部错误 | 未捕获异常 |
| `502` | 上游服务错误 | Coze Open API 调用失败 |

> 【注意】不新增语义相近的错误码；确需扩展须先更新本表并同步 `modules/common/errors.py`。

## 二、安全硬约束

| 类别 | 规则 | 正确示例 | 错误示例 |
|------|------|---------|---------|
| **XSS** | 前端渲染用户/外部数据必须用 `textContent` 或转义 | `el.textContent = data` | `el.innerHTML = data` |
| **注入** | SQL/命令注入防护 | 参数化查询、`subprocess` 列表参数 | 字符串拼接 SQL/命令 |
| **越权** | 外部可见数据必须脱敏，PAT Token / access_code 只进不出 | `get_work_public()` 过滤 | 直接返回 `work` 原始 dict |
| **敏感字段** | 日志、响应、前端均不得出现明文 Token | `logger.info("pat: ***")` | `logger.info(pat)` |
| **文件上传** | 校验扩展名白名单、大小上限 | `.md` 白名单 + 限长 | 接受任意扩展名 |
| **路径穿越** | 用户输入文件名不得直接拼路径 | 白名单 + `os.path.basename` | `open(user_input)` |
| **输入校验** | 所有用户输入先校验后使用 | `zod`/手动白名单 | 直接信任 body |

### 2.1 敏感字段清单

以下字段**禁止**出现在任何对外响应、日志、前端内存持久化中：

- `pat_token`（Coze PAT Token）
- `access_code`（站点访问码）
- 任何包含密钥/凭据的字段（`api_key`、`secret`、`token`）

**脱敏函数**：统一使用 `work_manager.get_work_public(work)` 或 `modules/common/dto.py` 的过滤方法。

## 三、JSON 文件存储规范

### 3.1 数据文件分布

| 路径 | 内容 | 说明 |
|------|------|------|
| `data/global_config.json` | 站点配置 | 含 `pat_token`、`access_code`（敏感） |
| `data/works/<id>.json` | 作品数据 | 每作品一文件，双层存储 |
| `data/knowledge/<id>.json` | 知识条目元数据 | 与 `<id>.md` 正文配套 |
| `data/knowledge/<id>.md` | 知识条目正文 | 独立正文文件 |
| `data/projects/<id>.json` | 项目数据 | 每项目一文件 |

### 3.2 文件锁与原子写

- **并发安全**：多用户/多线程写同一 JSON 必须加锁（`filelock` 或模块级 `threading.Lock`），禁止裸写。
- **原子写**：先写临时文件（`.tmp`），再 `os.replace()` 原子替换，避免半写损坏。
- 锁粒度：按数据域（如 knowledge store 一个锁）而非全局大锁，避免写放大。
- 写前校验结构（字段必填、类型），写后读回校验（`[SHOULD]`）。

```python
# ✅ 推荐：原子写 + 锁
with self._lock:
    tmp = path.with_suffix('.tmp')
    tmp.write_text(json.dumps(data, ensure_ascii=False, indent=2), encoding='utf-8')
    os.replace(tmp, path)
```

### 3.3 内容哈希与判重

- 知识条目内容哈希用 **SHA256**，去首尾空白后计算，作为判重键。
- 判重依据 = `标题 + 内容哈希`（`detect_conflict`），禁止仅凭标题判重。
- 哈希字段 `content_hash` 在写入时随数据持久化，避免每次重算。

## 四、敏感信息处理

| 场景 | 要求 |
|------|------|
| 配置存储 | `global_config.json` 含敏感字段，该文件**不提交 Git**（.gitignore） |
| 前端获取 | 配置接口返回时过滤敏感字段，只回传展示所需 |
| 日志 | 禁止记录 Token/访问码明文；用 `***` 占位 |
| 密钥轮换 | 用户更新 Token 后旧值立即失效（不缓存旧值） |
| 环境变量 | `[SHOULD]` 支持 `STORYFORGE_PAT` 等环境变量注入，减少硬编码 |

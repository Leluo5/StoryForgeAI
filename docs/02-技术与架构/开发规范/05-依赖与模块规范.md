## 一、运行环境

| 项 | 值 | 说明 |
|----|----|------|
| Python | 3.9+（CI 使用 3.9，兼容 3.12） | 类型注解用 `from __future__ import annotations` |
| Flask | 2.x（`flask`） | 蓝图 + 统一响应 |
| 前端 | 原生 JS/CSS/HTML（ES6+） | **无构建链、无 TypeScript、无框架** |
| 数据 | JSON 文件存储（`data/`） | 无数据库，无 ORM |
| 外部服务 | Coze Open API（`coze_client.py`） | HTTP 调用 |
| 测试 | pytest / unittest | `tests/` 目录 |

## 二、依赖管理规范

| 规则 | 说明 |
|------|------|
| 最小化 | 只引入确实需要的依赖；能用标准库不用第三方 |
| 版本锁定 | `requirements.txt` 写具体版本（`flask==2.x.x`），禁裸 `flask` |
| 前端零依赖 | 前端禁止引入需要构建的 npm 包；用原生 API 实现 |
| 兼容性 | 新增依赖须确认 Python 3.9.13 兼容；标注安装命令 |
| 许可证 | `[SHOULD]` 优先选 MIT/BSD/Apache 许可 |

> 【禁止】为「看起来专业」引入冗余依赖（如为简单 JSON 操作引入 ORM，为前端引入 React/Vue）。

## 三、模块拆分规范

### 3.1 模块分层

每个功能模块（如 `modules/knowledge_base/`）遵循三层：

```
modules/<模块>/
├── routes.py          # 蓝图 + 路由（薄）
├── <模块>_store.py    # 数据层（JSON 读写 + 锁 + 原子写）
├── <模块>_engine.py   # 业务引擎（纯函数 + 依赖注入）
└── __init__.py        # 模块注册
```

### 3.2 跨模块契约

| 约定 | 说明 |
|------|------|
| 共享契约 | 统一放 `modules/common/`（`dto.py`、`errors.py`） |
| 禁止 | 模块间直接 import 对方内部函数（走 `common`） |
| 引擎解耦 | 引擎不 import 数据层符号，通过 `store` 参数注入 |
| 注册 | 新模块在 `app.py` 用 `app.register_blueprint(module_bp)` 注册 |

## 四、数据契约规范

### 4.1 统一响应契约

所有接口返回 `{"code": 0, "data": ..., "message": "ok"}`，详见 [04-安全与数据规范](./04-安全与数据规范.md#一统一错误码)。

### 4.2 条目数据契约（知识库）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | str | 是 | 条目唯一 id（`k_xxx`） |
| `type` | str | 是 | `article`/`paper`/`novel`/`inspiration` |
| `title` | str | 是 | ≤ 60 字符 |
| `raw_content` | str | 是 | 原始 Markdown 正文 |
| `content_hash` | str | 是 | SHA256（去首尾空白） |
| `tags` | list[str] | 否 | 标签数组 |
| `source` | str | 否 | `upload`/`import`/`manual` |
| `created_at` | str | 是 | ISO 时间戳 |
| `updated_at` | str | 是 | ISO 时间戳 |

### 4.3 导入导出契约（Markdown IO）

| 对象 | 字段 | 说明 |
|------|------|------|
| 导入结果 | `{total, success, failed, failed_items[], created[], updated[], skipped[]}` | `failed_items[]` 含 `{file_name, reason}` |
| 冲突检测 | `{is_dup, reason, existing_id}` | `reason`: `identical` / `name_collision` / `""` |
| 导出文件 | `{files[], failed[]}` | `files[]` 含 `{file_name, content}` |

> 【注意】契约变更必须同步更新 `02-技术方案.md` 对应接口设计，并回归测试。

## 五、测试规范

### 5.1 覆盖要求

| 层级 | 要求 |
|------|------|
| 单元测试 | 引擎/数据层纯函数必测；覆盖正常 + 异常 + 边界 |
| 接口测试 | 路由端点用 `flask test_client` 验证响应契约、错误码 |
| 回归 | 修复 BUG 必加针对性单测防复发；全量测试须全绿 |
| 覆盖率 | `[SHOULD]` 核心模块 ≥ 80% |

### 5.2 测试组织

- 文件：`tests/test_<模块>.py`（如 `test_markdown_io.py`）。
- 用例类：`class Test<功能>(unittest.TestCase)`。
- 数据隔离：临时目录（`tempfile.mkdtemp()`）+ 独立 store，禁共用生产 `data/`。
- 命名：`test_<行为>_<场景>`（如 `test_rename_identical_skipped`）。

### 5.3 运行命令

```powershell
# 全量
python -m pytest tests/ -q

# 单文件
python -m pytest tests/test_markdown_io.py -q
```

### 5.4 边界用例必写清单

| 边界 | 用例 |
|------|------|
| 空输入/空文件 | `test_empty_fallback_title` |
| 非法编码 | `test_bad_bytes_raises` |
| 内容重复（identical） | `test_identical` |
| 同名不同内容（name_collision） | `test_name_collision` |
| 冲突策略各分支 | `test_rename_identical_skipped` 等 |
| 批量部分失败 | `test_single_failure_recorded` |

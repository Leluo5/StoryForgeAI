## 一、规则分级与总则

### 1.1 规则分级

| 级别 | 标识 | 含义 | 违规处理 |
|------|------|------|---------|
| **强制** | `[MUST]` | 违反即功能错误或不可维护，必须修改 | 禁止合入；评审一票否决 |
| **建议** | `[SHOULD]` | 影响可读性/一致性，但不破坏功能 | 评审指出并限期整改 |
| **可选** | `[MAY]` | 风格偏好，团队可自行取舍 | 不强制 |

> 【必读】本项目所有规则默认 `[MUST]`，仅在正文特别标注 `[SHOULD]` 或 `[MAY]` 时降级。

### 1.2 总则

1. **规范目的**：保证代码风格统一、命名一致、错误处理可预期、Git 工作流可追踪，让 AI 协作与人工维护都高效。
2. **强制约束**：下列规则均为硬性要求，每条附正确/错误对比。禁止出现「遵循最佳实践」这类无明确动作的表述。
3. **优先级**：本规范冲突时，按 `后端规范 > 前端规范 > Git 工作流 > 安全规范` 顺序执行。

## 二、目录与文件约定

### 2.1 目录职责边界

| 目录/文件 | 职责 | 禁止 |
|-----------|------|------|
| `app.py` | HTTP 路由层（共享底座） | 业务逻辑、直接写文件 |
| `coze_client.py` | Coze Open API 封装 | 路由逻辑、数据持久化 |
| `work_manager.py` | 作品数据持久化 | HTTP 响应构造 |
| `config_loader.py` | 站点配置读写 | 业务处理 |
| `modules/<模块>/` | 功能模块（路由+数据层+引擎） | 跨模块直接 import 对方内部符号 |
| `modules/common/` | 公共契约（dto/errors） | 任何业务逻辑 |
| `static/js/` | 前端逻辑 | 服务端渲染 |
| `static/css/` | 样式 | JS 逻辑 |
| `templates/` | 页面结构 | 业务处理 |
| `tests/` | 测试 | 生产代码 |
| `data/` | 运行时数据 | 提交源码逻辑 |

### 2.2 新增文件落位规则

- 新功能模块 → 新建 `modules/<模块>/` 目录，含 `__init__.py`、`routes.py`、数据层、引擎。
- 新前端组件 → `static/js/<组件>.js` + `static/css/<组件>.css`（如需），并在 `app.js` 入口挂载。
- 新测试 → `tests/test_<模块>.py`。
- 禁止在项目根目录新增散落 `.py` 文件（app.py / coze_client.py 等底座除外）。

## 三、Python 代码规范（Flask）

### 3.1 代码风格

| 规则 | 正确示例 | 错误示例 |
|------|---------|---------|
| 缩进 | 4 空格（禁 Tab） | `\t` 缩进 |
| 行宽 | ≤ 100 字符 | 长行无断行 |
| 引号 | 统一双引号 `"` | 混用单双引号 |
| 命名（函数/变量） | `snake_case`：`get_work_public()` | `camelCase`、`GetWork()` |
| 命名（常量） | `UPPER_SNAKE_CASE`：`DEFAULT_TIMEOUT` | `defaultTimeout` |
| 命名（类） | `PascalCase`：`WorkManager` | `work_manager` |
| 命名（私有） | 前置下划线：`_content_hash()` | 公开但仅模块内使用 |
| 导入顺序 | 标准库 → 第三方 → 本地，每组空行 | 随意混排 |
| 编码 | 文件头部声明 `# -*- coding: utf-8 -*-`（如含中文） | 缺失声明 |
| 类型注解 | 公开函数签名标注参数/返回类型（`typing`） | 纯裸函数无注解 |

### 3.2 函数设计

- 单一职责：一个函数只做一件事，超 30 行需考虑拆分。
- 参数 ≤ 5 个；超过时用 dict / dataclass 聚合。
- 必须包含 docstring（模块级、公开函数级），说明入参、返回、异常。
- 返回类型保持一致：成功返回 `data`，失败返回 `(None, error_msg)` 或抛异常，**不要混用**。

```python
# ✅ 推荐：明确返回契约
def get_work_public(work: dict) -> dict:
    """过滤对外可见字段（脱敏）。返回仅含展示字段的 dict。"""
    return {k: v for k, v in work.items() if k not in _SENSITIVE_FIELDS}
```

### 3.3 错误处理

```python
# ✅ 推荐：集中错误处理，明确错误信息
try:
    resp = coze_client.get_bots(pat)
except CozeAPIError as e:
    return jsonify({"code": 502, "data": None, "message": f"Coze 调用失败: {e.message}"}), 502
```

- 禁止裸 `except:` 吞掉所有异常（应捕获具体异常）。
- **统一响应契约**：`{"code": <int>, "data": <any>, "message": "<可读信息>"}`，code 语义：`0` 成功 / `400` 参数 / `401` 鉴权 / `403` 禁止 / `404` 未找到 / `409` 冲突 / `500` 服务器 / `502` 上游。见 [04-安全与数据规范](./04-安全与数据规范.md#一统一错误码).
- 日志用 `app.logger` 或标准 `logging`，禁止 `print()` 调试残留。
- 业务异常统一继承 `modules.common.errors.AppError`，用 `bad_request()/unauthorized()/not_found()/forbidden()/conflict()/server_error()/bad_gateway()` 工厂方法构造。

```python
# ✅ 推荐：业务异常用工厂构造
raise bad_request("请输入 PAT Token")
```

### 3.4 路由与接口规范

- 路由函数保持**薄**（只做参数解析 + 调用 service + 序列化响应），业务逻辑下沉到 `coze_client` / `work_manager` / `modules/*/`。
- RESTful 语义：
  - `GET /api/knowledge/entries` 列表、`GET /api/knowledge/entries/<id>` 详情
  - `POST /api/knowledge/import` 创建导入
  - `PUT /api/admin/config` 更新配置
  - `DELETE /api/admin/works/<id>` 删除
- **模块蓝图命名**：`Blueprint("<模块>", __name__, url_prefix="/api/<模块>")`，蓝图文件统一命名 `routes.py`。
- 参数校验：所有用户输入（含 query/body）必须校验类型与边界，非法输入返回 400。多文件/复杂参数用白名单（`PARAM_TYPES`）约束。
- 敏感字段（PAT Token、access_code）**只进不出**：任何对外响应必须经 `get_work_public()` 过滤。
- 返回必须统一走响应契约（见 3.3），禁止直接 `jsonify({"error": ...})` 裸结构（兼容旧接口除外，需标注 `[SHOULD]`）。

### 3.5 SSE 流式接口约定

- 响应头：`Content-Type: text/event-stream`，`Cache-Control: no-cache`。
- 事件格式：`data: {json}\n\n`，每事件独立换行。
- 结束时发送 `event: done` 或 `data: {"done": true}`。
- 必须处理客户端断开（`GeneratorExit` / `try-finally` 释放连接）。
- 禁止在 SSE 中发送非 JSON 文本（会破坏前端解析）。

### 3.6 模块间依赖约定

- `modules/<模块>/` 之间禁止直接互相 import 内部符号；跨模块共享走 `modules/common/`（dto.py / errors.py）。
- 引擎层（如 `knowledge_parser` / `knowledge_linker`）设计为**纯函数 + 依赖注入**：不直接 import 数据层，通过参数注入（如 `store`），便于单测与解耦。

```python
# ✅ 推荐：依赖注入解耦（knowledge_markdown_io.py 模式）
def import_files(file_items, target_type, conflict_strategy, store, progress_cb=None):
    """批量导入，store 由调用方注入。"""
```

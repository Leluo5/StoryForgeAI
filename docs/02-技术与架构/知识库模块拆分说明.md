# 知识库模块拆分说明

> 版本：v1.0 · 状态：规划中（2026-11-10）
> 适用范围：StoryForgeAI 模块化改造 —— 知识库模块（F5）独立为与小说创作模块同级的独立功能模块
> 维护：02-技术与架构｜关联：[文档中心](../README.md)、[目录结构](./目录结构.md)、[F5 需求澄清](../04-功能交付档案/F5-知识库管理/01-需求澄清.md)、[改造路线图](../03-规划与路线/小说AI写作软件改造实施路线图.md)
> 依据：F5 需求澄清 v1.1 + 改造路线图 v1.1（§9.5 创作工具联动规则）
> 权威口径：本说明为目标架构设计（不写实现代码）；模块拆分落地以改造路线图 P4-T18（F5）与 P3 核心开发（小说创作）为准

## 一、背景与约束

### 1.1 背景

StoryForgeAI 现为「Coze 作品展示与在线体验平台」，后端为单应用 Flask（`app.py` 承担全部路由 + SSE 流式代理，约 1193 行），前端为 IIFE 单文件 SPA（`app.js`，约 2337 行）。按 [改造路线图](../03-规划与路线/小说AI写作软件改造实施路线图.md)，项目将改造为专业小说 AI 写作软件，需在既有架构上新增知识库管理（F5）与小说创作（角色 Agent 驱动）两个同级功能模块。

### 1.2 现状探查结论

现有代码中知识库相关逻辑为零散内嵌，无完整模块：

| 现状位置 | 逻辑 | 拆分去向 |
| --- | --- | --- |
| `app.py` L225 | `get_datasets()` 获取 Coze 知识库列表路由 | 迁入知识库模块路由 |
| `app.py` L254 | `/api/datasets/import` 导入知识库（转为 agent 作品） | 迁入知识库模块路由 |
| `coze_client.py` L102 | `get_datasets()` 封装 Coze dataset 拉取 | 共享底座，不迁移 |
| `work_manager.py` L146 | `import_knowledge_base()` 将 dataset 转为 agent 作品 | 知识库模块经公共接口调用 |
| `app.js` L2373 / L2398 | 导入知识库 UI + toast | 迁入知识库前端面板 |

小说创作模块（角色 Agent 机制、项目/章节/角色存储、调度器）当前**尚未编码**，其目标结构按改造路线图 P3/P4 规划。

### 1.3 设计约束

- **边界守卫**：知识库模块与小说创作模块为系统同级功能模块，彼此无交叉依赖、无耦合代码。
- **数据流转**：知识库条目仅可注入角色上下文（只读），角色不可写知识库条目（沿用路线图 §9.5）。
- **技术栈标准**：沿用 Flask Blueprint + 原生 JS 模块化 + JSON 文件存储，不引入新框架。
- **功能保留**：知识库模块拆分后须保留 F5 全部原有能力（含 v1.1 大纲自动提取）及既有 dataset 导入能力。

## 二、拆分定位与模块边界

### 2.1 模块并列关系

改造后系统在**系统层级完全并列**地组织两个功能模块，均挂载于 `app.py` 统一入口：

```text
StoryForgeAI（Flask 主应用）
├── 知识库模块（F5）      注册名：knowledge_base    路由前缀：/api/knowledge/*
└── 小说创作模块（P3/P4）  注册名：novel_creation    路由前缀：/api/novel/*
```

两模块互不 import 对方代码，仅共享底座（`coze_client` / `config_loader` / 公共契约层）。

### 2.2 模块边界（无交叉依赖）

| 边界项 | 知识库模块（F5） | 小说创作模块（P3/P4） | 边界约束 |
| --- | --- | --- | --- |
| 代码依赖 | 依赖 `coze_client`、`config_loader`、公共契约层 | 依赖 `coze_client`、`config_loader`、公共契约层 | 两模块不互相 import |
| 数据存储 | `data/knowledge/*.json`（知识条目） | `data/works/*.json` + 项目/角色存储 | 各自独立数据域，不共享写 |
| 数据流转 | 知识条目 → 角色上下文（只读注入） | 角色 Agent 只读引用知识条目 | 角色不可写知识条目 |
| 前端资源 | `static/js/knowledge_panel.js` | `static/js/novel_editor.js` | 独立文件，经 `app.js` 入口加载 |
| 编排层 | `app.py` 统一注册蓝图 + 组装上下文 | `app.py` 统一注册蓝图 | 编排逻辑集中于入口，不在模块内 |

### 2.3 边界实现规则

- 知识库模块**禁止** import 小说创作模块任何符号。
- 小说创作模块**禁止** import 知识库模块任何符号。
- 知识条目注入角色上下文，经公共契约层 `RoleContextDTO` 单向传递（知识库 → 小说创作），不产生代码依赖。
- 模块间公共类型、上下文 DTO 统一放公共契约层 `modules/common/`，两模块共同依赖。

## 五、路由配置与模块入口

### 5.1 蓝图注册（`app.py` 入口层）

```python
# app.py —— 仅注册蓝图，不再内联知识库/小说创作路由
from modules.knowledge_base import create_blueprint as kb_bp

app.register_blueprint(kb_bp, url_prefix="/api/knowledge")
```

### 5.3 兼容性保留（旧路由别名）

为兼容既有前端旧引用，`/api/datasets` 与 `/api/datasets/import` 保留一个版本作为重定向别名，指向 `/api/knowledge/*` 对应端点，避免旧页面 404。别名在新版前端确认无引用后移除。

### 5.4 导航菜单与模块入口（并列）

`index.html` 主导航菜单在系统层级并列，与 `app.js` 路由切换对应：

| 现状菜单 | 目标菜单 | 模块入口 |
| --- | --- | --- |
| 首页 | 首页 | `app.js`（默认视图） |
| 体验 | 小说创作 | `novel_editor.js`（角色驱动工作台） |
| 管理后台 | 管理后台 | `app.js`（管理视图） |
| 无 | 知识库 | `knowledge_panel.js`（知识库面板） |

前端由 `app.js` 入口统一加载 `knowledge_panel.js` 与 `novel_editor.js`（ES Module），两模块互不引用对方，仅在 `app.js` 内按导航切换挂载。

## 七、风险与回滚

| 风险 | 影响 | 应对 | 回滚 |
| --- | --- | --- | --- |
| `app.py` 重构为蓝图注册引入路由回归 | 既有 API 失效 | 迁移后全量路由契约测试；保留旧路由别名 | 保留旧别名一个版本；`git revert` 蓝图注册 |
| 零散逻辑迁移遗漏 | 功能缺失 | 按 §1.2 现状核对清单逐项迁移 | 迁移前打 tag，逐项回退 |
| 前端单文件拆分引入 ES Module 加载顺序问题 | 面板不渲染 | 入口 `app.js` 统一 import，模块内无全局依赖 | 回退为 IIFE 顺序加载 |
| 数据域新增 `data/knowledge/` 未入版本控制 | 运行时数据丢失 | 加入 `.gitignore`，备份脚本覆盖 | 从备份恢复 |

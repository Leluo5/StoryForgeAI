## 一、背景与约束

### 1.1 现状基线

现有代码处于「文档注释 + 骨架」阶段：

| 层 | 现状 | 结论 |
| --- | --- | --- |
| `modules/novel_creation/` | 6 文件，5 个纯空壳（仅 `routes.py` 有蓝图工厂骨架） | 需全新实现 |
| `modules/knowledge_base/` | 6 文件，5 个纯空壳（仅 `routes.py` 有蓝图工厂骨架） | 需全新实现 |
| `modules/common/` | `errors.py`（AppError 体系）、`dto.py`（RoleContextDTO）已实现 | 直接复用 |
| `app.py` | 手动 `@app.route`，无蓝图注册，1194 行 | 需注册 modules 蓝图 |
| 底座（ConfigLoader/WorkManager/CozeClient） | 完整实现 | 直接复用 |

### 1.2 设计约束

1. **沿用 Flask 2.x + 原生 JS**，不引入前端框架。
2. **存储用 JSON 文件**（个人规模），预留 SQLite 迁移接口（并发 ≥ 50 时评估）。
3. **长任务走线程池/任务队列**，不阻塞 SSE 主通道。
4. **边界守卫**：角色 Agent 禁止跨角色读写、禁止访问管理端、禁止写知识库（见[功能边界定义](../01-产品与设计/功能边界定义.md)）。

## 三、关键数据流

### 3.1 角色 Agent 调用流（P3 核心）

```text
前端调用 /api/roles/<id>/agents/invoke
  → RoleAgentScheduler.invoke_role_agents(role_id, step_order, context)
    → 读取 bindings（enabled=true，按 step_order 排序）
    → 逐 binding 命中（step == 当前 或 step <= 当前）
      → 注入 role_id 系统提示词（身份一致性）
      → 恢复 memory_state（记忆连续性）
      → CozeClient 调用 agent（线程池非阻塞）
      → merge_result 透传上下文
    → 写回 memory_state（按 role_id 命名空间）
  → 返回合并后 context
```

### 3.2 多角色协同流

```text
开启协同 → project_id 获取写锁 → 各角色 Agent 依序调用（并行读/串行写）
  → 每角色输出写独立上下文 → 汇总到章节 → 释放写锁
  → 冲突检测（时间戳校验，后写覆盖告警）
```

### 3.3 工具-角色联动流（P4）

```text
调用工具 → ToolRegistry.dispatch(tool_name)
  → 若工具声明 role_link 且绑定角色 → 读取角色上下文（只读注入）
  → 执行工具 → 结果可选回写角色上下文 / 生成章节
```

### 3.4 F5/F6/F7 数据流

```text
F5：知识库条目 → 注入角色上下文（只读）→ 拆文后触发大纲四维度提取
F6：剧情推衍（角色上下文透传）→ 一步一断 → 多线程隔离
F7：剧情树节点 → 作推衍起始上下文 → 推衍结果回写（原子 + 环路检测）
F7 分支管理：主节点挂载多分支（branch_id 隔离）→ 创建/重命名/删除(二次确认)/排序/切换
  → 切换仅加载该分支 node_ids + content（数据隔离）→ 删除非空分支拒绝
F7 版本管理：剧情树变更 → 自动保存（阈值触发）或手动创建 → 生成 PlotVersion 快照
  → 切换/回滚（整体还原 snapshot，原子替换）→ 对比（差异摘要）→ 全部操作写日志
```

## 四、角色 Agent 调度机制设计（P2-T2）

### 4.1 调度器核心逻辑（伪代码）

```python
# modules/novel_creation/role_agent_scheduler.py
class RoleAgentScheduler:
    def __init__(self, role_store, agent_client, executor, max_workers=8):
        ...

    def invoke_role_agents(self, role_id, step_order, context):
        # 1. 读取启用的绑定并按 step_order 排序
        bindings = self.role_store.get_bindings(role_id, enabled=True)
        bindings = sorted(bindings, key=lambda b: b.step_order)
        # 2. 命中当前步骤或此前步骤的绑定
        for binding in bindings:
            if binding.step_order == step_order or binding.step_order <= step_order:
                # 3. 身份一致性：系统提示词前缀
                sys_prompt = f"你扮演角色{role_id}，保持身份一致"
                # 4. 记忆连续性：按 role_id 恢复
                memory = self.role_store.get_memory(role_id, binding.agent_id)
                # 5. 同步调用走线程池（非阻塞）
                result = self._invoke_sync(binding.agent_id, context, memory, sys_prompt)
                # 6. 上下文透传合并
                context = merge_result(context, result)
                # 7. 写回记忆（role_id 命名空间）
                self.role_store.set_memory(role_id, binding.agent_id, result)
        return context
```

### 4.2 身份一致性

| 机制 | 实现 |
| --- | --- |
| 系统提示词前缀 | `你扮演角色<role_id>，保持身份一致` |
| 会话隔离 | `conversation_id = f"{role_id}:{agent_id}"`，禁止跨角色复用 |

### 4.3 记忆连续性

| 机制 | 实现 |
| --- | --- |
| 记忆存储 | `Agent会话` 存 `memory_state`（JSON），按 `role_id` 独立命名空间 |
| 恢复 | 每次调用前 `get_memory(role_id, agent_id)` |

### 4.4 行为逻辑独立性

| 机制 | 实现 |
| --- | --- |
| Agent 独立 | 每角色绑定独立 `agent_id`，不共享上下文 |
| 写锁 | 多角色并行用 `project_id` 锁粒度（`fcntl`/`msvcrt`）防写冲突 |

## 五、11 步预设流程引擎设计（P2-T3）

### 5.1 流程配置结构

```python
# modules/novel_creation/step_flow_engine.py
DEFAULT_STEPS = [
    {"step_order": 1,  "name": "外貌特征", "desc": "角色外观设定", "tool": "gen_character_image"},
    {"step_order": 2,  "name": "个性特点", "desc": "性格特质", "tool": None},
    {"step_order": 3,  "name": "思维方式", "desc": "认知模式", "tool": None},
    {"step_order": 4,  "name": "个人能力", "desc": "技能特长", "tool": None},
    {"step_order": 5,  "name": "情感状态", "desc": "当前情绪", "tool": "emotion_analysis"},
    {"step_order": 6,  "name": "文化背景", "desc": "出身文化", "tool": None},
    {"step_order": 7,  "name": "信仰道德", "desc": "价值观与信念", "tool": None},
    {"step_order": 8,  "name": "成长线", "desc": "成长弧线", "tool": None},
    {"step_order": 9,  "name": "经历沉淀", "desc": "过往经历", "tool": None},
    {"step_order": 10, "name": "人际关系", "desc": "社交网络", "tool": None},
    {"step_order": 11, "name": "情节发展", "desc": "参与剧情", "tool": "gen_chapter"},
]
```

### 5.2 流程引擎接口

| 方法 | 说明 |
| --- | --- |
| `get_steps()` | 返回完整 11 步 |
| `reorder(new_order)` | 重排 step_order |
| `trigger_step(role_id, step_order, context)` | 单步触发 |
| `trigger_flow(role_id, context)` | 全流程顺序触发 |

### 5.3 流程规则

1. `step_order` 1-11 完整、可重排、可增删。
2. 单角色绑定多 Agent 时按 `step_order` 排序，命中当前步骤或此前步骤即调用。
3. 单步触发（`trigger_step`）与全流程触发（`trigger_flow`）双模式。

## 六、工具注册中心设计（P4-T1 预置）

### 6.1 注册中心

```python
# modules/novel_creation/tool_registry.py（P4 实现）
class ToolRegistry:
    def register(self, name, handler, role_link=None, is_long_task=False): ...
    def dispatch(self, name, params, role_id=None): ...
    def list_tools(self): ...
```

### 6.2 工具元数据

| 字段 | 说明 |
| --- | --- |
| `name` | 注册名（`gen_chapter` 等） |
| `handler` | 调用函数 |
| `role_link` | 是否联动角色（`read_role_ctx` / `write_role_ctx` / `None`） |
| `is_long_task` | 是否长任务（走队列） |

### 6.3 分支管理工具注册（F7）

| 工具注册名 | handler | 联动 | 说明 |
| --- | --- | --- | --- |
| `plot_branch_create` | `create_plot_branch` | 是 | 创建分支（挂载主节点） |
| `plot_branch_rename` | `rename_plot_branch` | 是 | 重命名分支 |
| `plot_branch_delete` | `delete_plot_branch` | 是 | 删除分支（二次确认 + 非空拒绝） |
| `plot_branch_reorder` | `reorder_plot_branch` | 是 | 分支排序（拖拽） |
| `plot_branch_switch` | `switch_plot_branch` | 是 | 切换分支（加载隔离内容） |

> 五个工具均 `is_long_task=False`（同步操作，走 SSE 通道）；分支隔离在 handler 内校验。

| 工具注册名 | handler | 联动 | 说明 |
| --- | --- | --- | --- |
| `plot_version_create` | `create_plot_version` | 是 | 创建剧情树版本（自动/手动） |
| `plot_version_switch` | `switch_plot_version` | 是 | 切换/回滚剧情树版本（原子还原） |
| `plot_version_compare` | `compare_plot_version` | 是 | 对比两版本差异（结构+内容） |

> 三个工具均 `is_long_task=False`（同步快照/对比，走 SSE 通道）；权限校验在 handler 内拦截（删除/重命名仅授权）。

## 七、存储层设计（P2-T1）

### 7.1 存储抽象

| 接口 | 实现 |
| --- | --- |
| JSON 文件存储 | `data/projects/*.json`（每项目一文件）+ `data/knowledge/*.json`（每条目一文件） |
| 文件锁 | `fcntl`（Linux）/ `msvcrt`（Windows）封装 `FileLock` |
| 迁移预留 | `StorageBackend` 抽象接口，JSON 实现 + SQLite 预留（并发 ≥ 50 时评估） |

### 7.2 存储目录

```text
data/
├── global_config.json       # 站点配置（沿用）
├── works/                   # 作品（沿用）
├── projects/                # 小说项目（每项目一文件）
│   └── <project_id>.json    # 内含 plot_branches[] + plot_versions[] + version_logs[]（F7 内嵌）
└── knowledge/               # 知识库条目（每条目一文件）
    └── <entry_id>.json
```

> F7 分支管理：`PlotBranch` 内嵌于项目文件 `plot_branches[]`，随项目原子读写。
> F7 版本管理：`PlotVersion` 与 `VersionOperationLog` 内嵌于项目文件 `plot_versions[]` / `version_logs[]`，随项目原子读写；版本快照量级大时可评估迁移 `data/plot_versions/<project_id>_<version_no>.json`。

## 十、风险与回滚

| 风险 | 应对 |
| --- | --- |
| JSON 并发写坏 | 文件锁 + 崩溃恢复（临时文件原子写） |
| 线程池阻塞 SSE | 长任务走队列，SSE 通道独立 |
| 角色上下文串线 | 命名空间隔离 + 自动化测试（R-05/R-08） |
| 记忆丢失 | `memory_state` 持久化 + 崩溃恢复测试（D-01） |
| SQLite 迁移成本 | 预留 `StorageBackend` 抽象，迁移不动领域层 |

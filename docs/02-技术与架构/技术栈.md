## 一、选型原则

本项目的技术栈遵循以下原则：

1. **最小可行**：目标是「让小说作者不写一行代码即可获得专业 AI 写作工作台」，技术复杂度应压到最低。
2. **单一运行时**：前后端尽量轻量，避免引入重型构建链（Webpack/Vite）、复杂框架（React/Vue 全家桶）和数据库服务。
3. **快速启动**：`pip install` + `python app.py` 即可运行，方便创作者本机或轻量服务器部署。
4. **够用即可**：数据量级为「个人作品集」，JSON 文件存储足以胜任，无需关系型数据库。

## 二、总体技术栈一览

| 层 | 技术 | 版本/说明 | 选型理由 |
|----|------|----------|---------|
| **运行时** | Python 3 | 3.10+（项目内 .pyc 缓存为 cpython-310） | 后端生态成熟，requests/flask 轻量 |
| **Web 框架** | Flask | 2.x | 单应用承载全部路由 + SSE，轻量无绑定 |
| **HTTP 客户端** | requests | 2.x | 调用 Coze Open API，同步简单直接 |
| **跨域** | flask-cors | 3.x | 前后端分离/本地调试跨域支持 |
| **模板** | Jinja2 | Flask 内置 | 单页应用壳，`templates/index.html` |
| **前端** | 原生 JavaScript | ES6+，IIFE 单文件（约2337行） | 无构建链、无框架依赖，SPA 状态机管理 |
| **样式** | 原生 CSS | 单文件（约1403行） | 支持浅/深主题，无 CSS 预处理器 |
| **数据存储** | JSON 文件 | `data/global_config.json` + `data/works/*.json` | 个人作品集规模，零运维 |

## 三、各模块技术明细

### 3.1 后端模块

| 模块 | 文件 | 技术要点 |
|------|------|---------|
| 主应用 | [app.py](app.py) | Flask 路由 + SSE 流式代理（约1193行） |
| 全局配置 | [config_loader.py](config_loader.py) | 站点名/密码/主题/LLM配置 的 JSON 读写 |
| Coze 客户端 | [coze_client.py](coze_client.py) | 封装 Coze Open API（requests） |
| 作品管理 | [work_manager.py](work_manager.py) | 作品 JSON 持久化 + `get_work_public` 字段过滤 |

**Coze Open API 对接清单**（coze_client.py 封装的端点）：

- `/v1/bots` — 拉取智能体列表
- `/v1/bots/{id}` — 获取智能体详情
- `/v1/datasets` — 拉取知识库
- `/v1/workflows` — 拉取工作流
- `/v1/workflow/run` — 运行工作流（非流式）
- `/v1/workflow/stream_run` — 运行工作流（流式 SSE）
- `/v3/chat` — 智能体对话（流式 SSE）
- `/v1/files/upload` — 文件上传

### 3.2 前端模块

| 模块 | 文件 | 技术要点 |
|------|------|---------|
| 应用逻辑 | [static/js/app.js](static/js/app.js) | IIFE 单文件，`state` 全局状态 + `api` 请求封装 + 视图渲染 |
| 样式 | [static/css/style.css](static/css/style.css) | 原生 CSS，CSS 变量实现浅/深主题 |
| 页面 | [templates/index.html](templates/index.html) | 单页应用，四种页面视图 |

**前端核心状态机**：

- 三种交互模式：`chat`（对话）/ `form`（表单）/ `mixed`（混合）
- 四种页面视图：`home`（大厅）/ `work`（体验）/ `admin`（后台）/ 访问码弹窗
- 关键状态：`works`、`currentWork`、`adminToken`、`accessTokens`、`conversationId`、`isStreaming`、`botList`、`workflowList`、`datasetList`

## 四、技术决策记录（ADR 摘要）

| # | 决策点 | 选择 | 备选方案 | 理由 |
|---|--------|------|---------|------|
| 1 | 后端框架 | Flask | Django / FastAPI | 路由简单、SSE 支持直接、无 ORM 绑定，适合轻量代理层 |
| 2 | 前端框架 | 原生 JS SPA | React / Vue | 无构建链，单文件即可维护；页面视图少、交互模式固定 |
| 3 | 数据存储 | JSON 文件 | SQLite / MySQL | 个人作品集规模，文件存储零运维、易备份 |
| 4 | 主题 | CSS 变量 | Sass / Tailwind | 浅/深双主题用 CSS 变量足够，避免预处理器依赖 |
| 5 | Coze 调用 | 同步 requests | aiohttp 异步 | 请求量小、无高并发需求，同步实现更易调试 |
| 6 | 部署 | 单进程 Flask | Gunicorn + Nginx | 演示/个人场景，`python app.py` 直接跑 |

## 七、安全与运维考量

| 项 | 现状 | 建议 |
|----|------|------|
| 管理接口鉴权 | `require_admin` 装饰器为空壳 | 生产部署前补齐 JWT/Session 鉴权 |
| 管理密码 | 明文存于 global_config.json | 迁移至环境变量或密码哈希 |
| PAT Token | 存于作品 JSON 文件 | 迁移至密钥管理服务/环境变量 |
| 会话 | 进程内存字典 | 单机演示可接受；多进程需外部存储 |
| 部署 | 单进程 Flask | 生产建议 Gunicorn + Nginx（如需公网） |

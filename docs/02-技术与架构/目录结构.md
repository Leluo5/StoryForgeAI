## 一、目录设计原则

1. **高内聚低耦合**：后端按职责分模块（路由 / Coze 客户端 / 作品管理 / 配置），前端按静态资源分离（css / js / 模板）。
2. **数据与代码分离**：运行时数据（`data/`）独立于源码目录，便于备份与版本控制豁免。
3. **零构建链**：前端无打包步骤，`static/` + `templates/` 直接由 Flask 托管。
4. **脚本即文档**：`start.bat` / `start.sh` 承载一键启动，避免人工拼命令。

## 四、数据流说明

```text
┌─────────────┐    HTTP    ┌──────────────┐    Coze Open API    ┌────────────┐
│  浏览器 SPA   │ ────────→ │  Flask app.py │ ──────────────────→ │  Coze 平台   │
│ app.js       │ ←───────  │  (注册模块)   │ ←────────────────── │  (bots/...) │
│  +模块JS      │   JSON/SSE  └──────┬───────┘                     └────────────┘
└─────────────┘                     │
                                    ├──── modules/knowledge_base ──→ data/knowledge/*.json
                                    ├──── modules/novel_creation ──→ data/projects/*.json
                                    ├──── work_manager ──→ data/works/*.json
                                    └──── config_loader ──→ data/global_config.json
```

- 浏览器 → Flask：REST + SSE 流式（聊天/工作流体验）
- Flask → Coze：`coze_client` 用 PAT Token 调用 Open API
- Flask → 数据：`work_manager` 写作品 JSON，`config_loader` 写站点配置
- Flask → 知识库：`knowledge_base` 模块写 `data/knowledge/*.json`（每条目一文件，文件锁）
- Flask → 小说项目：`novel_creation` 模块写 `data/projects/*.json`（每项目一文件）
- 模块间契约：知识库经 `common/dto.py::RoleContextDTO` 只读注入小说创作角色上下文

## 五、版本控制建议

| 目录/文件 | 建议 | 理由 |
|-----------|------|------|
| `__pycache__/` | **加入 .gitignore** | Python 字节码缓存，勿入库 |
| `data/works/` | **加入 .gitignore**（或仅提交示例） | 含 PAT Token 敏感凭据，且为运行时数据 |
| `data/knowledge/` | **加入 .gitignore** | 知识条目为运行时数据，且可能含用户敏感创作内容 |
| `data/projects/` | **加入 .gitignore** | 小说项目为运行时数据，含角色与章节内容 |
| `data/global_config.json` | 谨慎提交 | 含管理密码明文，建议仅提交模板 |
| `static/`、`templates/`、`*.py`、`modules/` | 正常提交 | 源码 |
| `扣子平台功能介绍/`、`*.zip`、`*.docx` | 视需要 | 附带素材，非运行代码 |
